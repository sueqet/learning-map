单表查询基础

从一张表里取数：投影、过滤、排序、分页、去重，以及 NULL 与逻辑执行顺序这两个最容易踩坑的地方。

✓本节学习目标

  • 能写出只取所需列、带别名的 SELECT / FROM，并说清 SELECT * 的代价。
  • 能用 WHERE 配合比较与 AND / OR / NOT 过滤行，并熟练使用 BETWEEN / IN / LIKE / IS NULL 四类谓词。
  • 能说清 NULL 的三值逻辑，知道什么时候必须用 IS NULL / COALESCE。
  • 能写 ORDER BY 多列排序与 LIMIT 分页，识别「分页不稳定」与深分页的性能问题。
  • 能解释 DISTINCT 是「整行组合去重」，并避开它与 ORDER BY 的冲突。
  • 能背出 SELECT 的逻辑执行顺序，并用它解释「别名为什么不能在 WHERE 里用」。

知识点SELECT / FROM / 列别名 / 常量列select-basic · 查询的地基：投影与数据源

SELECT 是 SQL 里最常用的语句，它由两个核心子句组成：FROM 指明数据从哪张表来，SELECT 决定最终输出哪些列——这个动作叫投影（projection）。写法上 SELECT 在前、FROM 在后，但语义上 FROM 先执行（见本页最后一个知识点）。

列别名（alias）用 AS 定义，AS 可以省略，但建议保留以提高可读性。别名只影响结果集的列标题以及后续对结果的引用，不会改变表结构。表达式（amount * 2）、函数调用、常量都必须起别名，否则结果列名会是一整串表达式，难以引用。

常量列（constant column）指在 SELECT 列表里直接写死的字面量，例如标记数据来源或导出日期。它不来自任何表，因此每一行都相同。MySQL 还允许完全不带 FROM 的查询（如 SELECT 1 + 1;），Oracle 里则需要写成 SELECT 1 + 1 FROM dual;。

  • SELECT 不改变存储的数据，只决定「返回什么」；FROM 决定「从哪来」。
  • 列别名可以在 ORDER BY / HAVING 中引用，不能在 WHERE 中引用。
  • 用 * 取全部列方便调试，生产代码应显式列出需要的列。
select-basic.sql
-- 1) 最基础：指定列，结果 8 行 3 列
SELECT id, name, city FROM customers;

-- 2) 列别名：结果列标题变成「客户姓名 / 城市 / 会员等级」
SELECT name AS 客户姓名, city AS 城市, level AS 会员等级
FROM customers;

-- 3) 常量列与表达式列：每一行都带上同样的标记
SELECT name, city, '2024 年度' AS 统计口径, 1 AS 是否有效
FROM customers
LIMIT 3;

-- 4) 别名可以在 ORDER BY 里引用（但不能写在 WHERE 里）
SELECT name AS 姓名, signup_date AS 注册日期
FROM customers
ORDER BY 注册日期 DESC;
写法结果列标题说明
SELECT name FROM customersname原样输出列名
SELECT name AS 客户姓名 …客户姓名用 AS 起别名
SELECT name 客户姓名 …客户姓名省略 AS 也能跑，但可读性差
SELECT '2024 年度' AS 统计口径 …统计口径常量列，每行值相同
SELECT amount * 2 AS 双倍金额 …双倍金额表达式列必须起别名
★

核心要点：SELECT 负责「输出什么」、FROM 负责「从哪来」；别名是给结果集起的名字，不是给表改列名。表达式一定要起别名。

!

易错：SELECT * 会把全部列都传回来——多传无用列、增加网络与内存开销、容易让覆盖索引（covering index）失效，列顺序变化时下游代码还可能错位。调试可以随手用，生产代码请显式列出列。

知识点WHERE 与比较、逻辑运算符where-basic · 逐行过滤，只留符合条件的行

WHERE 在 FROM 之后对每一行做判断，只有判断结果为 TRUE 的行才会进入后续步骤。判断由比较运算符（comparison operator）与逻辑运算符（logical operator）组合而成。

比较运算符有 =、<>（或 !=）、<、<=、>、>=。字符串与日期要用单引号包裹（MySQL 里双引号默认也是字符串，但受 ANSI_QUOTES 影响，建议统一用单引号）；数值不要加引号，否则会触发隐式类型转换。

逻辑运算符 AND / OR / NOT 的优先级是 NOT > AND > OR。不确定就加括号——这是本页最容易被扣分的细节，也是面试常问的点。

性能上，WHERE 里的列尽量保持「裸列」形式：对列做函数或运算（如 YEAR(order_date) = 2024）通常会让索引失效；等值比较的值的类型要与列定义一致，避免隐式转换。

  • WHERE 只保留判断结果为 TRUE 的行；FALSE 与 UNKNOWN 都会被丢弃。
  • 优先级 NOT > AND > OR，括号最可靠。
  • 与 NULL 做比较的结果是 UNKNOWN，永远不会被 WHERE 保留。
where-basic.sql
-- 等值过滤：2 行（张伟、赵磊）
SELECT id, name, city, level FROM customers WHERE city = '北京';

-- 多条件 AND：4 行（1002 / 1004 / 1010 / 1012）
SELECT id, amount, status FROM orders
WHERE status = 'paid' AND amount >= 1000;

-- 不等号：5 行（不含 city 为 NULL 的周涛）
SELECT id, name, level FROM customers WHERE level <> '普通';

-- NOT：同样 5 行，因为 NOT UNKNOWN 还是 UNKNOWN
SELECT id, name FROM customers WHERE NOT (city = '北京');

-- 优先级演示：加括号 2 行，不加括号 3 行
SELECT id, name, city, level FROM customers
WHERE (city = '北京' OR city = '上海') AND level = '金卡';   -- 2 行

SELECT id, name, city, level FROM customers
WHERE city = '北京' OR city = '上海' AND level = '金卡';      -- 3 行：AND 先算

核心要点：记住三句话——WHERE 只留 TRUE；优先级 NOT > AND > OR；不确定就加括号。

!

易错：WHERE city = NULL 一行都返回不了，必须写 IS NULL；WHERE amount = '1000' 在 MySQL 里能跑（隐式转换），但会让索引失效（列做隐式类型转换后无法用于查找）。

知识点BETWEEN / IN / LIKE / IS NULLwhere-special · 四类专用谓词

除了比较运算符，SQL 还提供四类语义更清晰的谓词（predicate）：BETWEEN 做区间判断、IN 做集合成员判断、LIKE 做模式匹配、IS NULL 判断空值。它们让条件更短更可读，但各有边界与性能特性。

BETWEEN a AND b 是闭区间，包含 a 和 b 两个端点，等价于 col >= a AND col <= b。NOT BETWEEN 是它的反义，但遇到 NULL 同样返回 UNKNOWN。

IN (v1, v2, …) 等价于一串 OR 等值比较，可读性更好，通常也能走索引；但 NOT IN 一旦子查询结果里出现 NULL，整条查询会返回空集（模块 05 详解）。LIKE 用 %（任意长度字符，含 0 个）和 _（恰好一个字符），前导通配符（如 '%伟'）会让 B-Tree 索引失效。

IS NULL / IS NOT NULL 是判断空值的唯一正确方式，因为任何与 NULL 的比较都返回 UNKNOWN。MySQL 的 LIKE 默认不区分大小写（取决于列的排序规则 collation）；PostgreSQL 要用 ILIKE 才是忽略大小写。

  • BETWEEN 是闭区间；日期范围要留意上界当天的边界。
  • IN 列表可写常量，也可写子查询；列表过长（几千个）会带来解析开销。
  • 判断空值只能用 IS NULL / IS NOT NULL，= NULL 恒不成立。
where-special.sql
-- BETWEEN 闭区间：4 行（1002 / 1007 / 1010 / 1012）
SELECT id, order_date, amount FROM orders WHERE amount BETWEEN 500 AND 1500;

-- IN 集合成员：5 行
SELECT id, name, city FROM customers WHERE city IN ('北京', '上海', '广州');

-- NOT IN：3 行（周涛的 city 是 NULL，任何比较都不成立）
SELECT id, name, city FROM customers WHERE city NOT IN ('北京', '上海');

-- LIKE 前缀匹配：1 行（张伟）
SELECT id, name FROM customers WHERE name LIKE '张%';

-- LIKE 单字符通配：1 行（张伟）
SELECT id, name FROM customers WHERE name LIKE '_伟';

-- IS NULL：1 行（周涛）
SELECT id, name, city FROM customers WHERE city IS NULL;

!

易错：NOT IN 的子查询只要出现一个 NULL，整条查询就返回空集。反连接（anti join）请优先用 NOT EXISTS 或 LEFT JOIN … WHERE … IS NULL。

◆

边界提醒：对 DATETIME 列写 BETWEEN '2024-01-01' AND '2024-03-31' 会漏掉 3 月 31 日当天的时间部分（因为上界等价于当天 00:00:00）。更稳的写法是 >= '2024-01-01' AND < '2024-04-01'。

★

核心要点：选择原则——区间用 BETWEEN、离散集合用 IN、模糊匹配用 LIKE、空值用 IS NULL。

知识点ORDER BY 排序与 LIMIT 分页order-limit · 让结果有序、可控

关系表是无序集合：不加 ORDER BY 时返回顺序由存储引擎与执行计划决定，不能依赖。ORDER BY 指定排序键，可以多列排序（前面的列值相同时才比较后面的列），每列可独立指定 ASC（升序，默认）或 DESC（降序）。

LIMIT 用来截断结果，常用于「取 TopN」和分页。MySQL 支持 LIMIT n OFFSET m 与简写 LIMIT m, n——注意简写里 m 是偏移量、n 是行数，顺序最容易记反。

分页必须有确定的排序键，否则同一页的数据可能在两次查询之间漂移（出现重复或遗漏）。排序键最好能唯一确定顺序，例如在末尾追加 id 作为最后一级排序。

性能上，LIMIT 100000, 20 这类深分页会先扫描并丢弃前 10 万行，代价随偏移量线性增长。优化方向：游标分页（keyset pagination）——用 WHERE id > 上一页最后一个 id 直接定位；或延迟关联——先用覆盖索引取主键，再回表取数据（模块 10 详解）。

  • NULL 在 MySQL 的 ORDER BY 中：ASC 时排最前，DESC 时排最后（部分数据库相反）。
  • ORDER BY 可以引用列别名，也可以写 SELECT 列表里的序号（如 ORDER BY 2 DESC）。
  • LIMIT 不带 ORDER BY = 顺序不确定。
order-limit.sql
-- 单列排序：NULL 的周涛排最前（MySQL 中 ASC 时 NULL 最小）
SELECT id, name, city FROM customers ORDER BY city;

-- 多列排序：先按会员等级，等级相同时再按 id
SELECT id, name, level FROM customers ORDER BY level, id;

-- 取金额最高的 3 笔订单：1004(2297) / 1012(1497) / 1010(1458)
SELECT id, amount FROM orders ORDER BY amount DESC LIMIT 3;

-- 分页第 2 页（每页 3 条）：LIMIT 3 OFFSET 3 与 LIMIT 3, 3 等价
SELECT id, amount FROM orders ORDER BY amount DESC LIMIT 3 OFFSET 3;
SELECT id, amount FROM orders ORDER BY amount DESC LIMIT 3, 3;   -- 前一个 3 是偏移，后一个 3 是行数

-- 跨库统一 NULL 位置：先排「是否为空」，再排值
SELECT id, name, city FROM customers ORDER BY city IS NULL, city;

-- 深分页优化：游标分页，直接定位到上一页最后一个 id
-- SELECT id, amount FROM orders WHERE id > 1005 ORDER BY id LIMIT 20;
写法含义结果（按 amount DESC）

!

易错：把 LIMIT m, n 理解成「第 m 页取 n 条」是高频错误——它是偏移 m 行后取 n 行。要取第 3 页（每页 10 条）应写 LIMIT 20, 10。另外 PostgreSQL 与 SQL Server 不支持这种逗号写法。

◆

跨库差异：NULL 在排序中的位置由数据库决定——MySQL / SQL Server 中 NULL 最小（ASC 排最前），PostgreSQL / Oracle 中 NULL 最大（ASC 排最后）。要跨库一致，可显式写 ORDER BY city IS NULL, city。

★

核心要点：分页三要素——确定的 ORDER BY、正确的偏移语义、别忘了唯一排序键。

知识点DISTINCT 去重与常见坑distinct · 作用于整个 SELECT 列表

DISTINCT 写在 SELECT 之后，对整行结果去重：只有当 SELECT 列表里所有列的值都相同，两行才会被合并成一行。它在逻辑执行顺序中位于 SELECT 之后、ORDER BY 之前。

因此多列 DISTINCT 是「组合去重」，不是「按第一列去重」。「每个城市只保留一条记录」这种需求 DISTINCT 做不到，需要窗口函数（模块 06）或 GROUP BY（模块 03）。

NULL 在 DISTINCT 中被视为相同值：多行 NULL 只会保留一行 NULL。顺带一提，COUNT(DISTINCT col) 会忽略 NULL，这与 COUNT(*) 不同（模块 03）。

性能上，DISTINCT 需要排序或哈希去重，代价不低。如果结果本来就不会重复（例如查主键），加 DISTINCT 只是白花成本；如果是想消除 JOIN 带来的重复行，先检查连接条件是否写错。

  • DISTINCT 作用于整个 SELECT 列表，多列即组合去重。
  • DISTINCT 与 ORDER BY 同用时，ORDER BY 的列必须出现在 SELECT 列表里，否则 MySQL 报错（ERROR 3065）。
  • DISTINCT 不能「按某一列去重、其他列随便取一行」。
distinct.sql
-- 单列去重：6 行（北京、上海、广州、深圳、杭州 + NULL）
SELECT DISTINCT city FROM customers;

-- 多列去重：是组合去重，本例 8 行（每对 (city, level) 都不同）
SELECT DISTINCT city, level FROM customers ORDER BY city, level;

-- 会员等级只有 3 种
SELECT DISTINCT level FROM customers;

-- 反例：MySQL 报错 ERROR 3065，ORDER BY 的列必须出现在 DISTINCT 的 SELECT 列表里
-- SELECT DISTINCT city FROM customers ORDER BY id;

-- 反例：以为按 city 去重，其实 (city, name) 组合都不重复，仍然 8 行
SELECT DISTINCT city, name FROM customers;
写法去重依据结果行数

SELECT DISTINCT citycity 的值6
SELECT DISTINCT levellevel 的值3
SELECT DISTINCT city, level(city, level) 组合8
SELECT DISTINCT city, name(city, name) 组合8
SELECT DISTINCT city … ORDER BY id列不在 SELECT 列表报错 3065
!

易错：DISTINCT 不是「按列去重」的开关。SELECT DISTINCT city, name FROM customers 返回 8 行（因为 name 各不相同），而不是 6 行——这是初学者最常踩的坑。

★

核心要点：DISTINCT 是「整行去重」。要「每组只保留一条」，请用 ROW_NUMBER()（模块 06）或 GROUP BY（模块 03）。

知识点NULL 与三值逻辑null-logic · UNKNOWN 不是 FALSE

NULL 表示「未知（unknown）」或「不适用」，它不是 0、不是空字符串、也不等于另一个 NULL。任何与 NULL 参与的算术、比较、字符串拼接，结果通常都是 NULL。

SQL 采用三值逻辑（three-valued logic）：TRUE、FALSE、UNKNOWN。比较运算符遇到 NULL 返回 UNKNOWN；而 WHERE 只保留结果为 TRUE 的行，所以 UNKNOWN 与 FALSE 一样会被过滤掉。

逻辑运算的三值规则是：AND 只要有一边是 FALSE 就是 FALSE，否则有 UNKNOWN 就是 UNKNOWN；OR 只要有一边是 TRUE 就是 TRUE，否则有 UNKNOWN 就是 UNKNOWN；NOT UNKNOWN 仍然是 UNKNOWN。

实用推论：判断空值只能用 IS NULL / IS NOT NULL；聚合函数（SUM / AVG / MAX / MIN / COUNT(col)）会忽略 NULL，只有 COUNT(*) 不忽略；GROUP BY 把 NULL 当成一个分组；需要默认值时用 COALESCE 或 IFNULL 兜底。

  • = NULL、<> NULL 恒为 UNKNOWN，永远不满足 WHERE。
  • NOT UNKNOWN = UNKNOWN，所以 NOT (city = '北京') 也会丢掉 city 为 NULL 的行。
  • CONCAT 遇到 NULL 会让整体变成 NULL；用 CONCAT_WS 或 COALESCE 规避。
  • MySQL 的唯一索引允许多个 NULL（因为 NULL 不等于 NULL）。
null-logic.sql
-- 错误写法：0 行（city = NULL 永远是 UNKNOWN）
SELECT id, name, city FROM customers WHERE city = NULL;

-- 正确写法：1 行（周涛）
SELECT id, name, city FROM customers WHERE city IS NULL;

-- 三值逻辑一览：结果依次为 UNKNOWN / UNKNOWN / UNKNOWN / TRUE / UNKNOWN
SELECT NULL = NULL AS 等, NULL <> NULL AS 不等,
       NULL AND TRUE AS 与, NULL OR TRUE AS 或, NOT NULL AS 非;

-- NULL 会「传染」：周涛这一行的拼接结果是 NULL
SELECT name, city, CONCAT(city, '-', level) AS 标签 FROM customers;

-- 兜底：把 NULL 显示成「未知」
SELECT name, COALESCE(city, '未知') AS city FROM customers;

易错：WHERE col <> 'x' 会漏掉 col 为 NULL 的行，因为 UNKNOWN 不是 TRUE。要让结果包含 NULL，必须写成 WHERE col <> 'x' OR col IS NULL。

◆

跨库差异：PostgreSQL 的 CONCAT() 会忽略 NULL（MySQL 返回 NULL，但 || 返回 NULL）；Oracle 把空字符串 '' 当作 NULL；SQL Server 的 ORDER BY 把 NULL 排最前。跨库迁移时这些差异最容易埋坑。

★

核心要点：NULL 的三条铁律——比较出 UNKNOWN、WHERE 只留 TRUE、判断用 IS NULL。

知识点SELECT 的逻辑执行顺序exec-order · 写在前面 ≠ 先执行

SQL 是声明式（declarative）语言：你写的是「想要什么」，而不是「怎么执行」。但为了理解语法限制，需要知道数据库处理 SELECT 的逻辑执行顺序（logical processing order）：FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT。

这个顺序能解释很多「为什么」：WHERE 里不能引用 SELECT 的别名（那时别名还没产生）；HAVING 里可以引用聚合结果；ORDER BY 可以引用别名（它在 SELECT 之后）；LIMIT 永远在最后，所以它截断的是排好序的结果。

逻辑顺序不等于物理执行顺序。优化器（optimizer）会做谓词下推、连接重排、索引选择等改写，实际执行计划可能完全不同（模块 09、10）。但对写 SQL 的人来说，逻辑顺序就是判断「语法是否合法、结果是否符合预期」的依据。

窗口函数（window function）在 SELECT 阶段求值，窗口的计算发生在 HAVING 之后、ORDER BY / LIMIT 之前（模块 06）。这也是为什么窗口函数不能直接写在 WHERE 里——要过滤窗口结果，必须套一层子查询或 CTE（模块 05、06）。

-- 书写顺序：SELECT → FROM → WHERE → ORDER BY → LIMIT
-- 逻辑顺序：FROM → WHERE → (GROUP BY → HAVING) → SELECT → DISTINCT → ORDER BY → LIMIT
SELECT id, amount
FROM orders
WHERE status = 'paid'
ORDER BY amount DESC
LIMIT 3;            -- 结果：1004(2297) / 1012(1497) / 1010(1458)

-- 报错示范：WHERE 阶段别名还不存在（ERROR 1054 Unknown column）
-- SELECT amount * 2 AS double_amount FROM orders WHERE double_amount > 2000;

-- 正确写法一：在 WHERE 里重复表达式
SELECT amount * 2 AS double_amount FROM orders WHERE amount * 2 > 2000;   -- 4 行

-- 正确写法二：用派生表让别名先产生（模块 05）
SELECT * FROM (SELECT amount * 2 AS double_amount FROM orders) t
WHERE double_amount > 2000;
步骤作用能否用 SELECT 别名
FROM加载表、做连接不适用
WHERE行过滤不能（别名尚未产生）
GROUP BY分组MySQL 允许（非标准扩展）
HAVING组过滤能（可引用聚合别名）
SELECT计算表达式、投影—
DISTINCT整行去重不适用
ORDER BY排序能
LIMIT截断结果不适用
★

核心要点：背下顺序 FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT。所有「为什么这里不能用别名」的问题，都由它回答。

!

易错：逻辑顺序 ≠ 物理顺序。优化器会重写查询，EXPLAIN 看到的是实际执行计划；但语法校验与结果语义仍然按逻辑顺序理解。

◆

面试点：窗口函数在 SELECT 阶段求值，所以不能直接出现在 WHERE 中。面试里被问到「为什么 WHERE 里不能用 ROW_NUMBER()」时，答案就是这个执行顺序。
