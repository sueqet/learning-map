窗口函数

✓本节学习目标

  • 能说清窗口函数与 GROUP BY 聚合的本质区别：一个不折叠行，一个折叠行。
  • 会写 函数() OVER (PARTITION BY … ORDER BY … [窗口帧]) 的完整骨架，并解释三个部分各管什么。
  • 能按场景选对排名函数：ROW_NUMBER / RANK / DENSE_RANK / NTILE，并预判并列值下的结果。
  • 会用 LAG / LEAD / FIRST_VALUE / LAST_VALUE 做同比环比、前后对比，并避开 LAST_VALUE 的默认帧陷阱。
  • 能用窗口聚合算累计值、组内占比、组内排名，替代「先聚合再 JOIN 回明细」的老写法。
  • 能写出分组内 TopN / 每组取最新一条的标准模板，并说明为什么不能直接在 WHERE 里过滤 rn。

知识点窗口函数 vs 聚合函数win-concept · 不折叠行的「分组计算」

窗口函数（window function）的写法是在普通函数后面加一个 OVER (...)，MySQL 里也叫分析函数（analytic function）。它和 GROUP BY 聚合最大的区别只有一句话：GROUP BY 把多行折叠成一行，窗口函数一行都不减少，只是给每一行额外算出一个「基于它所在那组行」的值。

这个「那组行」就是窗口（window），由三部分描述：PARTITION BY（按谁分组，可省略）、ORDER BY（组内怎么排序）、窗口帧（frame）（在组内取哪一段行）。可以把 OVER (...) 读成「把这组行借过来算一下，但别把它们合掉」。

  • 语法骨架：函数名(参数) OVER (PARTITION BY 列 ORDER BY 列 [窗口帧])。
  • 没有 PARTITION BY 时，整个查询结果就是一个分区；没有 ORDER BY 时，帧默认覆盖整个分区。
  • 窗口函数只能出现在 SELECT 列表与 ORDER BY 中，不能出现在 WHERE / GROUP BY / HAVING 里。
concept.sql
-- ① 聚合：12 行订单被折叠成 1 行，明细消失
SELECT SUM(amount) AS 总金额 FROM orders;

-- ② 窗口函数：12 行全部保留，每行都能看到总额与自己的占比
SELECT id,
       amount,
       SUM(amount) OVER ()                            AS 总金额,
       ROUND(amount / SUM(amount) OVER () * 100, 1)   AS 占比百分比
FROM orders
ORDER BY id;

核心要点：窗口函数 = 「不折叠行的分组计算」。它把「明细 + 组内统计」放在同一行，一次性省掉「先 GROUP BY 聚合、再 JOIN 回明细表」这一步，也因此成为占比、累计、排名这类指标的标准解法。

知识点ROW_NUMBER / RANK / DENSE_RANK / NTILEwin-rank · 四个排名函数怎么选

排名函数（ranking function）用来给分区内的行编号。它们都要写 ORDER BY，区别只在遇到并列值时的处理方式，而这个区别直接决定了「取第一名」时会不会多出几行。

  • ROW_NUMBER()：严格 1、2、3…… 即使值相同也强行分先后，序号唯一。
  • RANK()：并列同名次，后续名次跳号（1、1、3）。
  • DENSE_RANK()：并列同名次，后续名次不跳号（1、1、2）。
  • NTILE(n)：把分区尽量平均地切成 n 个桶，桶号 1..n，常用于分位数与 AB 分组。
rank.sql
-- 9 名员工按工资降序排名（本例工资互不相同，所以 rn / rk / dr 一致）
SELECT name, dept, salary,
       ROW_NUMBER() OVER (ORDER BY salary DESC) AS rn,
       RANK()       OVER (ORDER BY salary DESC) AS rk,
       DENSE_RANK() OVER (ORDER BY salary DESC) AS dr,
       NTILE(3)     OVER (ORDER BY salary DESC) AS nt
FROM employees
ORDER BY salary DESC;

-- 分组内排名：各部门内部按工资排名（PARTITION BY 打开「每部门一个分区」）
SELECT name, dept, salary,
       RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS 部门内排名
FROM employees
ORDER BY dept, 部门内排名;

★

核心要点：「每组取第一名」优先用 ROW_NUMBER（保证唯一）；想保留并列冠军就用 RANK / DENSE_RANK，但要接受结果可能多于 1 行。

!

易错：当 ORDER BY 的列存在并列值时，ROW_NUMBER 的先后顺序由执行计划决定，同一查询两次运行可能给出不同结果。要让结果稳定可复现，必须追加唯一的第二排序键，例如 ORDER BY amount DESC, id。

知识点LAG / LEAD / FIRST_VALUE / LAST_VALUEwin-offset · 看前一行、后一行与首尾

这四个函数解决「跨行取值」问题：不写自连接，也能在同一行里看到上一行、下一行、分区首行或末行的值。LAG 取前面第 n 行，LEAD 取后面第 n 行，FIRST_VALUE / LAST_VALUE 取分区（或帧）的首尾值。它们是环比、同比增长、相邻事件间隔这类分析的标配。

  • LAG(expr, 偏移量, 默认值)：偏移量默认 1；边界处没有前一行时返回默认值，不写默认值则返回 NULL。
  • LEAD(expr, 偏移量, 默认值)：方向相反，取后一行。
  • FIRST_VALUE(expr) / LAST_VALUE(expr)：取窗口帧的首尾值——注意 LAST_VALUE 的默认帧只到当前行。
  • 配合 PARTITION BY customer_id 就变成「每个客户内部的前后订单」，不会跨客户串行。
lag-lead.sql
-- 每笔订单的上一笔 / 下一笔金额（按订单日期排序）
SELECT id, order_date, amount,
       LAG(amount)       OVER (ORDER BY order_date) AS 上一笔,
       LEAD(amount)      OVER (ORDER BY order_date) AS 下一笔,
       LAG(amount, 1, 0) OVER (ORDER BY order_date) AS 上一笔_空填0,
       amount - LAG(amount) OVER (ORDER BY order_date) AS 与上一笔差额
FROM orders
ORDER BY order_date;

-- 首尾值：分区第一笔与最后一笔
SELECT id, order_date, amount,
       FIRST_VALUE(amount) OVER (ORDER BY order_date) AS 第一笔,
       LAST_VALUE(amount)  OVER (ORDER BY order_date
         ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS 最后一笔
FROM orders
ORDER BY order_date;

知识点窗口聚合与累计计算win-agg · 累计、占比、组内统计

聚合函数（SUM / COUNT / AVG / MIN / MAX）加上 OVER (...) 就变成窗口聚合：既能保留每一行明细，又能在同一行里拿到「组内累计」「组内总额」「组内占比」「组内排名」等信息。

  • 带 ORDER BY 且不写帧 → 默认帧是 RANGE UNBOUNDED PRECEDING AND CURRENT ROW，也就是累计到当前行。
  • 不带 ORDER BY → 帧覆盖整个分区，得到的是「组内总额」，每行都一样。
  • 窗口聚合是「先过滤、再开窗」：WHERE 先执行，所以只对通过 WHERE 的行计算。
window-agg.sql
-- 已付款订单：客户内累计消费 + 客户总额 + 客户订单数 + 单笔占客户总额的比例
SELECT o.id, o.customer_id, o.order_date, o.amount,
       SUM(o.amount) OVER (PARTITION BY o.customer_id ORDER BY o.order_date) AS 客户累计,
       SUM(o.amount) OVER (PARTITION BY o.customer_id)                        AS 客户总额,
       COUNT(*)      OVER (PARTITION BY o.customer_id)                        AS 客户订单数,
       ROUND(o.amount / SUM(o.amount) OVER (PARTITION BY o.customer_id) * 100, 1) AS 占客户比
FROM orders o
WHERE o.status = 'paid'
ORDER BY o.customer_id, o.order_date;

知识点窗口帧 ROWS / RANGE 与滑动窗口win-frame · 帧决定「算哪几行」

窗口帧（window frame）规定在分区内部「取哪一段行」参与计算。同一份数据，帧不同，SUM 的结果就完全不同：累计、滑动平均、整分区合计，全靠帧来区分。

  • ROWS 按物理行数数：ROWS BETWEEN 1 PRECEDING AND CURRENT ROW 就是「上一行 + 当前行」。
  • RANGE 按排序值算：RANGE BETWEEN 1 PRECEDING AND CURRENT ROW 会纳入所有「值在当前值 −1 到当前值之间」的行，并列值会被一起纳入。
  • 默认帧规则：有 ORDER BY 不写帧 → RANGE UNBOUNDED PRECEDING AND CURRENT ROW；没有 ORDER BY → 整个分区。
frame.sql
-- 同一份数据，四种帧 → 四种完全不同的 SUM
SELECT id, order_date, amount,
       SUM(amount) OVER (ORDER BY order_date
         ROWS BETWEEN 1 PRECEDING AND CURRENT ROW)                  AS 两行滑动,
       SUM(amount) OVER (ORDER BY order_date
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)          AS 累计,
       SUM(amount) OVER (ORDER BY order_date
         ROWS BETWEEN 2 PRECEDING AND 2 FOLLOWING)                  AS 五行居中,
       AVG(amount) OVER (ORDER BY order_date
         ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING)                  AS 三点均值
FROM orders
ORDER BY order_date;
帧写法覆盖范围并列值的影响
ROWS BETWEEN 1 PRECEDING AND CURRENT ROW前 1 行 + 当前行（最多 2 行）按行数数，不受并列影响
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW分区第一行 → 当前行按行数数，逐行增长
RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW第一行 → 当前行 及其所有并列行并列值一起纳入，可能一次跳多行
ROWS BETWEEN 2 PRECEDING AND 2 FOLLOWING前 2 行 → 后 2 行（最多 5 行）滑动居中窗口，常用于移动平均
ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING整个分区常用于 LAST_VALUE 取末行

知识点分组内 TopN 与取最新一条win-topn · 面试与报表的通用模板

「每个品类最贵的 2 个商品」「每位客户最近的一笔订单」「每个部门工资前 3 名」——这类分组内 TopN 问题，用 ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...) 加上外层过滤就能统一解决，模板只有三步：① 在 CTE/派生表里算出排名 → ② 外层 WHERE rn <= N → ③ 排序输出。

  • 取 TopN 用 rn <= N；取「最新一条 / 最贵一条」用 rn = 1。
  • 排序键一定要加唯一的第二列（如 id），否则并列时结果不稳定。
  • 想保留并列名次就换成 RANK() / DENSE_RANK()，代价是每组可能返回多于 N 行。
topn.sql
-- ① 每个品类取价格最高的 2 个商品
WITH ranked AS (
  SELECT id, name, category, price,
         ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC, id) AS rn
  FROM products
)
SELECT category, id, name, price
FROM ranked
WHERE rn <= 2
ORDER BY category, rn;

-- ② 每位客户取最新的一笔订单（每组取一条）
WITH latest AS (
  SELECT o.id, o.customer_id, o.order_date, o.amount,
         ROW_NUMBER() OVER (PARTITION BY o.customer_id
                            ORDER BY o.order_date DESC, o.id DESC) AS rn
  FROM orders o
)
SELECT customer_id, id AS order_id, order_date, amount
FROM latest
WHERE rn = 1
ORDER BY customer_id;

核心要点：分组 TopN 的模板 = CTE 里 ROW_NUMBER() OVER (PARTITION BY 组 ORDER BY 排序键 DESC, 唯一键) + 外层 WHERE rn <= N。这一套模板能覆盖面试里绝大多数「分组取前 N / 取最新」的题。

知识点窗口函数常见坑与限制win-pitfall · 执行顺序与默认帧

窗口函数最容易踩的坑，几乎都来自两件事：它在执行顺序里的位置，以及不写窗口帧时的默认行为。把这两点记牢，90% 的报错和「结果不对」都能立刻定位。

  • 逻辑执行顺序：FROM → WHERE → GROUP BY → HAVING → 窗口函数 → SELECT → ORDER BY → LIMIT。
  • 因此 WHERE / GROUP BY / HAVING 里不能出现窗口函数，别名 rn 在 WHERE 里也不可见（但 ORDER BY 里可以用）。
  • MySQL 8.0 不支持窗口函数嵌套，如 SUM(ROW_NUMBER() OVER (...)) OVER ()，必须拆成两层查询。
  • 不带 ORDER BY 时默认帧虽然覆盖整个分区，但「最后一行」是哪一行并不确定；真正容易踩的是带 ORDER BY 却不写帧——此时 LAST_VALUE 只取到当前行。
pitfall.sql
-- ✗ 错误：WHERE 在窗口函数之前执行，rn 还不存在 → 报错
SELECT * FROM orders
WHERE ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY amount DESC) = 1;

-- ✓ 正确：先算，再在外层过滤
WITH t AS (
  SELECT id, customer_id, amount,
         ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY amount DESC, id) AS rn
  FROM orders
)
SELECT * FROM t WHERE rn = 1 ORDER BY customer_id;

-- ✗ 错误：窗口函数不能嵌套（MySQL 8.0 不支持）
SELECT SUM(ROW_NUMBER() OVER (ORDER BY amount)) OVER () FROM orders;

-- ✓ 正确：拆成两层
SELECT SUM(rn) OVER () FROM (
  SELECT ROW_NUMBER() OVER (ORDER BY amount) AS rn FROM orders
) t;

-- LAST_VALUE 的默认帧陷阱：不写帧时「最后一行」就是当前行
SELECT id, amount,
       LAST_VALUE(amount) OVER (ORDER BY id) AS 默认帧,
       LAST_VALUE(amount) OVER (ORDER BY id
         ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS 全帧
FROM orders
ORDER BY id;
坑错误写法正确做法
在 WHERE 里过滤排名WHERE ROW_NUMBER() OVER (...) = 1放进 CTE / 派生表，外层 WHERE rn = 1
窗口函数嵌套SUM(RANK() OVER (...)) OVER ()拆成两层子查询，先算内层再开窗
LAST_VALUE 只到当前行LAST_VALUE(x) OVER (ORDER BY d)显式加 ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
ROW_NUMBER 结果不稳定ORDER BY amount DESC追加唯一键：ORDER BY amount DESC, id
以为 MySQL 5.7 能用5.7 直接执行 → 语法错误升级到 8.0，或用自连接 / GROUP BY 变通
大分区上直接开窗百万行全表开窗后再过滤先用 WHERE 缩小范围，并让排序列有索引

易错：WHERE 里写窗口函数会直接报错，但把 rn 写进 ORDER BY 是允许的（MySQL 支持 ORDER BY 引用 SELECT 别名）。别因为「别名不能用在 WHERE」就以为别名到处都不能用。

性能提醒：窗口函数一般需要对分区排序，执行计划里常出现 Using temporary; Using filesort。原则是先过滤、后开窗：把 WHERE 能筛掉的行先筛掉，再让排序列（如 customer_id, order_date）走索引，代价会明显下降（详见模块 09、10）。
