MODULE 04 · SQL / 数据库

多表连接

✓本节学习目标

  • 能说清「连接」的本质是按条件配对两表的行，并算出任意两表连接的结果行数。
  • 能正确写出 INNER / LEFT / RIGHT / FULL OUTER / CROSS JOIN，并说明各自保留哪些行。
  • 能区分 ON 与 WHERE 在 LEFT JOIN 中的不同效果（面试高频）。
  • 会用自连接解决「同一张表内比较」类问题（员工-经理、环比）。
  • 能写出三表以上连接，并判断连接顺序是否影响结果与性能。
  • 会用 EXISTS / NOT EXISTS 表达半连接、反连接，并说清 NOT IN 的 NULL 陷阱。
Pre-requisites · 前置知识

需要先掌握：SELECT / FROM / WHERE 单表查询、比较与逻辑运算符、主键与外键的概念（模块 01、02）。本页所有示例基于内置示例数据 customers（8 行）与 orders（12 行）。

知识点连接的本质与笛卡尔积join-basic

连接（JOIN）就是让两张表的行按某个条件「配对」，配对成功的组合成为结果表的一行。理解连接，先要理解它的地基——笛卡尔积（Cartesian product）：把左表每一行与右表每一行都组合一次，得到的行数是 左表行数 × 右表行数。

  • 连接 = 笛卡尔积 + 过滤条件（ON）。不写 ON 条件时，得到的就是完整笛卡尔积。
  • 结果行数由匹配关系决定，不由表的行数直接决定：一对多会让行数放大。
  • 外键（如 orders.customer_id → customers.id）是连接的「桥梁」，也让连接有意义。
cartesian.sql
-- 笛卡尔积：8 × 12 = 96 行（几乎都是无意义的组合）
SELECT c.name, o.id
FROM customers c
CROSS JOIN orders o;

-- 加上配对条件：只剩 12 行（每个订单找到它的客户）
SELECT c.name, o.id
FROM customers c
JOIN orders o ON c.id = o.customer_id;
写法配对条件结果行数（本例）
CROSS JOIN无条件，全组合8 × 12 = 96
JOIN … ON c.id = o.customer_id客户 id = 订单的客户 id12
LEFT JOIN 同上同上，但保留没配上的客户13
!

易错：忘写 ON 条件、或条件写错（比如把 c.id = o.customer_id 写成 c.id = o.id），会得到几十上百倍的重复行。看到「结果突然变多」先怀疑连接条件。

★

核心要点：连接 = 笛卡尔积 + 条件过滤；行数放大是「一对多」的正常现象，不是 Bug。

知识点INNER JOIN 与 ON / USINGinner-join

INNER JOIN（内连接）只保留两边都配对成功的行，是默认的连接类型：写 JOIN 等价于 INNER JOIN。

  • ON 后面写配对条件，可以是等值，也可以是范围、多个条件用 AND 连接。
  • USING(col) 是简写：要求两表有同名列，等价于 ON a.col = b.col，且结果里该列只出现一次。
  • 必须给表起别名（customers c），并用 别名.字段 限定，避免字段名歧义。
inner-join.sql
-- 三种等价写法
SELECT c.name, o.id, o.amount
FROM customers AS c
INNER JOIN orders AS o ON c.id = o.customer_id;

SELECT c.name, o.id, o.amount
FROM customers c JOIN orders o ON c.id = o.customer_id;   -- JOIN = INNER JOIN

-- USING 要求两表同名列；本例列名不同（id / customer_id），所以不能这么写
-- SELECT * FROM customers JOIN orders USING (id);   -- 错误示范：语义完全不同
客户订单号金额
张伟1001247.00
张伟10021299.00
李娜100389.00
… 共 12 行（周涛 id=8 没有订单，因此不出现在结果里）
★

核心要点：INNER JOIN 的结果行数 = 所有配对成功的组合数。一对多会展开成多行；右表没有匹配行时，该左表行直接消失。

◆

面试点：对 INNER JOIN 而言，把过滤条件写在 ON 还是 WHERE 结果相同；但对 LEFT JOIN 就完全不同（见下一个知识点）。

知识点LEFT / RIGHT / FULL OUTER JOINouter-join

外连接（OUTER JOIN）在配对失败时不丢弃行，而是把另一侧的列补成 NULL，从而「保留」这张表的全部行。

  • LEFT JOIN：保留左表全部行，右表没配上的补 NULL。
  • RIGHT JOIN：保留右表全部行（实际工作中一般调换表顺序写成 LEFT JOIN，可读性更好）。
  • FULL OUTER JOIN：两边都保留。MySQL 8.0 不支持该关键字，要用 LEFT JOIN UNION RIGHT JOIN 模拟。
outer-join.sql
-- LEFT JOIN：13 行（12 个订单 + 1 个没有订单的客户，右侧为 NULL）
SELECT c.name, o.id AS order_id
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
ORDER BY c.id;

-- 只在 ON 里过滤：保留所有客户，没付款的客户右侧为 NULL
SELECT c.name, o.id
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id AND o.status = 'paid';

-- 把过滤放到 WHERE：结果退化成 INNER JOIN（没付款的客户整行被过滤掉）
SELECT c.name, o.id
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
WHERE o.status = 'paid';
!

最经典的坑：对 LEFT JOIN 的右表列加 WHERE 条件（尤其是 WHERE o.col IS NOT NULL 或等值判断），会把补 NULL 的行全部过滤掉，LEFT JOIN 实际退化成了 INNER JOIN。要保留左表全部行，条件必须写在 ON 里。

写法结果行数周涛（无订单）是否出现
INNER JOIN12不出现
LEFT JOIN13出现（订单列为 NULL）
RIGHT JOIN12不出现
FULL OUTER JOIN13出现
CROSS JOIN96出现 12 次（每张订单一次）

知识点自连接（同一张表多次使用）self-join

自连接（self join）是把同一张表用两个不同别名当成两张表来连接，用来处理「表内行与行之间有关系」的问题，比如员工与直属经理、本月与上月、当前行与上一行。

  • 关键：必须起两个别名（如 e 和 m），否则数据库无法区分。
  • 连接条件指向同一张表的另一列：e.manager_id = m.id。
  • 顶层人员 manager_id IS NULL，用 LEFT JOIN 才能保留。
self-join.sql
-- 每位员工及其直属经理（9 行，顶层经理的经理为 NULL）
SELECT e.name AS 员工, m.name AS 经理, e.salary
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id
ORDER BY e.id;

-- 找出「比直属经理工资还高」的员工（自连接的典型写法）
-- 本例示例数据里没有这种员工，所以结果 0 行；换成 e.salary < m.salary 就能看到结果
SELECT e.name, e.salary, m.name AS 经理, m.salary AS 经理工资
FROM employees e
JOIN employees m ON e.manager_id = m.id
WHERE e.salary > m.salary;

核心要点：自连接不是新语法，只是「同一张表起两个别名」。想清楚「两个别名分别代表什么角色」，问题就清晰了。

知识点CROSS JOIN 与生成序列cross-join

CROSS JOIN 就是无条件笛卡尔积。它看似「没用」，其实是构造组合的利器：生成日期序列、补齐「每个品类 × 每个月」的空缺报表、生成测试数据。

  • 行数 = 两表行数相乘，注意别在大表上用。
  • JOIN … ON 1=1 与 CROSS JOIN 效果相同，但语义上前者容易被误读。
  • MySQL 8.0 可用递归 CTE 生成数字/日期序列，再与维度表 CROSS JOIN 补齐空行。
cross-join.sql
-- 6 个商品 × 8 个客户 = 48 行（常见于「给每个客户列出所有商品」的模板）
SELECT c.name, p.name AS product
FROM customers c
CROSS JOIN products p
LIMIT 5;

-- 用递归 CTE 生成 1..10，再和客户 CROSS JOIN，给每个客户补齐 10 个序号
WITH RECURSIVE nums AS (
  SELECT 1 AS n
  UNION ALL
  SELECT n + 1 FROM nums WHERE n < 10
)
SELECT c.name, nums.n
FROM customers c CROSS JOIN nums;
◆

性能提醒：CROSS JOIN 的结果规模是乘积级。1 万 × 1 万 = 1 亿行，务必先估算再执行；生产环境里通常要和 LIMIT 或维度过滤一起用。

知识点多表连接与连接顺序multi-join

真实查询往往要连 3 张以上的表。写法上依次 JOIN 即可；连接顺序由优化器决定，对纯 INNER JOIN 来说不改变结果，但会影响执行代价。

  • 链条式写法：A JOIN B ON … JOIN C ON … JOIN D ON …，每张表紧跟自己的条件，最易读。
  • 混用 LEFT 与 INNER 时顺序会影响结果：LEFT JOIN 之后再 INNER JOIN 右表，会把补 NULL 的行过滤掉。
  • 性能上，先连过滤后行数少的表、并保证连接列有索引，通常更快（见模块 09、10）。
multi-join.sql
-- 四表连接：每个商品品类的销售额（口径：只统计 status = 'paid' 的订单）
SELECT p.category AS 品类,
       SUM(oi.qty * oi.unit_price) AS 销售额
FROM order_items oi
JOIN products  p ON oi.product_id = p.id
JOIN orders    o ON oi.order_id   = o.id
JOIN customers c ON o.customer_id = c.id
WHERE o.status = 'paid'
GROUP BY p.category
ORDER BY 销售额 DESC;
品类销售额（paid 口径）构成
数码7519.00显示器 1299 + 键盘 499×5 + 鼠标 129×2
家居515.00保温杯 89×3 + 台灯 159×1
图书177.00笔记本 59×3
合计8211.00= 10 笔 paid 订单的金额总和

口径提醒：上表只统计 status = 'paid' 的 10 笔订单（合计 8211.00）。若去掉 WHERE、按全部 12 笔订单统计，结果是数码 7648.00 > 家居 833.00 > 图书 177.00（合计 8658.00）——多出的 447 元来自退款单 1005（台灯 159×2 = 318）与取消单 1009（鼠标 129×1）。

!

易错：把 LEFT JOIN 和 INNER JOIN 混用时，条件顺序会改变结果集。需要「保留左表全部行」时，后续连接要么也用 LEFT JOIN，要么把过滤条件写进对应的 ON。

知识点半连接 / 反连接（EXISTS 与 JOIN 互换）semi-anti

很多时候我们只想知道「另一张表里有没有对应的行」，并不需要它的列。这种「只做存在性判断」的查询叫半连接（semi join），它的反面（不存在）叫反连接（anti join）。

  • 半连接：WHERE EXISTS (子查询) 或 JOIN … + DISTINCT。结果不会因右表多行而重复。
  • 反连接：WHERE NOT EXISTS (子查询) 是安全写法；NOT IN 遇到 NULL 会返回空结果。
  • 优化器通常把 EXISTS 改写为半连接执行计划，二者性能相近，选可读性更好的写法。
semi-anti.sql
-- 半连接：有下单记录的客户（7 个）
SELECT c.name FROM customers c
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);

-- 等价写法：JOIN + DISTINCT（不 DISTINCT 会因为多订单而重复）
SELECT DISTINCT c.name FROM customers c
JOIN orders o ON o.customer_id = c.id;

-- 反连接：从来没有下单的客户（1 个：周涛）——推荐写法
SELECT c.name FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);

-- 反连接的危险写法：一旦子查询结果里出现 NULL，整条查询返回空集
SELECT c.name FROM customers c
WHERE c.id NOT IN (SELECT customer_id FROM orders);
!

NULL 陷阱：x NOT IN (1, 2, NULL) 的结果永远不是 TRUE 也不是 FALSE，而是 UNKNOWN，因此过滤后一行都不剩。这是面试与生产事故的常客——反连接优先用 NOT EXISTS。
