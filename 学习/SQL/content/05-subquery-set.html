01子查询的形态与位置

知识点标量、列、行、表子查询subquery forms · 先认清「返回什么」，再决定「写在哪」

子查询（subquery）就是嵌套在另一个 SQL 语句里的 SELECT。它最容易踩的坑不是语法，而是形态与位置的匹配：数据库允许你把哪种形态的子查询放在哪个位置，是有硬性规则的。所以第一步永远是问自己「这个子查询返回几行几列」。

按返回形态分四类：标量子查询（1 行 1 列，可以当普通值用）、列子查询（1 列多行，配合 IN / ANY / ALL 使用）、行子查询（1 行多列，用 (a, b) 整体比较）、表子查询（多行多列，只能出现在 FROM / JOIN 或 EXISTS 里）。

  • 标量子查询可以出现在任何「能写值」的地方：SELECT 列表、WHERE、HAVING、ORDER BY，甚至 SET。
  • 列子查询只能配合 IN / NOT IN / ANY / ALL，或放在 FROM 里（必须起别名）。
  • 标量子查询一旦返回超过 1 行，MySQL 直接报错 1242，不会帮你「随便挑一行」。
scalar_subquery.sql
-- ① 标量子查询写在 SELECT 列表：为每个客户附上订单数
SELECT c.id, c.name,
       (SELECT COUNT(*) FROM orders o WHERE o.customer_id = c.id) AS order_cnt
FROM customers c
ORDER BY order_cnt DESC, c.id;

-- ② 标量子查询写在 WHERE：金额高于全站平均的订单
SELECT id, customer_id, amount
FROM orders
WHERE amount > (SELECT AVG(amount) FROM orders)
ORDER BY amount DESC;

-- ③ 标量子查询写在 HAVING：总额超过平均订单额 2 倍的客户
SELECT customer_id, SUM(amount) AS total
FROM orders
GROUP BY customer_id
HAVING SUM(amount) > 2 * (SELECT AVG(amount) FROM orders);

-- ④ 行子查询：用 (customer_id, status) 这一整行去匹配
SELECT id, customer_id, status, amount
FROM orders
WHERE (customer_id, status) IN (
  SELECT customer_id, status FROM orders WHERE amount > 2000
);

列子查询1 列多行WHERE 的 IN / ANY / ALL，或 FROM（需别名）(SELECT customer_id FROM orders)
行子查询1 行多列WHERE 的 (a,b) = / (a,b) IN(SELECT customer_id, MAX(amount) FROM orders)
表子查询多行多列FROM / JOIN（必须别名）、EXISTS(SELECT city, COUNT(*) FROM customers GROUP BY city) t

共 8 行customers 有 8 行，一个客户一行，标量子查询逐行取值。

其余 7 行 order_cnt 之和 = 12与 orders 的 12 行一一对应，可用来核对子查询没有多算或漏算。
★

核心要点：标量子查询的隐含契约是「至多 1 行」。要保证这一点，子查询里通常得有聚合函数或 LIMIT 1，否则数据一变就报 1242。

!

易错：标量子查询返回 0 行时结果是 NULL（COUNT(*) 例外），NULL 参与算术会把整列结果污染成 NULL；而返回 2 行则直接报错。写标量子查询时先想清楚「它会不会返回多行」。

知识点IN / EXISTS / ANY / ALL 的语义差异in / exists / any / all · 一个比「值」，一个比「有没有行」

这四个写法都是「用子查询做条件」，但判断的东西不同：x IN (子查询) 等价于 x = ANY (子查询)，是把值拿去和集合比；x NOT IN (子查询) 等价于 x <> ALL (子查询)；而 EXISTS (子查询) 只判断子查询有没有返回至少一行，根本不在乎返回的是什么列。

这个差别带来两个实际后果：一是 EXISTS 里的 SELECT 列表写什么都没关系（习惯写 SELECT 1），二是 NULL 的处理完全不同——IN/NOT IN 受三值逻辑影响，EXISTS/NOT EXISTS 只看行数，天然 NULL 安全。

  • IN 与 EXISTS 在结果上常常等价，但语义与执行方式不同；性能要按具体数据与索引判断，不要背结论。
  • NOT IN 的子查询结果里只要有一个 NULL，整个条件就永远不成立，查询返回空集。
  • > ANY 相当于「大于最小值」，>= ALL 相当于「大于等于最大值」。
in_exists.sql
-- ① IN：下过单的客户
SELECT id, name FROM customers WHERE id IN (SELECT customer_id FROM orders);

-- ② EXISTS：同样的语义，但只判断「存在」
SELECT c.id, c.name
FROM customers c
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);

-- ③ NOT EXISTS：从未下单的客户（NULL 安全）
SELECT c.id, c.name
FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);

-- ④ ALL / ANY：最贵的那件产品 / 除最便宜之外的产品
SELECT name, price FROM products WHERE price >= ALL (SELECT price FROM products);
SELECT name, price FROM products WHERE price >  ANY (SELECT price FROM products);

-- ⑤ 危险写法：子查询若含 NULL，NOT IN 一行都返回不了
SELECT id, name FROM customers WHERE id NOT IN (SELECT customer_id FROM orders);

易错：SELECT 1 NOT IN (2, NULL); 的结果是 NULL 而不是 TRUE。所以只要子查询可能返回 NULL（比如某行 customer_id 为空），NOT IN 就一行都返回不了。改用 NOT EXISTS，或给子查询补上 WHERE customer_id IS NOT NULL。

★

核心要点：IN 和 EXISTS 谁更快没有固定答案：MySQL 8.0 常把二者改写成半连接（semi-join）。真正要记的是——NULL 安全用 EXISTS，集合枚举用 IN。

02相关子查询与派生表

知识点相关子查询与执行方式correlated subquery · 外层每行跑一次内层

相关子查询（correlated subquery）是指内层查询引用了外层的列，因此它不能再脱离外层单独执行：逻辑上外层每处理一行，内层就要带着该行的值重新执行一次。与之相对，非相关子查询与外层完全无关，可以只算一次、结果复用。

这就是「写法差不多、性能差很多」的根源。相关子查询天生依赖索引——内层过滤用的列（如 orders.customer_id、employees.dept）如果没有索引，外层每一行都会触发一次全表扫描，代价立刻爆炸。好在 MySQL 8.0 的优化器会把很多 IN / EXISTS 改写成半连接或 JOIN，实际执行不一定真的是「逐行嵌套」。

  • 判断标准只有一条：内层 WHERE 里有没有引用外层别名。
  • 相关子查询最常见的两个用途：逐行与「本组均值」比较、逐行判断「是否存在匹配行」。
  • 相关子查询里漏写关联条件，会从「逐行比较」退化成「全表算一次」，结果常常悄悄变错。
flowchart TB A["外层 FROM 取出一行"] --> B{"子查询是否引用外层列？"} B -- "否：非相关" --> C["内层只执行一次，结果复用"] B -- "是：相关" --> D["带着当前行的值执行内层"] C --> E["得到值 / 是否命中"] D --> E E --> F["用结果过滤或计算该行"] F --> G{"还有下一行？"} G -- "有" --> A G -- "没有" --> H["输出最终结果集"]
correlated.sql
-- ① 相关标量子查询：每行都与「本部门」的平均薪资比较
SELECT e.id, e.name, e.dept, e.salary,
       (SELECT ROUND(AVG(x.salary), 0) FROM employees x WHERE x.dept = e.dept) AS dept_avg
FROM employees e
ORDER BY e.dept, e.salary DESC;

-- ② 相关 EXISTS：找出「手下有人」的管理者
SELECT e.id, e.name, e.dept
FROM employees e
WHERE EXISTS (SELECT 1 FROM employees x WHERE x.manager_id = e.id);

-- ③ 非相关子查询：只算一次，结果被所有行复用
SELECT id, amount
FROM orders
WHERE amount > (SELECT AVG(amount) FROM orders);

!

易错：把 WHERE x.dept = e.dept 写漏或写成恒真条件，内层就变成非相关的全表统计，语法照样通过、结果却是错的。写完相关子查询后，一定把内层 WHERE 单独看一眼关联条件。

知识点派生表与 FROM 子查询derived table · 先把结果做成一张临时表，再连接

派生表（derived table）是写在 FROM 或 JOIN 里的子查询：它先产出一张临时结果集，再被外层当成一张普通的表来用。MySQL 硬性要求派生表必须有别名，否则报语法错误 1064。

派生表的核心价值是「分步」：先聚合、去重或限行，得到一个干净的小结果集，再参与后续的连接与过滤。很多「先分组算指标，再按指标筛选」的需求，用派生表一次就能表达清楚，而不必写两层嵌套。

MySQL 8.0 对派生表有两种处理方式：能被合并（derived merge）时，就把子查询直接揉进外层的 JOIN 里；不能合并时（例如带 GROUP BY、DISTINCT、LIMIT、聚合）会被物化（materialized）成临时表。想确认到底是哪种，用 EXPLAIN 看执行计划。

derived.sql
-- ① 先分组，再过滤：客户数不少于 2 的城市
SELECT t.city, t.cnt
FROM (SELECT city, COUNT(*) AS cnt FROM customers GROUP BY city) t
WHERE t.cnt >= 2
ORDER BY t.cnt DESC, t.city;

-- ② 派生表 + JOIN：客户订单总额排行
SELECT c.name, s.total
FROM customers c
JOIN (SELECT customer_id, SUM(amount) AS total
      FROM orders GROUP BY customer_id) s
  ON s.customer_id = c.id
ORDER BY s.total DESC;

-- ③ MySQL 8.0.14+ LATERAL：派生表可以引用左边的表
SELECT c.id, c.name, x.amount AS max_amount
FROM customers c
LEFT JOIN LATERAL (
  SELECT amount FROM orders o
  WHERE o.customer_id = c.id
  ORDER BY amount DESC LIMIT 1
) x ON TRUE;

03CTE 与集合运算

知识点CTE（WITH）与可读性重构common table expression · 给每一步起个名字

CTE（Common Table Expression，公用表表达式）用 WITH 名字 AS (SELECT …) 给一段查询起名，然后在主查询里像表一样引用它。它和派生表能力重叠，但胜在可以命名、可以多次引用、可以从上到下线性阅读，是把长 SQL 重构得能读的关键工具。MySQL 8.0 起支持，递归场景需要 WITH RECURSIVE。

CTE 的首要价值是可读性重构：把「嵌套三层才看懂」的 SQL 拆成 3 个有名字的步骤，每一步都能单独拿出来跑一遍验证。第二个价值是复用：同一段中间结果在主查询里被引用多次时，派生表写法必须整段重写，CTE 只写一次。

但要注意 CTE 不是缓存。MySQL 对被引用多次的 CTE 可能选择物化（算一次存起来），也可能内联展开（每次引用都重算），具体取决于是否被多次引用以及优化器判断，性能差异必须用 EXPLAIN 确认。

cte.sql
-- ① 把「部门均值」抽成 CTE，主查询立刻变短（练习台不支持 WITH，请到真实数据库验证）
WITH dept_avg AS (
  SELECT dept, AVG(salary) AS avg_salary
  FROM employees
  GROUP BY dept
)
SELECT e.name, e.dept, e.salary, ROUND(d.avg_salary, 0) AS dept_avg
FROM employees e
JOIN dept_avg d ON d.dept = e.dept
WHERE e.salary > d.avg_salary
ORDER BY e.dept, e.salary DESC;

-- ② 多个 CTE 串联：后一个可以引用前一个
WITH paid AS (
  SELECT customer_id, SUM(amount) AS total
  FROM orders
  WHERE status = 'paid'
  GROUP BY customer_id
),
big AS (
  SELECT customer_id, total FROM paid WHERE total > 1000
)
SELECT c.name, b.total
FROM big b
JOIN customers c ON c.id = b.customer_id
ORDER BY b.total DESC;

-- ③ 递归 CTE：从顶层经理往下展开汇报链（练习台不支持，请到真实数据库验证）
WITH RECURSIVE tree AS (
  SELECT id, name, manager_id, 1 AS lvl
  FROM employees
  WHERE manager_id IS NULL
  UNION ALL
  SELECT e.id, e.name, e.manager_id, t.lvl + 1
  FROM employees e
  JOIN tree t ON e.manager_id = t.id
)
SELECT lvl, id, name, manager_id
FROM tree
ORDER BY lvl, id;

知识点UNION / UNION ALL / INTERSECT / EXCEPTset operations · 按行做并集、交集、差集

集合运算（set operations）把两个 SELECT 的结果按行组合起来：UNION 合并去重、UNION ALL 直接拼接、INTERSECT 求交集、EXCEPT 求差集。它们要求两侧列数相同、类型兼容，结果的列名取第一个 SELECT 的列名。

最常考的差异是去重：UNION 隐含一次 DISTINCT，为了去重它必须排序或建哈希表，大结果集下代价明显；UNION ALL 只是把两块结果首尾相接，不比较不排序，是最便宜的写法。能用 UNION ALL 满足需求时就不要写 UNION。

版本差异也很关键：INTERSECT 与 EXCEPT 在 MySQL 8.0.31 才支持。在更早的版本里，求交集要用 INNER JOIN 或 EXISTS，求差集要用 LEFT JOIN … IS NULL 或 NOT EXISTS 来模拟。

set_ops.sql
-- ① UNION ALL：直接拼接，保留重复（练习台不支持，请到真实数据库验证）
SELECT id AS uid, name, 'customer' AS src FROM customers
UNION ALL
SELECT id, name, 'employee' FROM employees;

-- ② UNION：去重 + 隐式排序，代价更高
SELECT city FROM customers
UNION
SELECT city FROM customers WHERE id >= 4;

-- ③ INTERSECT（MySQL 8.0.31+）：两边都有的城市
SELECT city FROM customers
INTERSECT
SELECT city FROM customers WHERE id >= 4;

-- ④ EXCEPT（MySQL 8.0.31+）：A 有、B 没有
SELECT id FROM customers
EXCEPT
SELECT customer_id FROM orders;

-- ⑤ 全版本可用：用 EXISTS 模拟 INTERSECT
SELECT DISTINCT c.city
FROM customers c
WHERE EXISTS (SELECT 1 FROM customers x WHERE x.city = c.city AND x.id >= 4);

-- ⑥ 全版本可用：用 NOT EXISTS 模拟 EXCEPT
SELECT c.id
FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);

查询预期结果
①8 + 9 = 17 行；列名沿用第一个 SELECT 的 uid / name / src。
②右侧是左侧的子集，所以结果就是左侧去重后的 6 行：5 个城市 + 1 个 NULL（NULL 自成一组）。
③两侧都出现的城市，结果与 ⑤ 的 EXISTS 写法一致。
④从未下单的客户 id，预期 1 行（id = 8），与 ⑥ 结果一致。
!

易错：两侧列数不一致会报 1222「The used SELECT statements have a different number of columns」；ORDER BY / LIMIT 只能写在最后一个 SELECT 之后，作用于整个结果集；UNION 的去重是按整行比较，不是按某一列。

★

核心要点：并集优先 UNION ALL（除非确实需要去重）；交集、差集先看数据库版本，老版本一律用 EXISTS / NOT EXISTS 等价改写，既兼容又能利用索引。
