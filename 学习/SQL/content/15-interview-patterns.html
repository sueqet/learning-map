面试高频 SQL 题型

把面试里反复出现的七类 SQL 题拆成可复用的「套路」：TopN、排名并列、连续区间、去重取最新、自连接比较、行列转换、NULL 陷阱。

✓本节学习目标

  • 看到「每个/各 + 前 N」这类题干时，能在 30 秒内判断该用窗口函数、相关子查询还是派生表，并写出可运行的 SQL。
  • 说清 ROW_NUMBER()、RANK()、DENSE_RANK() 在并列时的输出差异，并按「要不要并列」选择函数。
  • 能用「日期 − 序号 = 常量」把连续登录/连续下单拆成连续区间，并解释断点为什么会自动分成新组。
  • 能写出「每个客户保留最新一笔订单」的三种写法（相关子查询 / 窗口函数 / 自连接删除），并说明各自适用场景。
  • 能识别 NULL 引发的边界陷阱（NOT IN、COUNT(列)、<> 比较），并改用反连接或 <=> 修正。
Pre-requisites · 前置知识

需要先掌握：单表查询与 WHERE/ORDER BY/LIMIT、多表 JOIN、GROUP BY 与聚合函数、子查询（相关子查询）、以及第 06 节的窗口函数基础（OVER (PARTITION BY … ORDER BY …)）。本页所有语法以 MySQL 8.0 为准。

Learning Points · 知识点

01取数与排名：
TopN、并列、组内排序

知识点TopN 与分组 TopNtop-n · 先全局排序取前几，再按组取前几

TopN 指按某个排序键取出前 N 行；分组 TopN（grouped TopN）则是「每个分组内部各取前 N 行」，本质是「先分组、再组内排序、最后每组截断」。它是面试出现频率最高的一类题，题干特征非常固定：出现「每个 / 各 / 每组」＋「最高 / 前 N / 最新」。

最容易踩的坑是把全局 TopN 的写法直接搬到分组场景：GROUP BY city ORDER BY amount DESC LIMIT 1 只会返回整个结果集的 1 行，因为 LIMIT 作用在最终结果上，跟分组没有关系。分组 TopN 必须做到「组内独立排序」，只有三种可行路线：窗口函数编号、相关子查询求组内极值、派生表求组内极值再 JOIN 回原表。

选型上：MySQL 8.0 优先窗口函数，一次分区排序即可完成，可读性和性能都最好；遇到不支持窗口函数的旧版本，就用相关子查询或派生表；如果组内可能有并列值，还要先想清楚「并列是否全部保留」——保留用 RANK() 或 = MAX()，只留一条用 ROW_NUMBER() 并在排序键后补一个唯一列（如 id）保证结果稳定。

  • 识别特征：题干里出现「每个 / 各 / 每组」＋「前 N / 最高 / 最低 / 最新」。
  • 解题步骤：① 定分组键（city / dept / customer_id）；② 定排序键（amount DESC，再补 id）；③ 选解法；④ 外层筛 rn <= N 或 amount = 组内 MAX。
  • 易错点：用 LIMIT 代替分组；GROUP BY 后选非分组列（MySQL 8.0 默认 ONLY_FULL_GROUP_BY 直接报错）；并列时结果条数不等于 N。
topn.sql
-- ① 全局 TopN：订单金额最高的 3 笔
SELECT o.id, o.customer_id, o.amount
FROM orders o
ORDER BY o.amount DESC, o.id      -- 补 id 保证并列时次序稳定
LIMIT 3;

-- ② 分组 TopN（MySQL 8.0 窗口函数，推荐）
SELECT t.city, t.name, t.order_id, t.amount
FROM (
  SELECT c.city, c.name, o.id AS order_id, o.amount,
         ROW_NUMBER() OVER (PARTITION BY c.city
                            ORDER BY o.amount DESC, o.id) AS rn
  FROM orders o
  JOIN customers c ON c.id = o.customer_id
) t
WHERE t.rn <= 1
ORDER BY t.amount DESC;

-- ③ 分组 TopN（无窗口函数的替代：相关子查询求组内极值）
SELECT c.city, c.name, o.id AS order_id, o.amount
FROM orders o
JOIN customers c ON c.id = o.customer_id
WHERE o.amount = (
  SELECT MAX(o2.amount)
  FROM orders o2
  JOIN customers c2 ON c2.id = o2.customer_id
  WHERE c2.city = c.city            -- 关键：随外行变化的关联条件
)
ORDER BY o.amount DESC;
写法能否按组取前 N并列处理代价版本
ORDER BY … LIMIT n不能，只作用于整个结果集可能截断并列一次排序所有版本
ROW_NUMBER() OVER (PARTITION BY …) + 外层 rn <= n能并列被强行拆开，序号唯一一次分区排序MySQL 8.0+
RANK() OVER (PARTITION BY …) + 外层 rk <= n能并列全保留，行数可能多于 N一次分区排序MySQL 8.0+
相关子查询 MAX + 回表匹配能并列全保留每行一次子查询，最坏 O(n²)所有版本
派生表求组内极值再 JOIN能并列全保留一次分组 + 一次 JOIN所有版本

核心要点：全局 TopN 用 ORDER BY + LIMIT；分组 TopN 必须让排序在「组内」发生——窗口函数 PARTITION BY 或相关子查询二选一。LIMIT 永远不是分组截断工具。

!

易错：相关子查询版一旦漏写 WHERE c2.city = c.city，就退化成「全表最高金额」，只会返回 1 行；用 GROUP BY c.city 又想同时选 c.name，MySQL 8.0 默认 ONLY_FULL_GROUP_BY 会直接报错——要用窗口函数或子查询，而不是靠关闭 sql_mode 蒙过去。

知识点排名与并列处理ranking · 并列怎么编号决定返回几行

排名类题目的核心不是「怎么写 ORDER BY」，而是并列值怎么编号。MySQL 8.0 提供三个排名窗口函数：ROW_NUMBER() 强制给每行唯一序号（并列被拆开），RANK() 并列同名并跳号（1,1,3），DENSE_RANK() 并列同名且不跳号（1,1,2）。同一个「取第 2 名」的需求，用不同函数返回的行数可能完全不同。

答题时先把需求翻译成一句明确的问法：「第 2 名」是「第 2 行」（用 ROW_NUMBER）、还是「并列第 2 名全部返回」（用 RANK）、还是「去重后的第 2 个值」（用 DENSE_RANK）。这句话问清了，SQL 几乎是模板化的：窗口函数在外层子查询里算序号，外层 WHERE 筛选。

如果面试官要求「不用窗口函数」，就用相关子查询计数法：统计同组内比自己大的行数，该人数 + 1 就是排名。它在并列时等价于 RANK，代价是每行一次子查询比较（最坏 O(n²)），大表上明显慢于窗口函数的一次排序。

  • 识别特征：出现「第 N 名 / 排名 / 并列 / 前 N 名」。
  • 解题步骤：① 明确并列语义；② 选函数（ROW_NUMBER / RANK / DENSE_RANK）；③ 子查询里算序号，外层筛选；④ 无窗口函数时改用「比我高的人数 + 1」。
  • 易错点：把 RANK 当 ROW_NUMBER 用导致返回多行；排序键不唯一导致分页/取数结果抖动。
rank.sql
-- 三个排名函数在同一份数据上的输出差异
SELECT o.id, o.amount,
       ROW_NUMBER() OVER (ORDER BY o.amount DESC, o.id) AS rn,
       RANK()       OVER (ORDER BY o.amount DESC)       AS rk,
       DENSE_RANK() OVER (ORDER BY o.amount DESC)       AS drk
FROM orders o;

-- 取「并列第 2 名」：用 RANK，并列的两行都返回
SELECT id, amount
FROM (SELECT id, amount, RANK() OVER (ORDER BY amount DESC) AS rk FROM orders) t
WHERE t.rk = 2;

-- 取「第 2 行」：用 ROW_NUMBER，只返回一行
SELECT id, amount
FROM (SELECT id, amount, ROW_NUMBER() OVER (ORDER BY amount DESC, id) AS rn FROM orders) t
WHERE t.rn = 2;

-- 不用窗口函数的替代：同部门内比我薪资高的人数 + 1 就是排名
SELECT e.dept, e.name, e.salary,
       (SELECT COUNT(*) FROM employees e2
        WHERE e2.dept = e.dept AND e2.salary > e.salary) + 1 AS 部门内排名
FROM employees e
ORDER BY e.dept, e.salary DESC;

-- 经典「第二高薪资」写法（没有第二名时返回 NULL）
SELECT MAX(salary) AS 第二高薪资
FROM employees
WHERE salary < (SELECT MAX(salary) FROM employees);

02时间序列与去重：
连续区间、保留最新、环比比较

知识点连续 N 天 / 连续区间consecutive · 日期 − 序号 = 常量

「连续 3 天登录」「连续 3 天有订单」「连续 3 个月增长」都属于连续区间问题。它的经典解法只有一句话：日期 − 序号 = 常量。对同一用户按日期排序并编号，如果日期每天递增 1、序号也每天递增 1，两者的差就不变；一旦日期断档（日期跳了 2 天而序号只 +1），差值就变了——于是所有连续的日子自动落进同一个「差值分组」，断点自然形成新组。

拿到连续段后，GROUP BY 用户, 差值 再用 MIN/MAX/COUNT 就能得到「起始日期、结束日期、连续天数」，最后 HAVING COUNT(*) >= N 筛出满足要求的段。注意 HAVING 是对分组结果筛选，不能写成 WHERE。

如果面试官不让用窗口函数，还有第二条路：自连接逐日探测。对「连续 3 天」，让 a、b、c 三份自身连接，分别要求 DATEDIFF = 1 和 DATEDIFF = 2，命中即连续。它直观但扩展性差（连续 N 天就要 N 次自连接），适合 N 很小、或者只判断「是否存在」而不需要给出区间的场景。

本页为连续类题目补充一张辅助表 signins(id, user_id, sign_date)，与内置数据集风格一致，下方练习台已加载，可以直接跑。

  • 识别特征：出现「连续 N 天 / 连续 N 个月 / 连续区间 / 最长连续」。
  • 解题步骤：① 先按天 DISTINCT 去重；② ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY sign_date) 编号；③ 用 DATEDIFF(日期, 基准日) − 序号 当分组键；④ 按「用户 + 分组键」聚合，HAVING COUNT(*) >= N。
  • 易错点：忘记按用户分区（不同用户会混成一段）；忘记去重（同一天多条记录把序号算错）；日期列是 DATETIME 时没做 DATE() 归一化。
consecutive.sql
-- 辅助表：signins(id, user_id, sign_date)
-- 解法一：日期 - 序号 = 常量（推荐，能拿到完整连续区间）
SELECT user_id,
       MIN(sign_date) AS 起始日期,
       MAX(sign_date) AS 结束日期,
       COUNT(*)       AS 连续天数
FROM (
  SELECT a.user_id, a.sign_date,
         DATEDIFF(a.sign_date, '2000-01-01')
         - ROW_NUMBER() OVER (PARTITION BY a.user_id ORDER BY a.sign_date) AS grp
  FROM (SELECT DISTINCT user_id, sign_date FROM signins) a   -- 必须先按天去重
) t
GROUP BY user_id, grp
HAVING COUNT(*) >= 3
ORDER BY user_id, 起始日期;

-- 解法二：自连接逐日探测（固定 N 小、无需窗口函数，练习台可跑）
SELECT DISTINCT a.user_id
FROM signins a
JOIN signins b ON b.user_id = a.user_id AND DATEDIFF(b.sign_date, a.sign_date) = 1
JOIN signins c ON c.user_id = a.user_id AND DATEDIFF(c.sign_date, a.sign_date) = 2
ORDER BY a.user_id;

-- 解法三：LAG 判断相邻两天是否连续（MySQL 8.0，练习台不支持，请到真实数据库验证）
SELECT user_id, sign_date,
       LAG(sign_date) OVER (PARTITION BY user_id ORDER BY sign_date) AS 上次签到,
       DATEDIFF(sign_date, LAG(sign_date) OVER (PARTITION BY user_id ORDER BY sign_date)) AS 间隔天数
FROM signins;

知识点去重与保留最新dedup · 先去重，再决定留哪一条

这类题要先区分两种完全不同的需求：去重（同一组值只出现一次）和保留最新（每组挑一条代表行，通常是日期最新或 id 最大）。DISTINCT 只能解决前者——它消除的是整行值组合完全相同的行，无法告诉你「哪一条是最新的」。

保留最新有三种主流写法：① 相关子查询定位每组最大日期，写法短、所有版本可用；② 窗口函数 ROW_NUMBER() 分区排序后取 rn = 1，最灵活，可以用多个排序键打破「同一天多笔」的并列；③ 物理删除重复行时用自连接 DELETE … JOIN … ON o1.id < o2.id，保留 id 最大的那条（属于 DML，练习台不支持，请到真实数据库验证）。

需要特别注意「最新」的判据：如果业务上同一天可能有多笔订单，只比 MAX(order_date) 会一次返回多行。这时要么在子查询里再加一层「同日期内取最大 id」，要么直接用 ROW_NUMBER() 的多级排序键一次性搞定。

  • 识别特征：出现「去重 / 重复 / 每个…只保留一条 / 最新的一条 / 删除重复」。
  • 解题步骤：① 明确「代表行」的判据（最新日期？最大 id？最高金额？）；② 相关子查询定位判据，或窗口函数编号；③ 外层 WHERE rn = 1／= MAX(...)；④ 删除场景用自连接。
  • 易错点：把 DISTINCT 当「保留最新」；GROUP BY 里选非聚合列；判据不唯一导致每组返回多行。
dedup.sql
-- ① 去重：只关心「值组合不重复」时用 DISTINCT
SELECT DISTINCT city FROM customers;

-- ② 保留最新：每个客户最新的一笔订单（相关子查询）
SELECT o.id, o.customer_id, o.order_date, o.amount
FROM orders o
WHERE o.order_date = (
  SELECT MAX(o2.order_date) FROM orders o2 WHERE o2.customer_id = o.customer_id
)
ORDER BY o.customer_id;

-- ③ 同一天多笔时，用多级排序键一次挑出一条
SELECT id, customer_id, order_date, amount
FROM (
  SELECT id, customer_id, order_date, amount,
         ROW_NUMBER() OVER (PARTITION BY customer_id
                            ORDER BY order_date DESC, amount DESC, id DESC) AS rn
  FROM orders
) t
WHERE t.rn = 1;

-- ④ 物理删除重复行、每组只留 id 最大的一条（DML，练习台不支持）
DELETE o1 FROM orders o1
JOIN orders o2
  ON o1.customer_id = o2.customer_id
 AND o1.order_date  = o2.order_date
 AND o1.id < o2.id;

DISTINCT整行值组合去重不能只消除完全相同的行，不表达优先级
GROUP BY + MAX每组取极值只能取极值本身想同时要其它列会踩 ONLY_FULL_GROUP_BY
相关子查询 = MAX(order_date)每组取代表行能同一天多笔会全部留下
ROW_NUMBER() + rn = 1每组取一条能可用多级排序键打破并列，最稳
DELETE + 自连接物理删除重复能DML 操作，练习台不支持

知识点自连接比较类（环比 / 上一条）self-join · 同一张表当两张用

自连接（self join）就是把同一张表用两个别名连接起来，分别代表「当前行」和「参照行」。环比、同比、上一条记录、相邻两行差值，都是它的典型场景：FROM orders o JOIN orders p ON …，其中 o 是本期、p 是上一期。

连接条件是全部难点。最常见的错误是 p.id = o.id - 1——它假设主键连续且同客户相邻，真实数据里完全不成立。正确做法是用业务排序键比较：p.customer_id = o.customer_id AND p.order_date < o.order_date。但这个条件在「一个客户有多笔更早订单」时会一对多，产生多行；要严格只取「上一条」，得再补一个子查询锁定唯一行（ORDER BY order_date DESC LIMIT 1），或者直接用窗口函数 LAG()。

写自连接时还要注意内连接语义：只有一个订单的客户（示例数据里的客户 4、6）不会出现在结果里，因为找不到参照行。如果需求要求「第一笔也要显示、环比记为空」，就要把 JOIN 换成 LEFT JOIN，缺失的上一笔自然是 NULL。

  • 识别特征：出现「环比 / 同比 / 与上一条比较 / 相邻两行 / 差值 / 增长率」。
  • 解题步骤：① 确定排序键（日期、序号）；② 自连接，别名区分本期与上期；③ 用严格小于 + 子查询/窗口函数锁定唯一参照行；④ 计算差值/比值，注意除零与 NULL。
  • 易错点：用 id 差 1 当「上一条」；漏写分组键导致跨客户比较；内连接丢掉了第一期。
compare.sql
-- ① 自连接求环比：当前订单与同客户上一笔订单比较（练习台可跑）
SELECT o.id, o.customer_id, o.order_date, o.amount,
       p.amount AS 上一笔金额,
       o.amount - p.amount AS 环比差额
FROM orders o
JOIN orders p
  ON p.customer_id = o.customer_id
 AND p.order_date  < o.order_date
ORDER BY o.customer_id, o.order_date;

-- ② 严格取「上一条」：用子查询锁定唯一行，避免一对多
SELECT o.id, o.customer_id, o.order_date, o.amount, p.amount AS 上一笔金额
FROM orders o
JOIN orders p
  ON p.id = (SELECT o2.id FROM orders o2
             WHERE o2.customer_id = o.customer_id
               AND o2.order_date  < o.order_date
             ORDER BY o2.order_date DESC, o2.id DESC
             LIMIT 1)
ORDER BY o.customer_id, o.order_date;

-- ③ MySQL 8.0 更简单的写法：LAG 取上一行（练习台不支持，请到真实数据库验证）
SELECT id, customer_id, order_date, amount,
       LAG(amount) OVER (PARTITION BY customer_id ORDER BY order_date) AS 上一笔金额,
       amount - LAG(amount) OVER (PARTITION BY customer_id ORDER BY order_date) AS 环比差额
FROM orders;

-- ④ 同比：与去年同期比较
SELECT o.id, o.order_date, o.amount, p.amount AS 去年同期金额
FROM orders o
JOIN orders p
  ON p.customer_id = o.customer_id
 AND p.order_date  = DATE_SUB(o.order_date, INTERVAL 1 YEAR);

写法同表两别名 + 业务排序键比较一次扫描 + PARTITION BY

核心要点：自连接的连接条件必须由业务排序键（日期、序号）构成，绝不能用主键差值。取「严格上一条」时，用子查询 + ORDER BY … DESC LIMIT 1 收敛成一行，或直接用 LAG()。

易错：环比算增长率的除法要防除零（上一笔为 0 或 NULL）：NULLIF(p.amount, 0) 是常用写法，否则结果为 NULL 或报错；另外 p.order_date < o.order_date 漏写会变成自己和自己比。

Learning Points · 知识点

03报表与陷阱：
行列转换、NULL 与边界

知识点行列转换与报表题pivot · 条件聚合代替 PIVOT

行转列（pivot）把某一列里的枚举值「摊」成多个列，报表里最典型的样子是：每行一个客户，列是各状态（paid / refunded / cancelled）的金额。列转行（unpivot）方向相反，把多个列压回多行。面试常考「MySQL 怎么做行转列」——答案是：MySQL 没有 PIVOT 语法（Oracle、SQL Server 有），要用条件聚合实现。

条件聚合的模板是 SUM(CASE WHEN 状态 = 'x' THEN 金额 ELSE 0 END) AS x金额，配合 GROUP BY 分组列。要点是 ELSE 0：不写 ELSE 会得到 NULL，后续参与求和或除法时容易出意外；而用 COUNT(CASE WHEN … THEN 1 END) 统计单数时，恰恰要靠 NULL 被忽略的特性，这里不要写 ELSE。

枚举值固定时手写列最清晰；枚举值动态变化（状态经常新增）时，只能拼动态 SQL：用 GROUP_CONCAT 生成列表达式，再 PREPARE 执行。生产环境更常见的做法是把「摊平」交给应用层或 BI 工具，数据库只输出长表。

  • 识别特征：出现「行转列 / 列转行 / 透视 / 报表 / 每种状态一列」。
  • 解题步骤：① 定行维度（客户/城市）与列维度（状态/月份）；② 每列写一个 SUM(CASE WHEN … THEN … ELSE 0 END)；③ GROUP BY 行维度；④ 列不固定时改动态 SQL。
  • 易错点：误以为 MySQL 有 PIVOT；忘记 ELSE 0 导致整列 NULL；列名带中文或空格没加反引号。
pivot.sql
-- 行转列：每行一个客户，列是各状态的订单金额（条件聚合）
SELECT c.name AS 客户,
       SUM(CASE WHEN o.status = 'paid'      THEN o.amount ELSE 0 END) AS 已付金额,
       SUM(CASE WHEN o.status = 'refunded'  THEN o.amount ELSE 0 END) AS 退款金额,
       SUM(CASE WHEN o.status = 'cancelled' THEN o.amount ELSE 0 END) AS 取消金额,
       COUNT(o.id) AS 订单数
FROM customers c
JOIN orders o ON o.customer_id = c.id
GROUP BY c.name
ORDER BY 已付金额 DESC;

-- 统计单数时用 COUNT(CASE WHEN … THEN 1 END)：不写 ELSE，NULL 会被自动忽略
SELECT c.level AS 等级,
       COUNT(CASE WHEN o.status = 'paid'     THEN 1 END) AS 已付单数,
       COUNT(CASE WHEN o.status = 'refunded' THEN 1 END) AS 已退单数,
       COUNT(o.id) AS 总单数
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
GROUP BY c.level;

-- 列转行：把多个列压回多行（练习台不支持 UNION ALL，请到真实数据库验证）
SELECT name, 'paid'      AS status, paid_amt      AS amount FROM customer_report
UNION ALL
SELECT name, 'refunded'  AS status, refund_amt    AS amount FROM customer_report
UNION ALL
SELECT name, 'cancelled' AS status, cancelled_amt AS amount FROM customer_report;

-- 枚举值不固定时：动态 SQL 拼列（MySQL 8.0）
SET @cols = (
  SELECT GROUP_CONCAT(DISTINCT
           CONCAT("SUM(CASE WHEN status='", status, "' THEN amount ELSE 0 END) AS `", status, "`"))
  FROM orders
);
SET @sql = CONCAT('SELECT customer_id, ', @cols, ' FROM orders GROUP BY customer_id');
PREPARE stmt FROM @sql;
EXECUTE stmt;
DEALLOCATE PREPARE stmt;

核心要点：MySQL 行转列 = SUM(CASE WHEN … THEN … ELSE 0 END) × N 列 + GROUP BY 行维度。求金额写 ELSE 0，求个数写 COUNT(CASE WHEN … THEN 1 END)（不加 ELSE）。

!

易错：行转列时用 INNER JOIN 会丢掉没有任何订单的客户（示例数据里的周涛），报表要保留全部客户请用 LEFT JOIN，并且注意此时 SUM 结果是 0 还是 NULL 取决于 ELSE 分支的写法。

知识点NULL 与边界陷阱题traps · 结果为空不一定是数据为空

面试里最容易「写对语法、拿错结果」的就是 NULL 相关的边界题。NULL 不是值，而是「未知」：任何与 NULL 的比较（=、<>、IN）结果都是 UNKNOWN，而 WHERE 只保留结果为 TRUE 的行——所以 WHERE city <> '北京' 只返回 5 行（李娜、王强、刘敏、陈晨、孙悦），两位北京客户被条件排除，city 为 NULL 的周涛也因为结果是 UNKNOWN 被静默丢掉。

最经典的陷阱是 NOT IN：id NOT IN (SELECT customer_id FROM orders)，只要子查询结果里出现一个 NULL，整个条件对所有行都变成 UNKNOWN，语句返回 0 行——看起来像「数据错了」，其实是三值逻辑。示例数据的 orders.customer_id 恰好没有 NULL，所以这里侥幸返回 1 行（周涛），但换一张表就可能翻车（下面表格里那一行列的就是这种子查询含 NULL 的情形）。安全写法是反连接：LEFT JOIN … WHERE 右表主键 IS NULL。

其它高频边界：COUNT(*) 统计行数（含 NULL），COUNT(列) 忽略 NULL，COUNT(DISTINCT 列) 再去重；聚合函数（除 COUNT(*) 外）都忽略 NULL，AVG 的分母是非 NULL 行数而不是总行数；GROUP BY 会把所有 NULL 归成一组；BETWEEN a AND b 含两端；字符串排序里 NULL 排在最前（MySQL 升序）。

MySQL 还提供 NULL 安全等号 <=>：city <=> NULL 等价于 city IS NULL，两个 NULL 比较返回 TRUE，常用于可空字段的等值匹配（其他数据库如 PostgreSQL 需用 IS NOT DISTINCT FROM）。

  • 识别特征：题干出现「没有下过订单 / 不存在 / 排除某些值 / 统计人数」，或结果「应该是 N 行却是 0 行」。
  • 解题步骤：① 先看字段是否可空；② 排除值改反连接（LEFT JOIN … IS NULL）或 NOT EXISTS；③ 统计时区分 COUNT(*) 与 COUNT(列)；④ 用 <=> 处理 NULL 等值。
  • 易错点：NOT IN + 含 NULL 子查询；INNER JOIN … WHERE 右表 IS NULL 永远 0 行；把 NULL 当 0 参与运算。
traps.sql
-- ① 反连接：没有下过订单的客户（NULL 安全，练习台可跑）
SELECT c.id, c.name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;

-- ② NOT IN 的陷阱：子查询结果里只要有一个 NULL，整条语句返回空集
SELECT COUNT(*) FROM customers
WHERE id NOT IN (SELECT customer_id FROM orders);   -- customer_id 无 NULL 时才安全

-- ③ COUNT(*) / COUNT(列) / COUNT(DISTINCT 列) 的差别
SELECT COUNT(*)            AS 总行数,
       COUNT(city)         AS 有城市的行数,
       COUNT(DISTINCT city) AS 城市个数
FROM customers;

-- ④ 三值逻辑：NULL 不参与 = 比较，必须用 IS NULL
SELECT id, name FROM customers WHERE city IS NULL OR city <> '北京';

-- ⑤ MySQL 的 NULL 安全等号 <=>：两个 NULL 也判等
SELECT id, name FROM customers WHERE city <=> NULL;

-- ⑥ NOT EXISTS 是 NOT IN 的安全替代
SELECT COUNT(*) FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);

!

易错：把 NULL 当 0 用：amount + NULL 还是 NULL，要先用 IFNULL(amount, 0) 或 COALESCE 兜底；AVG(amount) 的分母是非 NULL 行数，跟 SUM(amount)/COUNT(*) 并不相等。
