MODULE 15 · 数据结构与算法

动态规划

从「爬楼梯」到「背包问题」，动态规划用「记住重复出现的子问题」这一招，把指数级搜索变成高效递推——这是笔试与面试中权重最高、也最考验基本功的题型。

✓本节学习目标

  • 学完后你能判断一个最优化问题是否具备最优子结构与重叠子问题，从而确定是否该用 DP 求解。
  • 学完后你能用「定义状态 → 找转移方程 → 定边界 → 定遍历顺序」四步工序，独立写出爬楼梯、打家劫舍、最大子序和的转移方程与可运行代码。
  • 学完后你能写出 LIS（最长上升子序列）的 O(n log n) 贪心+二分解法，以及 LCS（最长公共子序列）的二维 DP，并说清「子序列 ≠ 子数组/子串」。
  • 学完后你能解释0-1 背包内层为何要倒序，并写出 0-1 / 完全 / 分组背包以及凑零钱（LC 322）的滚动数组代码。
  • 学完后你能用记忆化搜索与自底向上两种方式实现同一 DP，并说明区间 DP、树形 DP、单调队列/斜率优化各自适用的场景。
Pre-requisites · 前置知识

需要会一门编程语言（推荐 Python 或 C++）；理解递归与「函数调用栈」；熟悉时间复杂度与 O 记号；了解基本的最优化概念（最大/最小值）；建议先掌握「递归」与「贪心算法」两节——贪心里提到的「局部最优 vs 全局最优」正是理解 DP 为什么和贪心不同的入口。

15.1动态规划：两大前提与解题工序

知识点动态规划思想（最优子结构与重叠子问题）dp-basic · 概念与思想

动态规划（Dynamic Programming，DP）是一种把原问题拆分成互相重叠的子问题，取「记录已经算过的东西」来避免重复计算，从而高效求解最优化问题的方法。它有两个公认的前提，也是判断「能不能用 DP」的试金石：

  • 最优子结构（Optimal Substructure）：原问题的最优解能由它的子问题的最优解组合/递推得到。也就是说，子问题取到最优，才能拼出整体最优。
  • 重叠子问题（Overlapping Subproblems）：递归求解时，同一个子问题会被多次求解。只有子问题重叠，才值得把结果存下来复用；若不重叠，就退化为分治（Divide & Conquer），记忆化没有意义。

第三点常被忽略却同样重要：无后效性（No Aftereffect）——状态一旦确定，后续决策只依赖「当前状态」本身，不受之前是怎么走到这里的路径影响。这是你定义状态时必须满足的性质。

方法子问题关系是否记录典型例子
分治 Divide & Conquer互不相交不需要归并排序、快速排序、二分查找
贪心 Greedy只做局部最优，可回溯到更少不需要（不回头）找零、区间调度、最小生成树
动态规划 DP互相重叠 + 最优子结构一定要记录爬楼梯、背包、最长子序列

用斐波那契最能看出「重叠子问题」到底重叠在哪：朴素递归会反复计算 fib(2)、fib(3) 等，而记忆化或递推只算一次。

fib.py · 三种写法对比
# 1) 朴素递归：大量重复计算（可见重叠子问题）
def fib_naive(n):
    if n < 2:
        return n
    return fib_naive(n-1) + fib_naive(n-2)   # 同一个 n 会被算很多次

# 2) 记忆化搜索（自顶向下）：用缓存挡住重复计算
from functools import lru_cache
@lru_cache(None)
def fib_memo(n):
    if n < 2:
        return n
    return fib_memo(n-1) + fib_memo(n-2)

# 3) 自底向上 DP（递推 + 空间优化）：从边界一点点往上推
def fib_dp(n):
    if n < 2:
        return n
    a, b = 0, 1
    for _ in range(2, n+1):
        a, b = b, a + b
    return b
★

核心要点：拿到题先问两件事——①「大问题的最优解能不能由子问题最优解拼出来」→ 判断最优子结构；②「递归会不会反复求解同一个子问题」→ 判断重叠子问题。两个都成立，才值得 DP。

!

易错：子问题互不重叠的分治（归并、快排、二分）不是 DP，记忆化帮不上忙；子问题不满足最优子结构（比如某些需要全局最优、局部最优拼不出全局最优的问题）也不能用 DP。

⚠

易错：状态定义必须满足无后效性——不能把「未来才知道的信息」塞进状态，否则转移方程无法只依据前面已算好的状态来写。

知识点状态定义、转移方程与边界/遍历顺序dp-state · 固定四步工序

动态规划真正的难点不在「会用递推」，而在写出对的状态。这里给你一套可复用的固定思考工序，几乎可以套用到所有 DP 题：

  1. 定义状态：明确 dp[i]（或二维 dp[i][j]）表示什么。状态是「已经算好的、确定性的量」，必须无后效。
  2. 找转移方程：写出「由哪些已知状态推出 dp[i]」的等式，这是整道题的灵魂。
  3. 定边界（初始化）：确定 dp[0]、dp[1]、dp[0][0] 等初始值，并处理越界（下标 i-1/j-1）。
  4. 确定遍历顺序：从前往后 / 从后往前 / 外层组内层容量，保证在计算某状态时，它依赖的状态已经算好。（背包问题这里的顺序会直接改变答案！）

下面用「爬楼梯」把四步演示一遍，并给出一个通用可运行的 DP 模板骨架：

climb_stairs.py · 通用 DP 模板
# 问题：每次可走 1 阶或 2 阶，问走上 n 阶有多少种不同走法 (LC 70)
def climb_stairs(n):
    # 1) 定义状态：dp[i] = 走到第 i 阶的方法数
    # 2) 转移方程：dp[i] = dp[i-1] + dp[i-2]（最后一步从 i-1 或 i-2 来）
    # 3) 边界：dp[1]=1, dp[2]=2
    # 4) 遍历顺序：从小到大（自底向上）
    if n < 3:
        return n
    dp = [0]*(n+1)
    dp[1], dp[2] = 1, 2
    for i in range(3, n+1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]

# 模板骨架（通用）：四个注释位就是你的思考流程
def dp_template(...):
    # 1) 状态定义
    dp = [[...] for _ in range(...)]
    # 2) 边界初始化
    ...
    # 3) 遍历顺序 + 转移方程
    for i in ...:
        for j in ...:
            dp[i][j] = ...   # 只依赖已经算好的更小状态
    # 4) 返回答案（有时要取 max/min，或 dp[-1]）
    return ...
★

核心要点：「状态定义」决定其他三步，是 DP 的唯一难点。常见套路是问自己：「到一个位置/区间，我只需要记住哪个最小的信息，就能继续往下推？」 记住的越少、越干净，转移就越简单。

!

易错：边界与越界是最常见的 bug 来源——例如用 dp[i-1]、dp[i-2]、dp[i+1][j] 时，下标会不会走出数组？遍历顺序决定了「依赖是否已算好」，顺序写反会直接得到错误答案（区间 DP、背包尤其容易踩雷）。

15.2一维 DP 与子序列问题

知识点一维 DP（爬楼梯、打家劫舍、最大子序和）dp-1d · 递推形状

一维 DP 是入门必背的三道经典题，它们的转移只有两种形状：「累加型」（斐波那契式 f(n)=f(n-1)+f(n-2)）和「选/不选型」（max(dp[i-1], dp[i-2]+w[i])）。

  • 爬楼梯（LC 70）：最后一步要么从 i-1 跨 1 阶、要么从 i-2 跨 2 阶，故 dp[i]=dp[i-1]+dp[i-2]。
  • 打家劫舍（LC 198）：不能偷相邻两家。偷第 i 家则与 i-1 冲突，只能加 dp[i-2]；不偷则继承 dp[i-1]，故 dp[i]=max(dp[i-1], dp[i-2]+nums[i])。
  • 最大子序和（LC 53）：状态必须是「以 i 结尾」的最大连续子数组和，因为要保证连续性。转移 dp[i]=max(nums[i], dp[i-1]+nums[i])，答案为所有 dp[i] 的最大值。
dp_1d.py
# 打家劫舍 LC 198
def rob(nums):
    n = len(nums)
    if n == 0: return 0
    if n == 1: return nums[0]
    dp = [0]*n
    dp[0], dp[1] = nums[0], max(nums[0], nums[1])
    for i in range(2, n):
        # 选 i 家：dp[i-2]+nums[i]；不选 i 家：dp[i-1]
        dp[i] = max(dp[i-1], dp[i-2] + nums[i])
    return dp[-1]

# 最大子序和 LC 53（状态必须“以 i 结尾”才能无后效地转移）
def max_subarray(nums):
    cur = best = nums[0]          # cur = 以当前位结尾的最大和
    for x in nums[1:]:
        cur = max(x, cur + x)     # 要么重新开始，要么接在 cur 后面
        best = max(best, cur)
    return best
★

核心要点：一维 DP 就记两种递推形状——「累加型」（爬楼梯、斐波那契，结果相加）与「选/不选型」（打家劫舍、股票买卖，取 max/min），绝大多数一维题都能归类到其中之一。

!

易错：最大子序和的状态定义必须是「以 i 结尾」，而不能是「前 i 个元素中的最大和」——否则当前元素必须被接进来，状态无法用上一状态无后效地转移。这是 LC 53 最常见的写错点。

⚠

优化：这三种题的 dp[i] 只依赖前 1～2 个状态，可用滚动数组把空间压到 O(1)（详见「DP 常见优化」）。

知识点子序列问题（LIS / LCS）dp-subseq · 平台级系列

子序列问题几乎必考。先分清概念：子序列（subsequence）是从原序列中挑出若干元素、保持相对顺序、但可以不相邻；而子数组/子串（subarray/substring）要求必须连续。

  • LIS（Longest Increasing Subsequence，最长上升子序列，LC 300）：普通 DP 是 dp[i]=max(dp[j]+1)（j<i 且 nums[j]<nums[i]），O(n²)；更优的是贪心+二分，维护一个「每个长度的最小结尾」数组 tails，做到 O(n log n)。
  • LCS（Longest Common Subsequence，最长公共子序列，LC 1143）：二维 DP，dp[i][j] 表示 s1 前 i 个与 s2 前 j 个的 LCS 长度。字符相等则 +1，否则取左边或上边的较大者。
lis_lcs.py
# LIS 贪心 + 二分 · O(n log n)  LC 300
import bisect
def length_of_lis(nums):
    tails = []           # tails[k] = 长度为 k+1 的上升子序列的最小结尾
    for x in nums:
        i = bisect.bisect_left(tails, x)   # 找第一个 >= x 的位置
        if i == len(tails):
            tails.append(x)                # 比所有结尾都大，形成更长序列
        else:
            tails[i] = x                   # 用更小的结尾替换，降低后续接上的难度
    return len(tails)

# LCS · 二维 DP · O(m*n)  LC 1143
def lcs(s1, s2):
    m, n = len(s1), len(s2)
    dp = [[0]*(n+1) for _ in range(m+1)]   # 多开一行/列当边界
    for i in range(1, m+1):
        for j in range(1, n+1):
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]
★

核心要点：LIS 的贪心+二分核心就是「让每个长度的结尾尽量小」，这样后面更容易接上更大的数。注意 tails 只给出长度，要还原出真实序列还需额外记录每个位置的前驱。

!

易错：「子序列」可以跳着选（不相邻），「子数组/子串」必须连续。判断「严格上升」时用 bisect_left 找「第一个 ≥ x」；若是「非严格上升（可相等）」，要用 bisect_right。

⚠

提示：LCS 的状态转移在字符不等时取 max(上, 左)，这保证了「少一个字符」也能继承最长公共部分——理解这一点就能把 LCS 和「最长公共子串」（要求连续，转移只在相等时 +1）区分开。

15.3背包问题

知识点背包问题（0-1 / 完全 / 分组）dp-knapsack · 面试必考

背包是 DP 里最经典的「选/不选 + 容量」模型，也是面试重点。核心是给一个容量 W，从若干物品里选，使价值最大（或数量最少）。三种变体，唯一区别是「每个物品能用几次」：

  • 0-1 背包：每个物品最多选一次。一维滚动为 dp[j]=max(dp[j], dp[j-w[i]]+v[i])，内层容量倒序。
  • 完全背包：每个物品可以无限次选。一维滚动内层容量正序。凑零钱（LC 322）就是「求最小数量」的完全背包。
  • 分组背包：物品分成若干组，每组最多选一个。遍历顺序：先组 → 再容量（倒序）→ 再组内物品。
knapsack.py · 三种背包一维写法
# 0-1 背包 · 一维滚动 · O(N*W)
def knapsack_01(v, w, W):
    dp = [0]*(W+1)
    for i in range(len(v)):
        for j in range(W, w[i]-1, -1):   # 内层【倒序】：保证每个物品最多选一次
            dp[j] = max(dp[j], dp[j-w[i]] + v[i])
    return dp[W]

# 完全背包 · 内层【正序】：允许同一物品被反复放入
def knapsack_complete(v, w, W):
    dp = [0]*(W+1)
    for i in range(len(v)):
        for j in range(w[i], W+1):       # 内层【正序】
            dp[j] = max(dp[j], dp[j-w[i]] + v[i])
    return dp[W]

# 凑零钱 LC 322 · 完全背包求“最少硬币数”
def coin_change(coins, amount):
    INF = float('inf')
    dp = [INF]*(amount+1)
    dp[0] = 0
    for c in coins:
        for x in range(c, amount+1):     # 正序：硬币可重复使用（完全背包）
            dp[x] = min(dp[x], dp[x-c] + 1)
    return dp[amount] if dp[amount] != INF else -1
!

为什么 0-1 背包内层要倒序？ 一维 dp[j] 依赖的是「本轮还没被当前物品更新过」的 dp[j-w[i]]。若内层正序，dp[j-w[i]] 可能已在同一轮被当前物品填过（即已放进这个物品），再用它去推 dp[j] 就会把同一个物品再放一次，退化成「完全背包」。倒序时，dp[j-w[i]] 仍是上一轮（未放当前物品）的值，每个物品于是最多只被选一次。

★

核心要点：一个口诀：0-1 背包内层倒序、完全背包内层正序、分组背包「先组后容量再物品（容量倒序）」。方向一旦反了，0-1 就变完全背包，答案直接错。

⚠

延伸：「能不能恰好装满容量 / 恰好凑出金额」类问题（如分割等和子集 LC 416、目标和 LC 494）用 bool 型 dp 判断可达性；注意 0-1 背包内层同样要倒序。

15.4进阶：区间 DP、树形 DP 与优化

知识点区间 DP 与树形 DP 简介dp-advanced · 走进结构化状态

当一维/背包这类「线性流程」不够用，DP 状态会走向区间或树结构。

  • 区间 DP：状态是 dp[i][j]，表示区间 [i, j] 上的最优值。转移时枚举分割点 k：dp[i][j] = min/max(dp[i][k] + dp[k+1][j] + 合并代价)。典型：矩阵链乘、最长回文子序列（LC 516）、石子合并（洛谷 P1880）。遍历顺序是按区间长度从小到大（先填小区间）。
  • 树形 DP：在树上做 DP，用后序遍历（DFS）先算子树再传回父节点。状态常带「选/不选当前节点」两维。典型：打家劫舍 III（LC 337）、树的最大独立集、树的直径。
interval_tree_dp.py
# 最长回文子序列 LC 516 · 区间 DP
def longest_palindrome_subseq(s):
    n = len(s)
    dp = [[0]*n for _ in range(n)]
    for i in range(n):
        dp[i][i] = 1                      # 单个字符回文长度为 1
    for length in range(2, n+1):          # 按区间长度从小到大
        for i in range(n-length+1):
            j = i + length - 1
            if s[i] == s[j]:              # 两端相等 -> 两端都加入回文
                dp[i][j] = dp[i+1][j-1] + 2
            else:                         # 否则继承去掉一端的最优
                dp[i][j] = max(dp[i+1][j], dp[i][j-1])
    return dp[0][n-1]

# 打家劫舍 III LC 337 · 树形 DP（后序 DFS）
def rob_tree(root):
    def dfs(u):
        if not u:
            return (0, 0)
        l0, l1 = dfs(u.left)              # 先算子节点（后序遍历）
        r0, r1 = dfs(u.right)
        not_rob = max(l0, l1) + max(r0, r1)  # 不选 u：子节点可自由选择
        rob     = u.val + l0 + r0            # 选 u：子节点必须不选
        return (not_rob, rob)                # 返回 (本节点不选, 本节点选)
    return max(dfs(root))
★

核心要点：区间 DP 的复杂度一般是 O(n²) 个状态 × O(n) 的合并 = O(n³)；树形 DP 则是「每个节点算一次、汇总子树」，典型 O(n)（乘上状态的维度）。

!

易错：区间 DP 必须按区间长度从小到大，否则在填 dp[i][j] 时，它依赖的更小区间（dp[i+1][j-1]、dp[i+1][j]、dp[i][j-1]）可能还没算好，得到错误结果。树形 DP 则要保证子节点先于父节点被计算（后序 DFS）。

⚠

提示：区间 DP 的「分割点枚举」其实和「矩阵链乘 / 最佳二叉搜索树」是同一套结构；树形 DP 的「选/不选」和打家劫舍一维版的思路一脉相承，只是搬到了树上。

知识点记忆化搜索dp-memo · 自顶向下

记忆化搜索（Memoization Search / Top-down DP）用递归把递推关系自然写出来，再借助一张表（哈希表/数组，Python 常用 @lru_cache，C++ 用 map/vector）记录「状态 → 结果」，避免重复计算。它与自底向上的 dp 表对应同一棵状态树，只是方向相反、复杂度相同。

  • 何时更合适：状态转移不是简单线性的顺序（如图上依赖、博弈、需要回溯路径的问题），自底向上难以确定遍历顺序，用递归更直观、更不易写错。
  • 代价：递归有函数调用开销；层数过深在 Python 可能栈溢出（必要时 sys.setrecursionlimit 或改用自底向上）。
memo.py · 凑零钱的自顶向下写法
# 记忆化搜索：凑零钱 LC 322 的“自顶向下”版本
from functools import lru_cache

def coin_change(coins, amount):
    @lru_cache(None)
    def dfs(rem):
        if rem == 0:
            return 0                    # 已经凑满
        best = float('inf')
        for c in coins:
            if rem >= c:
                best = min(best, dfs(rem - c) + 1)
        return best

    ans = dfs(amount)
    return ans if ans != float('inf') else -1

# 何时用记忆化 vs 自底向上：
#   - 依赖关系复杂、遍历顺序难定、需回溯/博弈  -> 记忆化（递归更直观）
#   - 依赖顺序清晰、想省空间、要滚动数组        -> 自底向上（递推更可控）
★

核心要点：记忆化搜索 = 递归 + 记录。只要状态转移是对的、并且缓存了「已算过的状态」，它和自底向上 DP 就是同一个算法，连复杂度都一样，二者是同一枚硬币的两面。

!

易错：记忆化搜索必须真的缓存（@lru_cache、字典、数组），否则重叠子问题会被反复递归，退化成指数级。@lru_cache 适合「状态参数都可哈希」的题；如果状态维度多、参数不可哈希，得用显式 dict 或数组。

⚠

提示：很多面试官会问「记忆化搜索和递推 dp 的区别」。答案要点：同一状态树、方向相反、复杂度相同；记忆化贴近人类思考、适合依赖复杂的场景；自底向上循环控制顺序、能做滚动数组省空间、无栈溢出风险。

知识点DP 常见优化（滚动数组、单调队列等）dp-opt · 从能过到优雅

笔试/面试的进阶点在于「时间/空间超了怎么办」。优化前先看清瓶颈在时间还是空间，再按需选择：

  • 滚动数组（空间优化）：一维 DP 只依赖前面少数几个状态时，用几个变量或「取模」滚动，把 O(n) 压到 O(1)，把二维压到一维。背包的一维滚动就是这个原理。
  • 单调队列优化：当转移是「在一定窗口内取最值」时，用单调队列（队列中元素单调递减/递增，队头是最值）把 O(n) 的转移降为均摊 O(1)。典型：滑动窗口最大值（LC 239）、限制窗口长度的最值 DP。
  • 斜率优化（Convex Hull Trick）：当转移形如 dp[i]=max(dp[j] + a[i]·b[j])（斜率形式）且满足决策单调性时，用凸包维护若干条直线，可把 O(n²) 降到 O(n log n) 或 O(n)。
  • 四边形不等式（Knuth 优化）：区间 DP 满足四边形不等式时，决策点单调，可把 O(n³) 降到 O(n²)。典型：石子合并、矩阵链乘。
  • 状态压缩 DP（Bitmask）：当物品数 n 很小（如 ≤ 20）但组合很多时，用二进制位表示集合。典型：旅行商（TSP）、子集枚举。
opt.py · 滚动数组 + 单调队列
# 滚动数组：把 O(n) 空间压到 O(1)  （爬楼梯 / 打家劫舍）
def climb_stairs(n):
    if n < 3:
        return n
    a, b = 1, 2
    for _ in range(3, n+1):
        a, b = b, a + b        # 只保留最近两个状态
    return b

# 单调队列：滑动窗口最大值 LC 239 · O(n)
from collections import deque
def max_sliding_window(nums, k):
    dq = deque()               # 存下标，队头永远是当前窗口的最大值
    res = []
    for i, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:   # 维护队内单调递减
            dq.pop()
        dq.append(i)
        if dq[0] <= i - k:                 # 移出窗口
            dq.popleft()
        if i >= k - 1:
            res.append(nums[dq[0]])
    return res
★

核心要点：优化三板斧——① 空间是瓶颈 → 滚动数组；② 转移是「在滑动窗口里取最值」 → 单调队列；③ 转移满足决策单调性（斜率形式） → 斜率优化 / 四边形不等式。

⚠

提示：别为炫技而优化。先用朴素 DP 把题做对（面试通常更看重「状态定义对不对、能不能解释清楚」），再在确认时间/空间是瓶颈时，说明你知道能用滚动数组/单调队列/斜率优化把复杂度降到多少，并把瓶颈点讲明白。
