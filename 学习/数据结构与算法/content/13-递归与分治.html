13.1递归（Recursion）：从「自己调用自己」到三要素

知识点①递归的基本思想与三要素rec-basic · 三要素 / 调用栈 / 栈溢出

递归（Recursion）是指一个函数直接或间接调用自身来解题的编程范式。核心思想是：把原问题翻译成一个与原问题同构（same structure）但规模更小的子问题，通过「信任函数已能正确求解子问题」来把大问题化归为小问题。它天然契合许多数据结构（树、图）与数学定义，也是动态规划、回溯、分治的基座。

写一个正确的递归函数，必须同时具备三个要素：

  1. 终止条件（Base Case / 递归出口）：最小的、不需要再递归的情形必须直接返回，否则会无限递归。
  2. 递归体（Recursive Step / 递推关系）：把当前问题表示成更小规模子问题的关系，例如 f(n) = n * f(n-1)。
  3. 规模缩小（Progress / 收敛）：每次递归调用都必须向终止条件逼近，保证最终能触发 base case。
recursion_basic.py
def factorial(n):
    # 要素① 终止条件：规模小到不能再递归
    if n <= 1:
        return 1
    # 要素②③ 递归体 + 规模缩小：把 n! 化归为 n * (n-1)!
    return n * factorial(n - 1)

def fib(n):
    # 斐波那契：经典双分支递归（有重复计算，属易错点）
    if n <= 1:                 # 终止条件
        return n
    return fib(n-1) + fib(n-2)  # 递归体：规模缩为 n-1、n-2

递归的实际执行依赖调用栈（Call Stack）：每次函数调用，系统压入一个栈帧（Stack Frame），保存局部变量、参数与返回地址；递归返回时依次弹出。因此递归深度 = 系统调用栈的层数，这就是「栈溢出（Stack Overflow）」风险的来源。

要素含义反面教训
base case最小的、不再递归的直接解缺终止条件 → 无限递归
递归体f(n) 与更小子问题的关系式写错关系 → 结果错误
规模缩小每次调用都逼近 base case规模不变 → 无法收敛
★

核心要点：写递归的灵魂是「信任函数调用」——假设 f(n-1) 已经正确返回，你只需负责「当前这步」与「递归关系」。三要素就是：边界 + 关系 + 收敛。

!

易错点：① 忘记 / 写错终止条件会导致无限递归，最终 RecursionError：栈溢出；② 递归深度过大同样爆栈（如用朴素递归 fib(2000)）；③ 双分支递归（如 fib）会有大量重复计算，复杂度指数级，需用记忆化。

O(n) / O(2^n)
空间
O(n) 栈深
适用

知识点②递归式的时间/空间复杂度分析rec-analysis · 递归树 / 展开 / 栈空间

分析递归算法，通常先写出递归式（Recurrence Relation）：T(n) = a·T(n/b) + f(n)，其中 a 是分成子问题的个数、n/b 是子问题规模、f(n) 是「分解 + 合并」的代价。求解方法主要有：递归树（Recursion Tree）、代入法（Substitution）、展开法、主定理（Master Theorem）。

递归树法：把递归展开成一棵树，每层求和，再对层数求和。以归并排序 T(n)=2T(n/2)+n 为例：每层合并代价为 n，共 log₂n 层，故 T(n)=O(n log n)。这是「画图看规律」最直观的方法。

rec_analysis.py
# 线性递归：一次递归只走一条链路，深度 = n
def sum_list(arr):
    n = len(arr)
    def go(i):
        if i >= n:          # base case
            return 0
        return arr[i] + go(i + 1)  # 递归体，规模缩小
    return go(0)
# 时间 O(n)：每个元素被访问一次
# 空间 O(n)：递归深度 n，每个栈帧保存 i 与返回地址

def fib_memo(n, memo=None):
    # 记忆化：把 O(2^n) 降到 O(n) —— 递归 + 备忘 ≈ 动态规划
    if memo is None: memo = {}
    if n <= 1: return n
    if n in memo: return memo[n]
    memo[n] = fib_memo(n-1, memo) + fib_memo(n-2, memo)
    return memo[n]

常见递归式的复杂度对照（务必背熟，面试常问）：

递归式含义 / 例子时间复杂度
T(n)=T(n-1)+1线性递归（阶乘、顺序遍历）O(n)
T(n)=T(n-1)+n选择/插入排序、递归求和O(n²)
T(n)=2T(n/2)+n归并排序、快排平均O(n log n)
T(n)=2T(n/2)+1二叉树节点遍历O(n)
T(n)=T(n/2)+1二分查找（减治）O(log n)
T(n)=2T(n-1)+1指数展开（汉诺塔）O(2ⁿ)
★

核心要点：空间复杂度 = 递归深度 × 每个栈帧的空间。分治型递归深度通常是 O(log n)（如快排栈），线性递归深度是 O(n)；「额外空间 O(1)」在递归版本里常不成立。

!

易错点：非常容易把递归算法的空间误判为 O(1)。只要还有系统调用栈在压栈，递归本身就有 O(递归深度) 的空间。只有尾递归 + 尾调用优化或手动改迭代才能把额外空间降到 O(1)。

O(n) 或 O(n log n)
空间
O(递归深度)

知识点③尾递归与递归改迭代rec-opt · Tail Recursion / TCO / 显式栈

尾递归（Tail Recursion）指递归调用是函数体的最后一条语句，且递归调用的返回值直接作为函数返回值，不存在「返回后再做一次运算」。这样的写法配合尾调用优化（Tail Call Optimization, TCO），编译器/解释器可以复用当前栈帧，把递归变成循环，空间降到 O(1)。

tail_recursion.py
# 非尾递归：return n * factorial(n-1) —— 返回后还要乘 n，无法 TCO
def factorial(n):
    if n <= 1: return 1
    return n * factorial(n - 1)

# 尾递归：把中间结果用「累加器 acc」向前传递，返回值就是递归调用
def factorial_tail(n, acc=1):
    if n <= 1: return acc
    return factorial_tail(n - 1, n * acc)   # 最后一条语句，直接返回

# 手动改迭代：把「尾递归」翻译成 for 循环，空间 O(1)
def factorial_iter(n):
    acc = 1
    for i in range(2, n + 1):
        acc *= i        # 前向累计，替代递归的「回溯相乘」
    return acc

递归改迭代的通用思路：

  1. 用累加器（accumulator）保存中间结果，把「返回值在回归中计算」改为「前向累计」——通常就得到尾递归或循环。
  2. 用显式栈模拟系统调用栈，保存需要「回溯」的状态（树遍历、深搜常这样改）。
  3. 把 base case 变成循环终止条件。

注意：不是所有递归都能优雅改成尾递归。像树的两路递归、或 fib(n-1)+fib(n-2) 这种需要两个子结果合并的，通常要么用显式栈，要么换算法（如动态规划）。

⚠

关键提醒：CPython（Python 默认解释器）并不做尾调用优化。就算你写成「尾递归」，深递归依旧会抛 RecursionError。真正吃 TCO 红利的是 Scheme、某些 JIT/编译器优化。Python 里想避免爆栈，最靠谱的就是手动改成显式迭代。

★

核心要点：尾递归的判据是「递归调用在最后，且直接返回其结果」。收益是省一帧、省回归计算；但是否真的被优化取决于语言实现。面试问「如何避免递归爆栈」，答案往往是：改迭代 / 用显式栈 / 加记忆化。

尾递归+TCO
O(1) 空间
非尾递归
O(n) 栈深
适用
改迭代 / 省空间

13.2分治（Divide and Conquer）：把大问题拆成小问题

知识点④分治思想（分解 / 解决 / 合并）rec-divide · 归并排序 / 快速排序

分治法（Divide and Conquer, D&C）把原问题分解成若干个规模更小、结构与原问题相同的子问题，递归解决子问题，最后把子问题的解合并成原问题的解。它是递归思想的「工程化」应用，核心在三个步骤：

  1. 分解（Divide）：把原问题划分成若干规模更小、同构的子问题。
  2. 解决（Conquer / Solve）：递归地解决各子问题；当规模小到可作为 base case 时直接求解。
  3. 合并（Merge / Combine）：把子问题的解组合成原问题的解。
merge_sort.py
# 归并排序：分治三步的教科书例子
def merge(l, r):
    i = j = 0; res = []
    while i < len(l) and j < len(r):
        if l[i] <= r[j]:          # 稳定：<= 保持相等元素相对顺序
            res.append(l[i]); i += 1
        else:
            res.append(r[j]); j += 1
    res.extend(l[i:]); res.extend(r[j:])
    return res                    # ③ 合并

def merge_sort(a):
    n = len(a)
    if n <= 1:                   # ② 解决：base case
        return a
    mid = n // 2                  # ① 分解
    left  = merge_sort(a[:mid])
    right = merge_sort(a[mid:])
    return merge(left, right)     # 合并子问题解

# 快速排序：分治 + 就地划分（不稳定）
def quick_sort(a):
    if len(a) <= 1: return a      # base case
    pivot = a[len(a)//2]          # 取中位数附近，缓解最坏 O(n^2)
    lo = [x for x in a if x < pivot]
    eq = [x for x in a if x == pivot]
    hi = [x for x in a if x > pivot]
    return quick_sort(lo) + eq + quick_sort(hi)

快速排序 Quick SortO(n log n)O(n²)（划分失衡）O(log n)（栈）不稳定
二分查找 Binary SearchO(log n)O(log n)O(1)（迭代）—
★

核心要点：分治三要素对应递归三要素。归并排序之所以能把朴素排序从 O(n²) 提到 O(n log n)，就是让每一层合并的总代价都是 O(n)，且只有 log n 层。

!

易错点：① 快速排序最坏 O(n²)：当每次划分都极度不平衡（如已排序数组 + 固定取首位 pivot），递归深度 O(n)，每层 O(n)。用随机 pivot / 三数取中缓解。② 归并排序稳定但需要 O(n) 额外空间；快排不冲突但最坏退化——面试常对比二者取舍。

知识点⑤主定理（Master Theorem）与常见递推rec-master · 三种情形 / 公式应用

主定理（Master Theorem）用于求解分治型递归式 T(n) = a·T(n/b) + f(n) 的渐进界（a≥1, b>1）。关键在于比较 f(n) 与 n^(log_b a) 的增长快慢。记 c = log_b a，则：

  • 情形 1（叶子主导）：若 f(n) = O(n^(c-ε))，即 f(n) 增长慢于 n^c，则 T(n) = Θ(n^c)。
  • 情形 2（各方均衡）：若 f(n) = Θ(n^c)，每层代价相当，则 T(n) = Θ(n^c · log n)。
  • 情形 3（根主导）：若 f(n) = Ω(n^(c+ε))，且满足正则条件 a·f(n/b) ≤ k·f(n)（k<1），则 T(n) = Θ(f(n))。
master_theorem.py
# 主定理求解示例：判断 a、b、f(n) -> 选情形
def classify(a, b, f_formula):
    # c = log_b(a)  即  n^(log_b a)
    import math
    return f"a={a}, b={b}, log_b(a)={math.log(a, b):.3f}（拿它与 f(n) 比较）"

# T(n)=2T(n/2)+n      -> log2 2=1，f=n=n^1 均衡 -> 情形2 -> O(n log n)  归并
# T(n)=2T(n/2)+1      -> log2 2=1，f=1=n^0 慢  -> 情形1 -> O(n)        遍历
# T(n)=T(n/2)+1       -> log2 1=0，f=1=n^0 均衡 -> 情形2 -> O(log n)    二分
# T(n)=2T(n/2)+n^2    -> log2 2=1，f=n^2 快   -> 情形3 -> O(n^2)
# T(n)=3T(n/2)+n      -> log2 3≈1.585，f=n 慢 -> 情形1 -> O(n^1.585)
⚠

适用边界：主定理只对分治型 T(n)=aT(n/b)+f(n) 有效。形如 T(n)=T(n-1)+n 的线性递推不适用，需用展开/递归树法。情形 3 还要额外检查正则条件。

★

核心要点：三步速判：① 算 c=log_b a；② 把 f(n) 写成 n^d；③ 比较 d 与 c：d<c 取 n^c，d=c 乘 log n，d>c 取 f(n)。归并、二分、遍历三种复杂度都在此表里，一定要会背。

知识点⑥典型分治题（最大子段和、逆序对计数）rec-problems · LC53 / 逆序对 / 最近点对

分治题的共性在于：「合并」步骤往往是与跨边界相关的难题。下面两个代表作，正好展示「跨越左右两半」的合并逻辑。

① 最大子段和（Max Subarray，LeetCode 53）

max_subarray.py
NEG = float('-inf')

def cross_max(a, lo, mid, hi):
    # 合并：求「必须跨过 mid」的最大和 = 左半靠中后缀 + 右半靠中前缀
    s = 0; left = NEG
    for i in range(mid, lo-1, -1):
        s += a[i]; left = max(left, s)
    s = 0; right = NEG
    for j in range(mid+1, hi+1):
        s += a[j]; right = max(right, s)
    return left + right

def max_subarray(a, lo, hi):
    if lo == hi:                       # base case
        return a[lo]
    mid = (lo + hi) // 2              # 分解
    lmax = max_subarray(a, lo, mid)   # 解决左半
    rmax = max_subarray(a, mid+1, hi) # 解决右半
    return max(lmax, rmax, cross_max(a, lo, mid, hi))  # 合并

② 逆序对计数（Count Inversions，剑指 Offer 51）

count_inversions.py
# 借归并排序的合并阶段统计跨左右两半的逆序对
def merge_count(l, r):
    i = j = 0; res = []; cnt = 0
    while i < len(l) and j < len(r):
        if l[i] <= r[j]:
            res.append(l[i]); i += 1
        else:
            res.append(r[j]); j += 1
            cnt += len(l) - i   # 左半剩余都 > r[j]，与其构成逆序对
    res.extend(l[i:]); res.extend(r[j:])
    return res, cnt

def count_inversions(a):
    def go(arr):
        if len(arr) <= 1: return arr, 0
        mid = len(arr)//2
        left,  cl = go(arr[:mid])
        right, cr = go(arr[mid:])
        merged, cm = merge_count(left, right)
        return merged, cl + cr + cm
    return go(a)[1]

更多分治经典：最近点对（Closest Pair）：平面内找距离最近的两点，暴力 O(n²)，分治 O(n log n)——合并步骤凭「按 y 排序 + 跨界只需检查常数个点」剪枝，是分治最难的一题。二分查找（Binary Search）则常被看作减治（Decrease and Conquer）：每步只保留一半，不合并。

★

核心要点：最大子段和的最优解其实是Kadane 动态规划（O(n)），分治版 O(n log n) 用来展示思想——分治不一定最优，但思路通用。逆序对计数的归并版 O(n log n) 则是标准解法（暴力 O(n²)）。

!

易错点：① 最大子段和的「跨中」必须横跨 mid，取「靠中后缀最大 + 靠中前缀最大」，若只取左右递归的答案会漏掉跨界的候选。② 逆序对统计是在右半元素被取出时累加左半剩余个数，别漏了 len(l)-i 这个「跨两半」的计数。
