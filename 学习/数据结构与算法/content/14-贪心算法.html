贪心算法

从「每步取当前最优」出发，掌握贪心的思想与为何局部最优能推出全局最优，学会用交换论证/反证法证明正确性，并看清它何时可靠、何时必须改用动态规划。

✓本节学习目标

  • 学完后你能用一句话说清贪心算法的核心思想，并讲出它与「枚举所有解 / 回溯」的本质区别。
  • 学完后你能判断一个问题是否具备贪心选择性质与最优子结构，并用交换论证或反证法给出（或理解）正确性证明。
  • 学完后你能独立写出区间调度、分发饼干、跳跃游戏、加油站、哈夫曼、分数背包等经典贪心题的解，并标注它们的复杂度。
  • 学完后你能讲清贪心与动态规划的差异，尤其是「分数背包可贪心而 0/1 背包不能」的原因。
  • 学完后你能识别贪心会失效的反例，从而在贪心无法保证最优时果断改用动态规划或其它方法。

01贪心的本质与正确性
「每步最优」为什么能通向「全局最优」

知识点贪心算法的基本思想与策略greedy-basic

贪心算法（Greedy Algorithm）是一种在每一步决策中都「选择当前状态下看起来最优的那一个选项」，并且从此不再回头（不回溯、不撤销）的算法。它的核心猜想是：如果每一步都做局部最优的选择，累积起来就可能是全局最优解。正因为如此，贪心往往只需一次扫描 + 一次排序，是同类题中写法最短、最快的一种策略。

它和「枚举/回溯」式的暴力不同：枚举把每一种可能都试一遍，最坏情况是指数级；而贪心每一步都只走一条路，复杂度通常很低。代价是：贪心并不总是正确——只有当前问题同时满足下面两条性质时，局部最优才保证等于全局最优：

  • 贪心选择性质（Greedy-choice Property）：存在一个全局最优解，它第一步就包含（或可以换成）贪心选择。也就是说，「先做这个当前最优的选择」不会把通往最优解的路堵死。
  • 最优子结构（Optimal Substructure）：做出这个选择之后，剩下的问题仍是同类型子问题，且原问题的最优解 = 这一次贪心选择 + 子问题的最优解。

这两个性质正是「贪心为什么对」的理论根基——想在面试里说清「这题为什么用贪心」，本质上就是要论证它同时满足这两条（见下一个知识点「正确性证明」）。

greedy-cookie.py
# LeetCode 455 分发饼干：一个最典型的贪心模板题
def find_content_children(greed, size):
    # 思路：胃口小的孩子先喂、尺寸小的饼干先用，避免把大饼干浪费在小胃口上
    greed.sort()          # 孩子胃口，升序
    size.sort()           # 饼干尺寸，升序
    i = j = 0             # i 指向孩子，j 指向饼干
    while i < len(greed) and j < len(size):
        if size[j] >= greed[i]:   # 当前最小饼干能满足当前最饿的孩子 ——— 局部最优
            i += 1                # 这个孩子被满足
        j += 1                    # 无论能否满足，这块饼干都用掉（贪心：不留大饼干等后面）
    return i              # 被满足的孩子数，即全局最优

print(find_content_children([1,2,3], [1,1]))   # 1
print(find_content_children([1,2], [1,2,3]))   # 2

为什么这么选？因为「用最合适的饼干去满足最合适的孩子」既是用掉当前价值最高的选择，又不会挤占其它孩子更可能吃到更大饼干的机会——这正是贪心选择性质的直观体现。

★

核心要点：贪心 = 每一步只做一次「当前最优」且永不后悔的决策。它的优势是快（常常 O(n log n) 甚至 O(n)），代价是有可能错——所以写题顺序永远是「先想贪心 → 立刻验证正确性」，而不是「一上来就背代码」。

!

易错点：很多人把贪心等同于「排序后取第一个」。实际上贪心的选择次序和比较规则很有讲究——「按开始时间取最早」在区间调度里是错的，「按结束时间取最早」才对；「按单位价值取最大」在分数背包里对，在 0/1 背包里错。错误地把「排序算子」当作贪心的全部，是丢分主因。

时间
O(n log n)
空间
O(1)
适用
贪心选择+最优子结构

知识点正确性证明：交换论证 / 反证法greedy-proof

贪心最容易踩的坑是「看起来对，其实不对」。真正的高手不靠直觉，而靠证明。要证明一个贪心算法正确，通常需要走三步（这也是算法导论 / 算法竞赛里经典的证明框架）：

  1. 证明贪心选择性质：存在一个全局最优解，它的第一步就是贪心选择（或可以把某个最优解「调整」成以贪心选择开头）。
  2. 证明最优子结构：去掉第一步后，剩下的问题仍是同类型子问题，且其最优解和贪心解拼接起来就是原问题的最优解。
  3. （归纳法收官）由 1、2 归纳可知，每一步都做贪心选择最终得到全局最优。

而「论证第 1 步」最常用的武器就是 交换论证（Exchange Argument）和 反证法：

  • 交换论证：假设存在一个全局最优解，它不是贪心解。我们不断把最优解里的元素与「贪心想要的那个元素」做交换，交换后解不会变差。既然可以一步步把它们换成贪心解而结果不变差，说明贪心解同样是最优的——矛盾消解，命题得证。
  • 反证法：假设贪心解不是最优，那么必然存在某个更优的解。在这个更优解里找「第一个与贪心不同的决策」，通过分析这一步两种方案的差，推出与前提矛盾（例如「更优解里剩下的选择余地反而更小」），从而否定假设。

以最经典的 区间调度（活动选择，最多选几个互不重叠的活动，LeetCode 435 思维同源）为例：

interval-scheduling.py
# 区间调度：选出最多互不重叠的区间
def max_non_overlapping(intervals):
    # 贪心次序：按【结束时间最早】排序（这是灵魂，用开始/长度排都不保证最优）
    intervals.sort(key=lambda x: x[1])
    cnt, last_end = 0, float("-inf")
    for s, e in intervals:
        if s >= last_end:          # 与上一个入选区间不重叠 → 选它
            cnt += 1
            last_end = e           # 更新当前最靠右的右端点
    return cnt

print(max_non_overlapping([[1,3],[2,5],[3,7],[4,9]]))  # 3：选 [1,3],[3,7],[4,9]

为什么「按结束最早」是对的？（交换论证）取任意一个最优解 T。贪心第一步选的是「结束时间最早的区间」a。如果 T 的第一个区间不是 a，设 T 里第一个（结束得最靠前）的区间是 b。因为 a 结束不晚于 b，把 T 中的 b 换成 a，不会让后续区间更难安排（后续区间的开始都 ≥ b 的结束 ≥ a 的结束），解的数量不变。于是我们得到一个新的、同样最优且「第一步就是贪心选择」的解。依此类推，贪心解 = 最优解。

★

记法：证明贪心正确 = 贪心选择性质 + 最优子结构；常用手段 = 交换论证（把一个最优解拿来做「无害交换」变成贪心解）或 反证法（假设贪心不是最优，导出矛盾）。面试里能画出「交换示意图 + 一句『交换后不会更差』」就足够打动面试官。

✕

致命易错点：「贪心看起来对」≠「贪心是对的」。很多题（如区间调度按开始时间、0/1 背包按价值）贪心都会给出错误答案。凡是贪心解法，都必须先证明或至少清楚地说明它为何满足贪心选择性质，否则面试里被追问「为什么贪心可行」就露怯了。

O(n log n)
空间
O(1)

交换/反证+归纳

跳跃游戏（LC 55）：核心是把问题从「能否到终点」转化为「能否覆盖到终点」，用一次扫描维护最大可达下标。

jump-game.py
def can_jump(nums):
    reach = 0                                  # 当前能到达的最远下标
    for i, step in enumerate(nums):
        if i > reach:                          # 连这个位置都到不了 → 失败
            return False
        reach = max(reach, i + step)           # 贪心：只要能走，就往最远覆盖
        if reach >= len(nums) - 1:            # 已覆盖到终点
            return True
    return True

print(can_jump([2,3,1,1,4]))   # True
print(can_jump([3,2,1,0,4]))   # False

它为什么是贪心？因为在位置 i 我们能掌控的只有「从 i 能跳到哪」这一件事，把覆盖范围取到最大，绝不会亏——这就是贪心选择性质的体现，且 O(n) 一次遍历。

哈夫曼编码（Huffman Coding）：一种经典的前缀编码（prefix code），没有哪个码字是另一个的前缀，从而解码无歧义。核心是构造 Huffman 树：每次挑出频率最小的两个节点合并，反复直至只剩根。

huffman.py
import heapq  # 最小堆：用于每次取出频率最小的两个节点
def huffman(freq):                       # freq: 各符号出现次数/频率
    heap = [[f, [None, None], chr(96+i)] for i, f in enumerate(freq)].copy()
    heapq.heapify(heap)                  # 按频率建小顶堆
    # 真实实现建议用带权子树的节点对象；这里示意「每次取最小两个」的贪心骨架
    while len(heap) > 1:
        lo = heapq.heappop(heap)         # 频率最小
        hi = heapq.heappop(heap)         # 次小
        merged = [lo[0] + hi[0], [lo, hi], None]   # 合并成一个父节点，权值为和
        heapq.heappush(heap, merged)
    return heap[0]                       # 根节点，即 Huffman 树

print(huffman([3,2,1]))   # 示意：频率 3,2,1 合并成最优二叉树

为什么「每次合并最小两个」最优？Huffman 树是最优二叉树：它的目标是使 WPL = Σ(频次 × 码长) 最小。让频次小的符号走长路径、频次大的走短路径，才能压低总代价；而「每次合并最小两个」正是把这个原则贯彻到每一步——直观上等于「最便宜的代价最早被合并、成本多次累加」。其正确性同样可用交换论证严格证明。

★

核心要点：背三类高频题即可覆盖绝大多数面试：① 区间/活动调度类（按结束时间，LC435 / 452 / 646）；② 覆盖/跳跃类（维护最远可达，LC55 / 45）；③ 背包/择取类（分数背包按单位价值，与 DP 的 0/1 背包区分）。

!

易错点：「跳跃游戏」有人会误写成「每一步都跳到最远的那一格」，然后发现复杂又容易错。正确做法是维护『能到达的最远下标』这一覆盖范围，而不是记录实际跳到哪，二者差别很大。另外注意 can_jump 里要先判断 i > reach 再更新，否则会在不可达的位置误判。

知识点贪心与动态规划的区别greedy-vsdp

贪心和动态规划（Dynamic Programming, DP）都依赖「最优子结构」——即原问题的最优解可由子问题的最优解构造出来。但两者在「每一步怎么选」上根本不同：

维度贪心（Greedy）动态规划（DP）
决策方式自顶向下，每步只做一次选择，不回头、不回溯考虑所有候选选择，用状态记录子问题的最优解，可回溯
需要的性质贪心选择性质 + 最优子结构缺一不可只需最优子结构（可选地有重叠子问题做记忆化）
结果保证不一定得到最优，需额外证明按定义一定得到最优
复杂度更低：常 O(n log n) / O(n)更高：O(n·W) 或 O(n²) 等，视状态数
典型例子区间调度、哈夫曼、分数背包、找零（硬币最优面额）0/1 背包、最长公共子序列 LCS、编辑距离、打家劫舍

用一个最熟悉的对照就能牢牢记住：分数背包（可切分）用贪心，0/1 背包（不可切分）用 DP。

knapsack-vs.py
# ---- 分数背包：物品可切分，按【单位价值】贪心即可得到最优 ----
def fractional_knapsack(w, v, cap):         # w重量, v价值, cap容量
    items = sorted(zip(w, v), key=lambda x: x[1] / x[0], reverse=True)  # 单位价值降序
    total = 0
    for wg, vv in items:                   # 单位价值最高的尽量装，装不下就切一部分
        if cap >= wg:
            cap -= wg; total += vv
        else:
            total += vv * (cap / wg); break
    return total

# ---- 0/1 背包：物品【不可切分】，贪心会错，必须用 DP 枚举到底装还是不装 ----
def zero_one_knapsack(w, v, cap):
    n = len(w); dp = [0] * (cap + 1)
    for i in range(n):                     # 每个物品：选 或 不选（逆序遍历容量避免重复用）
        for c in range(cap, w[i] - 1, -1):
            dp[c] = max(dp[c], dp[c - w[i]] + v[i])   # 决策：要么不带，要么带
    return dp[cap]
★

判型口诀：一个问题能不能贪心，看它是否每一步的抉择都是「绝对主导、无副作用、无需比较其余候选」。只要「需要权衡当前这一件 vs 其它件的取舍」——例如装了这个可能就装不下那个——通常就得用 DP；只有「这一步的选择不会让后面变差」时，贪心才安全。

!

易错点：不要因为「背包」这两个字就默认能用贪心。区分的关键是物品能否切分：可切分→贪心；不可切分→DP。这也是面试里最容易被挖坑的一句：「你说这题是背包，你用贪心试试？」——要立刻意识到这是引导你走错方向。

知识点适用条件与贪心反例greedy-cond

贪心不是万能的。能不能用，就看问题是否同时满足 贪心选择性质 与 最优子结构。下面用三个高频反例说明「贪心会在哪里翻车」，同时也是面试常客。

反例一：0/1 背包（物品不可切分）。假设容量 10，物品如下，贪心按单位价值会选错。

greedy-counterexample.py
# 容量 cap = 10
# 物品：(重量, 价值, 单位价值)
items = [(6, 30, 5.0), (5, 24, 4.8), (5, 24, 4.8)]
# 单位价值最高的是 (6,30)，贪心先装它 → 剩余容量 4，装不下任何一件 → 总价值 30
# 但最优是装两件 (5,24)+(5,24) = 48！贪心错了。
def greedy_0_1(items, cap):
    # 按单位价值降序尝试『整件』装入（不可切分导致会“卡住”剩余容量）
    items = sorted(items, key=lambda x: x[2], reverse=True)
    val = 0
    for w, v, r in items:
        if cap >= w:
            cap -= w; val += v
    return val
print(greedy_0_1(items, 10))   # 30（错误！应为 48）

为什么错？因为贪心在装下第一件后「剩下一块不可用的空隙」，这空隙恰好不能容纳任何物品，白白浪费。这正是 0/1 背包缺了「贪心选择性质」的表现——局部的单位价值最高并不等于整体最优。

反例二：找零钱（非标准硬币面额）。面额 {1, 3, 4}，要凑 6 元。贪心会先取最大面额 4，剩余 2 只能用两个 1，共 3 枚；而最优是 3 + 3 = 2 枚。原因：面额不满足「贪心最优」结构时，取大额反而破坏了组合的奇偶性。

coin-change.py
def greedy_coin(coins, n):        # 目前都先取最大面额
    coins.sort(reverse=True); cnt = 0
    for c in coins:
        cnt += n // c; n %= c     # 能取多少张就取多少
    return -1 if n else cnt       # 不能恰好凑出则返回 -1

print(greedy_coin([1,3,4], 6))    # 4+1+1 → 3 枚（错误！最优是 3+3 → 2 枚）
# 只有特殊面额（如 1,5,10,25 这类"进制"面额）贪心才正确；任意面额需用 DP。

反例三：负权边上的最短路。Dijkstra 是最典型的贪心算法（每次从未定集合挑距离最近的顶点定性），但它要求边权非负。一旦出现负权边，先被定性为「最近」的点之后可能还能被更短路径更新，于是贪心失效，此时必须用 Bellman-Ford（可处理负权）或 Floyd-Warshall。

✕

判断时机（强烈建议）：拿到题先问三个问题——① 这一步的最优选择，会不会让后续变得更好而不是更差？（贪心选择性质）② 去掉这一步后，是不是还是一个同类子问题，且原问题最优 = 本次最优 + 子问题最优？（最优子结构）③ 能不能用一个具体反例反驳贪心？—— 只要有一条答不上来，就改用 DP 或别的算法。千万别背完贪心模板就套到所有题上。

★

一句话收尾：贪心的适用边界 = 贪心选择性质（这一刀切下去，后面只会更好）＋ 最优子结构（剩下的是同型子问题）。满足这两条，贪心又快又对；不满足，哪怕看起来再合理也要果断转向动态规划。
