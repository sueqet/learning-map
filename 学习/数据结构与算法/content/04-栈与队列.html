MODULE 04 · 数据结构与算法

栈与队列

一次削掉「一端进、一端出」的两个线性结构——栈用后进先出（LIFO）实现递归与撤销，队列用先进先出（FIFO）实现调度与缓冲；而它们各自的进阶版单调栈与单调队列，正是 LeetCode 高频题的解码器。

✓本节学习目标

  • 学完后你能独立用顺序/链式两种方式实现栈和队列，并说清各自的时间与空间复杂度。
  • 学完后你能用栈解决括号匹配（LeetCode 20）与逆波兰表达式求值（LeetCode 150），并讲出递归与函数调用栈的关系。
  • 学完后你能手写「下一个更大元素」风格的单调栈模板，并能用 O(n) 单调栈优化暴力 O(n²) 解法。
  • 学完后你能用循环队列（数组）实现 O(1) 的入队/出队（LeetCode 622），并解释为何要多浪费一个位置来判断队满。
  • 学完后你能用双端队列实现滑动窗口最大值（LeetCode 239），且能准确说出队头与队尾各自「何时出队」。

04栈（Stack）：后进先出
从基本操作到单调栈

知识点 1栈的定义与实现（顺序/链式）LIFO · push/pop/top

栈（Stack）是一种线性表，限定只在同一端（称为栈顶 top）进行插入和删除。后进先出（Last In First Out，LIFO）是其唯一的访问规则：最后压入的元素，最先被弹出。栈的抽象操作只有五个：push（入栈）、pop（出栈）、top/peek（取栈顶）、isEmpty（判空）、size（长度）。

  • 为什么要单独学它：递归、函数调用、括号匹配、浏览器后退、文本编辑器撤销、表达式求值，底层都是「栈」在支撑，因此它是面试的必考基础。
  • 顺序栈 vs 链式栈：顺序栈用数组（连续内存）实现，访问快但需预判容量；链式栈用链表（结点 + 指针）实现，容量不受限但每个元素多存一个指针。
stack.py
# 顺序栈：用 Python list 模拟（list.append/pop 从尾部操作即 O(1) 摊还）
class ArrayStack:
    def __init__(self):
        self.data = []

    def push(self, x):          # 从尾部压入 —— O(1) 摊还
        self.data.append(x)

    def pop(self):              # 从尾部弹出 —— O(1)
        if self.isEmpty():
            raise IndexError("栈为空，无法弹出")
        return self.data.pop()

    def top(self):              # 只看栈顶，不弹 —— O(1)
        if self.isEmpty():
            raise IndexError("栈为空")
        return self.data[-1]

    def isEmpty(self):
        return len(self.data) == 0

    def size(self):
        return len(self.data)


# 链式栈：用链表，把「栈顶」放在链表头（头插/头删都是 O(1)）
class Node:
    __slots__ = ("val", "next")
    def __init__(self, val, next=None):
        self.val, self.next = val, next

class LinkedStack:
    def __init__(self):
        self.top = None         # 栈顶指针 = 链表头
        self.n = 0

    def push(self, x):          # 头插：O(1)
        self.top = Node(x, self.top)
        self.n += 1

    def pop(self):              # 头删：O(1)
        if self.top is None:
            raise IndexError("栈为空")
        v = self.top.val
        self.top = self.top.next
        self.n -= 1
        return v

    def isEmpty(self):
        return self.top is None
!

易错点：Python 里 list.pop()（不带下标）从尾部删是 O(1)，但 pop(0) 或 insert(0, x) 从头部操作需整体搬移，是 O(n)。记住「栈顶在末尾」这一约定，才能既正确又高效。另外做 pop/top 前一定要判空，否则会越界或抛异常。

★

核心要点：栈的变化只发生在栈顶一端。只要「最近放入的元素最先被取走」这一 LIFO 规则确定，选择顺序实现还是链式实现就只看你对容量与内存的权衡——面试里两者都要能徒手写出来。

知识点 2栈的应用：括号匹配、表达式求值（后缀/递归）LeetCode 20 / 150

栈最经典的应用场景，是把「需要回头看最近的那个东西」的问题建模出来。下面三个例子共享同一种思考模式：用一个栈暂存还没能配对的元素，遇到能配对或能结算的就立刻弹出。

  • 括号匹配（LeetCode 20 有效的括号）：左括号入栈，遇到右括号就检查栈顶是不是配对的那一个。
  • 逆波兰表达式（RPN / 后缀表达式，LeetCode 150）：操作数入栈，遇到运算符就弹出两个操作数结算，结果再入栈。
  • 递归与函数调用栈：每进入一层函数，系统就在调用栈（call stack）上压入一段「栈帧（stack frame）」，返回时弹出。所以任何递归都可用显式栈改写为迭代。
stackapp.py
# 1) 括号匹配（LeetCode 20）：栈顶总是「最近未配对」的左括号
def isValid(s):
    pairs = {')':'(', ']':'[', '}':'{'}
    stack = []
    for ch in s:
        if ch in "([{":                 # 左括号：入栈等待配对
            stack.append(ch)
        else:                           # 右括号：必须和栈顶配对
            if not stack or stack[-1] != pairs[ch]:
                return False
            stack.pop()
    return not stack                    # 栈空 = 全部配对完成


# 2) 逆波兰表达式求值（LeetCode 150）：数字入栈，遇运算符弹两数结算
def evalRPN(tokens):
    stack = []
    for t in tokens:
        if t in "+-*/":
            b = stack.pop()   # ★ 注意弹出顺序：先弹出的是"右操作数"b
            a = stack.pop()   # 后弹出的是"左操作数"a
            if t == '+':   stack.append(a + b)
            elif t == '-': stack.append(a - b)
            elif t == '*': stack.append(a * b)
            else:          stack.append(int(a / b))  # C++ 向零取整
        else:
            stack.append(int(t))
    return stack[-1]


# 3) 递归 → 显式栈（以"逆序打印"为例）：两者等价，迭代版可控栈深
def print_rev_recursive(lst, i=0):        # 递归版：靠系统调用栈
    if i == len(lst): return
    print_rev_recursive(lst, i + 1)
    print(lst[i])
⚠

易错点：加减乘除丢弃括号后得到的是后缀表达式（RPN），它靠运算符出现顺序决定优先级，无需括号；但求值时弹出顺序要分清左右——先弹出的是右操作数 b。若写成 a = pop(); b = pop() 再做 a - b，减法与除法结果就错了。括号匹配里漏判「栈未为空」也是常见失误。

★

核心要点：凡是要「记住最近一个没处理完的事项、稍后再回来处理」的场景，都先想到栈。括号嵌套、括号内层优先、递归回溯、撤销操作，本质是同一件事：后进先出地回放历史。

知识点 3单调栈：下一个更大元素类LeetCode 739 / 496 / 503

单调栈（Monotonic Stack）指栈内元素保持严格单调（递增或递减）。它专门解决一类问题：找每个元素左边/右边「第一个比它大/小」的元素。朴素做法对每个元素都向后扫一遍，是 O(n²)；单调栈能把它优化到 O(n)——核心在于它能立刻知道哪些元素的答案已经被当前元素「激活」。

  • 何时用：题目出现「下一个更大 / 下一个更小 / 上一个更大 / 上一个更小」的字样，或者要求找出某种「边界」，就想到单调栈。
  • 怎么维护：找「下一个更大」，维护一个从栈底到栈顶递减的栈（栈底大、栈顶小）；找「下一个更小」则反过来。
  • 何时出栈：当前元素 x 比栈顶元素大/小时，说明栈顶的答案就是 x，于是弹出栈顶并记录答案；直到栈顶与 x 关系恢复单调，再把 x 压入。
monostack.py
# 单调栈模板：求每个元素"右边第一个比它大的元素"，O(n)
def nextGreater(nums):
    n = len(nums)
    res = [-1] * n      # 默认没有更大元素 → -1
    stack = []          # 栈里存"下标"，保持 nums[栈顶] 从底到顶单调递减
    for i in range(n):
        # 当前元素 nums[i] 比栈顶大：栈顶的下一个更大元素就是 nums[i]
        while stack and nums[stack[-1]] < nums[i]:
            res[stack.pop()] = nums[i]   # 弹出即结算
        stack.append(i)                  # 把"还没等到更大元素"的下标压入
    return res

print(nextGreater([2,1,2,4,3]))   # 结果 [4, 2, 4, -1, -1]


# LeetCode 739 每日温度：题目说"下一个更热"，即"下一个更大"
def dailyTemperatures(temps):
    res = [0] * len(temps)
    stack = []
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:   # 栈顶等到更热的这一天
            j = stack.pop()
            res[j] = i - j        # 记录"隔了几天"，注意存的是下标差
        stack.append(i)
    return res

易错点：① 栈里存下标而非值，因为很多题（如 739）要求返回「距离/下标差」。② 判断方向别写反：「下一个更大」用递减栈，当前元素比栈顶大时弹出栈顶。③ 严格 vs 非严格单调：遇到相等元素，按题意决定是否用 < 还是 <=（如「下一个更大」通常相等不算更大 → 用 <）。④ 单调栈的时间复杂度虽看着有嵌套循环，但每个元素最多入栈一次、出栈一次，故总体 O(n)。

核心要点：单调栈把「对每个元素都向后找」压缩成「每个元素只入栈/出栈各一次」。只要记住一句话——当新元素打破了单调性，就弹出栈顶并结算它——就能写出所有「下一个更大/更小」系列题目（含 LeetCode 42 接雨水、84 柱状图最大矩形等经典题）。

04队列（Queue）：先进先出
从循环队列到单调队列

知识点 4队列与循环队列FIFO · 顺序/链式 · LeetCode 622

队列（Queue）是另一种受限线性表：只在队尾（rear）插入、在队头（front）删除，先进先出（First In First Out，FIFO）。它天然贴合「先来先服务」的调度：打印机任务队列、进程调度、BFS（广度优先搜索）、消息队列都用它。队列同样可有链式实现（头删 + 尾插，用链表带 head/tail 指针，都 O(1)），这里重点讲面试更爱考的循环队列。

  • 为什么需要循环队列：普通顺序队列用数组，front 和 rear 都只往后走，很快会「数组满了但前面有空位」——明明有空间却填不进去。循环队列让 rear 走到末尾后绕回下标 0，复用已出队的空间。（rear+1）% 容量就是下一个要插入的位置。
  • 如何区分队空/队满：常用两种方案——① 浪费一个元素位置，约定 (rear+1) % cap == front 为队满；② 增加一个 计数器 count 记录元素个数（下面代码用这种，更直观）。
cirqueue.py
# LeetCode 622 设计循环队列：用 count 计数器区分空/满，更直观
class MyCircularQueue:
    def __init__(self, k):
        self.buf = [0] * k
        self.cap = k
        self.head = 0        # 队头下标（指向队首元素）
        self.count = 0       # 当前元素个数

    def enQueue(self, value):
        if self.isFull(): return False
        tail = (self.head + self.count) % self.cap   # 队尾 = head + 个数（循环取模）
        self.buf[tail] = value
        self.count += 1
        return True

    def deQueue(self):
        if self.isEmpty(): return False
        self.head = (self.head + 1) % self.cap       # 队头 +1，使用过的槽位被"绕回"复用
        self.count -= 1
        return True

    def Front(self):
        return self.buf[self.head] if self.count else -1

    def Rear(self):           # 队尾元素 = head + count - 1
        if self.isEmpty(): return -1
        return self.buf[(self.head + self.count - 1) % self.cap]

    def isEmpty(self): return self.count == 0
    def isFull(self):  return self.count == self.cap
!

易错点：① 「浪费一格」方案里，判满用 (rear+1) % cap == front，此时实际最多只能存 cap-1 个元素，面试常考这一点。② 队尾元素不是 buf[rear]，而是 buf[(rear-1+cap) % cap]。③ 所有下标运算都要取模（% cap），否则绕回会越界。④ C++ 中 head/tail 用 int，也要注意取模防溢出。

★

核心要点：队列是两端不对称的：一头只进、一头只出。循环队列用「取模绕圈」解决了顺序队列「假溢出」问题；用 count 或「浪费一格」任一约定都能正确区分空与满，但一定要在代码里明确并一致地贯彻。

知识点 5双端队列与单调队列：滑动窗口最值deque · LeetCode 239

双端队列（Deque，double-ended queue）允许在两端都能插入与删除，是栈与队列的泛化；Python 用 collections.deque，两端操作都是 O(1)。单调队列（Monotonic Queue）就是在双端队列上维护一种单调性，专门解决滑动窗口（sliding window）的区间最值问题：朴素法每个窗口都扫描一遍是 O(n·k)，单调队列能优化到 O(n)。

  • 何时用：题目给出固定长度 k 的窗口，要求每个窗口的最大值/最小值（LeetCode 239 滑动窗口最大值、还有滑动窗口最小值、以及一些「窗口内单调性」变体）。
  • 怎么维护：求窗口最大值就维持一个从队头到队尾单调递减的队列。队头永远是当前窗口的最大值；队列里存下标，方便判断过期。
  • 何时出队：①过期出队（队头）——当下标 q[0] <= i-k 说明它已滑出窗口，从头弹出；②单调性破坏出队（队尾）——当 nums[q[-1]] <= nums[i]，队尾元素不可能再当最大值，从尾弹出，再把当前下标压入队尾。
monoqueue.py
# LeetCode 239 滑动窗口最大值：单调队列模板，O(n)
from collections import deque

def maxSlidingWindow(nums, k):
    q = deque()      # 存下标；保持从队头到队尾"单调递减"
    res = []
    for i, x in enumerate(nums):
        # ① 过期出队（队头）：队头下标已滑出当前窗口
        while q and q[0] <= i - k:
            q.popleft()
        # ② 单调性破坏出队（队尾）：所有 <= x 的队尾元素不可能再是最大值
        while q and nums[q[-1]] <= x:
            q.pop()
        q.append(i)
        # 窗口形成后，队头就是当前窗口最大值
        if i >= k - 1:
            res.append(nums[q[0]])
    return res

print(maxSlidingWindow([1,3,-1,-3,5,3,6,7], 3))  # [3,3,5,5,6,7]
!

易错点：① 队列里存的是下标不是值——判断「过期」必须靠下标。② 出队时机分两支：队头管过期（从左端 popleft），队尾管单调性（从右端 pop），别把两者写反。③ 求最大值用递减队列，求最小值用递增队列，方向别搞混。④ 只有当 i >= k-1 窗口才完整，才能取队头作为答案。

★

核心要点：单调队列的「两个 while」是固定套路：先踢掉过期的（队头），再踢掉不可能当极值的（队尾），最后让队头成为答案。每个元素最多进队/出队一次，所以总复杂度是 O(n)。它与单调栈结构不同（栈只需一端操作，队列要两端），但「破坏单调性就弹出结算」的思想一致。

知识点 6用栈实现队列 / 用队列实现栈（相互模拟）LeetCode 232 / 225 · 摊还分析

这是一类「用 A 的 API 拼出 B 的语义」的经典面试题，考察你能否借助两个同构结构互相补足缺陷。思路核心：栈是「后进先出」，队列是「先进先出」，把元素在两个栈之间倒腾一次，顺序就会反转。

  • 双栈实现队列：一个 in_stack 负责入队，一个 out_stack 负责出队。只有当 out_stack 为空时，才把 in_stack 的元素一次性全部倒入 out_stack，从而让最早入队的元素到了栈顶。每个元素只会「被倒入」一次，所以整体摊还 O(1)。
  • 单队列实现栈：入栈时把新元素放到队尾后，把前面已有的 n-1 个元素依次旋转到后面，使最新元素出现在队头（即栈顶，先从队头出）。每个元素入栈被「旋转」的平均次数随元素增多而增大，故单次入栈 O(n)，入栈总成本 O(n²)。
convert.py
# LeetCode 232 用两个栈实现队列：in 负责进，out 负责出（摊还 O(1)）
class MyQueue:
    def __init__(self):
        self.in_st, self.out_st = [], []

    def push(self, x):                 # 入队：只管压进 in —— O(1)
        self.in_st.append(x)

    def _move(self):                   # 只有当 out 为空，才把 in 整体倒腾过去
        if not self.out_st:
            while self.in_st:
                self.out_st.append(self.in_st.pop())

    def pop(self):
        self._move()
        return self.out_st.pop()

    def peek(self):
        self._move()
        return self.out_st[-1]

    def empty(self):
        return not self.in_st and not self.out_st


# LeetCode 225 用一个队列实现栈：入栈时把前面元素旋转到队尾（O(n)）
from collections import deque

class MyStack:
    def __init__(self):
        self.q = deque()

    def push(self, x):
        self.q.append(x)
        for _ in range(len(self.q) - 1):   # 把其余元素转一圈，让 x 到队头
            self.q.append(self.q.popleft())

    def pop(self):  return self.q.popleft()   # 队头即"栈顶"
    def top(self):  return self.q[0]
    def empty(self): return not self.q
⚠

易错点：① 双栈实现队列，不要每次都把 in 全倒入 out，只有当 out 为空时才倒，否则元素顺序会被反复翻转而乱掉。② empty() 必须同时检查 in 与 out 两个栈都为空。③ 单队列实现栈的入栈是 O(n)，面试时若被追问复杂度，要能准确区分摊还 O(1)（双栈）与单次 O(n)（单队列旋转）两种成本。

★

核心要点：「倒腾一次就反转顺序」是这类题的灵魂。用一个附加结构暂存、在有需要时才搬运，往往能把「每次都搬」的坏复杂度变成摊还 O(1)——这就是摊还分析（amortized analysis）在面试里最常被问到的点。
