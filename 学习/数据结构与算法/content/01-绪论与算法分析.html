绪论与算法复杂度分析

本章是整门课的总纲：先弄清「什么是好算法」，再学会用大 O 记号度量算法的时间与空间复杂度，为后面每一个数据结构与算法打下分析基础。

✓本节学习目标

  • 学完后你能说出算法的五大特性，并判断一段描述是否构成一个「算法」。
  • 学完后你能准确地分析一段代码的时间复杂度，用大 O 记号表示。
  • 学完后你能运用加法/乘法法则及循环估算技巧，快速写出常见代码的复杂度。
  • 学完后你能区分时间与空间复杂度，指出原地算法（in-place）与递归栈开销的区别。
  • 学完后你能按增长率对常见复杂度阶排序，并用主定理解简单递归式。

算法是什么 · 时间与大 O

知识点算法的基本概念与特性intro-basics

算法（Algorithm）是对特定问题求解步骤的有穷、确定、可行的指令序列，它不依赖具体语言，是「怎么做的思想」；而程序（Program）是「数据结构 + 算法 + 语言实现」。同一个算法可以用 Python、C++ 或伪代码写出。

任何算法都必须满足五大特性（国内严蔚敏版教材）：

  • 有穷性：算法必须在有限步之后结束，不能无限循环。
  • 确定性：每条指令含义唯一，对同样的输入总是得到同样的输出。
  • 可行性：每一步都能通过有限的基本运算实现（现实中可执行）。
  • 输入：可以有 0 个或多个输入。
  • 输出：至少有 1 个输出，否则算法没有意义。
is_leap.py
# 判断闰年：一个满足"有穷、确定、可行"的算法
# 输入: 年份; 输出: 是否为闰年(bool)
def is_leap(year: int) -> bool:
    if year % 400 == 0:      # 能被400整除 -> 闰年
        return True
    if year % 100 == 0:      # 能被100整除但不能被400整除 -> 平年
        return False
    if year % 4 == 0:        # 能被4整除但不能被100整除 -> 闰年
        return True
    return False

print(is_leap(2024))   # True
print(is_leap(1900))   # False (整百要能被400整除)
★

核心要点：「好算法」的评价标准是正确性、可读性、健壮性与效率。本章重点研究「效率」，即用复杂度来衡量。注意：算法 ≠ 程序，算法是思想，程序是把思想落到具体语言。

!

易错点：「有穷性」强调必然在有限步结束，而不仅是「在现实可接受时间内」。一个理论上有穷、但需要几亿年的算法，仍满足有穷性，只是效率极差——这正是我们需要复杂度分析的原因。

知识点时间复杂度的定义与分析intro-time

时间不直接等于「运行秒数」（那取决于机器），而是指算法中基本操作（basic operation）的执行次数随输入规模 n 变化的增长趋势。我们关注的是当 n→∞ 时开销的量级，于是引入了记号。

大 O 记号（Big-O Notation）给出的是算法运行时间的渐进上界（asymptotic upper bound）：存在常数 c 与 n₀，使得对所有 n≥n₀ 都有 T(n) ≤ c·f(n)，记作 T(n)=O(f(n))。它忽略常数与低阶项，只关心「最高阶项」及其量级。

sum.py
# 同一问题(求 1..n 的和)，两种算法时间开销天差地别
def sum_loop(n: int) -> int:
    # 循环 n 次，每次做一次加法 -> 基本操作次数 ≈ n
    # 时间随 n 线性增长 -> O(n)
    s = 0
    for i in range(1, n + 1):   # 执行 n 次
        s += i
    return s

def sum_formula(n: int) -> int:
    # 用等差数列求和公式 -> 只做常数次运算
    # 与 n 无关 -> O(1)
    return n * (n + 1) // 2

# 比较: n 越大，差距越悬殊。n=10^9 时 sum_loop 要跑很久, sum_formula 瞬间完成
★

核心要点：复杂度看的是「增长的量级」而非具体次数。常数、低阶项、系数一律忽略：3n²+5n+100 = O(n²)。最坏/平均/最好三种情况都要会区分，分析时若无特别说明默认看最坏情况。

✕

易错点：不要用「机器运行时间」当复杂度；也不要把 O(n) 理解成「正好 n 步」。另外，O(n²) 表示上界，一个 O(n) 的算法当然也是 O(n²)，但我们总取「最紧」的界来描述。

时间
O(n)
空间
O(1)

知识点复杂度的计算与技巧intro-calc

手算复杂度无需逐条数语句，掌握两条法则 + 一个「看最深层循环」的直觉即可：

  • 加法法则（顺序）：前后两段先后执行，总开销取较大的一阶。若段 A 为 O(f)、段 B 为 O(g)，则整体 O(max(f,g))。
  • 乘法法则（嵌套）：循环嵌套，总次数 = 外层次数 × 内层次数。若外层 O(f)、内层 O(g),则整体 O(f·g)。
  • 对数型循环：每轮把规模折半/除以 k 的循环，次数为 log_k(n) → O(log n)，与底数无关（都相差常数倍）。
calc.py
# 估算技巧演示: 找"最深层循环"看它执行多少次
def f(n: int) -> int:
    s = 0
    for i in range(n):          # O(n)
        s += i
    for i in range(n):          # O(n^2) (嵌套)  <- 取较大者
        for j in range(n):
            s += i * j
    return s                   # 整体 O(n^2) —— 加法法则

def h(n: int) -> int:
    # 对数型循环: 每轮 n 折半, 总共约 log2(n) 轮 -> O(log n)
    cnt = 0
    while n > 1:
        n //= 2
        cnt += 1
    return cnt

def g(n: int) -> int:
    # 外层 log n 次, 内层 n 次 -> 乘法法则 O(n log n)
    cnt = 0; i = 1
    while i < n:
        for j in range(n):
            cnt += 1
        i *= 2
    return cnt
!

易错点：两种场景极易混淆——「外层折半、内层满 n」是 O(n log n)；而「外层满 n、内层折半」外层每次内层都重新从 n 开始，是 O(n log n) 的另一种写法。真正要警惕的是把「内层也随外层的 i 缩」误判成嵌套——那种 1+2+…+n 的三角循环是 O(n²)，不是 O(n)。

★

面试速算：看到 for+for 全量嵌套想 O(n²)；看到 while n/=2 想 O(log n)；看到 递归分治想用主定理。LeetCode 里二分查找、归并排序、双层枚举（如两数之和暴力版）分别是这三类的代表。

时间
O(n²)
空间
O(1)
技巧

知识点空间复杂度intro-space

空间复杂度（Space Complexity）衡量算法运行时所需的额外存储（即辅助空间，auxiliary space），不包括输入本身占据的空间。同样用大 O 表示：只用一个或常数个临时变量的算法是 O(1)，称为原地算法（in-place）。

特别注意：递归的额外空间等于调用栈（call stack）的最大深度。深度为 n 的递归，即使用 O(1) 的临时变量，总空间亦是 O(n)。

space.py
def sum_in_place(a) -> int:
    # 只用一个累加器 s -> 额外空间 O(1), 原地算法
    s = 0
    for x in a:
        s += x
    return s

def duplicate(a) -> list:
    # 新列表长度随输入增长 -> 额外空间 O(n)
    return a[:]                    # 复制一份, 需要 n 个新单元

def depth(n) -> int:
    # 递归深度 n -> 调用栈需要 n 层 -> 空间 O(n)
    if n <= 0:
        return 0
    return 1 + depth(n - 1)
✕

易错点：「用空间换时间」是常见策略（如哈希表、DP 记忆化）。但不要把输入本身的空间算进额外空间——分析时问的是「除了存放输入，我还额外用了多少」。某些题目要求 O(1) 空间即指除输入外只用常数个变量。

时间
O(n)
空间
O(1)
适用
原地/递归

知识点增长率与常见复杂度阶intro-growth

不同复杂度阶在 n 增大时的增长率差异巨大，这就是「为什么快排/归并比冒泡强」的根本原因。务必记住从小到大的顺序。

复杂度阶名字典型算法n=10⁶ 时约
O(1)常数级数组下标访问、哈希查找（均摊）1 步
O(log n)对数级二分查找≈20 步
O(n)线性遍历求最大值10⁶ 步
O(n log n)线性对数归并排序、快排（平均）≈2×10⁷ 步
O(n²)平方冒泡/选择/插入、暴力两数之和10¹² 步
O(2ⁿ)指数暴力枚举子集几乎不可计算
O(n!)阶乘全排列暴力几乎不可计算
growth.py
# 直观感受增长率: 打印各阶在给定 n 下大约多少次基本操作
import math
n = 10_000_000                       # 规模: 一千万
orders = [
    ("O(1)      ", 1),
    ("O(log n)  ", int(math.log2(n))),
    ("O(n)      ", n),
    ("O(n log n)", int(n * math.log2(n))),
    ("O(n^2)    ", n * n),           # 注意: 一千万的平方极其巨大
]
for name, cnt in orders:
    # 假设一次基本操作约 1 纳秒, 换算成秒, 感受量级差
    print(f"{name} 约 {cnt:>22,} 次操作 ≈ {cnt * 1e-9:>12.1f} 秒")
★

核心要点：完整的渐进记号有三个——大 O（上界）、大 Ω（下界）、大 Θ（紧确界，既是上界又是下界）。面试常考排序：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)。

!

易错点：O(n log n) 与 O(n²) 很大，但 O(2ⁿ) 与 O(n!) 是真正「不可承受」的。见到要求 n≤10⁵、时间 1s 的题，几乎必须 O(n log n) 或更低；O(n²) 在 n=10⁵ 时会超时。

递增
O(1)→O(n!)
实用上限
O(n log n)
典型

知识点递归式分析与主定理（选学）intro-recurrence

分治算法的时间可写成递归式（recurrence）：把问题拆成 a 个规模为 n/b 的子问题，再把结果合并需要 f(n) 的成本，即 T(n) = a·T(n/b) + f(n)。

主定理（Master Theorem）给出快速结论。记 c = log_b(a)，比较 n^c 与 f(n)：

情形条件结果 T(n)
情形 1f(n) = O(n^c) 且更小Θ(n^c)
情形 2f(n) = Θ(n^c)Θ(n^c · log n)
情形 3f(n) = Ω(n^c) 且更大Θ(f(n))
recurrence.py
# 归并排序: T(n) = 2·T(n/2) + O(n)
#   a=2, b=2, f(n)=n;  n^(log_b a) = n^(log_2 2) = n
#   与 f(n)=n 相等 -> 情形2 -> T(n) = O(n log n)
def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left  = merge_sort(a[:mid])   # 子问题1: 规模 n/2
    right = merge_sort(a[mid:])   # 子问题2: 规模 n/2
    # 合并两个有序序列 -> O(n)
    i = j = 0; res = []
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            res.append(left[i]); i += 1
        else:
            res.append(right[j]); j += 1
    return res + left[i:] + right[j:]

# 再如二分查找: T(n) = T(n/2) + O(1)
#   a=1, b=2, n^(log_2 1) = 1, 与 f(n)=1 相等 -> O(log n)
★

核心要点：先算 n^(log_b a)（即「子问题本身」的成本），再和合并成本 f(n) 比较——谁大听谁的，相等就多乘一个 log n。

✕

易错点：主定理只适用于形式规范的递归式（每层均匀拆分、固定的 a 与 b）。遇到非均匀递归（如 T(n)=T(n-1)+O(1) 这种线性递归）或 f(n) 不是多项式时，用递归树法或代入法更稳妥。面试中 T(n)=T(n-1)+O(1) 等于 O(n)，千万别乱套主定理。

时间
O(n log n)
空间
O(n)
方法
主定理
