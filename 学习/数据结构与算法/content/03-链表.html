线性表 · 链表

  • 学完后你能：讲明双向链表与循环链表的定义、优缺点与典型应用（如 LRU 缓存、约瑟夫环）。
  • 学完后你能：从随机访问、插入删除、缓存友好度等维度对比链表与顺序表，并在实际场景中选对结构。

01链表基础
概念、节点结构与单链表基本操作

知识点链表概念与节点结构概念 · 带头/不带头结点 · 哨兵节点

链表（Linked List）是一种物理上非连续、非顺序的线性存储结构：数据元素之间的逻辑顺序，依靠节点中保存的指针（指针域 / pointer field）链接而成。每个节点（node）包含两部分：数据域（data field）存放元素值，指针域（next）存放下一个节点的地址。

它最大的特点是「用空间换灵活」：不要求内存连续，因而插入、删除更加高效，但失去了数组那样的随机访问能力。面试里常见的「带头结点（亦称无头结点 / 带头指针）之争」就是下面这两套写法。

  • 不带头结点：head 直接指向第一个数据节点；空表时 head is None。
  • 带头结点（dummy / 哨兵节点）：head（即 dummy）不存业务数据，其 next 指向第一个真实节点；空表时 head.next is None。
node.py
# 链表节点：数据域(data) + 指针域(next)
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val    # 数据域：存放数据元素
        self.next = next  # 指针域：指向下一个节点（None 表示尾）

# --- 构造链表 ---
# 不带头结点：head 直接指向第一个数据节点；空表 head is None
head = ListNode(1)             # [1]
head.next = ListNode(2)        # [1 -> 2]
head.next.next = ListNode(3)   # [1 -> 2 -> 3]

# 带头结点（dummy / 哨兵）：dummy 是占位，不存业务数据
dummy = ListNode()             # [dummy]
dummy.next = ListNode(1)       # [dummy -> 1]
# 空表判定：不带头 head is None；带头 dummy.next is None
维度不带头结点带头结点（dummy）
空表判定head is Nonedummy.next is None
头插 / 删除首节点需单独判断空表、更新 head统一逻辑，无需特判
典型场景算法题裸写、简洁工程实现、简化边界
★

核心要点：链表节点 = 数据域 + 指针域；指针存的是「下一个节点的地址」，节点在内存里可以不连续。链表全靠指针串联，因此「改指针顺序」是它最核心也最容易出错的地方。

!

易错点：「结点」与「节点」同义，只是翻译差异，国内教材两类写法都有；另外很多书用 p->next（C 风格）表示指针域，Python 里即 p.next。理解「头结点不存数据」是判断是否带头结点的关键。

知识点单链表的基本操作插入 · 删除 · 遍历（带头结点版）

单链表（Singly Linked List）每个节点只有一个 next 指针，只能「从头往尾」单向访问。它的基本操作——插入、删除、遍历——是后面所有链表算法题的「积木」。下面统一采用带头结点写法，这样对第一个真实节点做插入/删除时，不需要额外特判空表。

  • 头插：新节点 next 先接上原来的首节点，再让 dummy 指向新节点，O(1)。
  • 尾插：先找尾节点，再接入新节点，O(n)（需要遍历）。
  • 删除首节点：dummy.next = dummy.next.next，O(1)。
  • 按值删除：保留前驱指针 cur，判断 cur.next.val，命中后让前驱跳过目标，O(n)。
singly.py
# 带头结点：dummy 是哨兵，dummy.next 指向第一个真实节点
def traverse(head):
    """遍历：从第一个真实节点开始打印，O(n)"""
    cur = head.next
    while cur:
        print(cur.val, end=" -> ")
        cur = cur.next
    print("None")

def insert_head(head, val):
    """头插：O(1)，无需特判空表"""
    new = ListNode(val)
    new.next = head.next   # ① 新节点先接着原首节点
    head.next = new        # ② 哨兵再指向新节点
    return head

def insert_tail(head, val):
    """尾插：O(n)"""
    new = ListNode(val)
    cur = head
    while cur.next:        # 走到最后一个节点
        cur = cur.next
    cur.next = new
    return head

def delete_by_value(head, val):
    """删除第一个值为 val 的节点：O(n)。删除需要「前驱指针」"""
    cur = head             # 从哨兵开始，cur 始终是被删节点的前驱
    while cur.next:
        if cur.next.val == val:
            cur.next = cur.next.next   # 让前驱跳过目标，完成删除
            return True
        cur = cur.next
    return False
操作带头结点复杂度说明
头插 / 删除首节点O(1)不需遍历
尾插O(n)需找到尾节点
遍历 / 按值查找/删除O(n)顺序访问，需保留前驱
!

易错点（插入顺序）：头插时必须先把新节点的 next 接上前驱原来的后继，再让前驱指向新节点。若先改前驱的 next，原后继的地址就丢了，链表即断——这是新手最容易踩的坑。

★

核心要点：「删除一个节点需要它的前驱指针」。所以代码里 cur 从 dummy 出发、判断的是 cur.next，而不是直接对 cur 下手，这样才保证始终持有前驱。

02链表进阶
双指针与快慢指针的经典设计题

知识点单链表经典设计题反转 · 判环 · 中点 · 倒数第 k 个 · 双指针/快慢指针

单链表最值钱的考点集中在「双指针 / 快慢指针」套路。核心思想：用两个指针（有时 fast 每次走 2 步、slow 走 1 步）拉开固定步差，从而在一次遍历里解决问题，把时间降到 O(n)、空间降到 O(1)。

patterns.py
# ===== 1) 反转链表 (LeetCode 206)  —— 三指针迭代 =====
def reverse_list(head):
    pre, cur = None, head
    while cur:
        nxt = cur.next       # ① 先保存后继，否则反转后丢失
        cur.next = pre       # ② 反转当前节点指针方向
        pre = cur            # ③ pre 前移
        cur = nxt            # ④ cur 前移
    return pre               # pre 指向新头

# ===== 2) 判断是否有环 (LeetCode 141) —— 快慢指针 =====
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:    # 保证 fast 能走两步
        slow = slow.next         # 慢走1步
        fast = fast.next.next    # 快走2步
        if slow is fast:         # 相遇 => 有环
            return True
    return False

# ===== 3) 找中间节点 (LeetCode 876) —— 快慢指针 =====
def middle_node(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow                  # fast 走完时 slow 恰在中点

# ===== 4) 删除倒数第 k 个 (LeetCode 19) —— 快慢指针 =====
def remove_nth_from_end(head, k):
    dummy = ListNode(0, head)    # 用哨兵避免删除头节点的特判
    slow = fast = dummy
    for _ in range(k):           # fast 先多走 k 步
        fast = fast.next
    while fast:                  # fast 走完时 slow 恰在倒数第 k 个的前驱
        slow = slow.next
        fast = fast.next
    slow.next = slow.next.next   # 跳过倒数第 k 个
    return dummy.next
★

核心要点：快慢指针之所以省空间，是因为它只在链表上移动两个指针、无需哈希表。反转则是「保存后继 → 改指 → 移动 pre/cur」三步循环；倒数第 k 个是「先拉开 k 步再同步前进」。三者都 O(1) 空间、一次遍历解决。

!

易错点（判环）：快慢指针的 while 条件必须是 while fast and fast.next，这样 fast 才能安全走两步。若写成 while fast.next，当链表无环且偶数长度时，fast.next.next 会因 fast.next 为 None 而报错（NoneType）。

!

找环入口（LeetCode 142）：相遇后把任一指针放回 head，两个指针每次各走一步，再次相遇处即为环入口。原理：慢指针进环前走了 d 步，fast 走的是 slow 的 2 倍，二者之差是环长的整数倍，故「从相遇点与头各走一步」会在入口相遇。

03链表变体与对比
双向链表、循环链表、链表 vs 数组

知识点双向链表Doubly Linked List · prev 前驱指针

双向链表（Doubly Linked List）的每个节点有三个域：数据域 val、前驱指针 prev、后继指针 next。它既能从头往尾走，也能从尾往头走，因此「已知某个节点时」可以方便地拿到它的前驱。

  • 优点：已知位置时，插入/删除可做到 O(1)（无需像单链表那样先 O(n) 找前驱）。
  • 缺点：每个节点多一个 prev 指针，占用更多空间，且插入/删除时要同时维护两个方向的指针，更容易出错。
doubly.py
# 双向链表节点：数据域 + 前驱 prev + 后继 next
class DListNode:
    def __init__(self, val=0, prev=None, next=None):
        self.val = val
        self.prev = prev
        self.next = next

def insert_after(cur, new):
    """在节点 cur 之后插入 new：O(1)。两个方向都要接。"""
    new.next = cur.next
    if cur.next: cur.next.prev = new   # 新节点的后继的前驱指向 new
    cur.next = new
    new.prev = cur

def delete_node(cur):
    """删除「已知位置」的节点 cur：O(1)。维护前后两侧。"""
    if cur.prev: cur.prev.next = cur.next
    if cur.next: cur.next.prev = cur.prev
维度单链表双向链表
指针域1 个（next）2 个（prev + next）
已知位置删除需先 O(n) 找前驱O(1)
典型应用高频算法题LRU 缓存、双向队列
!

易错点：双向链表的插入/删除要同时更新 prev 与 next 两个方向，漏掉任何一边都会断链或留下悬空指针。写代码前后画图核对每个指针最稳妥（这也是 LRU 缓存题的常见失分点）。

O(1)

O(n)

2 指针 + 数据

知识点循环链表Circular Linked List · 尾接首

循环链表（Circular Linked List）把链表的尾节点 next 指针指向头节点（或第一个节点），从而形成一个环。它可以是单链表的循环，也可以承继双向链表成为双向循环链表。

  • 特点：从任一节点出发都能访问整张表；尾部到头部只需 O(1)，去掉了「尾指针」判空。
  • 典型场景：轮转调度、进程时间片轮转、以及数学趣题约瑟夫环（Josephus Problem）。
circular.py
# 构造一个单向循环链表：关键一步是 tail.next = head
def make_circular(vals):
    if not vals: return None
    head = ListNode(vals[0])
    tail = head
    for v in vals[1:]:
        tail.next = ListNode(v)
        tail = tail.next
    tail.next = head     # 尾节点指回头 -> 成环
    return head

★

核心要点：循环表以「尾接首」成环，环的「入口」就是头节点位置。它和判环题（LeetCode 141/142）里的「环」不同：循环表是结构上天然成环，判环节是判断某个普通链表是否意外成环——方向正好相反，别混。

!

易错点（死循环）：遍历循环表若沿用 while cur: 会永远为真。必须用计数（统计节点数）或记录起始节点、走到再次回到起点才停，否则程序死循环。

知识点链表 vs 数组对比顺序表 vs 链表 · 选型

数组（顺序表 / Array / Sequential List）和链表是线性表的两大代表。面试官常让你现场对比并「按场景选型」。一句话总结：数组重随机访问，链表重插入删除。

compare.py
# 数组(顺序表)：O(1) 随机访问，直接按下标定位
arr = [10, 20, 30, 40]
print(arr[2])        # 30 —— 无需遍历

# 链表：O(n) 顺序访问，必须从头走到第 i 个节点
def get_by_index(head, i):
    cur = head.next          # 跳过哨兵
    for _ in range(i):
        cur = cur.next
    return cur.val
维度顺序表 / 数组链表
内存布局连续非连续（靠指针）
随机访问O(1)O(n)
插入/删除(已知位置)需搬移元素 O(n)定位后 O(1)
空间需预分配、可能浪费按需分配、有指针开销
缓存友好度好（局部性好）差（指针跳跃）
★

选型建议：「访问频繁、数据规模已知」用数组；「频繁插入删除、数据规模动态增长、元素需跨节点搬动」用链表。工程里（如 Java 的 ArrayList vs LinkedList、Python 的 list 优先）通常默认数组，链表多用于特定场景（LRU、跳表底层等）。
