MODULE 02 · 数据结构与算法

线性表 · 数组与顺序表

从「内存里一段连续地址」出发，理解顺序表为何随机访问能做到 O(1)、而插入删除却是 O(n)，并掌握动态扩容的均摊分析，以及前缀和、双指针等高频技巧。

  • 学完后你能区分行优先/列优先存储，并解释二维数组地址计算与「按行遍历更快」的缓存原理。

01顺序存储的本质：连续地址
（存储结构 · 随机访问 · 插入删除）

存储结构顺序表的存储结构：连续存储与元素地址array-storage

线性表（Linear List）是由 n 个数据元素组成的有限序列，是最基础的数据结构。它有两种经典存储方式：顺序存储（用一段地址连续的内存依次存放，即顺序表/数组）和链式存储（用指针把分散的结点串起来，见下一章链表）。本模块聚焦顺序存储。

顺序表的核心特征是一个词：「连续」。逻辑上相邻的元素，在物理内存里也紧挨着。于是第 i 个元素的存储位置 LOC(a_i) 可以由基地址 + 偏移量唯一算出：

LOC(a_i) = LOC(a_1) + (i − 1) × size

其中 size 是单个元素占用的字节数（C/C++ 中即 sizeof(T)）。这个公式是后面所有性能结论的「源头」——因为位置能被直接算出来，所以访问不需要遍历。

storage.py
# 顺序表 = 一段地址连续的内存；地址 = 基地址 + 下标 * 元素大小
def addr(base, elem_size, i):
    return base + i * elem_size   # 数组下标从 0 开始，偏移 = i * size

# C/C++ 里用指针更能体会“连续”二字：
#   int a[5] = {10,20,30,40,50};
#   int* p = a;                 // p 指向基地址（即 &a[0]）
#   &a[i] == p + i              // 等价于 base + i * sizeof(int)
#   sizeof(int) 通常为 4，所以相邻元素地址相差 4 字节。
对比顺序表（数组）链表
存储方式地址连续结点分散，指针相连
位置能否直接算出能（O(1) 随机访问）不能，需从头部遍历
是否需预先分配容量静态数组需，动态数组自动扩容需要时申请结点即可
★

核心要点：连续存储让元素地址可由公式直接推出，这是「随机访问 O(1)」的根本原因；也是它与链表最本质的区别。

⚠

易错点：① 数组中下标从 0 开始，逻辑序号（第 i 个）从 1 开始，所以公式里是 (i−1)×size 而非 i×size。② 偏移量单位是字节，不是「元素个数」，要乘上 sizeof(T)。③ Python 的 int 是任意精度对象，list 里存的其实是指向对象的指针，并非纯粹连续存放原始数据；但「按下标定位指针」的随机访问特性依然成立。

随机访问随机访问与性能array-random

随机访问（Random Access）指给定下标就能在 O(1) 时间定位到该元素，不需要从头逐个找。C/C++ 通过 a[i] 或 *(a+i) 完成，Python 通过 lst[i] 完成——编译器/解释器都把它翻译成一次「基地址 + 偏移」的地址计算，因此代价恒定。

与它相对的顺序查找就没这么快：若要在顺序表里找某个值，且没有额外索引，最坏要扫到末尾，O(n)。注意区分「按下标访问」「按值查找」两个概念——前者 O(1)，后者通常 O(n)（有序时可用二分降到 O(log n)）。

random_access.py
def linear_search(a, target):
    """按“值”查找：最坏要扫到末尾，O(n)——随数组规模线性增长"""
    for i, v in enumerate(a):
        if v == target:
            return i
    return -1

def index_access(a, i):
    """按“下标”访问：一次地址计算即得，O(1)——与规模无关"""
    return a[i]   # 等价于 C 里的 *(a + i)

def binary_search(a, target):
    """若数组有序，可用二分把查找降到 O(log n)（前提：a 已升序）"""
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
!

别混淆：「访问」是「我知道在哪、直接去取」；「查找」是「我不知道在哪、要去搜」。面试随口说的「数组 O(1)」通常指随机访问，而不是查找——把两者混为一谈是经典扣分点。

★

核心要点：随机访问 O(1) 是数组的「独门绝技」，也是它一旦排序后能配合二分、实现 O(log n) 查找的基石（LeetCode 704 二分查找）。

插入删除插入与删除：复杂度 O(n) 的本质array-ops

顺序表最大的「软肋」是插入与删除。因为元素必须紧挨着、且保持原相对顺序，一旦在某位置插入，就要把该位置及其后所有元素整体后移一位腾出空位；删除则要把它后面的所有元素整体前移一位补上空位。移动元素是 O(n) 的根源。

以含 n 个元素、逻辑序号从 1 到 n 的顺序表为例：

  • 插入到第 i 个位置：把第 i ~ n 个元素后移，共移动 n − i + 1 个；平均约 n/2 个，故 O(n)。
  • 删除第 i 个元素：把第 i+1 ~ n 个元素前移，共移动 n − i 个；平均约 (n−1)/2 个，故 O(n)，但仍比插入略少。
ops.py
def list_insert(a, n, i, x):
    """把 x 插入到下标记 i (0<=i<=n)，返回新长度。O(n)"""
    if i < 0 or i > n or n == len(a):
        raise IndexError("位置非法或已满")
    for j in range(n, i, -1):   # 从后往前移动，避免覆盖
        a[j] = a[j - 1]
    a[i] = x
    return n + 1

def list_delete(a, n, i):
    """删除下标记 i 的元素，返回新长度。O(n)"""
    if i < 0 or i >= n:
        raise IndexError("位置非法")
    for j in range(i, n - 1):   # 从前往后前移，填补空缺
        a[j] = a[j + 1]
    return n - 1
⚠

易错点：① 插入时移动必须从后往前（range(n, i, -1)），否则会把后面的值覆盖掉；删除时移动从前往后。② 插入后，被移动元素的新下标会+1，引用它们的旧下标全部失效。③ 别把「尾部追加 append」和「尾部删除 pop」与中间插入混淆——尾部操作是 O(1)（均摊），中间才是 O(n)。

★

核心要点：凡是要保持「连续 + 相对顺序不变」的插入/删除，代价都是 O(n)。若你的场景是「频繁在中间插删」，链表（下一章）更合适；若主要是「按下标访问」，顺序表更合适。这也是面试常让你权衡的地方。

面试高频：LeetCode 27 移除元素、LeetCode 26 删除有序数组重复项——都能用「快慢双指针原地操作」，在 O(1) 额外空间内完成，详见本模块第 5 个知识点。

动态数组动态数组与扩容策略（均摊分析）array-dynamic

静态数组容量一出生就固定，满了就再也不能加。于是有了动态数组：容量不足时申请更大的新数组、把旧元素整体拷贝过去、再释放旧空间，从而支持「越用越长」。C++ 的 std::vector、Java 的 ArrayList、Python 的 list 都是动态数组。

扩容的关键是每次扩到多大，这直接决定总代价：

扩容策略扩多少次总拷贝代价append 均摊
固定每次 +1≈ n 次O(n²)O(n) 差
固定每次 +K≈ n/K 次O(n²/K)O(n/K) 一般
每次×2（几何增长）≈ log n 次O(n)O(1) 优
dynamic.py
class DynArray:
    """简易动态数组：容量不足时扩容为原来的 2 倍"""
    def __init__(self):
        self.cap = 2
        self._buf = [None] * self.cap   # 底层连续存储
        self.n = 0                      # 实际元素个数

    def append(self, x):
        if self.n == self.cap:          # 只有满时才扩容
            self.cap *= 2
            new = [None] * self.cap
            for i in range(self.n):     # 拷贝旧元素：这一步是 O(n)
                new[i] = self._buf[i]
            self._buf = new
        self._buf[self.n] = x           # 常规情况：O(1)
        self.n += 1

    def __len__(self):
        return self.n

均摊分析（Amortized Analysis）用来衡量「部分操作昂贵、整体平均便宜」的情形。虽然某一次扩容要拷贝 O(n) 个元素、代价高达 O(n)，但扩容只发生 log n 次，把总代价 O(n) 平均分摊到连续 n 次 append 上，每次平均是 O(1)。结论：动态数组尾部追加的整体均摊时间复杂度为 O(1)。

⚠

易错点：①「均摊 O(1)」是平均概念，不保证每一次都 O(1)——某次扩容瞬间会明显变慢（可能引起卡顿）。② 扩容倍率过大浪费空间：×2 时容量最多浪费一半；若×1.5 则浪费约三分之一，是空间与拷贝次数之间的折中，故常见实现用 1.5 或 2。③ C++ 中扩容会导致全部迭代器/指针失效，用迭代器遍历时若同时 push_back 可能踩坑。

★

核心要点：几何增长（×2）让扩容次数降到 O(log n)、总拷贝 O(n)，从而 append 均摊 O(1)；固定步长增长会让总代价退化到 O(n²)。这是「为什么用 ×2 而不是 +1」的均摊答案。

array-app

顺序表的随机访问 O(1) 让很多「扫一遍数组」的套路成为可能。这里介绍两块高频板块：前缀和/差分（把区间查询与区间修改降到 O(1)）、双指针（把 O(n²) 的暴力优化到 O(n)）。

前缀和（Prefix Sum）：预处理出一个数组 pre[i] = 前 i 个元素之和。此后求任意区间 [l, r]（含两端）的和，只需 pre[r+1] − pre[l]，一次减法搞定，O(1)。差分（Difference Array）是前缀和的「逆运算」：对区间反复做加减，用差分数组 O(1) 记录、最后一次性还原，常用于区间修改。

apps.py
# 前缀和：预计算后，区间和查询降到 O(1)
def build_prefix(nums):
    pre = [0] * (len(nums) + 1)          # pre[i] = 前 i 个元素之和
    for i, v in enumerate(nums):
        pre[i + 1] = pre[i] + v
    return pre

def range_sum(pre, l, r):                # 含两端 [l, r]
    return pre[r + 1] - pre[l]

# 快慢双指针：原地删除有序数组重复项 (LeetCode 26)
def remove_duplicates(nums):
    if not nums:
        return 0
    k = 0                                # 慢指针：最后一个不重复元素下标
    for i in range(1, len(nums)):        # 快指针 i 扫描整个数组
        if nums[i] != nums[k]:
            k += 1
            nums[k] = nums[i]            # 把新值搬到慢指针后一位
    return k + 1                         # 返回去重后的长度

双指针（Two Pointers）常见三种形态：

  • 快慢指针：一快一慢，用于原地去重（LeetCode 26/27）、判环、找中点。
  • 对撞指针：一头一尾相向而行，用于有序数组两数之和（LeetCode 167）、盛水容器（LeetCode 11）。
  • 滑动窗口：维护一个窗口，用于最短子数组/最长不重复子串（LeetCode 209、3）。
!

易错点：前缀和的 pre 通常长度比原数组多 1（下标对齐），否则 pre[l-1] 会越界；区间含两端时用 pre[r+1]-pre[l]，不含左端时用 pre[r]-pre[l]，务必把边界写清楚。双指针要警惕「移动哪个指针」——快慢指针快指针永远前进，对撞指针依据单调性判断移动哪一头。

★

核心要点：前缀和把「O(n) 的区间查询」摊到「O(n) 预处理 + O(1) 每次查询」；双指针把「O(n²) 的枚举」降为「O(n) 一趟扫描」。两者都是「用记录换时间」的典型，也是数组题的必会套路。

02扩展：多维数组及其存储方式
（行优先 vs 列优先 · 缓存友好性）

多维数组多维数组与存储方式：行优先/列优先array-multi

二维数组 a[M][N] 在逻辑上是「M 行 × N 列」的表格，但物理内存依然是一段连续的一维地址。把二维「拍平」成一维有两种顺序：

  • 行优先（Row-major）：先存完一整行，再存下一行。a[i][j] 的偏移 = i × 列数 + j。C/C++、Java 及 Python 的 numpy（默认 C 序）都是行优先。
  • 列优先（Column-major）：先存完一整列，再存下一列。a[i][j] 的偏移 = j × 行数 + i。Fortran、MATLAB 及 numpy 的 order='F' 是列优先。
multi.py
# 行优先(row-major)二维数组 a[M][N]：a[i][j] 的偏移 = i*N + j
N = 4
def off_row(i, j):
    return i * N + j            # 先跳 i 整行，再跳 j 列

# 列优先(column-major)二维数组 a[M][N]：a[i][j] 的偏移 = j*M + i
M = 3
def off_col(i, j):
    return j * M + i            # 先跳 j 整列，再跳 i 行

# numpy 可显式指定存储顺序（默认为 'C' 行优先）
# import numpy as np
# m = np.array([[1,2,3],[4,5,6]], order='C')   # 行优先
# m = np.array([[1,2,3],[4,5,6]], order='F')   # 列优先
★

核心要点：在行优先的存储下，按行遍历(外层 i、内层 j) 访问的内存地址是连续的，能最大限度命中 CPU 缓存（cache locality），因此通常比按列遍历快得多。这也是做矩阵运算、图像处理时「先想好遍历顺序」的原因。

⚠

易错点：① 偏移公式取决于行优先还是列优先，且到底是「行×列数+列」还是「列×行数+行」，写错一个就全错。② 行优先下按列遍历（外层 j、内层 i）会造成「跨行跳地址」，严重破坏缓存命中率。a[i][j] 的下标顺序（i 行 j 列）与内存顺序（行优先先 i 后 j）要对应清楚。

面试延伸：给定行优先存储的 a[M][N]，把二维下标映射成一维偏移是基本功；进一步可思考「如何把稀疏矩阵用数组紧凑存储」（三元组表/十字链表）。
