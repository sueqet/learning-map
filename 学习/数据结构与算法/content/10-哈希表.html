MODULE 10 · 数据结构与算法

哈希表

哈希表用哈希函数把任意键映射成数组下标，让查找、插入、删除都逼近 O(1)——它是最典型的「用空间换时间」数据结构，也是字符串匹配、图论、设计题与笔试面试里出现频率最高的一类题。

✓本节学习目标

  • 学完后你能解释哈希表「键 → 下标」的映射思想，以及平均 O(1)、最坏 O(n) 的来源与成立前提。
  • 学完后你能按场景设计哈希函数（除留余数法 / 乘法散列 / 多项式滚动哈希），并说出 m 取素数 的作用。
  • 学完后你能分别用链地址法与开放定址法实现冲突解决，并说明线性探测删除为何必须打 DELETED 标记。
  • 学完后你能用负载因子 α 判断何时扩容，解释 rehash 的过程与摊还 O(1) 的代价来源。
  • 学完后你能熟练用哈希集合 / 映射，把「两数之和、去重、计数、最长连续序列」等题的暴力解优化到 O(n)。
Pre-requisites · 前置知识

会一门编程语言（推荐 Python，或 C++/Java 亦可）；理解数组随机访问为 O(1)、链表、循环与函数；了解时间复杂度的渐进分析，若懂一点摊还（amortized）分析，学「扩容」会更顺。

10.1哈希表基础：核心思想与哈希函数设计

知识点哈希表的基本思想与平均 O(1)hash-basic

哈希表（Hash Table，散列表）的核心思想：用一个哈希函数（hash function），把任意类型的键（key）计算成一个数组下标（index），从而把「查找」从线性/对数比较，变成一次随机访问。

  • 直接寻址（direct addressing）：当键本身就是 0..M-1 的整数时，直接用键当下标，O(1) 无冲突；但键域通常很大（如名字、字符串），无法开那么大数组。
  • 哈希推广：不直接用小键，而是用 index = h(key) 把它「压缩」到一个有限范围内，用数组存这个范围内的桶。
  • 平均 O(1) 的关键：哈希函数把键均匀分散到不同桶，每次操作只访问「大概率只有常数个」元素的桶；冲突不可避免，但期望冲突很少。
  • 最坏情况 O(n)：如果所有键都散到同一个桶（哈希函数被攻击或设计极差），链表/探测退化成线性查找。
hash_basic.py
# 用「桶数组 + 链地址」搭一个最简哈希表，体会 O(1) 的由来
class SimpleHashMap:
    def __init__(self, m=13):
        self.m = m
        self.buckets = [[] for _ in range(m)]     # 每个桶是一条链（冲突时挂到链上）

    def h(self, key):            # 除留余数法：把任意整数压到 [0, m-1]
        return key % self.m

    def put(self, key, val):
        i = self.h(key)
        for j, (k, _) in enumerate(self.buckets[i]):   # 桶内线性扫：期望极短
            if k == key:
                self.buckets[i][j] = (key, val)        # 覆盖旧值
                return
        self.buckets[i].append((key, val))             # 链上新键

    def get(self, key):
        i = self.h(key)
        for k, v in self.buckets[i]:                   # 桶内找
            if k == key:
                return v
        raise KeyError(key)

d = SimpleHashMap()
d.put(42, "answer"); d.put(55, "five")
print(d.get(42))     # answer —— O(1) 平均
★

核心要点：哈希表的精髓是以空间换时间——花一块数组，把「比较查找」变成「映射 + 随机访问」。平均 O(1) 是期望意义，建立在哈希函数均匀 + 负载因子合理两个前提下。

!

易错点：不要把「平均 O(1)」当成「永远是 O(1)」。最坏是 O(n)（全部冲突到同一桶）。面试里被追问「哈希表一定快吗？」时，要答出 了期望/均摊、好哈希函数、合适负载因子、扩容 这些前提。

知识点哈希函数的设计hash-func

好的哈希函数要满足三点：确定性（同一键恒返回同一值）、计算快、分布均匀（把键域均匀撒到每个桶，减少聚集）。常见设计方法如下。

方法公式 / 思路特点 / 用途
除留余数法（division method）h(k) = k mod m最简单常用；m 宜取素数，减少键的规则性带来的聚集。
乘法散列法（multiplication）h(k) = floor(m · frac(k·A))m 取 2 的幂也可，A 常用 0.618…；对 m 不敏感。
平方取中 / 折叠法取平方的中间若干位；把键分段相加适合键本来是数串、需打散位数分布时。
多项式滚动哈希（polynomial / rolling）h = (h·base + c) mod m字符串哈希（Rabin–Karp）的核心；base 常取 31/13331。
完美哈希（perfect hashing）两级哈希 / cuckoo 哈希键集静态时构造零冲突映射，可实现最坏 O(1)。
hash_func.py
# 除留余数法：m 建议取不接近 2 的幂的素数
def division_hash(key: int, m: int) -> int:
    return key % m          # m=13 而非 16，避免低位规则性被直接用作下标

# 乘法散列法（Knuth 建议 A≈0.6180339887）
def multiply_hash(key: int, m: int, a=0.6180339887) -> int:
    return int(m * ((key * a) % 1))

# 字符串多项式滚动哈希：像进制数一样逐位累加，用于字符串题
def polynomial_hash(s: str, base=31, mod=1_000_000_007) -> int:
    h = 0
    for ch in s:
        h = (h * base + ord(ch)) % mod   # base 大且为素数，罕见重散
    return h
⚠

为什么 m 取素数：若键本身呈「等差数列」或「低 2 位固定」，用 2 的幂作 m 会让这些键永远落在少数桶里（聚集）。取素数可以打破这种周期性，让分布更均匀。

!

易错点 — 哈希洪水（hash-flooding）：若哈希函数对恶意输入高度可预测，攻击者可构造大量同桶键，把哈希表拖成 O(n²)。防御做法是加随机盐（random seed），或让冲突桶树化（见 Java HashMap）。

知识点冲突解决（链地址 / 开放定址）hash-collision

冲突（collision）是指两个不同键被映射到同一位置。解决思路分两大流派：链地址法（separate chaining）让每个桶「能装多个」，开放定址法（open addressing）让冲突的键顺延放到后续空位。

  • 链地址法：每个桶是链表（或红黑树）。Java HashMap 在链表过长时树化；负载因子可大于 1。简单、无聚集、删除容易。
  • 开放定址法：桶只存一个元素，冲突就按探测序列找下一个空位。负载因子必须 <1（常在 0.5~0.75 触发扩容）。删除要打 DELETED 标记。
  • 线性探测（linear probing）：h + i，依次找下一个；实现简单但易主聚集（primary clustering）。
  • 二次探测（quadratic probing）：h + i²，跳跃式探测，缓解主聚集；但可能跳不到所有桶。
  • 双重哈希（double hashing）：h + i·h₂(key)，用第二个哈希函数定步长，分布最均匀。
hash_collision.py
# 开放定址 + 线性探测：插入 / 查找；删除必须用 DELETED 占位
class LinearProbe:
    def __init__(self, m=11):
        self.m, self.table = m, [None] * m   # None=空，__DEL__=被删除
        self.__DEL__ = object()

    def h(self, key):
        return key % self.m

    def find(self, key):                     # 查找：沿探测序列找键
        i = self.h(key)
        for step in range(self.m):
            j = (i + step) % self.m
            cell = self.table[j]
            if cell is None:                 # 遇到真正的空才可断定"不在"
                return -1
            if cell is not self.__DEL__ and cell[0] == key:
                return j
        return -1

    def insert(self, key, val):
        i = self.h(key)
        for step in range(self.m):
            j = (i + step) % self.m
            c = self.table[j]
            if c is None or c is self.__DEL__:   # 空位或被删除位都能放
                self.table[j] = (key, val)
                return
            if c[0] == key:
                self.table[j] = (key, val); return
        raise RuntimeError("表已满，需扩容")

    def delete(self, key):
        j = self.find(key)
        if j < 0: return False
        self.table[j] = self.__DEL__          # 只标记，不置 None！
!

为何删除要打 DELETED 标记：线性探测中，若直接把键所在格置 None，就会切断探测链——后面本来与该位置「同链」的键在查找时会提前遇到 None 而误判「不存在」。用 DELETED 占位即可保持探测链连续。

★

面试对照：Java HashMap 用链地址，并在桶数≥64 且单链长≥8 时把链表转红黑树（把最坏 O(n) 降到 O(log n)）；Python dict/set 用开放定址的探测式存储。

10.2负载因子与扩容（rehash）

知识点负载因子与扩容（rehash）hash-load

负载因子（load factor） α = n / m（已存元素 n ÷ 桶数 m），它是判断哈希表「有多挤」的核心指标。α 越大，冲突期望越高、操作越慢，因此要设一个上限阈值，超过就扩容（resize / rehash）。

  • 链地址法：α 允许 >1（链表变长即可），工程上常设 0.75 左右。
  • 开放定址法：α 必须 <1，否则永远插不进；实际常控制在 0.5~0.75，再高就扩容。
  • 扩容过程：把桶数组扩为约 2 倍（如 m → 2m），并把所有旧键重新哈希进新表——因为 m 变了，每个键的下标几乎全变。
  • 摊还分析：单次扩容 O(n)，但元素数量指数增长，分摊到每次插入是均摊 O(1)（类比动态数组）。
hash_rehash.py
# 链地址 + 阈值扩容：装得越满冲突越多，宁可提前扩大
class RehashMap:
    def __init__(self, init=8, factor=0.75):
        self.cap, self.n, self.factor = init, 0, factor     # n=cnt of keys
        self.buckets = [[] for _ in range(init)]

    def h(self, key):                # m 用当前容量
        return key % self.cap

    def _touch(self):                # 每次插入后检查负载
        if self.n / self.cap >= self.factor:      # α 超阈值 → 扩容
            self._rehash(self.cap * 2)

    def _rehash(self, new_cap):
        old = self.buckets
        self.cap, self.n, self.buckets = new_cap, 0, [[] for _ in range(new_cap)]
        for chain in old:                                    # 旧元素逐个重散
            for k, v in chain:
                self[k] = v

    def __setitem__(self, key, val):
        self._touch()                        # 先扩容再插入（体现"提前"）
        i = self.h(key)
        for j, (k, _) in enumerate(self.buckets[i]):
            if k == key:
                self.buckets[i][j] = (key, val); return
        self.buckets[i].append((key, val))
        self.n += 1
★

核心要点：负载因子是「空间与时间」的平衡开关——调小则更省冲突但更费内存，调大则省内存但更易冲突。阈值（0.75）是工程上的经验值，不是定理。

!

易错点：「扩容后要把所有键重新哈希」——不能把旧槽位直接拷贝过来，因为 m 变了，下标已失效。另外扩容不是 O(1)，是 O(n)；但通过摊还分析，整体平均仍是 O(1)。

O(n)

O(1)

10.3哈希集合 / 映射与算法实战

知识点哈希集合 / 映射与计数去重实战hash-usage

哈希集合（hash set）与哈希映射（hash map）是把 O(n²) 暴力优化成 O(n) 的万能钥匙：凡是「我有没有见过它」「它出现了几次」「它对应的那个人是谁」，都能用哈希在常数时间回答。

  • 去重：set 天然去重，len(set(x)) != len(x) 即可判断是否有重复。
  • 计数：Counter / dict 统计频率，O(n)。
  • 查找 / 映射：存「值 → 它出现位置」或「键 → 配对对象」，把双重循环拆成一次遍历。
  • 集合运算：交集 / 并集 / 差集用 set 直接做；图 / 树的 visited 标记也用 set 达到 O(1)。
  • 注意：set / dict 无序，需要有序结果时要显式排序或用有序容器。
hash_usage.py
from collections import Counter

def contains_duplicate(nums):          # LeetCode 217：去重后长度不同 => 有重复
    return len(set(nums)) != len(nums)

def count_chars(s):                     # 计数：统计频率用 Counter（内部即哈希表）
    return Counter(s)

def intersection(a, b):                 # LeetCode 349：两个数组的交集
    return sorted(set(a) & set(b))      # set 的 & 即交集，O(n)

def single_number(nums):                # LeetCode 136：只出现一次的数字
    seen = set()
    for x in nums:
        if x in seen: seen.remove(x)    # 出现两次就移除
        else:           seen.add(x)
    return seen.pop()                   # 剩下的就是只出现一次的那个
★

核心要点：花 O(1) 的哈希存储，把「需要回头再找一遍」的二次扫描变成一次扫描 + 哈希反查——这就是所谓用空间换时间。

!

易错点 — 可哈希性（hashable）：Python 里 list、dict、set 是可变的，不可作为 dict 的 key / set 的元素；tuple 的所有元素都不可变时可哈希。要用列表做 key，先转成 tuple。

知识点设计题与应用（两数之和 / 最长连续序列等）hash-problems

哈希最经典的考法，是把它当作「加速找伴侣 / 判断存在」的辅助结构，把找配对从两层循环变一次遍历。以下两道是几乎必考的模板。

  • 两数之和（LeetCode 1）：一遍哈希，每遇到一个数，立刻查「target - 它」是否出现过。
  • 最长连续序列（LeetCode 128）：用 set 判断「我是不是连续段的最左端点」，是才开始向后数，保证每段只数一次，整体 O(n)。
  • 字母异位词分组（LeetCode 49）：把「排序后的字符串」或「字符计数字符串」作为 key，异位词归到同一组。
  • 设计 LRU 缓存（LeetCode 146）：哈希表负责 O(1) 定位键，双向链表维护访问顺序并支持 O(1) 摘下/插入。
hash_problems.py
# 1) 两数之和（LC 1）：一遍哈希，边遍历边查"互补数"
def two_sum(nums, target):
    pre = {}
    for i, x in enumerate(nums):
        y = target - x
        if y in pre:                  # O(1) 找到之前出现过的互补数，返回两下标
            return [pre[y], i]
        pre[x] = i                    # 记下"值 -> 它的下标"
    return []

# 2) 最长连续序列（LC 128）：只从"连续段最左端"开始数，保证每段 O(1) 处理
def longest_consecutive(nums):
    s, best = set(nums), 0
    for x in s:
        if x - 1 in s:                # 左边还有人，说明自己不是起点，跳过
            continue
        cur, y = 0, x
        while y in s:                 # 只在起点往后数整段
            cur += 1; y += 1
        best = max(best, cur)
    return best

print(two_sum([2, 7, 11, 15], 9))      # [0, 1]
print(longest_consecutive([100, 4, 200, 1, 3, 2]))  # 4 (1,2,3,4)
★

答题套路：看到「找配对 / 查存在 / 统计频率 / 去关注过没」的题，先想能不能用哈希把第二层循环变成 O(1) 反查。这就是哈希在算法题里 60% 以上的出场动机。

!

易错点 — 连续序列别爆 O(n²)：若对每个数都向后 while 延伸，最坏会重复数同一段而超时。关键是判断起点（x-1 in s），保证每个连续段只被数一次，整体才是 O(n)。
