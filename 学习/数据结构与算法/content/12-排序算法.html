知识点1排序的基本概念与稳定性sort-basic · 概念先行

排序（sorting）是指把一组记录按照某个关键字（key）递增或递减排成有序序列的操作。排序是数据结构的核心操作之一，几乎每本算法书、每次面试都绕不开它。按数据规模是否全部装入内存，可把排序分为内排序（在内存中完成）与外排序（数据量大，需借助外部存储，如归并思想用于外排）。

这一节最重要的是稳定性（stability）：若序列中存在相等的元素，排序前后它们相对次序保持不变，则该排序算法是稳定的；否则是不稳定的。(a[i] == a[j] 且在排序前 a[i] 位于 a[j] 之前，排序后仍需 a[i] 在 a[j] 之前)。

  • 为什么关心稳定性？当排序关系到「先后次序带来的隐含顺序」时，稳定才有意义。例如先按姓名排序，再按分数排序，稳定的算法能保留「分数相同者仍按姓名有序」，不稳定的算法则会破坏这份次序。
  • 基数排序的前提：基数排序需要对每一位做稳定排序，因此它依赖偶数次的稳定排序作为子步骤。
stability_demo.py
# 稳定性演示：按 (score) 排序，score 相同的元素要保持原先后顺序
records = [("小明", 90), ("小红", 85), ("小刚", 90), ("小丽", 85)]

# 若不稳定的算法把两个 90 / 两个 85 的先后顺序打乱，就叫"不稳定"
# 下面用一种"稳定"的插入排序验证：相等时不做交换，次序得以保留
def stable_insertion_by_score(arr):
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j][1] > key[1]:   # 用 > 而非 >=：相等即停，保证稳定
            arr[j+1] = arr[j]
            j -= 1
        arr[j+1] = key
    return arr

print(stable_insertion_by_score(records))
# 输出：(小明,90),(小刚,90),(小红,85),(小丽,85)  90 与 85 的内部次序都没变
★

核心结论：稳定性与「相等元素相对次序」挂钩，与时间 / 空间复杂度无关。一个算法可以很慢却是稳定的（冒泡、插入），也可以很快却不稳定（快速、堆、选择、希尔）。

!

易错点：很多人把「非原地（需要额外空间）」误当成「不稳定」，这是两码事。稳定性仅取决于相等元素的处理，与是否原地、复杂度无关。同理，不是所有 O(n log n) 都稳定——归并稳定，快速 / 堆不稳定。

知识点2插入排序 / 选择排序 / 冒泡排序（含希尔）sort-simple · O(n²) 家族

这四者是「入门三件套 + 一个改进」，平均复杂度都是 O(n²)，但各自的思路与稳定性差异很大，是面试中「手写 + 追问细节」的高频点。

插入直接插入排序（Insertion Sort，稳定）

思想：把数组看成「已排序前缀」+「未排序后缀」，每次把后缀的第一个元素与前面元素逐个比较后插入到正确位置，像整理扑克牌一样。相等时停止移动，因此稳定。

insertion_sort.py
def insertion_sort(arr):
    for i in range(1, len(arr)):
        key = arr[i]          # 取出待插入元素
        j = i - 1
        while j >= 0 and arr[j] > key:   # 严格大于才后移；相等不移动 -> 稳定
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key       # 插入到空出的位置
    return arr

print(insertion_sort([3, 1, 4, 1, 5]))  # [1, 1, 3, 4, 5]

希尔希尔排序（Shell Sort，不稳定）

思想：直接插入排序的改进。先选取一个增量 gap，把相距 gap 的元素看作一组做插入排序，让数组"基本有序"；然后逐步缩小 gap（常取 gap = n//2 递减到 1），最后做一次间隔为 1 的直接插入。因为元素会跨间隔移动，相等元素可能被交换，因此不稳定。复杂度取决于增量序列，平均约为 O(n^1.3)～O(n^(3/2))。

shell_sort.py
def shell_sort(arr):
    n = len(arr)
    gap = n // 2
    while gap > 0:
        for i in range(gap, n):          # 对每组做插入排序(在同一遍内交错处理)
            key = arr[i]
            j = i
            while j >= gap and arr[j - gap] > key:
                arr[j] = arr[j - gap]
                j -= gap
            arr[j] = key
        gap //= 2                        # 缩小增量
    return arr

print(shell_sort([3, 1, 4, 1, 5, 9, 2, 6]))

选择简单选择排序（Selection Sort，不稳定）

思想：每一轮在未排序部分中选出最小的元素，放到开头。由于是「选出再交换」，交换时会把相等元素的相对次序打乱，故不稳定。无论数据如何，比较次数固定为 n(n-1)/2，所以最坏 / 平均 / 最好都是 O(n²)。

selection_sort.py
def selection_sort(arr):
    n = len(arr)
    for i in range(n - 1):
        m = i
        for j in range(i + 1, n):
            if arr[j] < arr[m]:
                m = j
        arr[i], arr[m] = arr[m], arr[i]   # 交换可能破坏相等元素的次序 -> 不稳定
    return arr

print(selection_sort([64, 25, 12, 22, 11]))
▲

稳定性的反例：对 [5a, 5b, 2] 用选择排序，第一轮选出 2 与 5a 交换，得到 [2, 5b, 5a]——两个 5 的次序被颠倒了，所以选择排序不稳定。

冒泡冒泡排序（Bubble Sort，稳定）

思想：相邻两两比较，逆序就交换，每轮把当前最大（或最小）的元素"冒"到数组一端。因为只在相邻逆序时交换，相等元素不会被越过，所以稳定。若某轮没有任何交换，说明已全局有序，可提前结束——此时最好情况为 O(n)。

bubble_sort.py
def bubble_sort(arr):
    n = len(arr)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):        # 每轮末尾已就位，范围减小
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swapped = True
        if not swapped:                   # 已有序，提前结束
            break
    return arr

print(bubble_sort([5, 1, 4, 2, 8]))
!

易错点：① 插入排序比较时要用 arr[j] > key（严格大于）才稳定，写成 >= 会破坏稳定性。② 选择排序与希尔排序都不稳定，冒泡与直接插入都稳定——别记混。③ 冒泡、插入在「基本有序」时几乎线性（最好 O(n)），选择排序则是"无论多有序都 O(n²)"。

知识点3快速排序与 partitionsort-quick · 分治 O(n log n)

快速排序（Quicksort）由 Hoare 提出，是使用最广的内排序之一。核心思想：每次选取一个基准（pivot），通过一次 partition（划分）把数组分成"小于基准"与"大于基准"两部分，基准归位后，对两部分递归排序。它属于分治（divide and conquer），且划分是在原数组上进行的，因此是原地排序。

  • 平均时间 O(n log n)：理想情况下每次划分接近对半，规模减半，递归深度 log n，每层总比较 O(n)。
  • 最坏时间 O(n²)：当数组已有序 / 逆序且每次都取固定端点（如第一个元素）作基准时，单侧每次只削掉一个元素，递归变成链状，每层比较 O(n)，共 O(n) 层。
  • 不稳定：划分过程中会远距离交换元素，相等元素相对次序可能被破坏。
quick_sort_挖坑法.py
def quick_sort(arr, lo=0, hi=None):
    if hi is None:
        hi = len(arr) - 1
    if lo >= hi:
        return arr
    pivot = arr[lo]        # 挖坑法：先取基准值，arr[lo] 成为"坑"
    i, j = lo, hi
    while i < j:
        while i < j and arr[j] >= pivot:   # 从右往左找小于基准的
            j -= 1
        if i < j:
            arr[i] = arr[j]; i += 1        # 填入左坑
        while i < j and arr[i] <= pivot:   # 从左往右找大于基准的
            i += 1
        if i < j:
            arr[j] = arr[i]; j -= 1        # 填入右坑
    arr[i] = pivot                          # 基准归位
    quick_sort(arr, lo, i - 1)              # 递归排左半
    quick_sort(arr, i + 1, hi)              # 递归排右半
    return arr

print(quick_sort([3, 6, 8, 2, 4, 1, 9, 5]))
quick_sort_左右指针法.py
def partition_2ptr(arr, lo, hi):
    """左右指针法(也叫两路划分)：把 < 基准的放左边，> 基准的放右边"""
    pivot = arr[lo]
    i, j = lo, hi
    while i < j:
        while i < j and arr[j] >= pivot:   # 右指针找小
            j -= 1
        while i < j and arr[i] <= pivot:   # 左指针找大
            i += 1
        if i < j:
            arr[i], arr[j] = arr[j], arr[i]  # 交换大/小元素
    arr[lo], arr[i] = arr[i], arr[lo]        # 基准放到中间
    return i

def quick_sort_2ptr(arr, lo=0, hi=None):
    if hi is None: hi = len(arr) - 1
    if lo >= hi: return arr
    p = partition_2ptr(arr, lo, hi)
    quick_sort_2ptr(arr, lo, p - 1)
    quick_sort_2ptr(arr, p + 1, hi)
    return arr

print(quick_sort_2ptr([5, 3, 8, 4, 2, 7, 1]))
★

如何避免最坏 O(n²)？关键是让划分更均衡：① 随机选取基准（random），使平均意义下不易退化；② 三数取中（median-of-three），取首、中、尾的中位数作基准对有序数据友好；③ 数据规模小时切换到插入排序（减少递归开销）。这几招是面试常问的「快排优化」。

!

易错点：① 内层 while 一定要先判断 i < j 再访问 arr[j]/arr[i]，否则会越界或下标错乱。② partition 的两层循环边界（用 >=/<= 跳过相等值）决定基准归位位置，写错会让相等元素反复交换而不收敛。③ 牢记快排不稳定、最坏 O(n²)。

⌁

面试延伸：partition 是快速排序的灵魂，也是许多题的基础。只递归一侧的「快速选择（quickselect）」用同款划分思路求第 K 大（LeetCode 215），平均复杂度 O(n)。而 Python 内置的 sorted() 在 CPython 中用的是 Timsort（归并 + 插入的混合），稳定且 O(n log n)。

知识点4归并排序sort-merge · 稳定的 O(n log n)

归并排序（Merge Sort）是典型的分治排序：把数组一分为二，递归地对两半排序，再把两个已有序的子数组合并成一个整体。合并两个有序序列的过程（merge）是它的核心，也是很多其他题目的基础。

  • 稳定：合并时若左右两半元素相等，先取左半的那个，相等元素的相对次序得以保留。
  • 复杂度稳定为 O(n log n)：无论输入如何都恒定，缺点是需要 O(n) 辅助空间（用于合并时的临时数组），不是原地排序。
  • 应用：适合需要稳定的场景、链表排序（归并对链表友好，可 O(1) 额外空间）、以及大规模数据的外排序（如数据库中的归并）。
merge_sort.py
def merge(left, right):
    res = []
    i = j = 0
    while i < len(left) and j < len(right):
        # <= 保证稳定：相等时先取 left 的元素
        if left[i] <= right[j]:
            res.append(left[i]); i += 1
        else:
            res.append(right[j]); j += 1
    res.extend(left[i:])   # 剩余部分直接拼接
    res.extend(right[j:])
    return res

def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    L = merge_sort(arr[:mid])   # 左半
    R = merge_sort(arr[mid:])   # 右半
    return merge(L, R)

print(merge_sort([38, 27, 43, 3, 9, 82, 10]))
★

核心结论：归并排序是「能拿稳定性又想保证 O(n log n)」时的首选。它与快排同为分治，但归并先切分后合并且稳定、耗 O(n) 空间；快排先划分后递归、原地、不稳定、最坏 O(n²)。面试常让你对比两者。

!

易错点：① 合并时务必写 left[i] <= right[j]（用 <=），写成 < 会丢稳定性。② 递归终止条件是 len(arr) <= 1，不要少写 = 导致死循环。③ 归并不是原地，额外空间 O(n)——这是它与快排、堆排序的重要区别。

⌁

面试延伸：「合并两个有序数组」是 LeetCode 88；「链表排序」可用归并（LeetCode 148），此时无需额外数组、空间降至 O(log n)（递归栈）。此外，「数组中的逆序对」问题也常借助归并过程统计（LeetCode 315），是归并思想的高级用法。

知识点5堆排序sort-heap · 用堆 O(n log n)

堆排序（Heapsort）借助堆（heap）这种完全二叉树来实现。思想：把数组调整成最大堆（大顶堆）（堆顶是整棵树的最大值），把堆顶与末尾元素交换，最大值就到末尾了；对剩余元素重新"下沉（sift-down）"恢复堆，再取堆顶……如此重复，得到升序序列。它原地排序、整体 O(n log n)，但不稳定。

  • 建堆（build-heap）：从最后一个非叶节点开始自底向上做下沉，复杂度 O(n)（不是 O(n log n)）。
  • 排序：每次取堆顶（最大值）并下沉，共 n 次，每次 O(log n)，故排序阶段 O(n log n)。
  • 不稳定原因：下沉时会把较远的元素往上 / 往下换，相等元素的相对次序可能被破坏。
heap_sort.py
def sift_down(arr, n, i):
    """把以 i 为根的子树调整成最大堆(下沉)"""
    largest = i
    l, r = 2*i+1, 2*i+2          # 左/右孩子下标(0-based)
    if l < n and arr[l] > arr[largest]:
        largest = l
    if r < n and arr[r] > arr[largest]:
        largest = r
    if largest != i:             # 有孩子更大，交换并继续下沉
        arr[i], arr[largest] = arr[largest], arr[i]
        sift_down(arr, n, largest)

def heap_sort(arr):
    n = len(arr)
    for i in range(n//2 - 1, -1, -1):   # 建堆：从最后一个非叶节点开始
        sift_down(arr, n, i)
    for i in range(n - 1, 0, -1):       # 重复：堆顶(最大)换到末尾
        arr[0], arr[i] = arr[i], arr[0]
        sift_down(arr, i, 0)            # 对剩余部分重新调整(注意规模缩小为 i)
    return arr

print(heap_sort([4, 10, 3, 5, 1, 2]))
★

核心结论：堆排序整体稳定在 O(n log n)、原地 O(1)，但不稳定。若只想求前 K 大（或第 K 大），不必完整排序——维护一个大小为 K 的最小堆，遇到比堆顶大的就替换并下沉，整体 O(n log K)，比堆排序 O(n log n) 更快。这就是 LeetCode 215 的经典解法。

⌁

面试延伸：① Top-K 问题（LeetCode 215 / 347）：小顶堆求前 K 大，大顶堆求前 K 小，或直接用快速选择。② 优先队列 / 调度（LeetCode 23 合并 K 个有序链表）也依赖堆。③ 注意下标换算：节点 i 的孩子是 2i+1、2i+2（0-based），写错会导致越界。

知识点6计数 / 基数 / 桶排序（非比较排序）sort-noncompare · 突破 O(n log n)

前面的排序都是基于比较的，比较排序有一个理论下界：Ω(n log n)。而非比较排序（Non-comparison Sort）不靠"两两比较"决定顺序，而是直接利用元素的取值区间、位数或分布，从而在特定条件下做到 O(n + k)。

计数计数排序（Counting Sort，稳定，O(n+k)）

适用于取值范围小的非负整数（如 0~1000 的分数、频次统计）。先统计每个值出现次数，再借助前缀和确定每个元素在有序数组中的位置，并倒序放置以保证稳定性。

counting_sort.py
def counting_sort(arr, k):
    """k 为数据最大值(值域 0..k)"""
    cnt = [0] * (k + 1)
    for v in arr:                # 1. 统计各值出现次数
        cnt[v] += 1
    for i in range(1, k + 1):    # 2. 前缀和：得到每个值在结果中的"最后一个下标+1"
        cnt[i] += cnt[i - 1]
    out = [0] * len(arr)
    for v in reversed(arr):      # 3. 倒序遍历保证稳定
        cnt[v] -= 1
        out[cnt[v]] = v
    return out

print(counting_sort([4, 2, 4, 1, 0, 2, 3, 0], 4))  # [0,0,1,2,2,3,4,4]

基数基数排序（Radix Sort，稳定）

按低位到高位（或高位到低位）逐位对元素排序，每一位都用一次稳定的排序（通常用计数排序）做"分配—收集"。适合定长整数 / 字符串。设最大位数为 d，每位值域为 k，复杂度 O(d·(n+k))。

radix_sort.py
def radix_sort(arr):
    """按十进制位从低位到高位做稳定排序，每次用计数排序思想(这里用桶)"""
    if not arr:
        return arr
    max_val = max(arr)
    exp = 1
    while max_val // exp > 0:
        buckets = [[] for _ in range(10)]
        for v in arr:                       # 1. 按当前位装入桶(分配)
            buckets[(v // exp) % 10].append(v)
        arr = [x for b in buckets for x in b]  # 2. 依次取出(收集)
        exp *= 10
    return arr

print(radix_sort([170, 45, 75, 90, 802, 24, 2, 66]))

桶桶排序（Bucket Sort）

把数据按值域分到若干桶，桶内再用其它排序（如插入 / 归并）排好，最后按桶顺序拼接。适合分布均匀的数据（如均匀浮点数）。桶内排序若为插入排序且数据分布均匀，平均 O(n + k)；若数据极端不均匀（都挤进一个桶）则退化成桶内排序的复杂度（可能 O(n²)）。

bucket_sort.py
def bucket_sort(arr, bucket_count=5):
    if not arr:
        return arr
    lo, hi = min(arr), max(arr)
    n = len(arr)
    buckets = [[] for _ in range(bucket_count)]
    for v in arr:                          # 1. 按值均匀分桶
        idx = int((v - lo) / (hi - lo + 1e-9) * bucket_count)
        buckets[min(idx, bucket_count - 1)].append(v)
    out = []
    for b in buckets:                      # 2. 桶内排序后顺序拼接
        out.extend(sorted(b))
    return out

print(bucket_sort([0.78, 0.17, 0.39, 0.26, 0.72, 0.94, 0.21]))
!

易错点：① 非比较排序的 O(n+k) 是"看起来很快"，但 k 随值域变化——计数排序对 64 位随机整数（k 巨大）会爆炸，此时用比较排序更合适。② 基数排序每一位的子排序必须稳定，否则整体不稳定。③ 计数/基数都需要额外空间（O(k) 或 O(n+k)），不是原地。④ 它们通常只适用于键为整数 / 定长字符串，通用性不如比较排序。

★

何时用非比较排序？当键是"值域受限"的非负整数（如年龄、分数、频次）、或定长数字 / 字符串（如身份证、固定宽度编码），并且能接受 O(k) 或 O(n+k) 额外空间时，用计数 / 基数 / 桶排序可把比较排序的下界 Ω(n log n) 突破到 O(n)。
