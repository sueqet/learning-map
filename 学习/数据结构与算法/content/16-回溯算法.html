MODULE 16 · 数据结构与算法

回溯算法

回溯（Backtracking）就是在解空间树上做深度优先搜索：每一步「选择 → 递归 → 撤销」，系统化地穷举所有可能。它既是笔试/面试的常客（全排列、子集、N 皇后、数独、单词搜索），也是你理解「暴力搜索 + 剪枝」的思维起点。

✓本节学习目标

  • 学完后你能复述回溯法的三步模型「选择 → 递归 → 撤销」，并写出一份通用的回溯模板。
  • 学完后你能独立写出全排列、组合、子集三件套，并对含重复元素的输入做正确去重。
  • 学完后你能看懂并运用剪枝（可行性剪枝 / 剩余数量剪枝 / 上下界剪枝）减少无效搜索。
  • 学完后你能用回溯解决棋盘/网格类问题（N 皇后、数独、单词搜索），并正确处理搜索状态的撤销恢复。
  • 学完后你能说清回溯法与分支限界的区别，知道各自的适用场景。
Pre-requisites · 前置知识

需要掌握一门编程语言（示例以 Python 为主、C++ 为辅）；熟悉递归与深度优先搜索（DFS）、栈/递归调用栈、以及集合与去重的基本用法。若对递归不熟，建议先复习「递归与分治」再回来看本模块。

16回溯算法：在解空间树上做深度优先搜索

知识点回溯的基本思想（选择 → 递归 → 撤销）Backtracking · 核心模型

回溯法（Backtracking）是一种在解空间树 / 状态空间树（solution space tree / state space tree）上做深度优先搜索（DFS）的系统化穷举方法。它把「要做的决定」一步步铺成一棵树：每个节点代表一个部分解（partial solution），每条边代表一个选择（choice）。我们从根出发，深入一条路径直到遇到叶子（完整解）或死胡同（当前部分解已不可能通向合法解），就「回退（backtrack）」到上一层，换一条路继续走，直到穷尽所有分支。

所有回溯问题都能浓缩成三步循环：

  • 选择（choose）：在当前层做出一个候选决定，并把状态推进到下一层。
  • 递归（explore）：带着这个决定，递归进入下一层继续搜。
  • 撤销（un-choose）：从下层回来后，把这次决定造成的一切改动恢复原状，再去尝试下一个候选。
backtrack_template.py
# 通用回溯模板：你自己把"路径/选择列表/结束条件"换成具体问题即可
def backtrack(路径, 选择列表):
    # 结束条件：到达叶子，得到一个完整解
    if 满足结束条件:
        记录(结果, 路径)          # 通常复制一份，避免引用被后续改动污染
        return

    for 选择 in 选择列表:
        if 该选择不合法:          # 剪枝：明确不可能就走这一步能省大量时间
            continue
        做选择                    # 1) 推进状态：标记、加入路径、占用某资源
        backtrack(路径, 选择列表)  # 2) 递归进入下一层
        撤销选择                  # 3) 恢复现场：解除标记、弹出路径、释放资源

# 一句话记忆：先"做选择"深挖，再"撤销选择"换下一个，保证每条分支独立不互相污染。
★

核心要点：回溯的每一步都必须是「可逆的」——做了就要撤销。它是暴力枚举 + 按约束提前剪枝，不是聪明地猜，而是有组织地穷举。

!

易错点（面试高频）：第 3 步忘了「撤销」会导致状态被污染——上一次分支留下的痕迹会泄漏到下一次分支，产生重复或错误结果。凡是你第 1 步动过的全局状态（visited 集合、棋盘格、当前路径、计数值）都要在第 3 步对应的还原。另外，往结果里加路径时要用path[:] 复制一份，否则保存的是同一个列表对象的引用。

时间
O(分支数^深度)
空间
O(深度)
适用
排列/组合/搜索/存在性

知识点全排列 / 组合 / 子集（含去重）LeetCode 46 · 77 · 78 · 90

回溯最经典的入门题就是「排列 / 组合 / 子集」三件套。它们的区别在于「当前层能选的候选范围」和「什么是完整解」：

问题候选范围完整解常用参数代表题
全排列所有没用过的元素用满 n 个used[]LeetCode 46
组合从 start 起的元素刚好 k 个start 下标LeetCode 77
子集从 start 起的元素每个节点都是解start 下标LeetCode 78

要记住一个关键结论：全排列用 used[]（因为顺序相关、每层都要从 0 重新扫），组合/子集用 start 下标（因为组合与顺序无关、避免重复的排列）。「组合」其实是「子集剪掉长度不为 k 的」特例。

perm_comb_subset.py
# ---- 1) 全排列：无重复元素 (LeetCode 46) ----
def permute(nums):
    res, path, used = [], [], [False]*len(nums)
    def dfs():
        if len(path) == len(nums):        # 用满了 n 个，得到完整排列
            res.append(path[:])           # 复制！不能直接 append(path)
            return
        for i in range(len(nums)):        # 每层都从 0 重新扫，顺序相关
            if used[i]: continue          # 已经用过，跳过
            used[i] = True; path.append(nums[i])   # 1. 选择
            dfs()                                 # 2. 递归
            path.pop(); used[i] = False           # 3. 撤销
    dfs(); return res

# ---- 2) 组合：从 n 里选 k (LeetCode 77) ----
def combine(n, k):
    res, path = [], []
    def dfs(start):
        if len(path) == k: res.append(path[:]); return
        for i in range(start, n+1):       # start 保证不回头，避免重复组合
            path.append(i)
            dfs(i+1)                      # 下一层从 i+1 开始
            path.pop()
    dfs(1); return res

# ---- 3) 子集 (LeetCode 78)：每个节点都是解 ----
def subsets(nums):
    res = []
    def dfs(start, path):
        res.append(path[:])               # 进入即记录，节点即答案
        for i in range(start, len(nums)):
            path.append(nums[i])
            dfs(i+1, path)
            path.pop()
    dfs(0, []); return res
!

易错点（含重复元素必须去重）：当输入有重复元素（如 [1,1,2]）时，直接暴力会产生重复解。标准做法是先排序，然后在同一层跳过与上一个相同的元素：if i > start and nums[i]==nums[i-1]: continue（start 下标法）或 if i > 0 and nums[i]==nums[i-1] and not used[i-1]: continue（used[] 法）。核心是「只用同一层第一次出现的那个重复值」。

subsets_with_dup.py
# 子集 II：含重复元素去重 (LeetCode 90)
def subsetsWithDup(nums):
    nums.sort()                       # 关键：先排序，让重复元素相邻
    res = []
    def dfs(start, path):
        res.append(path[:])
        for i in range(start, len(nums)):
            if i > start and nums[i] == nums[i-1]:   # 同层去重
                continue
            path.append(nums[i])
            dfs(i+1, path)
            path.pop()
    dfs(0, []); return res

# used[] 法（用于顺序相关、如全排列 II / 排列 47）：
#   if i > 0 and nums[i]==nums[i-1] and not used[i-1]: continue
# 两种写法都是"同层跳过重复"，只是判定"上一次是否已被撤销"的方式不同。
★

核心要点：「顺序相关 → used[]（每层从头扫）；顺序无关 → start（每层从 i+1 扫）」。去重一律「先排序，再在同层剪掉与前一个相同的元素」。

全排列时间
O(n·n!)
子集时间
O(n·2^n)
空间
O(n)

16.2进阶模型：剪枝优化与棋盘/网格搜索

知识点剪枝优化Pruning · 提前砍掉不可能的分支

回溯本质是穷举，一旦分支多就会爆炸。**剪枝（pruning）**就是在还没深入之前，判断当前分支不可能通向合法解 / 也不可能优于已知最优，于是直接不去递归它，从而砍掉整棵子树。剪枝分为几类：

  • 可行性剪枝（feasibility pruning）：当前状态已经不满足约束，再往下也救不回来。例如 N 皇后当前格会与已有皇后冲突、数独当前格填了冲突数字、括号生成时右括号数已超过左括号数——直接 continue。
  • 剩余数量剪枝：即使把剩下所有能选的全用上，也凑不够目标长度。例如组合 combine(n,k) 中，当 n - start + 1 < k - len(path) 时就无需再搜。
  • 上下界剪枝（bound pruning）：即使当前分支达到最好情况，也比不上已找到的最优解，就砍掉它。这是分支限界法的核心，见下一节。
combine_pruned.py
# 组合 + 剩余数量剪枝 (LeetCode 77)：i 的上界不再搜到 n，直接填上界
def combine(n, k):
    res, path = [], []
    def dfs(start):
        if len(path) == k: res.append(path[:]); return
        # 还要选 need=k-len(path) 个，i 至多取到 n - need + 1，保证够选
        for i in range(start, n - (k - len(path)) + 2):
            path.append(i)
            dfs(i+1)                 # 注意：这里是 i+1，不是 start+1
            path.pop()
    dfs(1); return res

# 这一行 for 上界的写法，就是经典的"剩余数量剪枝"：
#   当从 start 到 n 的元素总数 < 还需要选的个数 时，就提前结束循环。
generate_parentheses.py
# 括号生成：可行性剪枝 (LeetCode 22)
def generateParenthesis(n):
    res = []
    def dfs(path, left, right):
        if len(path) == 2*n: res.append(path); return
        if left < n:                       # 还能放左括号
            dfs(path+"(", left+1, right)
        if right < left:                   # 右括号必须少于左括号，这是合法性约束
            dfs(path+")", left, right+1)
    dfs("", 0, 0); return res
    # 剪枝点：right 一旦 >= left，就不可能合法，直接不再递归。
★

核心要点：剪枝口诀是「先判断、后递归」。把检查放在 for 循环里用 continue 跳过，或直接在 for 的上下界上做文章，能指数级减少搜索量。剪枝越靠前、越早，收益越大。

!

易错点：① 递归参数容易写成 dfs(start+1,…) 而不是 dfs(i+1,…)，导致组合去重失效；② 剪枝条件箭头方向写反（如 right < left 写成 right <= left）会漏掉合法解；③ 剪枝只影响「快慢」，不影响正确性——千万别为了剪枝而误删合法分支。

无剪枝
O(分支^深度)
有剪枝
大幅减少
空间
O(深度)

知识点棋盘与网格类（N 皇后、数独、单词搜索、岛屿）LeetCode 51 · 37 · 79

棋盘/网格类是回溯最好的练兵场：每放一个子/填一个格/走一个格都构成一个「选择」，且必须做状态标记与恢复。N 皇后、数独是「可行性剪枝」的典型；单词搜索、岛屿则是「在邻接格上沿 DFS 深入、探索完复原格子」的典型。

N 皇后（LeetCode 51）：逐行放皇后，保证每一列、两个对角线都不能有冲突。用三个集合（列、副对角线 r-c、主对角线 r+c）做到 O(1) 冲突判断：同一副对角线上 r-c 相等，同一主对角线上 r+c 相等。

solve_n_queens.py
def solveNQueens(n):
    res = []
    cols, diag1, diag2 = set(), set(), set()   # 列 / 副对角线(r-c) / 主对角线(r+c)
    board = [["."]*n for _ in range(n)]
    def dfs(r):
        if r == n:                     # 每行都放好，得到完整解
            res.append(["".join(row) for row in board]); return
        for c in range(n):
            if c in cols or (r-c) in diag1 or (r+c) in diag2:
                continue               # 可行性剪枝：已有皇后冲突，跳过该列
            board[r][c] = "Q"          # 1. 选择
            cols.add(c); diag1.add(r-c); diag2.add(r+c)
            dfs(r+1)                    # 2. 递归下一行
            board[r][c] = "."           # 3. 撤销：恢复格子与三个集合
            cols.discard(c); diag1.discard(r-c); diag2.discard(r+c)
    dfs(0); return res
    # 注：因为每行只放一个皇后，这里用 r+1 逐行即可，不必额外回溯"行"。

16.3思想对比：回溯 vs 分支限界

知识点回溯 vs 分支限界Backtracking vs Branch and Bound

二者都在解空间树上搜索，但方向与目标不同：

维度回溯法（Backtracking）分支限界法（Branch and Bound）
搜索顺序深度优先（DFS），一条路走到头再回头广度优先 / 最佳优先，用队列或优先队列按层/按代价扩展
主要目标求可行解 / 所有解（是否存在、列举）求最优解（最大化/最小化目标）
剪枝依据以可行性剪枝为主（不满足约束就砍）以上/下界剪枝为主（当前分支的界不优于已知最优就砍）
维护结构递归调用栈活结点表（队列 / 优先队列）
代表问题N 皇后、全排列、数独、单词搜索0-1 背包、旅行商（TSP）、货郎担

这里用一个例子说明两者差别——0-1 背包：

  • 回溯法：把「选 / 不选」当成一棵二叉树，先一路搜到底记录可行解，主要靠「当前重量是否超负重」来剪枝（可行性剪枝），输出可能是最优也可能不是。
  • 分支限界法：把物品按单位价值（value/weight）排序，给每个结点算一个上界（bound）——即使把剩余物品全塞进包里也最多值多少。若这个上界低于当前已知最优，就不再扩展该结点（上界剪枝）。优先队列保证总是先扩展最有希望的结点，更快逼近最优解。
★

核心要点：一句话区分——回溯 = 深度优先 + 可行性剪枝（求可行/所有解）；分支限界 = 最佳优先 + 上下界剪枝 + 活结点表（求最优解）。面试常让你「说出区别、各自适用场景」，把这张表背下来即可。

▲

补充：不要把 DFS 与回溯、分支限界划等号。DFS 只是一种遍历/搜索方式；回溯是「带状态恢复 + 可行性剪枝的 DFS」；分支限界则是「带上下界剪枝 + 活结点表」的另一种搜索框架，常用 BFS/优先队列实现。

回溯(可行解)
O(分支^深度)
分支限界(最优)
取决于界质量
空间
回溯 O(深度) / 限界 O(结点数)
