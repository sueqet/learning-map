MODULE 11 · 数据结构与算法

并查集

并查集（Union-Find / Disjoint Set，不相交集合）用一种近乎 O(1) 的方式维护元素分组、回答「两个元素是否同组」，也是 Kruskal 最小生成树与动态连通性问题的核心工具。

✓本节学习目标

  • 学完后你能用一个 parent 数组实现基础的 find / union，并用「根是否相同」正确回答连通性查询。
  • 学完后你能解释路径压缩与按秩/按大小合并各自的作用，并说出二者组合后均摊复杂度约为 O(α(n)) 的原因。
  • 学完后你能实现带权并查集（维护到根的距离 / 相对关系），独立解出「食物链」这类模关系题。
  • 学完后你能用并查集解决连通分量计数、Kruskal 判环、动态连通、岛屿连通等典型应用，并指出易错点。
  • 学完后你能对并查集给出时间 / 空间复杂度，并说明它对后端 / 面试题的取舍与适用边界。
Pre-requisites · 前置知识

会一门编程语言（优先 Python 或 C++），理解「树 / 森林」「图」「哈希表」的基本概念，熟悉函数递归与数组下标操作；最好知道「根节点」与「链式存储」的含义。

11并查集
基本操作与优化：find / union、路径压缩、按秩合并

知识点并查集的基本操作（find / union）基础 · 核心思想

并查集（Union-Find，也叫 Disjoint Set，不相交集合 / 并查不相交集合）是一个专门处理元素分组的数据结构：它维护若干个互不相交的子集，支持两种核心操作——find(x) 确定 x 属于哪个集合（返回该集合的代表元素 / 根节点），以及 union(x, y) 把 x 与 y 所在的两个集合合并成一个。两者配合，就能快速回答「x 和 y 是否连通（同组）」。

  • 存储方式：用一维数组 parent[i] 记录元素 i 的父节点。每个集合用一棵树表示，树的根就是该集合的代表元素（也叫「掌门 / 父」）。初始时每个元素自成一组：parent[i] = i。
  • find(x)：沿 parent 向上走到根。返回 x 所在树的根。
  • union(x, y)：先 find 出 x、y 各自的根。若根相同说明已在同一集合，无需操作（此时再加这条边会成环，判环就靠这一条）；否则把一方的根挂到另一方根下。
  • 判断连通：find(x) == find(y) 即为同组。
union_find_basic.py
class UnionFind:
    def __init__(self, n):
        # parent[i] = i 表示 i 是根（代表元素）；初始每个元素各自成一组
        self.parent = list(range(n))

    def find(self, x):
        # 沿 parent 一路往上找根（此版本还不做路径压缩）
        while self.parent[x] != x:
            x = self.parent[x]
        return x

    def union(self, x, y):
        # 先找到两者的根
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False        # 已在同一集合 / 连通块：加这条边会成环
        self.parent[ry] = rx    # 把 y 的根挂到 x 的根下（下一步再做优化）
        return True             # 发生了合并，-1 连通分量计数

    def is_connected(self, x, y):
        # 判断连通：比较的是"根"，不是直接父节点
        return self.find(x) == self.find(y)

uf = UnionFind(5)
uf.union(0, 1); uf.union(1, 2)       # 0-1-2 合成一组
print(uf.find(2))                     # 根是 0
print(uf.is_connected(0, 2))          # True
print(uf.is_connected(0, 3))          # False（3 自成一组）
操作作用返回
find(x)找 x 所属集合的代表元素（根）根的下标
union(x, y)把 x、y 所在两个集合合并是否发生了合并（bool）
is_connected(x, y)是否同组find(x)==find(y)
parent[i]元素 i 的父节点parent[root]==root
★

核心要点：「两个元素是否连通」永远看 find(x) == find(y)（比根），而不是比直接父节点。find 返回的是根。把 union 写成返回 bool，能顺便用于判环与连通分量计数。

!

易错点：① 初值必须是 parent[i] = i，否则根无法自指、find 会死循环或越界；② 下标从 0 还是 1 开始要统一，很多题目（如「食物链」、LeetCode 冗余连接）用 1..n 编号，可开 n+1 或整体平移；③ 不压缩时 find 会沿父链逐级上溯，一条长链会导致 find 变慢（见下个知识点）。

知识点路径压缩与按秩/按大小合并优化 · 摊还分析

朴素并查集在极端情况下（如按 0-1-2-3-… 顺序不断合并）会形成一条长链，此时 find 要一步步爬到根，最坏 O(n)。为此引入两种经典优化，两者结合后单次操作的摊还（均摊）复杂度降到 O(α(n)) 的常数级。

  • 路径压缩（Path Compression）：在 find 的过程中，把沿途访问过的每个节点直接指向根，让树被「拍扁」。之后同一路径上的 find 几乎一步到根。
  • 按秩合并（Union by Rank） / 按大小合并(Union by Size)：合并时让较矮 / 较小的树挂到较高 / 较大的树下，避免树不断变高。秩（rank）是树的近似高度；大小（size）是子树节点数。
union_find_optimized.py
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n            # rank[i]: 树的近似高度（只做合并维护，不随 find 改）

    def find(self, x):
        # 路径压缩（递归版）：把沿途节点直接指向根
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def find_iter(self, x):
        # 路径压缩（迭代版）：两趟遍历同样能拍扁路径
        r = x
        while self.parent[r] != r:
            r = self.parent[r]
        while self.parent[x] != x:
            nxt = self.parent[x]
            self.parent[x] = r
            x = nxt
        return r

    def union(self, x, y):
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False                 # 已连通：这条边会成环
        # 按秩合并：秩小的挂到秩大的下面
        if self.rank[rx] < self.rank[ry]:
            rx, ry = ry, rx
        self.parent[ry] = rx
        if self.rank[rx] == self.rank[ry]:
            self.rank[rx] += 1           # 两棵等秩树合并，秩才 +1
        return True

为什么能到 O(α(n))？路径压缩让树高度增长很慢，按秩合并又给树高加上「指数级」的硬上界；两者共同作用，使得单独一次操作的最坏代价被反复「摊销」到一个极小的常数。这里的 α 是阿克曼（Ackermann）函数的反函数，增长极慢——对任何现实规模的 n，α(n) 都 ≤ 4～5，因此工程上就把它当作 O(1) 使用。

策略find 摊还union 摊还特点
朴素（不优化）O(n)O(n)会退化成链，不可取
只做路径压缩O(α(n))O(α(n))实践基本够用
路径压缩 + 按秩合并O(α(n))O(α(n))理论最优（实际最常用）
按大小(Union by Size)替代O(α(n))O(α(n))更直观，便于数连通块大小
★

核心要点：只做路径压缩（不按秩）在实践中通常可接受；但要做到理论上限 O(α(n))，需同时用路径压缩 + 按秩/按大小合并。这是面试的「标准答案」式组合。

⚠

易错点：路径压缩后秩（rank）不再是真实高度，它只是「上界 / 近似高度」，所以 rank 只在 union 时维护、绝不能随 find 更新。若改用「按大小」，则严格维护子树节点数，在需要统计连通块大小时更好用。另外 judge 时注意：find 常在 union 内部被调用，务必先压缩再合并，避免把旧的中间父节点当作根。

时间
摊还 O(α(n))
空间
O(n)
适用
近常数连通查询

12带权并查集与应用
维护相对关系、连通分量、Kruskal、动态连通、判环

知识点带权并查集（维护相对关系/到根距离）进阶 · 食物链

把并查集从「只维护分组」升级为「带权」：除了 parent[x]，再记录 w[x]——x 到其父节点的关系 / 距离。这样不仅能合并集合，还能推断任意两个元素之间的相对关系。这类题最典型的是《食物链》（POJ 1182 / 洛谷 P2024），以及「奇偶带权」「区间和」等，本质都是在路径压缩与合并时同步累积权值。

  • 关系编码（模 3）：设 d[x] ∈ {0,1,2} 表示 x 相对父节点的关系：0（同父/同类）、1（吃父）、2（被父吃）。
  • find 时累积：路径压缩时把 x 对父、父对根的两段关系相加取模，得到 x 对根的关系。
  • 判断任意两元素关系：(d[x] - d[y] + 3) % 3 就是 x 相对 y 的关系。
  • 合并时列等式：由已知的 w[x]、w[y] 和「x 相对 y = 给定值 d」解出新根的关系。
weighted_uf.py
class WeightedUF:
    def __init__(self, n):
        self.parent = list(range(n))
        # w[i]: i 到父节点的关系，取模 3。0=同类 1=吃父 2=被父吃
        self.w = [0] * n

    def find(self, x):
        # 路径压缩 + 关系累积：压缩后再找会一步到根
        if self.parent[x] != x:
            p = self.parent[x]
            root = self.find(p)              # 先压缩父节点
            self.w[x] = (self.w[x] + self.w[p]) % 3   # 累积到根的关系
            self.parent[x] = root            # 指向根
        return self.parent[x]

    def union(self, x, y, d):
        # 记录一条陈述："x 相对 y 的关系 = d"
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            # 已在同一集合，校验是否与已有关系矛盾
            return (self.w[x] - self.w[y]) % 3 == d
        # 合并：把 rx 挂到 ry 下，并算出 rx 相对 ry 的新关系
        self.parent[rx] = ry
        self.w[rx] = (d + self.w[y] - self.w[x]) % 3
        return True
★

核心要点：带权并查集的精髓是「在 find 的路径压缩里同步累积、在 union 里列等式解新根关系」。常见取模：食物链模 3，奇偶带权模 2，区间和/距离则是普通累加（取差值）。判断矛盾 = 相等与不等两类陈述冲突。

!

易错点（合并新根的推导）：想清楚再写，绕晕就画图。以根 ry 为基准：x 到 ry 的总关系 = w[x]（x 到 rx）+ w[rx]（rx 到 ry）；它又应等于给定的 d（x 相对 y）再 + w[y]（y 到 ry）。所以 w[rx] = d + w[y] - w[x]（取模）。别写成 d + w[x] - w[y]，方向反了整题就错。编号若是 1..n，记得平移或用 n+1 大小。

时间
摊还 O(α(n))
空间
O(n)
适用
相对关系/矛盾判定

知识点并查集的应用应用 · 面试高频

并查集在算法题里几乎总是「配角」，但往往决定复杂度。四个最经典的场景：联通分量计数（每成功 union 一次就减一）、Kruskal 最小生成树的判环、动态连通性（边不断加入，实时查询是否连通）、无向图判环。

  • 连通分量计数：初始计数 = 元素个数，每次 union 返回 True 就减一，最终计数 = 连通分量数（LeetCode 547 省份数量、323 无向图中连通分量数目）。
  • Kruskal 判环：边按权重升序排序，依序 union；若两端已在同一连通块（find 相同）则跳过，否则合并并入生成树，直到选出 n-1 条边。并查集让「判环」近乎 O(1)。
  • 动态连通性：在线地加入边并查询连通（LeetCode 684 冗余连接、990 等式方程的可满足性）。
  • 判环：无向图中，若某条边的两端 find 相同，则该边与已有路径成环。
uf_application.py
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
        self.cnt = n              # 连通分量数
    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]
    def union(self, x, y):
        rx, ry = self.find(x), self.find(y)
        if rx == ry: return False
        if self.rank[rx] < self.rank[ry]: rx, ry = ry, rx
        self.parent[ry] = rx
        if self.rank[rx] == self.rank[ry]: self.rank[rx] += 1
        self.cnt -= 1             # 合并一次，连通分量减一
        return True

# --- Kruskal 最小生成树（求最小权重和） ---
def kruskal(n, edges):          # edges: [(w, u, v)]
    uf = UnionFind(n)
    total = 0; mst = []
    for w, u, v in sorted(edges):   # 先按权重升序
        if uf.union(u, v):          # 两端不在同一连通块，才并入
            total += w; mst.append((u, v))
            if len(mst) == n - 1:   # 生成树已含 n-1 条边
                break
    return total, mst

# --- 冗余连接（LeetCode 684） ---
def find_redundant(n, edges):
    uf = UnionFind(n + 1)          # 编号从 1 开始
    for u, v in edges:
        if not uf.union(u, v):     # 已连通却要加边 = 成环的冗余边
            return [u, v]

岛屿判连通（LeetCode 200）：把每个陆地格子看成节点，用并查集把上下左右的相邻陆地合并；或更常见地把「二维坐标」线性化为 i * col + j 再并查集。相较 BFS / DFS，并查集在边动态加入、需要持续查询连通的场景更有优势，而 BFS/DFS 更简单直观。

应用并查集扮演的角色关键判断典型题
连通分量计数维护分组并计数union 返回 True 时计数 -1LeetCode 547、323
Kruskal 最小生成树判环 + 连通两端 find 相同则跳过排序后贪心
动态连通性在线查询连通find 是否相同LeetCode 684
相对关系 / 矛盾带权并查集取模差值判断矛盾POJ 1182 食物链
★

核心要点：并查集做 Kruskal 的复杂度瓶颈在排序 O(E log E)，并查集本身只是 O(E·α(V)) 的辅助。凡是「边/点不断加入、随时问是否同组」的题，先想到并查集。

⚠

易错点：① 判环是针对无向图，有向图判环要用拓扑排序 / DFS 染色；② 二维网格线性化时坐标换算要正确（id = r * cols + c），别把行列写反；③ Kruskal 中「跳过已连通边」不是「跳过已选边」，二者别混淆；④ 连通分量计数别忘了在 union 更新 cnt，且 init 里 cnt = 节点数。
