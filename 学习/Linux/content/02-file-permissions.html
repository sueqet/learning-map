LINUX · 文件

文件与权限

看懂 ls -l 的权限字符串，会用 chmod / chown / chgrp 决定谁能读、写、执行——这是 Linux 多用户系统的安全基石。

✓本节学习目标

  • 学完后，你能逐列读懂 ls -l 输出，并拆解 10 位权限字符串（类型 + user/group/other）。
  • 学完后，你能说清 r / w / x 对「普通文件」与「目录」在行为上的不同。
  • 学完后，你能用数字法和符号法两种方式 chmod 修改权限。
  • 学完后，你能用 chown/chgrp 修改文件所有者与所属组，并知道何时需要 root。
  • 学完后，你能解释 SUID / SGID / sticky 三位特殊权限的作用与用法（含 /tmp、/usr/bin/passwd）。
  • 学完后，你能用 umask 推断新建文件与目录的默认权限。
Prerequisites · 前置知识

你已经会用终端做基本导航与文件查看（见「命令行基础与文件导航」）；本讲假设你大致理解「用户」「组」，并知道文件由 所有者、所属组、其他人 三类主体访问。

Learning Content · 学习内容

01文件权限：谁能读、写、执行

01解构 ls -l 输出权限字符串与各列

执行 ls -l 看到的是长格式列表，一行就是一个文件/目录的元信息。看懂它，是所有权限操作的第一步。

shell
ls -l
# 输出示例：每个部分用 | 分隔示意
-rw-r--r-- 1 alice dev 4096 Jun 12 10:30 report.txt
# ^^^^^^^^^^ ^   ^^^^^ ^^^  ^^^^ ^^^^^^^^^^^^^ ^^^^^^^^^
# ①权限字符串 ②硬链接 ③所有者 ④组 ⑤大小 ⑥修改时间 ⑦文件名
  • ① 权限字符串（10 位）：第 1 位是文件类型，后 9 位是 user/group/other 三组 rwx。
  • ② 硬链接计数：指向该文件的目录项数量（普通文件通常为 1，目录至少为 2）。
  • ③ 所有者（user）、④ 所属组（group）：决定权限的归属主体。
  • ⑤ 大小（字节）、⑥ 修改时间、⑦ 文件名。
首字符类型说明
-普通文件最常见，文本/二进制数据
d目录directory
l符号链接指向另一路径
c / b字符 / 块设备如 /dev/null、磁盘
p / s命名管道 / 套接字进程间通信
★

核心：后面 9 位永远按 rwx rwx rwx 三段读，对应 所有者(user) · 所属组(group) · 其他(other)，顺序固定。

02rwx 对「文件」与「目录」的含义一字之差，行为不同

同一个 r / w / x，作用在普通文件和目录上含义不同，这是初学者最容易踩坑的地方。

权限对普通文件对目录
r读取文件内容列出目录里有哪些条目（ls 能看名字）
w修改/清空文件内容在目录内创建、删除、重命名文件（增删目录项）
x把文件当作程序执行进入目录（cd）并访问其中文件
  • 对目录：x（又称 traverse）决定能否 cd 进去并访问里面的文件；r 只能列名字，w 只决定增删条目。
  • 要删除或重命名某文件，看的是它所在目录的写w与执行x权限，而不是该文件自己的权限。
  • 要访问目录内文件（读取/修改其内容），通常需要目录有 x；若只有 r 无 x，能列出名字却 stat/访问失败。
!

易错点：「删不掉文件」时，请先检查父目录的 rwx，而不是盯着文件本身的权限。文件能否被删除由所在目录是否可写决定。

i

典型签名：目录权限常见 rwxr-xr-x(755)——自己有全部权限，别的用户/组只可读、可进入；/tmp 为 rwxrwxrwt——谁都能读写，但带 sticky 位（见下文）。

03修改权限：chmod 数字法与符号法两种改法

权限的本质是 r=4, w=2, x=1 三个数的加和，三组各凑成一个 0~7 的数字，三位连写就是八进制权限。

数字对应含义常用例子
74+2+1rwx755 = rwxr-xr-x（程序/目录）
64+2rw-644 = rw-r--r--（普通文件）
54+1r-x可读可进入，不可写
0—---无任何权限
shell · 数字法
chmod 755 script.sh   # rwxr-xr-x
chmod 644 report.txt  # rw-r--r--
chmod 700 ~/.ssh      # 只有自己能读写进入（私钥目录标准）

符号法用 主体（u=用户, g=组, o=其他, a=全部）+ 操作（+加, -去, =直接设定）+ 权限（rwx 等）。

shell · 符号法
chmod u+x script.sh      # 给所有者加执行
chmod go-w file          # 去掉组和其他的写
chmod a+r file           # 所有人可读
chmod u=rw,go=r file     # user=r+w，group/other=r
chmod -R g+w dir/        # 递归给目录内所有条目加组写
★

记忆：「数字法」适合整段设置（一次给三组赋值，不易出错）；「符号法」适合相对微调（只改某一位）。

04所有者与所属组：chown / chgrp / id

先搞清楚我是谁、我属于哪些组，再谈修改归属。

shell
whoami            # 当前用户名
id                # uid / gid / 所属组列表
id alice          # 查看 alice 的 uid/gid/groups
groups            # 当前用户所在的所有组
chgrp dev file    # 只改所属组为 dev
chown bob file    # 只改所有者为 bob
chown bob:dev file  # 一条命令：所有者 bob、组 dev（最常用）
chown -R bob:dev dir/  # 递归改整个目录树
  • chown 通常需要 root 权限；普通用户只能把文件chgrp 到自己所属的组。
  • chown 用户:组 文件 这种「用户:组」写法，比分开改更原子、更不易错。
  • 安全习惯：不要把敏感文件所有者轻易改成他人；生产环境通常由 root 或专用账户持有服务目录。
i

新旧语法：老写法 chown bob.dev file（点号）可用，但为区分主机名/组名，现代更推荐 chown bob:dev file（冒号）。

05特殊权限：SUID / SGID / Sticky第四个八进制位

除了 rwx，还有三个特殊权限位，用一个额外的前导数字表示：4=SUID、2=SGID、1=sticky。

特殊位数字作用常见例子
SUID（setuid）4xxx执行该程序时，以文件所有者身份运行/usr/bin/passwd
SGID（setgid）2xxx文件上：以所属组身份运行；目录上：新文件自动继承目录的组/usr/bin/wall、共享目录
Sticky（粘滞）1xxx目录内文件只能由其所有者（或 root）删除，他人不能删/tmp（1777）

在 ls -l 中，特殊位显示在对应的执行位上：SUID 看 user 的 x，SGID 看 group 的 x，Sticky 看 other 的 x。

执行位显示含义
s / S设了 SUID（owner 段）或 SGID（group 段）。小写 s=对应 x 也存在；大写 S=设了位但没有x
t / T设了 sticky（other 段）。小写 t=有 x；大写 T=设了位但没有 x
shell
ls -l /usr/bin/passwd        # rwsr-xr-x  → 第4位有 s = SUID
chmod 4755 prog               # 设 SUID + rwxr-xr-x
chmod 2755 dir                # 文件 SGID；对目录则让新文件继承组
chmod 1777 /tmp               # sticky + rwxrwxrwx（/tmp 标准值）
chmod u+s file / chmod g-s file   # 符号法加/去 SUID SGID
chmod +t dir                  # 给目录加 sticky
!

安全风险：给可执行文件加 SUID＝让它以所有者（往往是 root）身份跑。若程序有漏洞，很可能被利用来提权。除非确有必要，不要随便给程序设 SUID/SGID。

★

典型记忆：passwd 之所以能改 /etc/shadow（root 才能写），正是因为它带 SUID，普通用户执行时以 root 身份运行。/tmp 带 sticky，所以大家都能建临时文件，却删不掉别人的。

06默认权限：umask新文件/目录的出生权限

新建文件或目录时不手动 chmod 也会有一个默认权限，它由 基准值 减去 umask 决定：普通文件基准 666，目录基准 777。

shell
umask          # 查看当前（常见输出 0022）
umask 022      # 设置遮蔽值
touch a.txt    # 默认文件 → 666-022 = 644 (rw-r--r--)
mkdir dir      # 默认目录 → 777-022 = 755 (rwxr-xr-x)
umask新建文件新建目录适用场景
022644755最常见：本类可读可执行，他人只读
002664775同组协作：组内可读写
027640750更严格：组内只读，他人无权限
★

为什么文件基准是 666 而目录是 777？因为普通文件默认不带执行位 x（大多数数据文件不该被执行），而目录必须带 x 才能进入。所以是「文件 - x，目录 - x」两条路径的差。

07梳理：一次访问如何判定从上到下匹配

进程访问文件时，内核按“所有者 → 所属组 → 其他”的顺序，对命中那一段的 rwx 做判断，命中即停，只看一次。

flowchart TD A[进程请求访问文件] --> B{我是文件所有者?} B -- 是 --> C[用 owner 的 rwx 判断] B -- 否 --> D{我在文件的所属组?} D -- 是 --> E[用 group 的 rwx 判断] D -- 否 --> F[用 other 的 rwx 判断] C --> G{命中的权限含所需操作?} E --> G F --> G G -- 有 --> H[✅ 允许访问] G -- 无 --> I[❌ Permission denied]
i

易错点：匹配到一段就不再往下看。例如你是所有者，owner 位没有 x，即使 group 位有 x 也不能执行——permission denied。这不是「取各方并集」。
