LINUX · 网络

防火墙与 iptables

给服务器「把关」——决定哪些流量能进、哪些不能。理解 netfilter 框架里的表、链、target，才能真正看懂 iptables 与 firewalld 在做什么，而不是死记命令。

✓本节学习目标

  • 学完后，你能区分「用户空间的 iptables 工具」与「内核的 netfilter 框架」，并说出规则实际在哪个层面生效。
  • 学完后，你能说出一张 iptables 规则的组织层次是表 → 链 → 规则，并列出 4 张表各自的职责。
  • 学完后，你能列出 5 条钩子链（PREROUTING/INPUT/FORWARD/OUTPUT/POSTROUTING）及各自的触发时机。
  • 学完后，你能解释规则从上到下匹配、各种 target（ACCEPT/DROP/REJECT/DNAT/SNAT/MASQUERADE/LOG）的行为，以及「遍历完未命中后执行默认策略」。
  • 学完后，你能画出数据包从网卡进入到离开的完整路径，并指出 DNAT 与 SNAT/MASQUERADE 分别在哪个链生效。
  • 学完后，你能说出 iptables 与 firewalld 的关系，并用 firewall-cmd 查看/设置 zone 与放行服务。
Prerequisites · 前置知识

会用终端执行简单命令；已经了解第 16 节「网络配置与包处理流程」中网卡收/发包会经过 netfilter 的拦截点，并对 IP 地址、端口有基本认识即可。

Learning Content · 学习内容

01内核 netfilter：规则真正生效的地方

01什么是 iptables：用户空间工具 + 内核 netfilter

一条 iptables 规则不会「自己」干活。你可以把 iptables 看成用户空间里敲命令的前台工具，它把规则写到内核的 netfilter 框架里；真正执行规则的是内核。每个网络包经过内核时，netfilter 会在固定的 hook 点（也就是下面的「链」）按顺序检查规则，决定放行、丢弃还是改写。

  • 用户空间：iptables 命令、规则文件，方便人操作，但它本身不拦包。
  • 内核空间：netfilter 框架按 hook 点检查每一个包，规则在这里真正生效。
  • 两者协同：工具负责「写规则」，内核负责「执行规则」。
shell
# 查看默认 filter 表里所有链的规则
iptables -L

# 查看 NAT 表（-t 用于选择表）
iptables -t nat -L

# 以「可再执行的语句」方式列出规则（等价于 iptables-save 的输入）
iptables -S

# 追加一条规则：允许源地址 10.0.0.5 的流量进入本机
iptables -A INPUT -s 10.0.0.5 -j ACCEPT
★

核心要点：iptables 是工具，netfilter 是框架；规则写进内核并由 netfilter 执行。firewalld、ufw 也只是基于这套机制的上层封装。

02规则的组织方式：四张表（Table）

iptables 把规则按功能分到 4 张表里，每张表管一类事情。运行规则时用 -t 先选表，再在表内找链；不写 -t 时默认操作 filter 表。

表职责常用链
filter过滤包，决定放行还是拒绝（默认表）INPUT / FORWARD / OUTPUT
nat地址转换，修改源/目标 IP 和端口PREROUTING / OUTPUT / POSTROUTING
mangle修改包头字段（TTL、TOS 等），用于 QoS全部 5 条链
raw在连接跟踪之前处理，用于跳过连接跟踪PREROUTING / OUTPUT
shell
# 不写 -t 时默认操作 filter 表
iptables -L filter

# 显式指定 nat 表，看地址转换规则（-n 不反解域名，-v 显示计数）
iptables -t nat -L -n -v

# 在 filter 表 INPUT 链放行目标端口 80 的 TCP（HTTP）
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
⚠

常见误区：filter 表只做「过滤」，不做地址变换。把 DNAT/SNAT/MASQUERADE 写进 filter 表不会生效——它们是 nat 表的事。选错表是 iptables 初学最常见的错误之一。

03规则挂载点：五条链（Chain）

链是 netfilter 的 5 个 hook 点，也就是包经过内核时「可以检查」的固定位置。每条链上挂着一组有序的规则。

链触发时机
PREROUTING包刚进入网卡，尚未做路由决定之前
INPUT包的目标是本机，交给本机进程之前
FORWARD包需要转发到其它主机
OUTPUT本机进程发出的包
POSTROUTING包即将离开网卡，路由决定之后
shell
# 只查看 INPUT 链的规则
iptables -L INPUT

# 在 INPUT 链末尾追加：放行目标端口 22 的 TCP（SSH）
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# 在 INPUT 链的第 1 条插入：拒绝来自 10.1.1.99 的包
iptables -I INPUT 1 -s 10.1.1.99 -j DROP

# 精确删除上面那条（-D 时给出与添加时一致的条件）
iptables -D INPUT -s 10.1.1.99 -j DROP
★

一句话记链：接收看 INPUT，转发看 FORWARD，本机发出看 OUTPUT；路由决定之前是 PREROUTING，路由决定之后是 POSTROUTING。

04规则怎么跑：匹配、Target 与默认策略

包进入某条链后，从上到下依次匹配规则：命中第一条匹配的规则，就执行那条规则的 target 并停止——除非用 LOG 这类「只记日志、继续匹配」的 target。如果遍历完所有规则都没命中，就执行该链的默认策略（ACCEPT 或 DROP）。

Target行为
ACCEPT放行
DROP丢弃，不响应，发送方等超时
REJECT拒绝并返回错误消息，发送方立即知道被拒
DNAT修改目标地址（目标 NAT，常做端口映射）
SNAT修改源地址（源 NAT）
MASQUERADE动态 SNAT，自动用出口网卡 IP 替换源 IP
LOG记录日志，然后继续匹配后续规则
shell
# 设置默认策略：先放行必要流量，再改成 DROP
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# REJECT 与 DROP 的差别
iptables -A INPUT -p tcp --dport 8080 -j REJECT
iptables -A INPUT -p icmp -j DROP

# 只记日志、不拦截，继续走后面的规则
iptables -A INPUT -p tcp --dport 80 -j LOG --log-prefix "WEB "
!

重要：把 INPUT 默认策略设为 DROP 前，务必先放行 SSH（--dport 22）、回环接口（-i lo）等必要流量，否则很容易把自己锁在服务器外。对远程服务器操作防火墙时尤其要小心。

05数据包完整流转路径

把前面的表、链、target 串起来，就得到数据包在内核里的完整旅程。重点记住两件事：DNAT 在 PREROUTING（路由决定前就改目标地址），SNAT/MASQUERADE 在 POSTROUTING（路由决定后、离开网卡前改源地址）。

flowchart TB A[网卡收包] --> B[PREROUTING
nat表：DNAT在此修改目标地址] B --> C{目标是本机还是转发?} C -->|本机| D[INPUT
filter表：决定是否放行给进程] D --> E[进程] C -->|转发| F[FORWARD
filter表：决定是否允许转发] F --> G[POSTROUTING
nat表：SNAT/MASQUERADE在此修改源地址] H[进程发包] --> I[OUTPUT
filter/nat表] I --> G G --> J[网卡发出]
shell
# 目标 NAT：把外网访问本机 8080 的流量映射到内网主机 192.168.1.10 的 80 端口
iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.10:80

# 源 NAT：让内网主机以本机（出口网卡）IP 访问外网
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -j MASQUERADE
★

三条典型路径：发给本机的包走 PREROUTING → INPUT → 进程；需要转发的包走 PREROUTING → FORWARD → POSTROUTING → 发出；本机发出的包走 OUTPUT → POSTROUTING → 发出。所有路由决定都发生在 PREROUTING 之后、POSTROUTING 之前。

06iptables 与 firewalld：关系与 Zone

两者都只是管理内核 netfilter 规则的工具，操作的是同一套机制。iptables 偏底层、用命令逐条直改；firewalld 是动态防火墙管理器，底层仍调用 iptables/nftables，用 zone 概念封装，支持动态修改、无需重启，规则用 --permanent 自动持久化。CentOS/RHEL 7+ 默认用 firewalld，Ubuntu 默认用 ufw（底层也是 iptables）。

iptablesfirewalld
定位底层工具，直接操作 netfilter 规则动态防火墙管理器，底层仍调用 iptables/nftables
配置方式命令行逐条添加规则zone 概念，支持动态修改，无需重启
规则持久化需手动保存（如 iptables-save）自动持久化（--permanent）
适用场景精细控制、脚本管理日常服务器管理

Zone是一组预定义的规则集，按网络接口所处的信任级别来分配。

Zone信任级别说明
drop最低丢弃所有入站包，不响应
block很低拒绝所有入站包，返回拒绝消息
public低公共网络，仅允许指定服务（默认）
external中外部网络，启用 NAT 伪装
internal较高内部网络，比 public 宽松
trusted最高允许所有连接
shell
# 查看当前默认 zone 的所有规则
firewall-cmd --list-all

# 查看默认 zone（通常为 public）
firewall-cmd --get-default-zone

# 放行 http 服务与 8080 端口，永久生效，然后重载落地
firewall-cmd --add-service=http --permanent
firewall-cmd --add-port=8080/tcp --permanent
firewall-cmd --reload
⚠

发行版差异：CentOS/RHEL 7+ 默认用 firewalld，Ubuntu 默认用 ufw。同一台机器上同时用 iptables 与 firewalld 容易乱；日常管理只用一个。
