LINUX · Shell

命令行基础与文件导航

这是 Linux 的第一课：学会在终端里输入命令、看懂它在哪一层帮你干活，并用 ls/cd 自由移动、用 cat/less 读取文件、用通配符与管道把它们组合起来。所有后续知识（权限、脚本、系统管理）都建立在你对「命令 → 文件 → 输出」这条链路的手感上。

✓本节学习目标

  • 学完后，你能说出终端 / Shell / 命令行三者是什么关系，并打开一个 Shell 会话验证当前用的解释器。
  • 学完后，你能用 pwd / ls / cd 在目录之间自由移动，并区分绝对路径与相对路径，看懂 .、..、~ 的意义。
  • 学完后，你能用 cat / less / head / tail 读取文件内容，并在 less 里翻页、搜索、退出。
  • 学完后，你能用通配符 * ? [] 与 Tab 自动补全批量匹配文件名或路径，并说出它会带来哪些误删风险。
  • 学完后，你能用 touch / mkdir / cp / mv / rm 创建、复制、移动和删除文件与目录。
  • 学完后，你能用 man 查询命令帮助，并用管道 | 把命令串起来（例如 ls | grep）。
Prerequisites · 前置知识

你能在图形界面里打开一个「终端 / Terminal」应用；知道「文件」「文件夹/目录」「路径」这些日常概念。不需要任何编程基础——这一节会从「我在哪、我面前有什么」讲起。

Learning Content · 学习内容

01命令行基础与文件导航

小节终端、Shell 与命令行01 · 概念

很多新手把「终端」「Shell」「命令行」混着叫，但它们其实是三件不同的事：终端是那个黑色的窗口（输入/输出界面），Shell 是真正接收并执行你命令的解释器程序，而命令行就是你在终端里敲进去的那一行文本。你在终端里输入的每一行，都会被 Shell 解析、找到对应程序、然后执行，并把结果显示回终端。

flowchart LR User((你在终端输入)) --> Parse{Shell 解析命令} Parse --> Lookup{在 PATH 里找命令?} Lookup -->|找不到| NF[command not found] Lookup -->|找到| Exec[fork + exec 执行] Exec --> Out(结果 → stdout
错误 → stderr)

要确认当前用的是哪个 shell，以及它默认登录 shell，下面的命令很有用：

shell
echo $0          # 当前 shell 进程名，常输出 -bash / bash / /bin/zsh 等
echo $SHELL      # 默认登录 shell 的完整路径，如 /bin/bash

# 查看当前用户是谁、在哪个目录
whoami           # 当前用户名
pwd              # 当前工作目录（present working directory）
★

核心要点：无论你给它起什么名字，你敲命令的这条链路是「终端窗口 → Shell 解释 → 执行程序 → 输出结果」。搞清楚你面前是哪个 shell（bash / zsh / sh），后面讲变量、脚本的语法差异才有依据。

小节用 pwd / ls / cd 导航02 · 位置

在文件系统里，「我在哪」由 pwd 回答，「眼前有什么」由 ls 回答，「去哪」由 cd 回答。三者是文件导航的最小三件套。

shell
pwd                 # 打印当前目录，如 /home/alice
ls                  # 列出当前目录内容
ls -l               # 长格式：权限、链接数、属主属组、大小、时间、文件名
ls -a               # 包含隐藏文件（以 . 开头，如 .bashrc）
ls -la              # 组合：-l 长格式 + -a 隐藏文件
ls -lh              # -h：人类可读大小（配合 -l 更好用）

cd                  # 无参数：直接回到家目录（同 cd ~）
cd ~                # 显式回到家目录
cd ..               # 进入上一级（父目录）
cd .                # 仍然留在当前目录（几乎无意义，但 `.` 是当前目录）
cd -                # 回到上次所在目录（可用它快速往返两个目录）

路径分两种：绝对路径以 / 开头，从根目录写起，任何时刻都指向同一个位置；相对路径不以 / 开头，从当前目录出发，换个目录就变了。三个缩写必须记住：

记号含义示例
.当前目录cd ./docs
..上级（父）目录cd ../.. 上溯两级
~家目录（当前用户的 home）ls ~/Documents
/文件系统根目录cd /etc
flowchart TD Root[/ / 根目录/] --> Home[~ 家目录] Home --> Cur[当前目录 .] Cur --> Par[父目录 ..] Par --> Home2[… 再往上] Cur --> C1[子目录 A] Cur --> C2[子目录 B]
★

核心要点：绝对路径从 / 开始且结果唯一；相对路径从当前目录开始、结果随位置变化。遇到「找不到文件」，先 pwd 看清自己在哪，再决定用绝对还是相对路径。

!

易错：cd . 什么都不做；cd - 回到的是上一个目录，不是家目录——只有 cd（无参数）或 cd ~ 才回家。

小节查看文件内容：cat / less / head / tail03 · 读文件

读文件有四种常见工具，关键区别在是否适合大文件、能否翻页搜索。直接把整文件一股脑倒出来的 cat，对短文件最方便；一旦文件很长，就该用 less。

命令用途/特点典型用法
cat一次性输出整个文件；适合短文件、或拼接/重定向cat a.txt · cat -n a.txt（按行号）
less分页查看、可上下滚动、可搜索；大文件首选less /var/log/messages
head只看文件开头，默认前 10 行head -n 5 a.txt
tail只看文件结尾，默认后 10 行；-f 可实时跟随tail -n 5 a.txt · tail -f app.log

less 打开后是交互界面，记住这几个按键就够用了：

less
空格        向下翻一页
g / G       跳到文件开头 / 结尾
/pattern    向下搜索（n 跳到下一个匹配，N 上一个）
q           退出 less
★

核心要点：cat 适合短文件、「把内容喂给下一步」，less 适合人肉翻页读大文件。tail -f 是看日志的招牌技能，能实时看到新追加的行。

小节通配符与 Tab 自动补全04 · 批量匹配

文件多了以后不想一个个打名字，就用通配符（globbing）让 Shell 帮你批量选出文件名。注意：这是 Shell 在把命令交给程序之前就完成的展开，不是某个命令自己支持的。

通配符匹配什么示例结果
*任意长度的字符序列（含 0 个）*.log → 所有以 .log 结尾的文件
?恰好一个字符file?.txt → file1.txt、filea.txt，不含 file10.txt
[abc]集合中任意一个字符file[12].txt → file1.txt / file2.txt
[!abc]（或 [^abc]）不在集合中的任意一个字符file[!0].txt → 非 file0.txt
shell
ls /var/log/*.log        # 列出该目录下所有 .log
ls chart[0-9].txt        # chart0.txt..chart9.txt
echo "*.log"             # 双引号阻止展开，* 按字面输出（单引号更彻底）
rm -i *.tmp              # 删除所有 .tmp，-i 逐个确认（重要！）
!

易错：通配符会被 Shell 展开，若某些模式没匹配到任何文件，Shell 默认把原样模式传给命令（例如 ls *.xyz 会真的去列名为字面 *.xyz 的文件）。想阻止展开就用引号把模式包起来。

!

危险：rm * / rm -rf 目录 删除不可恢复；通配符误匹配会让 rm 一次删错一大片。养成好习惯：先 ls * 看清会匹配到什么，再 rm -i 逐条确认。

Tab 补全是另一个省力大杀器：只输入文件名或命令的前几个字符，按一次 Tab，Shell 自动补全；如果候选有多个，按两次 Tab 会列出所有可能。它几乎免费，还能减少拼写错误。

小节文件与目录：创建、复制、移动、删除05 · 文件管理

光看不动手不够，五个命令覆盖文件与目录的基本操作。看名字就大概能猜出用途，但它们对目录的处理各不相同——尤其复制/删除目录，往往要加一个 -r（递归）。

命令作用数组/目录要点
touch更新文件时间；不存在就创建空文件只创建文件，见 touch note.txt
mkdir创建目录mkdir -p a/b/c 递归创建；缺 -p 父目录不存在会报错
cp复制文件复制目录加 -r：cp -r src dst
mv移动 / 重命名移动目录不用 -r；跨文件系统=复制+删除
rm删除删除目录加 -r，强制加 -f，谨慎
shell
touch readme.txt                  # 新建空文件
mkdir -p projects/src             # 递归创建两级目录
cp readme.txt readme.bak          # 复制文件
cp -r projects projects_bak       # 递归复制整个目录
mv readme.bak docs/               # 移动文件到 docs 目录
mv old.txt new.txt                # 重命名（不动就改名）
rm readme.bak                     # 删除文件
rm -r projects_bak                # 递归删除目录（-f 强制，慎用）
!

易错：cp 复制目录必须带 -r，否则报「omitting directory」；而 mv 移动目录不需要 -r，这是两者最容易记混的地方。

★

核心要点：给会覆盖已有文件的命令养成加 -i（交互确认）的习惯，比如 cp -i、mv -i、rm -i，能有效避免误覆盖 / 误删除。

小节帮助 man 与管道 | 入门口06 · 组合

记不住参数很正常，man 就是 Linux 内置的「说明书」。而 管道 | 是把一个小工具的输出，直接喂给下一个小工具做输入——这正是 Linux 「一条管一件小事、组合起来干大事」哲学的核心。

shell
man ls                  # 查看 ls 的手册（q 退出，/ 搜索）
man -k keyword          # 按关键字搜所有手册（等价 apropos）

ls -l | less           # 长列表太长，用 less 分页看
ps aux | grep nginx    # 列出进程，再用 grep 过滤出含 nginx 的行
cat data.txt | wc -l   # 统计 data.txt 的行数
ls | grep -i log       # 列出文件名里含 log 的（-i 忽略大小写）

与管道容易混淆的是重定向。这一节只需记住最基础的三个区别，完整的文件描述符详解在后面的「重定向与文件描述符」一节：

符号含义说明
|管道左边命令的 stdout → 右边命令的 stdin
>覆盖重定向清空文件后再写入
>>追加重定向写到文件末尾，不清空原有内容
2>错误输出重定向把 stderr 单独送去文件
!

易错（这是本套内容修正过的地方）：>> 是追加，把内容写到文件末尾、不清空原内容；只有 > 才是覆盖（先清空再写入）。原始笔记把 >> 说成「清空文件再写入」是错的，请务必记住：>>＝追加、>＝清空覆盖。

★

核心要点：管道 | 只传标准输出，错误输出（stderr）默认不经过管道。所以日志报错经常看不到——那正是「重定向与文件描述符」小节要解决的进阶问题。
