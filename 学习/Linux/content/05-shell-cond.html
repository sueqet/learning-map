Shell 条件判断

学会用 if / elif / else 与 case 给脚本加上判断能力：用 [ ]、[[ ]]、(( )) 三种表达式测试文件、字符串、数值，再组合逻辑条件，让脚本能针对不同情况走不同分支。

✓本节学习目标

  • 学完后，你能写出结构完整的 if / elif / else / fi 分支脚本，并理解命令退出码「0=真、非 0=假」的含义。
  • 学完后，你能区分 [ ]、[[ ]]、(( )) 三种条件表达式，并选出适用场景。
  • 学完后，你能用文件判断（-e/-f/-d/-r/-w/-x/-s/-L）检查一条路径的属性和状态。
  • 学完后，你能用字符串判断（-z/-n/= /!=/=~）与数值判断（-eq/-ne/-gt/-ge/-lt/-le）比较变量，并注意引号与类型的陷阱。
  • 学完后，你能用 &&、||、! 组合多个条件，理解短路求值的顺序。
  • 学完后，你能用 case 处理多分支的字符串/模式匹配，读懂一个含条件判断的脚本流程。

01if / elif / else 的基本结构关键：then 与 fi 缺一不可

Shell 的 if 不要求条件是一个「布尔值」，它只看每一条命令结束后的退出状态码：0 = 成立（truthy），非 0 = 不成立（falsy）。条件既可以是一个 测试表达式（如 [ -f file ]），也可以是任意一条命令（如 grep、test）。

shell · if
if <condition>; then
  echo "in if"
elif <condition>; then
  echo "in elif"
else
  echo "in else"
fi

# 单行写法：then 前必须加分号
if <condition>; then echo "yes"; fi
  • 结构要素：if 开始、then 里写成立时执行的命令、elif 可写多个、else 可省略，fi 结束。
  • 分隔符：条件与 then 之间用 分号（; 或换行）隔开；不同命令也用分号分隔。
  • 退出码真相：if grep -q key file 之所以能当条件，是因为 grep 命中返回 0、没命中返回 1。
★

核心要点：别忘了「; then」里的分号，以及结束用的 fi。写错了最典型的报错是 syntax error near unexpected token `then' 或 `fi'。

i

单行技巧：若一行写完 if ... then ... else ... fi，每个语句之间都要用分号隔开；写成一行只是为了省行数，可读性不如多行。

02三种条件表达式：[ ] 与 [[ ]] 与 (( ))先分清「命令」「关键字」「算术」

括号并不是语法糖，它们的本质完全不同：[ ] 是一个命令（等价于 test），[[ ]] 是 bash 的关键字，(( )) 是算术表达式。选哪个，取决于你要可移植性、还是要更安全的扩展能力。

表达式本质支持的运算适用场景
[ ]test 命令（POSIX）-f、-z、=、-eq 等；== 非 POSIX跨 shell 可移植（sh/脚本）需要最通用写法
[[ ]]bash 关键字额外支持 ==、!=、=~（正则）、&& / || / !bash 脚本里更稳：不做词拆分、支持模式与正则
(( ))算术表达式==、>、<、>= 等；结果非 0 为真纯数值运算与比较，写法更直观

★

一句话记法：[ ] 是「命令」（要空格、要引号、可移植）；[[ ]] 是「bash 增强」（能 &&、能正则、不用怕空变量）；(( )) 是「算数」（比较两个数字）。

!

易错：[ ] 里的操作符与操作数两侧必须留空格，[a=b] 会被当成单个字符串；且 [ ] 中比较字符串要用 =，== 只是部分 shell 才支持。

03三类测试：文件、字符串、数值判断一个对象「是什么、是否、多大」

条件判断的三种常见对象：路径（文件/目录）、字符串、整数。下面分别给出常用选项与示例。

① 文件判断

shell · 文件
[ -f file ]     # 是普通文件且存在
[ -d dir ]      # 是目录且存在
[ -e path ]     # 路径存在（文件或目录均可）
[ -r file ]     # 文件可读
[ -w file ]     # 文件可写
[ -x file ]     # 文件可执行
[ -s file ]     # 文件存在且大小不为 0
[ -L file ]     # 是符号链接

② 字符串判断

shell · 字符串
[ -z "$str" ]            # 字符串为空
[ -n "$str" ]            # 字符串不为空
[ "$a" = "$b" ]          # 字符串相等（POSIX 用 =）
[ "$a" != "$b" ]         # 字符串不相等
[[ "$str" =~ ^[0-9]+$ ]] # 正则匹配（bash 专属, 且需用 [[ ]]）

③ 数值判断

shell · 数值
[ $a -eq $b ]   # 等于
[ $a -ne $b ]   # 不等于
[ $a -gt $b ]   # 大于
[ $a -ge $b ]   # 大于等于
[ $a -lt $b ]   # 小于
[ $a -le $b ]   # 小于等于
(( a > b ))     # 数值比较（更直观）
i

提醒：数值比较的操作符（-eq/-gt/...）只用于整数；字符串比较（=、!=）绝不能混用数字比较符，否则会遇到「integer expression expected」之类的报错。

!

易错：在 [ ] 里尽量给变量加上双引号（[ "$a" = "$b" ]）。若不引号且变量为空，命令行会被拆掉而误判；[[ ]] 不会做词拆分，通常不需要。

04逻辑组合：&&、||、!短路求值决定走到哪一步

把多个条件组合起来有三种方式。注意它们都有短路特性：&& 左边成立才执行右边，|| 左边失败才执行右边。

shell · 逻辑
[ cond1 ] && [ cond2 ]        # 与（都成立才执行下一句）
[ cond1 ] || [ cond2 ]        # 或（任一成立即可）
! [ cond ]                    # 非（取反）
[[ cond1 && cond2 ]]          # bash 扩展写法, 更贴近逻辑
[[ cond1 || cond2 ]]
  • 短路的用途：mkdir -p dir && cd dir —— 目录创建成功才进入；command || echo "失败" —— 失败才提示。
  • bash 中推荐：用 [[ ]] 把多个条件像真布尔逻辑一样组合，避免 [ ] && [ ] 那种「串外部命令」的写法。
  • 非：! [ -f file ] 等价于「文件不存在」。注意 ! 与 [ 之间也要空格。
!

易错：不要用 [ cond1 -a cond2 ] 或 [ cond1 -o cond2 ] 写「与/或」——-a/-o 在 POSIX test 中很含糊且已被弃用。要组合逻辑，宁可写成 [ cond1 ] && [ cond2 ]，或在 bash 里用 [[ cond1 && cond2 ]]。

i

提示：&&/|| 是整条指令链的语义，并非「布尔表达式的运算符」。可以把 c1 && c2 || c3 想象成「c1 且 c2，否则 c3」，它不等价于严格的三元逻辑——c1 失败但 c2 也没执行时仍会落到 c3。

05case 语句：多分支字符串匹配用 glob 模式代替重复的 elif

当一个变量要匹配多个可能取值时，case 比一串 elif 更清晰。它自上而下匹配模式（支持 *、?、[...] 等 glob），命中即执行该分支，;; 结束。

shell · case
case $var in
  "a")
    echo "is a"
    ;;
  "b"|"c")
    echo "is b or c"
    ;;
  *)
    echo "other"
    ;;
esac
  • 多值合并：用竖线 | 把多个模式并到一个分支，如 "b"|"c"。
  • 兜底分支：*) 匹配其余情况（相当于 else），强烈建议写上。
  • 结束标记：每个分支用 ;; 结束；整体用 esac 结束（case 倒过来写）。
★

核心要点：case 匹配的是模式而非精确串，所以 "a|b" 若写成 * 会匹配一切；想精确匹配就加引号。适合写菜单、处理命令行参数（如 $1）。
