SSH 远程登录与安全

SSH(Secure Shell)是你在运维和开发中最常用的远程通道：它把远程登录、文件传输与隧道转发统一到一条加密连接上。学完这一节，你会安全地连上任何一台 Linux 主机，并懂得如何把它锁得更紧。

✓本节学习目标

  • 学完后，你能用 ssh 命令登录远程 Linux 主机，并理解其连接过程。
  • 学完后，你能用 scp 与 sftp 在本地与远程之间安全地传输文件。
  • 学完后，你能用 ssh-keygen 生成密钥对，并配置「免密登录」。
  • 学完后，你能区分 ssh_config 与 sshd_config，并用 ~/.ssh/config 简化连接。
  • 学完后，你能排查常见的 SSH 报错（权限、密钥、known_hosts、连接被拒）。
  • 学完后，你能做基础安全加固：禁用密码登录、限制 root、用防火墙放行最小端口。
Prerequisites · 前置知识

会用终端、理解 Linux 用户与目录（如 ~、whoami）、知道基本权限 chmod；若已过「防火墙」一节，理解 firewall-cmd 会更好上手本节的网络放行部分。

Learning Content · 学习内容

01SSH 的«是什么»与«怎么走»
架构、端口与连接流程

01SSH 是什么：C/S 架构与加密先建立整体心智模型

SSH 是客户端/服务端(C/S) 架构。服务端通常指 sshd（监听 22 端口），客户端用 ssh 命令行工具连接。整个链路被 TLS 类似的非对称加密保护——先协商会话密钥，之后所有命令、输出、文件都走 AES 等对称加密，因此对窃听、中间人攻击有很强的抵抗力。

  • 身份认证：服务端先验证客户端「是不是你」（密码或密钥），再验证客户端身份。
  • 主机确认：首次连接时，服务端把它的主机指纹（公钥指纹）给你确认，并记录进 ~/.ssh/known_hosts。
  • 一套协议多用途：登录、传文件、端口转发都建立在同一条 SSH 加密通道上。
flowchart LR C[客户端
ssh 命令] -- 建立 TCP 22 加密通道 --> S[服务端 sshd] S -- 发送主机指纹 / 公钥 --> C C -- 校验 known_hosts 指纹 --> C2{指纹一致?} C2 -- 不一致 --> WARN[警告: 可能中间人攻击] C2 -- 一致 --> AUTH{身份认证} AUTH -- 密码 或 密钥 --> OK[认证通过] OK --> SESSION[(进入远程 Shell)] AUTH -- 认证失败 --> FAIL[拒绝连接]
shell
# 查看 sshd 是否在监听 22 端口
ss -tlnp | grep :22        # 或 netstat -tlnp | grep :22

# 查看 SSH 服务端状态并启动（systemd 发行版）
systemctl status sshd
sudo systemctl enable --now sshd

# 查看客户端版本
ssh -V
⚠

首连指纹警告别忽略：首次连陌生主机会提示 The authenticity of host ... can't be established.。若这是一台你信任的主机，核对指纹后输入 yes；若已连接过的主机再次出现该提示，多半是对方主机或端口被替换，先确认再继续。

02基本用法：登录、命令直跑与退出最常用的三条路径

最简单的做法是把 ssh 用户@主机 当作一条命令来用。登录即得到交互式 shell；也可以在命令行尾部直接带一条命令，执行完即断开（适合在脚本/自动化里跑远端任务）。

shell
# 1) 交互式登录（默认 22 端口，用当前用户名）
ssh root@192.168.1.10

# 2) 指定用户名 + 执行一条命令后退出
ssh admin@192.168.1.10 'hostname && whoami'

# 3) 换端口（服务端改了/防火墙只放行高位端口时）
ssh -p 2222 user@192.168.1.10

# 4) 用指定私钥文件登录（我们会在下一小节讲密钥）
ssh -i ~/.ssh/id_ed25519 user@192.168.1.10
shell
# 在远程 shell 内常用操作
hostname          # 我在哪台机器
whoami            # 我是哪个用户
exit              # 退出并关闭连接
# 连接卡住/窗口异常时：回车键后按  ~ .  （tilde-dot）强制断开
★

核心要点：SSH 的命令语法是 ssh [-p 端口] [-i 私钥] 用户@主机 [命令]。缺省时「当前用户」「22 端口」「默认私钥」都会自动使用，所以常常一个 ssh ip 就够。

03文件传输：scp 与 sftp安全地把文件搬进搬出

两者都走 SSH 加密通道，适用于不同场景：scp 适合一次性、脚本化地复制文件或目录；sftp 提供交互式文件管理器，可浏览、cd、上传下载，更像 FTP 但每一步都加密。路径中
本地写成普通路径、远程写成 用户@主机:路径。

命令作用方向
scp a.txt user@host:/tmp/上传单个文件本地 → 远程
scp user@host:/tmp/a.txt ./下载单个文件远程 → 本地
scp -r mydir/ user@host:~/递归复制整个目录（需 -r）本地 → 远程
scp -P 2222 ...指定端口（注意是大写 P）—
sftp user@host进入交互式文件会话双向
shell
# sftp 交互会话常用指令
sftp user@192.168.1.10
  put  report.log      # 上传
  get  /var/log/syslog # 下载
  ls ; cd /tmp ; mkdir bak
  bye                  # 退出
!

易错点：scp 里端口参数是大写 -P，而 ssh 里是小写 -p。复制整个目录必须加 -r，否则会报错或只拷单个文件。

04密钥认证：生成、分发与免密登录生产环境登录方式的首选

公钥认证是比密码更安全的登录方式。ssh-keygen 在你本机生成一对密钥：私钥（id_ed25519） 永远留在客户端、绝不外传；把公钥（id_ed25519.pub） 追加到目标主机的 ~/.ssh/authorized_keys。登录时客户端用私钥对随机挑战做签名，服务端用公钥验签，通过即放行——全程不传密码，天然抵御暴力破解。

shell
# 1) 生成密钥对（Ed25519 更小更快，推荐；或 -t rsa -b 4096）
ssh-keygen -t ed25519 -C "your_email@example.com"
# 一路回车，会在 ~/.ssh/ 生成 id_ed25519 和 id_ed25519.pub

# 2) 查看并复制公钥
cat ~/.ssh/id_ed25519.pub

# 3) 一键把公钥装到远程主机的 authorized_keys（之后即可免密）
ssh-copy-id user@192.168.1.10

# 4) 也可手工追加
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo "<你的公钥内容>" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
shell
# ssh-agent：把私钥加进内存代理，免得每次输 passphrase
ssh-add ~/.ssh/id_ed25519
ssh-add -l      # 列出代理里的密钥
文件 / 命令所在端作用
~/.ssh/id_ed25519客户端私钥，绝不外发，权限建议 600
~/.ssh/id_ed25519.pub客户端公钥，可公开，分发到远端
~/.ssh/authorized_keys服务端允许登录本机的公钥列表，权限 600
~/.ssh/known_hosts客户端记录已信任主机的主机公钥指纹
ssh-keygen客户端生成密钥对（-l -f 可查看指纹）
!

最常见的“密钥登不上”：多半是权限太宽。SSH 严格要求：~/.ssh 目录权限 700、authorized_keys/私钥 权限 600；如果所属用户/目录属主不对或权限过松，服务端会直接拒绝。用 ssh -v 看细节。

★

核心要点：私钥在客户端、公钥在服务端的 authorized_keys。它们搭配使用，ssh-copy-id 只是帮你把公钥安全“搬运”过去，本身不存放或传输私钥。

05配置文件与端口转发：ssh_config vs sshd_config把常用连接“存起来”，把本地端口“穿过去”

客户端配置文件是 ~/.ssh/config（用户级），可给常用主机起别名、固定端口/用户/私钥，以后 ssh prod 一条命令即可。服务端配置是 /etc/ssh/sshd_config，影响别人如何连进来，改完要 systemctl reload sshd（或 sshd -t 先做语法检查）。

shell
# ~/.ssh/config 内容示例
Host prod web1
  HostName 192.168.1.10
  User deploy
  Port 2222
  IdentityFile ~/.ssh/id_ed25519

# 之后直接
ssh prod           # 等价于 ssh -p 2222 deploy@192.168.1.10 -i ~/.ssh/id_ed25519
配置文件端作用改后生效
~/.ssh/config客户端定义别名、端口、私钥、跳板机等新建连接即生效
/etc/ssh/ssh_config客户端(全局)客户端全局默认值新建连接即生效
/etc/ssh/sshd_config服务端谁、怎样能登录进来systemctl reload sshd
shell
# 端口转发（隧道）：把本地 8080 转发到远端数据库端口 3306
ssh -L 8080:localhost:3306 user@dbhost
# 访问本机 8080 就等价于访问远端 dbhost 的 3306

# 跳板机：先过跳板，再从跳板连目标机
ssh -J jumpuser@jumpbox user@target
⚠

别混淆两个 config：客户端 ~/.ssh/config（影响“我出站连别人”）与服务端 /etc/ssh/sshd_config（影响“别人进我主机”）。很多“改了没生效”都是在改错文件——服务端只有 sshd_config，且需重载 sshd 服务。

06安全加固与排障让 SSH 更稳、更锁、更可诊断

有了密钥认证后，通常禁用密码/空密码登录，并限制什么人能从哪里登录。这些都在服务端 /etc/ssh/sshd_config 里配置，改完务必先用 sshd -t 做语法检查再重载，避免把自己锁在门外。

shell
# /etc/ssh/sshd_config 建议加固项
Port 2222                 # 视需要换个非默认端口（配合防火墙放行）
PermitRootLogin no        # 禁止 root 直接登录（改用普通用户 + sudo）
PasswordAuthentication no # 禁用密码登录，只用密钥
PubkeyAuthentication yes  # 允许密钥认证（默认即 yes）
MaxAuthTries 3            # 限制单次连接认证次数，降低暴力破解面
AllowUsers deploy         # 只允许 deploy 用户登录（可加来源IP）

# 修改后：先语法检查，再重载生效（不中断已有连接）
sudo sshd -t
sudo systemctl reload sshd
shell
# 排查连接问题：-v 逐级看握手细节
ssh -v user@192.168.1.10

# 认错的主机指纹：删除后重新信任（确认无风险再删！）
ssh-keygen -R 192.168.1.10

# 查看登录/认证日志（发行版路径或有差别）
sudo journalctl -u sshd -n 30        # systemd 日志
sudo grep -i 'Failed password' /var/log/auth.log   # Debian/Ubuntu
sudo tail -f /var/log/secure         # RHEL/CentOS
现象 / 报错常见原因与对策
Connection refusedsshd 没起 / 端口不对 / 防火墙没放行该端口
Permission denied (publickey)密钥不对或没用密钥；看是否 PasswordAuthentication no
REMOTE HOST IDENTIFICATION HAS CHANGED主机指纹变了，先确认风险再 ssh-keygen -R
Bad owner or permissions~/.ssh=700、文件=600、属主正确
能连但很快被断开检查服务端日志、认证次数限制、来源白名单
★

加固顺序三原则：① 先用密钥验证能登录；② 再禁用密码登录；③ 最后才限制端口/root/用户白名单。顺序错了容易把自己锁在门外。改了 sshd_config 一律 sshd -t 后再 reload。

!

保命提醒：改 SSH 配置、防火墙、端口时，务必在新终端里先测试一条新连接能成功再关闭旧连接；远程改 sshd_config 出问题时，PermitRootLogin/端口一旦改错可能立刻断线。稳妥做法是保留一个能回退的本地或带外会话。

▲ 进阶挑战

  • 在一台虚拟机或云主机上，生成 ed25519 密钥对并配置免密登录；接着把 PasswordAuthentication 设为 no，验证密码登录被拒绝而密钥登录正常。

  • 故意把 authorized_keys 权限改成 644 再登录，观察报错并用 ssh -v 定位原因；随后修正权限恢复登录。
