LINUX · 系统管理

软件包管理

学会用 dnf / rpm 安装、查询、更新、卸载软件包，理解软件源的配置与依赖关系——这是 RHEL 系 Linux 上安装软件的基石。

✓本节学习目标

  • 学完后，你能用 dnf 完成软件包的安装、删除、更新、搜索与历史回滚。
  • 学完后，你能用 rpm 查询已安装包的信息、文件归属、并校验包内容。
  • 学完后，你能说清 dnf 与 rpm 的分工差异，并解释依赖关系。
  • 学完后，你能读懂并编写 /etc/yum.repos.d 下的 .repo 软件源文件。
  • 学完后，你能为 Rocky Linux 配置一个国内软件源并刷新缓存。
Prerequisites · 前置知识

会使用终端（ls、cd、grep、重定向/管道），了解文件系统中的 /etc、/usr/bin 等目录，并知道什么是环境变量与配置文件。

01从软件包到包管理器
理解"装软件"这件事如何被自动化

概念软件包是什么？两种主流格式packages · formats

软件包是把一个程序的二进制文件、配置文件、文档、依赖声明等打包到一起的压缩文件，方便分发和安装。Linux 世界主要有两种主流封装格式：Red Hat 系的 .rpm 和 Debian 系的 .deb。

格式工具（低层 → 高层）适用发行版
.rpmrpm、dnf、yumRHEL、CentOS、Rocky Linux、Fedora
.debdpkg、aptDebian、Ubuntu
  • rpm：低层工具，直接操作 .rpm 文件，不会自动解决依赖。
  • dnf：基于 rpm 的高层工具，会自动从软件源拉取并安装所有依赖。
★

核心要点：本页以 RHEL 系（Rocky/CentOS/Fedora）为例，重点掌握 rpm 与 dnf 这一套；Ubuntu 用 dpkg/apt，思路完全平行。

分层包管理的层次：dnf → rpm → 内核hierarchy

安装软件时，命令并不是直接写入文件系统，而是经过一层层的"包装"：高层工具负责找包、解依赖、下载，低层工具负责把 .rpm 文件真正解包并安装到系统。

flowchart TD A[用户 / 管理员] --> B{"dnf / yum
高层工具"} A -->|手动指定文件| C["rpm
低层工具"] B -->|从软件源下载、自动解析依赖| C C -->|直接把文件安装进系统| D[内核 / 文件系统]
  • dnf / yum：自动处理依赖、从软件源下载（你只说出软件名，如 nginx）。
  • rpm：直接操作本地 .rpm 文件、不处理依赖（你给它一个文件路径）。
  • 内核（文件系统）：最终把文件写入系统的底层。
!

易错点：很多人以为 rpm 也能像 dnf 一样自动补齐依赖——不是的。rpm -i 缺依赖会直接报错，而 dnf 会替你解决。

02rpm 与 dnf 的常用操作

rpmrpm：底层包管理器install · query · verify

rpm（RPM Package Manager）直接操作 .rpm 文件，不自动处理依赖。最常用的三个动作是：安装（装本地文件）、卸载（按包名）、查询（只读，几乎不会出错）。

rpm
# 安装 / 升级
rpm -ivh package.rpm         # -i 安装，-v 显示详情，-h 显示进度
rpm -Uvh package.rpm         # 升级（不存在则安装）
rpm -Fvh package.rpm         # 升级（不存在则跳过）

# 卸载（注意：这里用"包名"，不是文件名）
rpm -e package
rpm -e --nodeps package      # 强制删除、忽略依赖（慎用！）

# 查询
rpm -qa                      # 列出所有已安装的包
rpm -qa | grep nginx         # 在已安装包里搜索
rpm -qi package              # 查看包的详细信息
rpm -ql package              # 列出该包安装的所有文件
rpm -qf /usr/bin/git         # 某个文件属于哪个包
rpm -qc package              # 列出该包的配置文件
rpm -q --changelog package   # 变更记录

# 验证
rpm -V package               # 验证包内文件是否被改动
rpm -K package.rpm           # 验证 .rpm 文件的签名与完整性
★

记忆技巧：-q 是 query（查询）；-f 是 file（文件），所以 rpm -qf 就是"这个文件归谁"。查询类操作对系统只读、安全，可以放心练。

dnfdnf：高层包管理器（自动解依赖）install · remove · update

dnf（Dandified YUM）是 RHEL/CentOS/Rocky 的高层包管理工具，yum 的继任者，自动处理依赖关系。你只需要说"我想要什么软件"，它负责找到并装齐一切。

dnf
# 安装
dnf install nginx             # 安装（会提示确认）
dnf install nginx -y          # 自动确认
dnf install ./local.rpm       # 安装本地 rpm（同时解决依赖）
dnf reinstall nginx           # 重新安装

# 删除
dnf remove nginx              # 删除软件包
dnf autoremove                # 清理不再需要的孤立依赖包

# 更新
dnf update                    # 更新所有包
dnf update nginx              # 更新指定包
dnf check-update              # 只检查有无可用更新（不执行）

# 搜索与查询
dnf search keyword            # 按关键词搜包名/描述
dnf info nginx                # 查看包详细信息
dnf list installed            # 列出所有已安装包
dnf list available            # 列出软件源中所有可用的包
dnf provides /usr/bin/git     # 哪个包提供了某文件

# 软件源与缓存
dnf repolist                  # 列出所有启用的软件源
dnf repolist all              # 列出所有（含禁用）
dnf makecache                 # 更新软件源缓存
dnf clean all                 # 清除所有缓存

# 历史（可回滚）
dnf history                   # 查看操作历史
dnf history undo <id>         # 撤销指定操作（回滚）
场景推荐工具 / 命令
从软件源安装软件dnf install <pkg>（自动解依赖）
安装本地 .rpm 文件dnf install ./xxx.rpm（也能处理依赖）
查询已安装包信息rpm -qi、rpm -ql
查询文件归属rpm -qf
撤销一次误操作dnf history undo <id>
✕

易错点：dnf remove 一定别加上系统必需的依赖；rpm -e --nodeps 会强行跳过依赖检查，可能弄坏系统。生产环境优先用 dnf 并先看 dnf history。

03软件源（Repository）配置

repo软件源配置：/etc/yum.repos.dmirror · gpgcheck

软件源（Repository）是存放软件包的服务器。dnf 通过软件源的索引来搜索并下载包，配置文件统一放在 /etc/yum.repos.d/ 目录下，每个 .repo 文件可以定义一个或多个软件源。

.repo 文件格式
# /etc/yum.repos.d/mirror.repo
[repo-id]                                           # 软件源唯一标识
name=描述名称
baseurl=https://mirror.example.com/path/            # 软件源地址
enabled=1                                           # 1 启用，0 禁用
gpgcheck=1                                          # 1 校验 GPG 签名，0 跳过
gpgkey=https://mirror.example.com/RPM-GPG-KEY       # GPG 公钥地址

下面以 Rocky Linux 配置 163 国内镜像源为例。先备份原有的 rocky 源，再写入新的镜像源，最后刷新缓存。

shell · 配置 163 源
cd /etc/yum.repos.d
# 1) 备份原有 repo 文件
for repo in rocky*.repo; do mv "$repo" "$repo.backup"; done

# 2) 写入 163 镜像源（注意 $releasever 与 $version 的差异！）
repos=(BaseOS AppStream extras)
version=9
url=https://mirrors.163.com
file=/etc/yum.repos.d/mirror.repo
rm -f ${file}
for repo in "${repos[@]}"; do
  echo -e "[rocky-$repo]\nname=Rocky Linux \$releasever - $repo\nbaseurl=${url}/rocky/\$releasever/$repo/\$basearch/os/\nenabled=1\ngpgcheck=1\ngpgkey=${url}/rocky/RPM-GPG-KEY-Rocky-$version\n\n" >> ${file}
done
unset repos version url file

# 3) 更新缓存
dnf makecache
✕

务必注意：上面脚本里 name 用的是 \$releasever（dnf 运行时变量，由包管理器解析），而 gpgkey 用的是 shell 变量 $version（写死为 9，在 echo 执行时立即被替换成字面量 9）。二者来源不一致。

★

建议：统一用 \$releasever（或全部统一用 $version）保持一致。若镜像的 GPG 公钥文件名固定带版本号（如 RPM-GPG-KEY-Rocky-9），用 \$releasever 也能由 dnf 自动展开成对应的系统版本号，更省心、跟系统自动匹配。

还原备份（如需恢复原源）：

shell · 还原
for repo in *.repo.backup; do mv "$repo" "${repo%.backup}"; done
★

为什么要有 gpgcheck：开启 gpgcheck=1 会校验下载到的包的 GPG 签名，防止被篡改或替换成恶意包。生产环境建议保持开启、并配置正确的 gpgkey。

▲ 进阶挑战

  • 动手：为 Rocky Linux 配置一个国内软件源（阿里云/清华镜像均可），注意把 \$releasever 与 $version 统一，再用 dnf repolist 和 dnf makecache 验证。

  • 动手：在虚拟机里用 rpm -ivh 故意安装一个缺依赖的 .rpm，记录报错；随后用 dnf install ./xxx.rpm 重复同样安装，观察它如何自动补齐依赖。
