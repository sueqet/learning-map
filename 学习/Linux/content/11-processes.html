LINUX · 系统管理

进程状态与优先级

一个进程此刻在「忙什么、睡在哪、有没有被卡死」，以及它凭什么拿到 CPU——看懂 ps/top 里的状态字母与 PR/NI 数字，是排查系统卡顿、优化负载的第一步。

✓本节学习目标

  • 学完后，你能从 ps/top 输出中认出 R、S、D、T、Z 五种进程状态，并说出各自的含义与典型场景。
  • 学完后，你能区分 PR（内核视角的优先级）与 NI（用户可调的 nice 偏移），并解释普通进程 PR = 20 + NI。
  • 学完后，你能正确区分普通进程（PR 0~39）与实时进程（RT，调度优先级 0~99）两套范围，避免混淆。
  • 学完后，你能用 nice -n N 以指定优先级启动进程，用 renice -n N -p PID 调整运行中进程的优先级。
  • 学完后，你能说明「NI 越小越不友好、优先级越高」的含义，并理解降低 nice 值需要 root 权限。
  • 学完后，你能解释为何 D（不可中断）状态的进程即使 kill -9 也难以立刻终止，以及 Z（僵尸）进程是怎么来的。
Prerequisites · 前置知识

你会终端基本操作、知道「进程」与「父进程」的大致关系（可用 ps 看 PID/PPID）；会用 ls -l 或 kill 等简单命令即可，不需要掌握内核细节。

Learning Content · 学习内容

01从一张状态表到优先级
—— 读懂「进程的一生」与「调度规则」

01进程状态：R / S / D / T / Z

ps 状态列的字母，描述进程此刻在干什么、能不能被打断。五种最常出现的状态如下，重点是区分「睡在写 IO 上的 D」和「睡在等着被唤醒的 S」。

状态缩写含义典型场景
RunningR正在运行，或在运行队列中等待被调度CPU 密集任务在跑
SleepingS可中断睡眠，等待某个事件（如 I/O、锁、定时器）绝大多数进程的空闲态，可被信号唤醒
Uninterruptible SleepD不可中断睡眠，通常正在等待磁盘等内核态 I/O读写繁忙磁盘；此时 kill 也常常无效
StoppedT被暂停（如 Ctrl+Z，或被调试器停下）Job Control / gdb 调试断点
ZombieZ已退出，但父进程未给它「收尸」，仍占用一个进程表项父进程忘了 wait()，进程退出后遗留
flowchart LR CRT["创建 Created"] --> R["R · 运行/可运行"] R -->|等待事件| S["S · 可中断睡眠"] S -->|事件到达| R R -->|等待磁盘 I/O| D["D · 不可中断睡眠"] D -->|I/O 完成| R R -->|Ctrl+Z / 调试器| T["T · 已停止"] T -->|fg / SIGCONT| R R -->|exit| Z["Z · 僵尸"] Z -->|父进程 wait() 回收| E["退出，释放进程表项"]
★

核心要点：平时随手 ps 会看到一堆 S（这是正常的空闲态）；D 说明进程正卡在内核态 I/O 上、kill 无效；Z 说明父进程没回收、进程表被白占。

02优先级：PR 与 NI 的关系

关于「谁能先用 CPU」，内核靠优先级来排定运行顺序。这里有两个容易混淆的概念：PR（Priority，内核视角的调度优先级）与 NI（Nice Value，用户可调的偏移）。数值越小，优先级越高。

概念谁控制的取值范围说明
PR（Priority）内核普通进程 0~39内核动态计算的实际调度优先级，越小越优先
NI（Nice Value）用户（可调整）-20 ~ 19用户能改的偏移；越小越「不友好」
实时进程 RT内核 / 特权配置调度优先级 0~99实时优先级，与普通进程的 0~39 是另一套范围

普通进程遵循 PR = 20 + NI。例如 NI=10 时 PR=30；NI=-5 时 PR=15——数值越小，越「不友好」，进程抢到 CPU 的概率越高、独占时间越长。

✕

易混淆点（务必区分）：「PR 范围 0~39」只针对普通进程（由 PR = 20 + NI 推出）。实时进程（RT，SCHED_FIFO/SCHED_RR）的调度优先级是 0~99，是另一套独立范围，优先级高于任何普通进程。不要把「0~39」误解成所有进程的全局范围。

!

理解 nice 的「友好」：名字里的「nice」指的是对他人友好——NI 越大（越接近 +19），进程越谦让、把 CPU 让给别人；NI 越小（越接近 -20），越霸道、独占更多 CPU。

03调整优先级：nice 与 renice

nice 用来启动一个程序时指定它的 nice 值；renice 用来修改运行中进程的 nice 值。两者都以 -n 指定数值。

shell · nice / renice
# 以 nice 值 10 启动程序（比默认 0 更"友好"，让出部分 CPU）
nice -n 10 ./my_program

# 用短横线写法：-10 表示 nice 值 10（注意不是 -20）
nice -10 ./my_program

# 修改运行中进程 PID=12345 的 nice 值为 -5
# 需要 root 权限才能把 nice 值"降低"（让进程更霸道）
sudo renice -n -5 -p 12345

# 普通用户把 nice 值"提高"（更友好）通常是允许的
renice -n 10 -p 12345
★

核心要点：降低 nice 值（让进程更优先）需要 root 权限；普通用户通常只能提高自己的 niche 值（更友善）。数值越小=优先级越高=越「不友好」。

!

易错点：nice -10 的「-10」指的是nice 值 = 10，不是负 10。要指定负的 nice 值，必须写成 nice -n -10（或 nice -- -10），且通常需要 root。

04查看进程：ps 与 top

状态和优先级要到了 ps / top 里才能看到。常用的是 ps aux（BSD 风格）和 ps -eo（指定列），以及能实时刷新的 top。

shell · ps / top 查看进程
# BSD 风格：STAT 列显示状态，PRI/NI 显示优先级
ps aux

# 自定义要显示的列：PID 状态 优先级 nice CPU 命令行
ps -eo pid,stat,pri,ni,pcpu,comm

# 只看某种状态（例如找僵尸进程）
ps -eo pid,stat,comm | grep Z

# 实时监控（每 2 秒刷新），关注 %CPU 与 STAT 列
top -d 2

# 按 PID 查某个进程的状态与优先级
ps -o pid,stat,pri,ni,cmd -p 12345
列名说明对应概念
STAT状态（可能带后缀，如 S+ 前台、Rs 现实时）上文的 R/S/D/T/Z
PRIps 视角的优先级普通进程 ≈ 20 + NI；实时进程另有显示
NI用户可调的 nice 值-20 ~ 19
%CPUCPU 占用百分比看谁在「抢 CPU」
PID / PPID进程号 / 父进程号可定位父子关系与僵尸的「债主」
★

核心要点：top 看实时动态（哪个进程在烧 CPU），ps aux 看某一时刻快照（哪种状态有多少个）。排障时先看 %CPU，再看 STAT 是否有 D/Z。

05进阶：D 状态与僵尸进程

排障时最让人头疼的两个状态是 D（不可中断睡眠）和 Z（僵尸）。理解它们的本质，才知道该不该、能不能去 kill。

  • D（Uninterruptible）：进程在内核态等待一段不可中断的 I/O（通常是磁盘/块设备）。因为处于内核态且临界资源上，内核在它完成这段 I/O 前不处理任何信号，所以 kill -9 也只能等它「自己回过神来」。通常应排查 I/O 是否卡死（磁盘故障、NFS 挂死），而不是硬杀。
  • Z（Zombie）：进程已经退出，但它仍在进程表里占一个表项，直到父进程用 wait() 收回其退出状态。子进程先死、父进程没回收，就留下僵尸。僵尸不占 CPU、不占内存，只占一个进程表项。它无法被杀掉（已经死了），只能让父进程去回收——若父进程早已退出，会被 init（PID 1）收养并回收。
shell · 排查 D / Z 进程
# 找出所有不可中断睡眠(D)进程
ps -eo pid,stat,comm | awk '$2 ~ /D/'

# 找出所有僵尸(Z)进程及其父进程，判断"债主"
ps -eo pid,ppid,stat,comm | awk '$3 ~ /Z/'

# 僵尸无法被 kill（它已退出）；正确做法是让父进程回收，
# 或等父进程退出后由 init 收养回收。强行 kill 只会报错/无效。
✕

不要盲目 kill -9：对 D 状态进程，kill -9 往往不立即生效，还可能在 I/O 完成后才处理；对 Z 僵尸进程，kill 完全无效（它已经死了）。先判断是磁盘卡死、父进程未回收，还是系统正常忙碌，再对症处理。

⌕
