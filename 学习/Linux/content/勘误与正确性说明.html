笔记正确性说明

本套学习页面基于朋友的 linux笔记（朋友的） 整理而成。整理过程中逐篇核对，下面列出发现的问题、修正与补充。原始笔记文件（linux笔记（朋友的）\）保持原样未改动，学习页里写入的是修正后的内容。

√一、发现并修正的错误

1. 重定向：>> 的描述错误（最重要）

原笔记「文件/重定向.md」把追加重定向 >> 写成「清空文件的内容，再向文件中写入内容」——这是错的，那描述的是覆盖 > 的行为。

✖ 原文（错误）：>>　作用：对于文件：清空文件的内容，再向文件中写入内容。
√ 修正：>>＝追加，把内容写到文件末尾，不清空原内容；>＝覆盖，清空后再写入。

2. 文件系统：/run 与 /var/run 的符号链接方向写反

原笔记「文件/文件系统.md」写「/run 是 /var/run 的符号链接（如 Ubuntu）」，方向反了。

✖ 原文：/run 是 /var/run 的符号链接
√ 修正：实际是 /var/run → /run（/var/run 作为 /run 的符号链接），两者指向同一临时目录。现代 systemd 发行版均如此。

3. 证书管理：追加到 tls-ca-bundle.pem 是不规范做法

原笔记「证书管理/根证书.md」把自签证书直接追加到 /etc/pki/ca-trust/extracted/pem/tls-ca-bundle.pem。这在 RHEL 系上能临时生效，但属于 hack；下次运行 update-ca-trust 该文件会被重新生成，导致追加内容丢失，也不利于管理。

√ 标准做法：把证书放到 /etc/pki/ca-trust/source/anchors/，再执行 update-ca-trust。学习页 19-certs.html 已按标准方法讲解，并保留原思路作为补充。

i二、需要澄清 / 补全的点

4. 进程优先级 PR 的范围

原笔记「进程与线程/进程基础.md」说「PR 范围 0~39」——这是普通进程的简化概括（PR = 20 + NI，NI 为 -20~19，因此 PR 为 0~39）。实时进程（RT）的 PR 范围是 0~99，是另一条调度通道。二者叠在一起容易歧义，学习页已区分说明。

5. 环境变量配置文件路径

原笔记「shell编程/变量.md」用 /etc/bashrc。不同发行版文件名不同：RHEL/CentOS 用 /etc/bashrc，Debian/Ubuntu 用 /etc/bash.bashrc。两者含义相同（系统级非登录 shell 配置），学习页已加注。

6. 软件源配置的一致性

原笔记「软件包/软件源配置.md」生成 rocky-$repo 源时，name 里用转义的 \$releasever（由 dnf 替换），而 gpgkey 直接用 shell 变量 $version（固定为 9）。两者指向不同版本来源，实际可用，但建议统一用 \$releasever 或 $version，学习页已注明。

7. 重定向 1>&2 顺序问题的表述

原笔记用「值传递 / 赋值」来类比，容易绕。本质是从左到右依次执行重定向：cmd 2>file 1>&2 先把 stderr 指向 file、再把 stdout 指向「当前的 stderr」（即 file），于是 stdout+stderr 都进 file；cmd 1>&2 2>file 则相反，stdout 与 stderr 分开。学习页已用「先重定向到哪、再复制到哪」的清晰表述。
