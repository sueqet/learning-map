LINUX · Network

网络配置与包处理流程

用 nmcli 把主机接到正确的网段，再顺着数据包从进程到网卡、再从网卡回到进程的路径，弄清 netfilter 到底在哪里拦截——这是理解网络、排查时延与丢包问题的一张「地图」。

✓本节学习目标

  • 学完后，你能用 nmcli 查看连接与设备，并把一个接口配置成静态 IP（地址/网关/DNS）再应用，或随时改回 DHCP。
  • 学完后，你能按顺序说明发送流程：Socket 缓冲区 → TCP/UDP → IP 查路由 → netfilter → 以太网帧 → TX Ring Buffer → 网卡 DMA。
  • 学完后，你能按顺序说明接收流程：网卡 DMA → 硬中断 → 软中断 → 网络设备层 → netfilter → IP → 传输层按端口找 Socket → 进程。
  • 学完后，你能指出 netfilter 的 5 个 hook 点，并说出 DNAT、SNAT/MASQUERADE 各发生在哪条链。
  • 学完后，你能解读 Ring Buffer / DMA / 硬中断(hi) / 软中断(si)，并据 top 与 netstat -s 的现象定位网络性能瓶颈。
  • 学完后，你能基于本节的流程图，解释两台主机直连共享网络时网关该指向哪台机器。
Prerequisites · 前置知识

你需要会基本终端操作，能看懂 ip addr、ping 等查看命令；若对 TCP/IP 分层（传输层/网络层/链路层）有基本印象，会更容易理解下文的收发路径。本节以 CentOS/RHEL/Rocky 系（NetworkManager）为例。

Learning Content · 学习内容

01先配置，再懂包
—— 网络配置与包在系统里如何走动

01用 nmcli 配置静态 IP

NetworkManager 的命令行工具 nmcli 是 CentOS/RHEL/Rocky 等使用 NetworkManager 发行版上配置网络的主流方式。先查看连接与设备，再修改连接配置，最后激活生效。

shell · nmcli 配置静态 IP
# 1) 查看已建立的网络连接 与 设备状态
nmcli connection show
nmcli device status

# 2) 把一个连接改为手动静态 IP（把 <device-name> 换成实际连接名，如 eth0）
nmcli connection modify <device-name> \
  connection.autoconnect yes \
  ipv4.method manual \
  ipv4.addresses 192.168.20.11/24 \
  ipv4.gateway 192.168.20.1 \
  ipv4.dns 192.168.20.1

# 3) 应用配置
nmcli connection up <device-name>

# 4) 改回 DHCP（自动获取）
nmcli connection modify <device-name> ipv4.method auto
nmcli connection up <device-name>
  • ipv4.method manual＝手动指定；auto＝DHCP 自动获取。
  • ipv4.addresses 192.168.20.11/24 中的 /24 是 CIDR 掩码，必须与网关处于同一网段（这里网关为 192.168.20.1）。
  • 改完必须 nmcli connection up 才会生效，方法 auto 与 manual 互斥。
★

核心要点：三要素地址、网关、DNS 缺一不可。地址与网关必须在同一网段（/24 表示前 24 位固定，最后一位不同）。ipv4.method 决定了是「手动」还是「自动」。

02两台主机直连共享网络

适用场景：用网线直连两台电脑，借助其中一台已经连上 VPN 的主机，让另一台也能访问外网。有 VPN 的主机负责「共享」：在网络设置里把 VPN 网卡的流量共享给以太网网卡，并给出以太网的网段与网关地址；另一台主机则配静态 IP，网关指向有 VPN 的那台主机。

shell · 从机配置（网关指向 VPN 主机）
# 另一台主机（没有 VPN 的那台）：
nmcli connection modify <device-name> \
  connection.autoconnect yes \
  ipv4.method manual \
  ipv4.addresses 192.168.20.11/24 \
  ipv4.gateway 192.168.20.1 \
  ipv4.dns 192.168.20.1

nmcli connection up <device-name>
!

易错点：在这里，192.168.20.1 并不是路由器，而是那台有 VPN 的主机自己配置在这条直连网线上的地址。数据包先走到它，再由它转发 / NAT 到 VPN 出口。

★

核心要点：两台主机要用同一网段的地址（如都是 192.168.20.x/24）；从机的网关必须指向VPN主机的直连地址。

03发送流程：进程 → 网卡

应用程序调用 write() / send() 后，数据从用户态进入内核态，逐层「加头」，最终由网卡把比特流送上物理网络。

flowchart TD A[进程
write() / send() 系统调用] --> B[Socket 缓冲区
用户态 → 内核态] B --> C[传输层 TCP/UDP
加 TCP/UDP 头: 源端口 / 目标端口 / 序列号] C --> D[网络层 IP
加 IP 头: 源 IP / 目标 IP / TTL
查路由表决定从哪个网卡发出] D --> E[netfilter
OUTPUT 链 → POSTROUTING 链] E --> F[网络设备层
加以太网帧头 MAC 地址
放入发送队列 TX Ring Buffer] F --> G[网卡驱动 → 网卡硬件
DMA 把数据从内存拷到网卡缓冲区] G --> H[物理网络
发出数据帧]
  • Socket 缓冲区：每个 Socket 有发送、接收两个缓冲区，进程与内核之间异步交换数据；缓冲区满时 send() 会阻塞（或返回 EAGAIN）。
  • 传输层加 TCP/UDP 头（端口、序列号等）；网络层加 IP 头并通过路由表决定出网卡。
  • netfilter 在 OUTPUT → POSTROUTING 之间可以拦截 / 改写（这是 iptables/firewalld 的地盘）。
  • 网络设备层加以太网帧头（源/目的 MAC），挂进 TX Ring Buffer；DMA 让网卡绕过 CPU 直接读内存。
★

核心要点：发送是逐层加头：传输层头 → IP 头 → 以太网帧头。数据先在 OUTPUT 链被检查一次，发出前又在 POSTROUTING 链被检查一次。

04接收流程：网卡 → 进程

发送要「加头」，接收则反过来逐层剥头。网卡收到数据帧后，用硬中断通知 CPU，真正干活的是软中断，最后数据被放到 Socket 接收缓冲区，等进程 read()/recv() 取走。

flowchart TD A[物理网络收到数据帧] --> B[网卡硬件
DMA 把数据帧写入 RX Ring Buffer
触发硬件中断 hi 通知 CPU] B --> C[网卡驱动
硬中断只做最小登记
随后触发软中断 si] C --> D[软中断 ksoftirqd
从 RX Ring Buffer 取出数据帧] D --> E[网络设备层
剥除以太网帧头
识别上层协议 IP / ARP 等] E --> F[netfilter
PREROUTING 链 → INPUT 链] F --> G[网络层 IP
剥除 IP 头 校验目标 IP
判断是本机处理还是转发] G --> H[传输层 TCP/UDP
剥除 TCP/UDP 头
按目标端口找到对应 Socket
写入 Socket 接收缓冲区] H --> I[进程
read() / recv() 读取数据]
!

易错点：硬中断（hi）只做最少的事——登记一下、触发软中断就撒手，把真正的协议处理交给软中断（si，由 ksoftirqd 跑）。这不是「多此一举」，而是为了避免长时间屏蔽中断导致丢包、妨碍其它设备。

★

核心要点：top 里 hi、si 两个字段就来自这套「硬中断→软中断」机制：hi 高＝硬中断多，si 高＝软中断忙。

05netfilter 的拦截点（iptables/firewalld 的地盘）

iptables / firewalld 工作在内核的 netfilter 框架上，共有 5 个 hook 点：PREROUTING、INPUT、FORWARD、OUTPUT、POSTROUTING。理解一个包在哪个链上「被检查」，是配防火墙/做 NAT 的前提。

flowchart TD RX[网卡收到包] --> PRE{PREROUTING 链
DNAT 目标地址转换} PRE -->|目标是本机| INP[INPUT 链] --> PROC[进程] PRE -->|需要转发| FWD[FORWARD 链] FWD --> POST1[POSTROUTING 链] TXP[进程发包] --> OUT[OUTPUT 链] OUT --> POST2[POSTROUTING 链
SNAT / MASQUERADE 源地址转换] POST1 --> SEND[发出] POST2 --> SEND
钩子 / 链作用典型用途
PREROUTING路由决策之前、最先检查收包DNAT（改目标地址，端口映射）
INPUT目标是本机的入包放行 / 拒绝访问本机服务的包
FORWARD主机充当路由器转发的包转发策略、路由器上的访问控制
OUTPUT本机进程发出的包限制本机对外访问
POSTROUTING发出之前、路由决策之后SNAT / MASQUERADE（改源地址、共享上网）
✕

不要记反：改目标地址（DNAT）在 PREROUTING——包进来先改「要去哪」；改源地址（SNAT / MASQUERADE）在 POSTROUTING——包出去前把「从哪来」改成网关地址。MASQUERADE 是 SNAT 的「动态版」，常用于动态 IP（如家用上网共享），无需固定源地址。

06关键机制与性能瓶颈排查

收发路径上有几个反复出现的「要害」：相互共享内存的 Ring Buffer、绕过 CPU 的 DMA、分两步走的硬/软中断，以及进程与内核之间缓冲数据的 Socket 缓冲区。它们一旦超载，就会表现为延迟与丢包。

现象可能原因方向
top 中 si 占用高收包量大，软中断处理繁忙考虑网卡多队列 / RSS、绑核
top 中 hi 占用高硬中断过多开启 RSS / 网卡多队列分散中断
netstat -s 中大量丢包Ring Buffer 满，或 Socket 缓冲区太小调大 ring buffer / socket buffer
wa 占用高与网络 I/O 等待有关（如 NFS）定位是哪个存储/网络挂载卡住
  • Ring Buffer（环形缓冲区）：网卡与内核之间共享的环形内存区，收、发包都通过它传递，避免频繁分配内存。读写速度跟不上就会满了丢包。
  • DMA（直接内存访问）：网卡不经 CPU 直接读写内存，大大降低 CPU 开销。
  • 硬中断(hi) vs 软中断(si)：网卡收包触发硬中断，硬中断只做最少工作，把实际处理甩给软中断，避免长时间屏蔽中断。
  • Socket 缓冲区：每个 Socket 有发送和接收两个缓冲，进程与内核异步交接数据；满时 send() 阻塞或返回 EAGAIN。
★

排查口诀：先看 top 的 hi/si（谁在忙），再看 netstat -s（是否丢包），最后回到 Ring Buffer 与 Socket 缓冲是否太小。
