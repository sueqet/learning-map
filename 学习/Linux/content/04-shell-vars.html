LINUX · Shell

Shell 变量与替换

变量是 Shell 的"地基"：普通变量只活在当前 shell，环境变量靠 export 传给子进程；再学会 $?、$@ 这些特殊变量和 ${...} 的变量替换，你就能读取、改造并对外传递数据，这是写脚本与配置系统的基础。

✓本节学习目标

  • 学完后，你能区分普通变量与环境变量，说清普通变量为什么不传给子进程、export 的作用，并能用 unset 删除变量。
  • 学完后，你能用 $#、$?、$*、$@、$$、$!、$0 等特殊变量读取参数个数、退出码、脚本名等，并解释 $? 与脚本错误处理的关系。
  • 学完后，你能讲清 "$*" 与 "$@" 的区别，并知道在 for 循环遍历参数时应优先使用 "$@"。
  • 学完后，你能用 ${var:-default}、${var:=default}、${var:?message} 三组默认值与报错替换来安全地取值。
  • 学完后，你能用 ${#var} 取长度，用 #/##/%/%% 删除最长/最短前后缀，用 ${var/old/new} 与 ${var//old/new} 替换内容。
  • 学完后，你能知道把 export 写入哪个初始化配置文件可让它永久生效，并区分不同发行版的系统级配置文件名（RHEL 与 Debian/Ubuntu）。
Prerequisites · 前置知识

会用终端、能创建并执行脚本（见 03 Shell 基础与脚本执行）。理解"shell 是一个解释器、脚本由 bash 逐行执行"，并知道命令通常返回一个退出码，是本节理解 $? 的前提。

01基础：变量是什么、怎么定义与使用

01变量命名、赋值与引用

变量就是一个"名称 ↔ 值"的容器。Shell 变量没有类型，所有值本质上都是字符串；变量名必须由字母、数字、下划线组成，且不能以数字开头。赋值时的语法是 名字=值，= 两边不能有空格，这是新手最容易踩的坑。

shell
# 定义与引用
name="hello"           # = 两边不能有空格，否则会当成命令
echo $name             # 输出 hello（变量用 $name 或 ${name} 引用）

# 引用与赋值细节
greet="world $name"    # 双引号会展开变量 → world hello
echo "$greet"
echo '$greet'          # 单引号不展开 → $greet（原样输出）

# 删除变量
unset name             # 删除 name，之后 $name 为空
echo "name=$name"      # 输出 name= （空）
写法作用
name=value给变量赋值（等号两侧不允许有空格）
$name / ${name}取变量的值（${name} 更严谨，可避免歧义）
"..."双引号：会展开其中的 $变量 与命令替换
'...'单引号：不展开，一切按字面输出
unset name删除变量
!

易错点：name = hello（等号两侧有空格）是错的——shell 会把它当成执行命令 name 并传入参数 = 和 hello。另外，不能写 export name = hello，应写 name=hello; export name 或 export name=hello。

02普通变量 vs 环境变量：export 让值传给宝宝

关键区别在于作用范围：普通变量只属于当前 shell / 当前脚本，不传给子进程；环境变量则被"导出"到环境里，当前 shell 及所有子进程都能读到。这个边界决定了"为什么在脚本里定义的变量，命令和子shell 看不到"。export 把普通变量变成环境变量；它声明的是临时的环境变量，退出 shell 后销毁。

类型作用范围说明
普通变量当前 shell / 当前脚本不传递给子进程，仅本进程可见
环境变量当前 shell 及所有子进程用 export 声明，写入进程环境
shell
name="hello"           # 普通变量
export name            # 转为环境变量（也可以 export age=18 一步到位）
export age=18          # 定义并同时导出

echo $name             # 使用变量
env | grep age         # 用 env 查看：age 已进入环境

unset name             # 删除变量；unset age 同理
# 注意：export 是临时的，退出当前 shell 后这些环境变量会被销毁
flowchart TD A["父 shell
定义 name（普通变量）"] -->|"不是环境变量"| B{"启动子进程 / 子 shell"} A -. "export name" .-> E["进程环境（Environment）"] E --> B B -->|"读不到 name ❌"| C["子进程看不到普通变量"] B -->|"读到环境变量 ✔"| D["子进程可读 name / age"]
★

核心要点：普通变量"不出门"，环境变量"带护照（export）". 判断一个变量是否会被子进程看到，就看它有没有被 export。用 env、printenv、export -p 都可以查看当前环境变量。

03特殊变量：位置参数、退出码与进程 ID

除了自己定义的变量，Shell 还内置了一组只读特殊变量，用于读取脚本接收到的位置参数、上一条命令的退出码、以及当前/后台进程号。写脚本时它们几乎必用。

shell
echo $#     # 传递给脚本的参数个数
echo $?     # 上一条命令的退出码（0 成功，非 0 失败）
echo $*     # 所有参数，合成一个字符串
echo $@     # 所有参数，每个参数保持独立（for 循环推荐用这个）
echo $$     # 当前 shell 的进程 ID
echo $!     # 最后一个后台进程的 PID
echo $0     # 当前脚本名称
echo $1     # 第一个参数
echo $2     # 第二个参数（不存在时为空，不报错）
特殊变量含义举例
$#传给脚本的参数个数脚本跑 ./a.sh x y → 2
$?上一条命令的退出码（0 成功，非 0 失败）任何执行过的命令都会更新它
$*所有参数，合成一个字符串加引号后整体为一个值
$@所有参数，每个参数独立for 循环遍历首选
$$当前 shell 的进程 ID常用于生成唯一临时文件名
$!最后一个后台进程的 PID配合 & 使用
$0当前脚本名称打印自己的名字
$1 / $2 ...第 1 / 2 ... 个位置参数不存在时为空，不报错
⚠

易错点：$? 反映的是最近一条执行的命令。只要之间又跑了一条命令（哪怕只是 echo），$? 就会被覆盖。所以想捕获某命令是否成功，要立刻取 $?，或直接用 if cmd; then ... fi 判断。

04"$*" 与 "$@" 到底差在哪

不加引号时两者几乎一样；真正拉开差距的是加了引号之后：$* 把所有参数合并成一个整体字符串（用一个空格分隔），而 $@ 让每个参数保持独立。因此 for 循环逐个遍历参数时，应优先使用 "$@"。

shell
# 假设调用：./a.sh "a b" c
for arg in "$*"; do echo "一个整体: $arg"; done   # 只循环 1 次，arg 是 "a b c"
for arg in "$@"; do echo "独立: $arg"; done        # 循环 2 次：一次 "a b"，一次 "c"

# $* 是整体、$@ 逐个，对比输出：
echo "$*"   # 输出: a b c
echo "$@"   # 输出: a b  c（每个参数独立，但 echo 拼接后看起来差不多）
▲

关键在"空格"：如果参数里包含空格，用 "$*" 会把它们粘成一个值，丢掉参数边界；而 "$@" 会保留每个参数（包括内部空格）为独立元素。所以需要逐参数处理（例如遍历、逐个传给命令）时，务必用 "$@"。

02变量替换：${...} 的默认值、长度与裁剪

05${...} 替换：默认值、长度、删前后缀、替换

用花括号包住变量，就能对"取值"做加工——这就是变量替换。它既能提供默认值、测量长度，也能裁剪前后缀、做替换，是写健壮脚本与解析路径的核心手段。

shell
# 默认值与报错
${var:-default}     # var 未定义或为空时用 default（不改 var 本身）
${var:=default}     # var 未定义或为空时，赋值 default 给它
${var:?message}     # var 未定义或为空时，打印 message 并退出

# 长度
${#var}             # 变量字符串长度

# 删除前后缀
${var#prefix}       # 删除最短前缀匹配
${var##prefix}      # 删除最长前缀匹配
${var%suffix}       # 删除最短后缀匹配
${var%%suffix}      # 删除最长后缀匹配

# 替换
${var/old/new}      # 替换第一个匹配
${var//old/new}     # 替换所有匹配
表达式作用示意结果
${var:-def}var 为空/未定义时用 def（不改 var）unset v; echo ${v:-hi} → hi
${var:=def}为空/未定义时赋值 def 给 varecho ${v:=hi} → hi，且 v=hi
${var:?msg}为空/未定义时打印 msg 并退出未定义则报错终止脚本
${#var}变量字符串长度v=programming → 11
${var#prefix}删除最短前缀匹配${f#*/}，f=/a/b.c → a/b.c
${var##prefix}删除最长前缀匹配${f##*/}，f=/a/b.c → b.c（取文件名）
${var%suffix}删除最短后缀匹配${f%.*}，f=/a/b.c → /a/b
${var%%suffix}删除最长后缀匹配${f%%.*}，f=/a/b.c → /a
${var/old/new}替换第一个匹配${s/ab/XY}
${var//old/new}替换所有匹配${s//ab/XY}
★

记忆口诀：- 只是借（用默认值但不改），= 会赋值，? 会报错退出；裁剪时 # 在前 = 去前缀、% 在后 = 去后缀，单个字符短、双个字符长（一个 #/% 最短匹配，两个 ##/%% 最长匹配）。通配符用法与文件名通配一致（*、?）。

▲

典型组合：取路径的文件名用 ${var##*/}（去掉最长的前缀到最后一个 /）；取路径去掉扩展名用 ${var%.*}（去掉最短后缀，即最后一段 .xxx）。这两句在脚本里高频出现。

06让变量"永久生效"：写入初始化配置文件

前面说过 export 是临时的，退出 shell 就没了。要让每次打开终端都自动带上某个环境变量，就把 export 变量=值 写进 shell 的初始化配置文件。这些文件按"系统级 / 用户级"和"登录式 / 非登录式 shell"分成几档。

文件级别触发时机
/etc/profile系统级登录式 shell，会顺带执行 /etc/profile.d/ 下所有脚本
/etc/bashrc系统级非登录式 shell（RHEL / CentOS / Rocky）
/etc/bash.bashrc系统级非登录式 shell（Debian / Ubuntu）
~/.bash_profile用户级登录式 shell，会调用 ~/.bashrc
~/.bashrc用户级非登录式 shell；建议把用户自定义环境变量写这里
!

发行版差异（务必注意）：笔记里写的 /etc/bashrc 在 RHEL 系是正确的；但 Debian/Ubuntu 用的是 /etc/bash.bashrc，两者含义相同（都是"系统级 / 非登录式 shell"的配置），只是文件名不同。看到 /etc/bashrc 时要先判断是哪个发行版；Debian/Ubuntu 上应写 /etc/bash.bashrc。

flowchart LR L["登录式 shell"] --> P["/etc/profile"] --> PD["/etc/profile.d/*.sh"] L --> UP["~/.bash_profile"] --> UR["~/.bashrc"] N["非登录式 shell\n（如打开新终端）"] --> SYS SYS{"系统级文件"} -->|"RHEL/CentOS"| RC["/etc/bashrc"] SYS -->|"Debian/Ubuntu"| RC2["/etc/bash.bashrc"] N --> UR
shell
# 推荐：写入 ~/.bashrc 让用户级环境变量永久生效
echo 'export MY_VAR=hello' >> ~/.bashrc
source ~/.bashrc        # 立即让配置生效，免得重开终端
echo $MY_VAR            # 输出 hello

# 系统级（对全系统用户生效，需要 root）——注意发行版差异
# RHEL/CentOS:       /etc/bashrc
# Debian/Ubuntu:     /etc/bash.bashrc
★

怎么选：只想让自己用，就往 ~/.bashrc 写；要全系统每个用户都生效，才动系统级文件（/etc/profile 或 /etc/bashrc、/etc/bash.bashrc）。改完用 source（或 . ）加载，或重开终端验证。

▲ 进阶挑战

  • 写一个脚本 args.sh，分别用 "$*" 和 "$@" 遍历所有参数，然后在你的终端里执行 ./args.sh "a b" c，观察两者循环次数差异，并解释原因。

  • 把自己的某个常用变量（例如 EDITOR=vim 或 CLICOLOR=1）写入 ~/.bashrc，source 后验证；若你在 Debian/Ubuntu 上给全系统配置，尝试对比 /etc/bashrc 与 /etc/bash.bashrc 的区别。
