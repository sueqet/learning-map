重定向与文件描述符

让命令的输出「换个地方去」——把结果写进文件、把错误单独收集。理解 0/1/2 三个标准文件描述符，才能把 >、>>、>& 用得正确。

✓本节学习目标

  • 学完后，你能说出 0/1/2 三个标准文件描述符各自的含义与默认去向。
  • 学完后，你能分清「覆盖 >」与「追加 >>」，并说明追加不清空原内容。
  • 学完后，你能用 > / >> 把命令输出收集到文件，并把标准错误单独存一份。
  • 学完后，你能用 bash 特有的 &> / &>> 把 stdout 与 stderr 一起写入同一个文件。
  • 学完后，你能解释 cmd 2>file 1>&2 与 cmd 1>&2 2>file 两种顺序的结果差异，并知道重定向是从左到右依次执行的。
  • 学完后，你能结合缓冲区刷新策略，说明为何 fork 之后 printf 的内容会输出两次。
Prerequisites · 前置知识

会用终端执行简单命令（echo、ls），并已经了解文件与目录的概念即可。缓冲区小节的 printf/fork/write 需要一点点 C 基础，但不影响前几节内容。

Learning Content · 学习内容

01输出重定向：让结果「换个地方去」

01什么是输出重定向

一条命令默认把结果打印到终端（屏幕）。所谓重定向，就是改变输出的去处：不再打印到屏幕，而是写到文件、送到另一个程序或另一条「流」里。

  • 正常结果走标准输出（stdout），如 ls 的文件列表。
  • 报错信息走标准错误（stderr），如 ls /不存在 的报错。
  • 两条流默认都显示在终端，看起来混在一起；重定向后它们可以各走各路。
flowchart LR A[命令 cmd] -->|stdout 1| S[屏幕] A -->|stderr 2| S A -->|"stdout > 1"| F[文件 file] A -->|"stderr 2>> err.log"| E[err.log]
★

核心要点：重定向不改命令「做什么」，只改结果「送到哪」。分清 stdout 与 stderr，是理解日志能分开收集的前提。

02文件描述符：0 / 1 / 2

在 Unix/Linux 中，进程的输入输出通过文件描述符（file descriptor）管理。它是内核「打开文件表」的索引，是一个整数。前三个惯例固定为：

文件描述符名称默认去向用途
0stdin · 标准输入键盘/终端命令读取的数据来源
1stdout · 标准输出终端正常结果输出
2stderr · 标准错误终端错误信息输出
3, 4, 5…用户打开的文件—进程额外打开的文件，从 3 起递增
shell / C
fd = open("example.txt", O_RDWR);   // 打开文件，返回一个 fd（通常是 3）
read(fd, buffer, size);              // 用这个 fd 读
write(fd, buffer, size);             // 用这个 fd 写

本质：每个进程都有一张打开文件表，文件描述符指向其中一项，该项记录偏移量（当前读写位置）、访问模式、文件类型等。每次读写后偏移量自动更新。正因为它只是「指向」，重定向才能通过换这张表里的指向来「偷偷」改变输出的去向。

★

核心要点：文件描述符是内核打开文件表的索引，0/1/2 是系统预置的三个标准流。记住「0 进、1 出、2 错」。

03覆盖 > 与 追加 >>

把输出送到文件时，关键要区分覆盖和追加——这是本节最容易出错的地方。

符号对文件的作用示例
>覆盖：清空文件原有内容，再写入echo hi > log.txt
>>追加：写到文件末尾，不清空原有内容echo hi >> log.txt
shell
# 覆盖：每次重新写，文件里只留最后一次内容
echo "第一行" > log.txt
echo "第二行" > log.txt      # log.txt 现在只有「第二行」

# 追加：接在末尾写，保留之前的内容
echo "第一行" >> log.txt
echo "第二行" >> log.txt     # log.txt 现在是「第一行」+「第二行」

# 只想存错误，不管正常输出
ls /不存在 /etc 2> err.log     # 出错信息进 err.log，正常列表照旧打印到屏幕
!

重要修正：>> 是追加（写到文件末尾、不清空原内容）；只有 > 才是覆盖（清空后写入）。不要把 >> 也描述成「清空文件再写入」——那是一处典型错误。

04bash 特有：&> 与 &>>

当你想把 stdout 和 stderr 同时收进同一个文件，bash 提供了便捷写法，同样区分覆盖与追加：

符号行为说明
&>stdout + stderr 一起覆盖写入等价于 cmd >file 2>&1（覆盖）
&>>stdout + stderr 一起追加写入等价于 cmd >>file 2>&1（追加）
shell
# 一条命令，把正常输出和报错都收进同一个文件
cmd &> all.log          # 覆盖：清空 all.log 后写入
cmd &>> all.log        # 追加：接在 all.log 末尾写入
⚠

区分：&> 是 bash 语法糖；2>&1 是更通用的写法（任何 POSIX shell 都能用）。二者达到的效果一样，但 2>&1 出现在命令里的位置很关键，下一节讲。

05重定向到文件描述符：1>&2 的顺序

语法 <内容> [fd]>&<fd> 表示把某个流「复制/指向」到另一个流，>& 是重定向操作符。它的关键点是：重定向从左到右依次执行。每一步都基于「当前」的状态。

命令执行顺序结果
cmd 2>file 1>&2① stderr → file　② stdout →（现在的 stderr = file）stdout + stderr 都进 file
cmd 1>&2 2>file① stdout →（现在的 stderr = 终端）　② stderr → filestdout 与 stderr 分开
shell
echo "hello world!" 2> test.log 1>&2   # stdout 和 stderr 都进 test.log（推荐）
echo "hello world!" 1>&2 2> test.log   # stdout 还在终端，只有 stderr 进 test.log（分开）
⚠

别用「值传递/赋值」类比：那不是「赋值」，而是「此刻指向哪」。要从左到右逐条看：2>file 先把 stderr 指向 file，1>&2 再把 stdout 指向「现在 stderr 所在的位置」= file，于是两者都进 file。把顺序反过来，第一步时 stderr 还在终端，第二步才把 stderr 挪到 file，于是两者分开。

★

一句话记忆：想让两个流「合流」进同一文件，就让 1>&2 出现在 2>file 之后：cmd 2>file 1>&2。

06进阶：缓冲区与 dup2

输出为何有时「看起来」没生效？这与缓冲区有关。缓冲区是进程内存中的临时区域，数据先攒在缓冲区，达到触发条件再真正写入设备。常见刷新策略：

策略触发场景
无缓冲一写入立刻刷到设备系统调用（write）、fsync
行缓冲遇到换行 \n 刷新终端交互
全缓冲缓冲区写满才刷新普通文件
特殊情况进程退出时自动刷新—
c
# mytest.c
#include <stdio.h>
#include <unistd.h>   // fork()
#include <string.h>
int main(){
    printf("Hello, World!\n");
    fprintf(stdout, "This is a test.\n");
    const char* msg = "hello write\n";
    write(1, msg, strlen(msg)); // 系统调用，直接写
    fork();                    // 产生子进程
    return 0;
}

为什么 fork 后库函数的内容打印两次？把输出从「终端」重定向到「普通文件」时，刷新策略从行缓冲变成全缓冲：printf/fprintf 写完后缓冲区还没满，因此没有刷新。接着执行 fork()，父子进程各继承了一份缓冲区；进程退出时父子各自刷新，于是库函数内容打印了两次。而 write() 是系统调用，直接写内核缓冲区，不经过用户态缓冲，所以只打印一次。

编程中的 dup2：系统调用 dup2(oldfd, newfd) 把已存在的 oldfd 复制到 newfd（若 newfd 已打开则先关闭它）。例如打开 log.txt 得到 fd=3，再 dup2(3, 1) 让 fd=1 也指向 log.txt，于是原本打到屏幕的 stdout 就改写到文件里——这正是 shell 重定向在程序内部的效果。
