# 信号（Signal）

信号是内核向进程发送的异步通知，用于通知进程发生了某个事件。

## 常用信号

| 信号 | 编号 | 默认行为 | 能否被捕获/忽略 | 典型用途 |
|------|------|----------|----------------|---------|
| **SIGHUP** | 1 | 终止 | 能 | 重新加载配置（守护进程约定） |
| **SIGINT** | 2 | 终止 | 能 | Ctrl+C，请求用户中断 |
| **SIGQUIT** | 3 | 终止 + core dump | 能 | Ctrl+\，退出并生成 core dump |
| **SIGTERM** | 15 | 终止 | 能 | 请求程序优雅退出，程序可做清理 |
| **SIGKILL** | 9 | 强制终止 | **不能** | 强制立即杀死进程，内核直接终止 |

## 发送信号

```bash
kill -15 <PID>          # 发送 SIGTERM（默认，优雅退出）
kill -9 <PID>           # 发送 SIGKILL（强制杀死）
kill -1 <PID>           # 发送 SIGHUP（重载配置）
kill -s SIGTERM <PID>   # 等价写法

killall nginx           # 按进程名发送 SIGTERM
pkill -9 nginx          # 按进程名发送 SIGKILL
```

最佳实践：先发 SIGTERM，等几秒无响应再发 SIGKILL：

```bash
kill -15 <PID> && sleep 5 && kill -9 <PID>
```

## 各信号说明

**SIGTERM（15）- 优雅退出**
- 最常用的关闭信号，给程序机会做清理（关闭连接、刷写缓冲区、保存状态等）
- `kill <PID>` 不带参数默认就是发 SIGTERM

**SIGKILL（9）- 强制终止**
- 由内核直接终止，程序没有任何机会执行清理代码
- 无法被捕获、阻塞或忽略
- 适用于程序假死、无法响应 SIGTERM 的情况

**SIGINT（2）- 中断**
- 来源于键盘 Ctrl+C
- 与 SIGTERM 语义相近，区别在于来源：SIGINT 是用户交互触发，SIGTERM 是程序/系统管理触发

**SIGQUIT（3）- 退出并 core dump**
- 来源于键盘 Ctrl+\
- 终止进程并生成 core dump 文件，用于事后调试
- 程序假死时可用此信号获取崩溃现场

**SIGHUP（1）- 重载配置**
- 原始含义：终端断开连接（挂断）
- 守护进程将其约定为"重新加载配置"的信号（社区约定，非系统强制）
- 常见支持程序：nginx、sshd、rsyslog 等

```bash
kill -1 $(cat /var/run/nginx.pid)   # 重载 nginx 配置
```
