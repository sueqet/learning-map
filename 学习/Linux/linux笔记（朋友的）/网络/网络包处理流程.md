# 网络包处理流程

## 发送流程（进程 → 网卡）

```
进程
  │  write() / send() 系统调用
  ▼
Socket 缓冲区（用户态 → 内核态）
  │
  ▼
传输层（TCP/UDP）
  │  添加 TCP/UDP 头（源端口、目标端口、序列号等）
  ▼
网络层（IP）
  │  添加 IP 头（源 IP、目标 IP、TTL 等）
  │  查询路由表，决定从哪个网卡发出
  ▼
netfilter（iptables/firewalld 在此处拦截）
  │  OUTPUT 链 → POSTROUTING 链
  ▼
网络设备层
  │  添加以太网帧头（MAC 地址）
  │  放入发送队列（TX Ring Buffer）
  ▼
网卡驱动 → 网卡硬件
  │  DMA 将数据从内存复制到网卡缓冲区
  ▼
物理网络（发出数据帧）
```

## 接收流程（网卡 → 进程）

```
物理网络（收到数据帧）
  │
  ▼
网卡硬件
  │  DMA 将数据帧写入内存（RX Ring Buffer）
  │  触发硬件中断（HI）通知 CPU
  ▼
网卡驱动
  │  硬中断处理：简单登记后触发软中断（SI）
  ▼
软中断（ksoftirqd）
  │  从 RX Ring Buffer 取出数据帧
  ▼
网络设备层
  │  剥除以太网帧头，识别上层协议（IP/ARP 等）
  ▼
netfilter（iptables/firewalld 在此处拦截）
  │  PREROUTING 链 → INPUT 链
  ▼
网络层（IP）
  │  剥除 IP 头，校验目标 IP
  │  判断是本机处理还是转发
  ▼
传输层（TCP/UDP）
  │  剥除 TCP/UDP 头
  │  根据目标端口找到对应的 Socket
  │  数据写入 Socket 接收缓冲区
  ▼
进程
   read() / recv() 系统调用读取数据
```

## netfilter 的拦截点

iptables/firewalld 工作在内核的 netfilter 框架上，有 5 个 hook 点：

```
网卡收包
  │
PREROUTING     ← NAT 目标地址转换（DNAT）在此处
  │
  ├─ 目标是本机 → INPUT → 进程
  │
  └─ 需要转发  → FORWARD → POSTROUTING → 发出
                                  ↑
进程发包 → OUTPUT → POSTROUTING   ← NAT 源地址转换（SNAT/MASQUERADE）在此处
```

## 关键概念

**Ring Buffer（环形缓冲区）**：网卡和内核之间的共享内存区域，收发包都通过它传递，避免频繁内存分配。Ring Buffer 满了会丢包。

**DMA（直接内存访问）**：网卡直接读写内存，不经过 CPU，减少 CPU 开销。

**硬中断 vs 软中断**：网卡收包触发硬中断（`hi`），硬中断只做最少的工作，把实际处理交给软中断（`si`）执行，避免长时间屏蔽中断。这就是 `top` 中 `hi` 和 `si` 字段的来源。

**Socket 缓冲区**：每个 Socket 有发送和接收两个缓冲区，进程和内核通过它异步交换数据。缓冲区满时 `send()` 会阻塞（或返回 EAGAIN）。

## 性能瓶颈排查方向

| 现象 | 可能原因 |
|------|---------|
| `top` 中 `si` 占用高 | 收包量大，软中断处理繁忙 |
| `top` 中 `hi` 占用高 | 硬中断过多，可考虑开启 RSS/网卡多队列 |
| `netstat -s` 中有大量丢包 | Ring Buffer 满，或 Socket 缓冲区太小 |
| `wa` 占用高 | 与网络 I/O 等待有关（如 NFS） |
