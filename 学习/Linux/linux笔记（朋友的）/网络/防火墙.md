# 防火墙

## iptables 工作原理

iptables 是用户空间的工具，实际规则运行在内核的 **netfilter** 框架中。每个网络包经过内核时，netfilter 会在固定的 hook 点检查规则，决定如何处理这个包。

### 表（Table）

iptables 将规则按功能分为 4 张表，每张表负责不同的事情：

| 表 | 作用 |
|----|------|
| `filter` | 过滤包，决定允许还是拒绝（默认表） |
| `nat` | 地址转换，修改源/目标 IP 和端口 |
| `mangle` | 修改包头字段（TTL、TOS 等），用于 QoS |
| `raw` | 在连接跟踪之前处理，用于跳过连接跟踪 |

### 链（Chain）

链是 netfilter 的 5 个 hook 点，每条链上挂着一组有序的规则：

| 链 | 触发时机 |
|----|---------|
| `PREROUTING` | 包刚进入网卡，路由之前 |
| `INPUT` | 包目标是本机 |
| `FORWARD` | 包需要转发到其他主机 |
| `OUTPUT` | 本机进程发出的包 |
| `POSTROUTING` | 包即将离开网卡，路由之后 |

### 规则匹配与处理

数据包进入一条链后，**从上到下依次匹配规则**，命中第一条匹配的规则后执行对应的 target：

| Target | 含义 |
|--------|------|
| `ACCEPT` | 放行 |
| `DROP` | 丢弃，不响应（对方超时） |
| `REJECT` | 拒绝，返回错误消息（对方立即知道被拒） |
| `DNAT` | 修改目标地址（目标 NAT） |
| `SNAT` | 修改源地址（源 NAT） |
| `MASQUERADE` | 动态 SNAT，自动用出口网卡 IP 替换源 IP |
| `LOG` | 记录日志，继续匹配后续规则 |

若遍历完所有规则都没有命中，执行该链的**默认策略**（ACCEPT 或 DROP）。

### 数据包完整流转路径

```
网卡收包
  │
  ▼
PREROUTING（nat 表：DNAT 在此修改目标地址）
  │
  ├── 目标是本机 ──► INPUT（filter 表：决定是否允许进入进程）──► 进程
  │
  └── 需要转发  ──► FORWARD（filter 表：决定是否允许转发）
                        │
                        ▼
进程发包                POSTROUTING
  │                      ▲
  ▼                      │
OUTPUT（filter/nat）────►┘
（nat 表：SNAT/MASQUERADE 在 POSTROUTING 修改源地址）
```

## iptables 与 firewalld 的关系

两者都是管理内核 netfilter 规则的工具，本质上操作的是同一套机制。

| | iptables | firewalld |
|---|---|---|
| 定位 | 底层工具，直接操作 netfilter 规则 | 动态防火墙管理器，底层仍调用 iptables/nftables |
| 配置方式 | 命令行逐条添加规则 | zone 概念，支持动态修改无需重启 |
| 规则持久化 | 需手动保存 | 自动持久化（`--permanent`） |
| 适用场景 | 精细控制、脚本管理 | 日常服务器管理 |

CentOS 7+ / RHEL 7+ 默认使用 firewalld，Ubuntu 默认使用 ufw（底层也是 iptables）。

## firewalld Zone 概念

Zone 是一组预定义的规则集，根据网络接口所处的信任级别来分配。

| Zone | 信任级别 | 说明 |
|------|---------|------|
| `drop` | 最低 | 丢弃所有入站包，不响应 |
| `block` | 很低 | 拒绝所有入站包，返回拒绝消息 |
| `public` | 低 | 公共网络，仅允许指定服务（默认） |
| `external` | 中 | 外部网络，启用 NAT 伪装 |
| `internal` | 较高 | 内部网络，比 public 宽松 |
| `trusted` | 最高 | 允许所有连接 |

> 命令用法见 [命令大全/firewall-cmd](../../命令大全/firewall-cmd.md)
