算法 · 哈希表与查找

哈希表用空间换时间：一点点额外的内存，换来几乎恒定时间的查找与去重。这一节你会真正理解「为什么需要快速找/去重/统计时，第一反应是字典或集合」，并用它拿下力扣 1 两数之和、49 字母异位词分组、128 最长连续序列、3 无重复字符的最长子串。

✓本节学习目标

  • 学完后，你能说清哈希表「空间换时间」的核心思想，并解释为什么平均查找是 O(1)、什么情况会退化。
  • 学完后，你能用「一遍遍历 + 字典」在 O(n) 内解决【力扣 1 · 两数之和】，并说出字典里存「值 → 下标」而非只存值的原因。
  • 学完后，你能用「排序/计数签名 + 字典分组」解决【力扣 49 · 字母异位词分组】，并比较两种签名做法的复杂度。
  • 学完后，你能用「集合去重 + 只从每段起点向后延伸」解决【力扣 128 · 最长连续序列】，保证整体 O(n)。
  • 学完后，你能用「滑动窗口 + 字典（记录字符最近出现位置）」解决【力扣 3 · 无重复字符的最长子串】，并说明左边界为何能直接跳跃。
  • 学完后，你能快速识别「看到计数/去重/快速找就想到哈希表」，并判断它何时可用、何时应换用排序或有序结构。

01哈希表：空间换时间
（先把「找」变成 O(1)，再谈套路）

原理为什么哈希表快从 O(n) 到平均 O(1)

在列表里找一个值，可能要把整个数组扫一遍，是 O(n)。哈希表（Python 里的 dict 与 set）则把键交给 hash() 算出一个位置，直接跳到那个槽位去取——于是「找 / 去重 / 判断是否存在」变成了平均 O(1)。它用一份额外的表（哈希/映射）换来了速度，这就是空间换时间。

  • 找一处地址：key → hash(key) → 槽位索引，一步定位。
  • 冲突：不同键可能落到同一槽位，用开放寻址 / 拉链解决；极端冲突时复杂度会退化到 O(n)。
  • 键必须可哈希：即不可变对象（int / str / tuple / frozenset）；list、dict、set 不能当键。
  • 哈希表无序：Python 3.7+ 的 dict 只是「保持插入顺序」，它并不按 key 排序。
python
# 直觉示范：两种"统计字符频次"的做法
text = "banana"

# 1) 朴素：对每个字符再扫一遍 —— 本质是 O(n^2)
def count_slow(t):
    res = []
    for ch in sorted(set(t)):
        res.append((ch, t.count(ch)))
    return res

# 2) 哈希表：一遍遍历，一边计数一边查 —— 平均 O(n)
def count_fast(t):
    freq = {}
    for ch in t:
        freq[ch] = freq.get(ch, 0) + 1   # O(1) 查找 + 修改
    return freq

print(count_fast(text))   # {'b':1, 'a':3, 'n':2}
# 从 collections import Counter 也能一行搞定：Counter(text)

核心要点：看到「找、去重、计数、判断存在、配对」这类问题，就想到把数据放进 set/dict，用 O(1) 的查找换掉双层循环或全表扫描。代价是 O(n) 的额外空间，以及「键必须可哈希」这条硬约束。

力扣 1两数之和一遍遍历 + 字典

【力扣题号 1 · Two Sum】给定整数数组 nums 和目标值 target，返回和为 target 的两个数的下标。暴力两层循环是 O(n²)；最优做法是一遍遍历，用字典记录「已经看过的值 → 下标」。

  • 对当前数 x，算它的补数 need = target - x。
  • 若 need 已在字典里，说明之前遇到过它，直接返回 [字典[need], 当前下标]。
  • 否则把 x 和它的下标写进字典，供后面的数来配对。
python
def twoSum(nums, target):
    seen = {}                       # 值 -> 下标
    for i, x in enumerate(nums):
        need = target - x           # 还差多少
        if need in seen:            # 之前出现过
            return [seen[need], i]
        seen[x] = i                 # 记下当前值的位置
    return []

print(twoSum([2, 7, 11, 15], 9))    # [0, 1]（2 + 7 = 9）
print(twoSum([3, 2, 4], 6))         # [1, 2]
print(twoSum([3, 3], 6))            # [0, 1]（两个相同值也能处理）

# 复杂度：时间 O(n)（一次遍历，每步 O(1)）；空间 O(n)（哈希表存已见值）
★

核心要点：字典存的是「值 → 下标」的映射——这样既能 O(1) 查到补数是否出现过，又能立刻拿到它的下标拼成答案。若只记录值不记录下标，就无法同时返回两个下标。

⚠

注意：要理解「B 依靠 A」的方向。我们是向后借：当前 x 去找「前面已经见过的补数」，而不是等以后的人来找它。这样一次循环就够了。若先存当前值再查补数，会错误地匹配到自身。

力扣 49字母异位词分组排序签名 / 计数签名 + 字典分组

【力扣题号 49 · Group Anagrams】把由相同字母重新排列产生的词（异位词）分到同一组。关键是把「判断两个词是否异位」变成一个统一签名，把同签名的词放入同一组。

  • 签名法 1（排序）：把每个词的字母排序，如 "eat"/"tea"/"ate" → "aet"。排序后相同即异位，作为字典键。
  • 签名法 2（计数）：统计 26 个小写字母各自出现次数，组装成元组 (e:1,a:1,t:1,...) 作键，不必排序。
  • 两种都借助哈希表按签名分组，把「两两比较复杂度」降下来。
python
from collections import defaultdict

def groupAnagrams(strs):
    groups = defaultdict(list)
    for w in strs:
        key = "".join(sorted(w))    # 排序后的"签名"
        groups[key].append(w)
    return list(groups.values())

print(groupAnagrams(["eat","tea","tan","ate","nat","bat"]))
# [['eat','tea','ate'], ['tan','nat'], ['bat']]

# 复杂度：时间 O(n·k·log k)（k 为单词平均长度，主要耗在排序每个词）；
# 空间 O(n·k)（分组结果 + 哈希表）。
python
def groupAnagrams_count(strs):
    groups = defaultdict(list)
    for w in strs:
        cnt = [0] * 26
        for ch in w:
            cnt[ord(ch) - ord('a')] += 1
        key = tuple(cnt)            # 26 个计数的元组作为签名
        groups[key].append(w)
    return list(groups.values())

# 复杂度：时间 O(n·k)（不再排序，改为线性统计）；空间 O(n·k)。
★

核心要点：异位词问题的本质是「找一种与顺序无关的表示方式」。排序签名最直观（O(n·k·log k)），计数签名更优（O(n·k)）。哈希表在这里的作用是把「判断异位」从昂贵的比较中解放出来，用签名 O(1) 归组。

力扣 128最长连续序列集合去重 + 只从起点延伸

【力扣题号 128 · Longest Consecutive Sequence】在一个未排序数组中找出最长连续序列的长度（如 [100,4,200,1,3,2] 中最长连续的是 1,2,3,4，长度 4）。朴素做法要先排序再扫，是 O(n log n)。用哈希表可做到 O(n)。

  • 先把所有数放进 set，得到 O(1) 的成员判断与去重。
  • 只对「连续段的起点」开始向后延伸：若 x - 1 not in set，说明 x 是一段连续序列的最小值，才进入 while 找 x+1, x+2, ...。
  • 这样每个元素最多被访问一次，整体仍是 O(n)，不会重复统计。
python
def longestConsecutive(nums):
    numset = set(nums)              # 去重 + O(1) 判断
    best = 0
    for x in numset:
        if x - 1 in numset:         # 不是连续段起点，跳过
            continue
        length = 1
        while x + length in numset: # 从起点向后延伸
            length += 1
        best = max(best, length)
    return best

print(longestConsecutive([100,4,200,1,3,2]))  # 4（1,2,3,4）
print(longestConsecutive([0,3,7,2,5,8,4,6,0,1]))  # 9

# 复杂度：时间 O(n)（每个数最多作为某段的一段被访问一次）；空间 O(n)（set）。
★

核心要点：关键不是「排序」，而是「如何让每段只算一次」。用 x-1 in set 判定「是否为起点」，确保了每段只在它的最小值处被完整统计，从而避免 O(n²) 的重复扫描。

力扣 3无重复字符的最长子串滑动窗口 + 字典记录位置

【力扣题号 3 · Longest Substring Without Repeating Characters】给定字符串 s，找出不含重复字符的最长子串长度。用「滑动窗口」维护一个无重复的窗口，配合字典记录每个字符最近一次出现的位置。

  • left 为窗口左边界，right 用 enumerate 右移。
  • 若当前字符 ch 之前在窗口内出现过，就把 left 跳到 ch 上一次位置的后一位。
  • 窗口长度 = right - left + 1，取最大即可。
python
def lengthOfLongestSubstring(s):
    seen = {}        # 字符 -> 最近一次出现的下标
    left = 0
    best = 0
    for right, ch in enumerate(s):
        if ch in seen and seen[ch] >= left:
            left = seen[ch] + 1     # 左边界直接跳到重复字符之后
        seen[ch] = right
        best = max(best, right - left + 1)
    return best

print(lengthOfLongestSubstring("abcabcbb"))  # 3（"abc"）
print(lengthOfLongestSubstring("pwwkew"))    # 3（"wke" / "kew"）
print(lengthOfLongestSubstring("bbbbb"))     # 1

# 复杂度：时间 O(n)（每个字符最多被左右边界各处理一次）；空间 O(字符集大小)（字典）。
★

核心要点：滑动窗口 + 哈希表的经典组合：哈希表让「判断字符是否重复」瞬间完成，并能记住它的位置、让左边界立刻跳跃，而不是一格一格地回退重扫。这比纯滑动窗口（重复时逐个右移）更进一步。

!

易错点：比较要用「是否在窗口内」，即 seen[ch] >= left。若只写 ch in seen，会错误地把「窗口外已丢弃的旧位置」也当成重复，导致左边界被拉回，结果偏小。
