算法 · 数组与字符串

这是刷题面试的第一块敲门砖。本节只讲两大最常用的技巧——双指针与滑动窗口，用它们在 O(n) 时间、O(1) 额外空间内就地解决数组与字符串问题。每道题都标注【力扣题号】，给出可运行、可直接提交的 Python 代码与复杂度分析：从移除元素 27、移动零 283 到 合并有序数组 88、三数之和 15，再到 长度最小的子数组 209。练熟这些，你就掌握了 90% 数组题的套路。

✓本节学习目标

  • 学完后，你能用快慢双指针在原地完成数组修改，并独立写出【力扣 27 移除元素】与【283 移动零】的 O(n)、O(1) 解法。
  • 学完后，你能说清「覆盖写入」（快慢指针）与「左右夹逼」（相向指针）两类双指针的区别，并判断每种技巧适合的问题特征。
  • 学完后，你能用排序 + 相向双指针 + 去重解出【力扣 15 三数之和】，并口算其 O(n²) 复杂度与剪枝逻辑。
  • 学完后，你能用三指针从后往前原地合并两个有序数组（【力扣 88】），并解释为什么倒序填充能避免覆盖。
  • 学完后，你能用可变滑动窗口求解【力扣 209 长度最小的子数组】，说清窗口何时扩展右边界、何时收缩左边界。
  • 学完后，你能快速判断一道数组/字符串题该用双指针还是滑动窗口，并为每道题写出时间复杂度与空间复杂度。
Prerequisites · 前置知识

已掌握 Python 列表的索引 / 切片 / len / 排序 / 推导式，理解什么是「序列与下标」；同时要有最基本的复杂度概念（知道 O(n)、O(n²)、O(1) 分别指什么）。这些是看懂数组题解法的前提。

Learning Content · 学习内容

01双指针与滑动窗口
（数组与字符串的核心技巧）

力扣 27双指针入门 · 原地移除元素快慢双指针 · 覆盖写入

很多数组题的「最优解」都依赖一个朴素观察：与其真正删掉元素，不如「覆盖」——用一个慢指针划定「已经处理好的前缀」，用一个快指针去扫描，遇到要保留的就写进来。这就是双指针（two pointers），它能把需要额外数组的解法压到 O(1) 额外空间、一次遍历 O(n)。

先看【力扣 27 移除元素】：给你数组 nums 和目标值 val，原地移除所有等于 val 的元素，返回移除后数组的新长度。

python
def removeElement(nums, val):
    slow = 0                      # 下一个可写入的位置，也即最终长度
    for fast in range(len(nums)):
        if nums[fast] != val:     # 只保留不等于 val 的元素
            nums[slow] = nums[fast]
            slow += 1             # 前缀范围扩一格
    return slow                    # slow 就是移除后数组长度

nums = [3, 2, 2, 3]
print(removeElement(nums, 3))     # 2
print(nums)                       # [2, 2, 3, 3]（前两位有效，后面是无用旧值）
flowchart LR
  init["slow = 0"] --> scan["fast 扫描每个元素"]
  scan --> look{"nums[fast] == val ?"}
  look -- "是" --> skip["只看不动，fast++"]
  look -- "否" --> write["nums[slow] = nums[fast]; slow++"]
  write --> skip
  skip --> scan
  scan --> done["返回 slow（新长度）"]
★

核心要点：慢指针 slow 永远是「下一个该填的位置」，同时它恰好等于已经放入的有效元素个数；快指针 fast 负责探路。最终 slow 之前的元素全部合法，后面的旧值可以忽略。复杂度 O(n) 时间、O(1) 空间——原数组被就地覆盖，无需新建数组。

✕

高频错误：① 用 nums.remove(val) 或 pop 逐个删——删除会移动大量元素，最坏是 O(n²)；② 忘了「slow 既是写入指针也是长度」这一层含义，返回的错误值导致答案不对；③ 提前用 for x in nums 遍历已经改过的列表，逻辑混乱。

力扣 283快慢双指针进阶 · 移动零与去重同一套「覆盖写入」的多重变体

「覆盖写入」不只是移除元素，它可以重排数组。看【力扣 283 移动零】：把数组里所有 0 移到末尾，同时保持非零元素的相对顺序，且必须原地。思路与 27 几乎一样，只是把「不等于某值」「不等于 0」后，再把末尾填上 0。

python
def moveZeroes(nums):
    slow = 0
    for fast, x in enumerate(nums):
        if x != 0:                # 非零元素保留，往前挪
            nums[slow] = x
            slow += 1
    # 走到头后，slow 及之后的槽位统统填 0
    for i in range(slow, len(nums)):
        nums[i] = 0
    return nums

nums = [0, 1, 0, 3, 12]
print(moveZeroes(nums))           # [1, 3, 12, 0, 0]

同样地，【力扣 26 删除有序数组中的重复项】也用同一招：因为数组已升序，重复元素一定相邻，用 slow 记录「已去重前缀的末尾」，只要当前元素与前一个已保留元素不同就写入。

python
def removeDuplicates(nums):
    if not nums:
        return 0
    slow = 1                      # 第一个元素必然保留
    for fast in range(1, len(nums)):
        if nums[fast] != nums[slow - 1]:   # 与上一个保留的比，不重复才写入
            nums[slow] = nums[fast]
            slow += 1
    return slow

nums = [0, 0, 1, 1, 1, 2, 2, 3]
print(removeDuplicates(nums))     # 4（前四项有效：0,1,2,3）
问题快慢指针关键判断写入内容收尾
移除元素（27）nums[fast] != val快指针的值无需处理（最终长度由 slow 决定）
移动零（283）nums[fast] != 0快指针的值把 slow 之后全部填 0
去重（26）nums[fast] != nums[slow-1]快指针的值无需处理（结果为前 slow 项）
!

易错点：判断对象各不相同——27 是「和目标值比」，283 是「和 0 比」，26 是「和上一个已保留的元素比」。三个都用一个 slow 指针，但「拿谁比较」要写对。26 里比较的是 nums[slow-1]，不是 nums[fast-1]——因为 nums[fast-1] 可能是已被覆盖的旧值。

力扣 15相向双指针 · 三数之和排序 + 左右夹逼 + 去重剪枝

快慢双指针让 fast 一直往一个方向走；而相向双指针则是让 lo 从头、hi 从尾相向靠拢。它通常配合「先排序」使用，用于求和、配对、找两个数之类的问题。看【力扣 15 三数之和】：在数组里找所有 nums[i] + nums[j] + nums[k] = 0 且下标互不相同的三元组，要求去重。

flowchart LR
  sort["先排序 O(n log n)"] --> fix["固定 i（跳过重复 & 剪枝）"]
  fix --> pair["lo = i+1, hi = n-1"]
  pair --> sum{"nums[i]+nums[lo]+nums[hi] ?"}
  sum -- "== 0" --> ok["记录三元组
lo++ 且 hi-- 同时跳过重复"]
  sum -- "< 0" --> inc["lo++（和太小，加大的）"]
  sum -- "> 0" --> dec["hi--（和太大，减小）"]
  ok --> pair
  inc --> pair
  dec --> pair
python
def threeSum(nums):
    nums.sort()                       # 关键：先排序，才能夹逼 & 去重
    n = len(nums)
    res = []
    for i in range(n - 2):
        if i > 0 and nums[i] == nums[i - 1]:   # 跳过重复的固定值（去重）
            continue
        if nums[i] > 0:                        # 最小元素 > 0，后面的和必 > 0，直接停
            break
        lo, hi = i + 1, n - 1
        while lo < hi:
            s = nums[i] + nums[lo] + nums[hi]
            if s == 0:
                res.append([nums[i], nums[lo], nums[hi]])
                lo += 1
                hi -= 1
                while lo < hi and nums[lo] == nums[lo - 1]:   # 跳过重复的左值
                    lo += 1
                while lo < hi and nums[hi] == nums[hi + 1]:   # 跳过重复的右值
                    hi -= 1
            elif s < 0:
                lo += 1
            else:
                hi -= 1
    return res

print(threeSum([-1, 0, 1, 2, -1, -4]))
# [[-1, -1, 2], [-1, 0, 1]]
★

核心要点：三数之和 = 「固定一个数」+「对剩下的有序子数组做两数之和（相向双指针）」。相向指针为什么能把 O(n²) 的两层嵌套压成 O(n)？因为一旦排序，指针只会单向移动：和太小就 lo++ 变大，和太大就 hi-- 变小，绝不回头。整体复杂度 O(n log n)（排序）+ O(n²)（双指针）= O(n²)，额外空间 O(1)（不计结果）。

✕

高频错误：① 忘了排序——在乱序数组上相向双指针不成立；② 去重漏了，结果出现重复三元组；③ 用了 set 每次 in 判断去重，空间变 O(n)；④ 排序后没有利用 nums[i] > 0 提前 break 剪枝，白白多跑。

顺带一提，相向双指针也能解「有序数组的两数之和」【力扣 167】，逻辑更简单：和等于目标返回下标，小于则 lo++，大于则 hi--。你会在「哈希表」一节用另一种做法把 167 再做一遍，体会「空间换时间」的取舍。

力扣 88从后往前的三指针 · 合并有序数组利用尾部空位，逆序填充避免覆盖

合并两个有序数组，最直觉的写法是「双指针从前往后」，但这需要额外数组，因为小的放前面会覆盖还没比较的元素。妙招是：从后往前。因为 nums1 尾部有空位，且两数组都有序，把「较大者」放到 nums1 的最末尾，永远不会覆盖我们还没用到的东西。

python
def merge(nums1, m, nums2, n):
    i, j, p = m - 1, n - 1, m + n - 1   # i: nums1 有效尾, j: nums2 尾, p: 写入位置
    # 每次把较大的放到 nums1 末尾；nums2 空了就结束（nums1 剩余自然有序）
    while j >= 0:
        if i >= 0 and nums1[i] > nums2[j]:
            nums1[p] = nums1[i]
            i -= 1
        else:
            nums1[p] = nums2[j]
            j -= 1
        p -= 1
    return nums1

nums1, nums2 = [1, 2, 3, 0, 0, 0], [2, 5, 6]
print(merge(nums1, 3, nums2, 3))     # [1, 2, 2, 3, 5, 6]
★

核心要点：三个指针各司其职——i 看 nums1 有效部分、j 看 nums2、p 指向 nums1 要填的位置（从末尾往前）。因为「大的放最后」且尾部是空的，倒序填充不会覆盖任何未处理的有效元素。复杂度 O(m+n) 时间、O(1) 空间。

!

易错点：① 把「从前往后」的写法直接套用会覆盖 nums1 里还没比较的元素；② 忘记 nums1 的有效长度是 m（前 m 个有值，后面的 0 是占位），直接用 len(nums1) 会导致错误；③ 循环结束条件是 j >= 0——当 nums2 已全部放完就结束，因为此时 nums1 剩余的部分已经有序且无需移动。

力扣 209滑动窗口 · 长度最小的子数组可变窗口 · 单调扩展与收缩

滑动窗口（sliding window）专门对付「连续子段 / 子串」类问题——要求满足某个条件，且条件随窗口「扩大或缩小」能维持。看【力扣 209 长度最小的子数组】：给一个正整数数组和一个目标值 target，找和 ≥ target 的最短连续子数组。left 与 right 两个指针共同圈出一个「窗口」，右边界不断向右扩展，一旦窗口和满足条件，就尽量把左边界收进来，找更短的窗口。

flowchart LR
  l["left = 0, cur = 0"] --> r["right 向右扩展
cur += nums[right]"]
  r --> chk{"cur >= target ?"}
  chk -- "是" --> shrink["更新最短长度
cur -= nums[left]; left++"]
  shrink --> chk
  chk -- "否" --> r
  shrink --> ret["返回最短长度（无解返回 0）"]
python
def minSubArrayLen(target, nums):
    left = 0
    cur = 0
    ans = float('inf')
    for right in range(len(nums)):
        cur += nums[right]                    # 右边界扩展，纳入新元素
        while cur >= target:                  # 窗口满足条件，尝试收缩左边界
            ans = min(ans, right - left + 1)
            cur -= nums[left]
            left += 1
    return ans if ans != float('inf') else 0

print(minSubArrayLen(7, [2, 3, 1, 2, 4, 3]))  # 2（子数组 [4,3]）
print(minSubArrayLen(11, [1, 1, 1]))          # 0（无解）
★

核心要点：窗口的两个边界都只向右移动，绝不回头——这是滑动窗口 O(n) 的关键。外层 for 让 right 走完全程；内层 while 只要满足了条件就不断收缩 left，从而得到「以当前 right 结尾的最短可行窗口」。每个元素至多被 right 和 left 各碰一次，所以总 O(n) 时间、O(1) 空间。

!

易错点：① 窗口收缩条件写错——应当用 while cur >= target（满足条件就继续收缩），而不是 if（只收一次，会漏掉更短窗口）；② 忘了处理「始终凑不齐」的情况，应返回 0；③ 窗口必须连续，若题目允许跳过元素（如子序列），滑动窗口就不适用，要换动态规划。

进阶：把「求和 ≥ 某值」换成「包含某字符串所有字符」就变成了【力扣 76 最小覆盖子串】。步骤一样——扩展右边界、用计数器维护窗口内字符、满足条件后收缩左边界，但收缩条件更复杂（要看是否还包含目标字符）。这道题可以作为「进阶挑战」自己动手练一练。
