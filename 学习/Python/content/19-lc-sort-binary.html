小节快速排序与归并排序：分治思想divide & conquer · 稳定性 · 复杂度

排序把无序变有序，是几乎所有算法的地基。两大经典都基于分治（divide & conquer），区别在于「拆」与「合」的顺序与代价：快排在分解阶段就按基准把元素分成「小/等/大」，递归后天然有序；归并则先等分到最小，再在合并阶段逐层有序地两两合并。理解它们的取舍（原地 vs 空间、稳定 vs 不稳定）才能在实际中选对。

python
import random

# ---------- 快速排序（先按基准分左右，再递归） ----------
def quicksort(arr):
    if len(arr) <= 1:
        return arr
    pivot = random.choice(arr)                 # 随机选基准，避免最坏 O(n^2)
    left  = [x for x in arr if x < pivot]      # 小于基准
    mid   = [x for x in arr if x == pivot]     # 等于基准
    right = [x for x in arr if x > pivot]      # 大于基准
    return quicksort(left) + mid + quicksort(right)

print(quicksort([3, 6, 1, 8, 2, 9, 4]))        # [1, 2, 3, 4, 6, 8, 9]

# ---------- 归并排序（先等分，再合并两个有序段） ----------
def mergesort(arr):
    if len(arr) <= 1:
        return arr
    m = len(arr) // 2
    left  = mergesort(arr[:m])
    right = mergesort(arr[m:])
    return merge(left, right)

def merge(a, b):
    res, i, j = [], 0, 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:                # 用 <= 保证相等元素相对次序 → 稳定
            res.append(a[i]); i += 1
        else:
            res.append(b[j]); j += 1
    res.extend(a[i:]); res.extend(b[j:])
    return res

print(mergesort([5, 2, 7, 1, 9, 3]))           # [1, 2, 3, 5, 7, 9]
算法平均时间最坏时间额外空间稳定特点
快速排序O(n log n)O(n²)（选到坏基准）O(log n)（递归栈）否原地交换、cache 友好、实际常更快
归并排序O(n log n)O(n log n)O(n)是稳定、最坏仍有保证，但需额外数组
sorted()/sort()O(n log n)O(n log n)O(n)是Timsort（归并 + 插入）混合，工程首选
flowchart TD A["arr = [3,6,1,8,2]"] --> B["split: [3,6,1]"] A --> C["split: [8,2]"] B --> D["merge to [1,3,6]"] C --> E["merge to [2,8]"] D --> F["merge to [1,2,3,6,8]"] E --> F F --> G["有序结果"]
★

核心要点：快排「先分后合」、归并「先拆后并」。归并用 a[i] <= b[j] 保证稳定性；快排交换基准时会破坏稳定性，所以快排不稳定。随机选基准能让快排平均稳定在 O(n log n)。

!

易错点：若快排固定取首/尾作基准且输入已近乎有序，会退化为 O(n²)。此外，递归版快排的最坏递归深度可达 n，要防栈溢出；用随机基准或三数取中可缓解。

力扣 · 215数组中的第 K 个最大元素快速选择 · 最小堆

【力扣 215】给一个数组和整数 k，返回第 k 大元素（注意：是「第 k 大」，不是第 k 小）。直接排序是 O(n log n)；想要更快可以借用快排的 partition做快速选择（每次只递归「可能含答案的一半」，平均 O(n)），或者维护一个大小为 k 的最小堆（堆顶就是第 k 大，O(n log k)）。

python
import random, heapq

# ============ 力扣 215. 数组中的第 K 个最大元素 ============

# 方案 A：快速选择（借快排的 partition，每次只递归一半）
def findKthLargest(nums, k):
    def quickselect(arr, k):                # k 从 1 开始计数，找第 k 大
        if len(arr) == 1:
            return arr[0]
        pivot = random.choice(arr)
        left  = [x for x in arr if x < pivot]
        mid   = [x for x in arr if x == pivot]
        right = [x for x in arr if x > pivot]
        if k <= len(right):                 # 答案在更大的那一半
            return quickselect(right, k)
        if k <= len(right) + len(mid):      # 答案就是基准
            return pivot
        return quickselect(left, k - len(right) - len(mid))
    return quickselect(nums, k)

print(findKthLargest([3, 2, 1, 5, 6, 4], 2))            # 5
print(findKthLargest([3, 2, 3, 1, 2, 4, 5, 5, 6], 4))   # 4

# 方案 B：维护大小为 k 的最小堆，堆顶即第 k 大
def findKthLargest_heap(nums, k):
    heap = []
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)             # 弹掉最小的，保住最大的 k 个
    return heap[0]

print(findKthLargest_heap([3, 2, 1, 5, 6, 4], 2))       # 5
方法时间复杂度空间适用场景
直接 sorted(nums)[-k]O(n log n)O(n)代码最短，但没利用「只需第 k 大」
快速选择平均 O(n)，最坏 O(n²)O(log n)只需一个答案、不想改动全部顺序
最小堆（size=k）O(n log k)O(k)数据流/输入很大、k 较小时稳定
★

核心要点：「第 k 大」= 排序后从大的那头数第 k 个。快速选择每次只递归可能包含答案的那一半，因此期望 O(n)；而维护 size=k 的最小堆时，堆顶天然是「前 k 大中最小的」，即答案。

!

易错点：快速选择只适合找一个位置，它不是完整排序，结果不能保证数组有序。其次，第 k 大与第 k 小容易搞混：大的一侧递归时 k <= len(right)，别写成小的一侧。

力扣 · 704二分查找与边界模板左闭右闭 · 左闭右开 · 死循环

【力扣 704】给定升序数组和一个 target，返回下标，找不到返回 -1。二分的前提是数据有序：每次比较中间元素，由于有序，可以确定目标只可能出现在左半或右半，从而把搜索区间对半砍。写对二分的唯一难点是边界：循环条件用 <= 还是 <，以及 mid±1 怎么收缩。

python
# ============ 力扣 704. 二分查找 ============
def search(nums, target):
    left, right = 0, len(nums) - 1       # 左闭右闭 [left, right]
    while left <= right:                  # 注意：是 <=
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1               # 排除已比较过的 mid
        else:
            right = mid - 1              # 排除已比较过的 mid
    return -1

print(search([-1, 0, 3, 5, 9, 12], 9))   # 4
print(search([-1, 0, 3, 5, 9, 12], 2))   # -1

# ---------- 左闭右开写法（更适合求边界 / 插入位置）----------
def search_open(nums, target):
    left, right = 0, len(nums)           # 左闭右开 [left, right)
    while left < right:                   # 注意：是 <
        mid = (left + right) // 2
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid                  # 不排除 mid，因为是开区间
    return left if left < len(nums) and nums[left] == target else -1

print(search_open([-1, 0, 3, 5, 9, 12], 9))   # 4
区间约定初始区间循环条件分支收缩能否求边界
左闭右闭[0, n-1]while left <= rightleft=mid+1 / right=mid-1可，较直觉
左闭右开[0, n)while left < rightleft=mid+1 / right=mid适用于边界/重复元素
flowchart TD A["left=0, right=n-1"] --> B{"区间还有元素可查?"} B -- 否 --> C["返回 -1"] B -- 是 --> D["mid = (left+right)//2"] D --> E{"mid 等于 target?"} E -- 是 --> F["返回 mid"] E -- 否 --> G{"target 在右半段?"} G -- 是 --> H["left = mid+1"] G -- 否 --> I["right = mid-1"] H --> B I --> B
★

核心要点：一套口诀：左闭右闭 → 循环用 <=，收缩时 mid±1；左闭右开 → 循环用 <，收缩时 left=mid+1、right=mid。只要「区间约定、循环条件、收缩」三者一致，就不会出错。

!

易错点：用左闭右闭却写 while left < right，会漏掉最后一个元素；用左闭右开却写 right=mid-1，会跳过目标或导致死循环。还有 mid=(left+right)//2 建议写 left+(right-left)//2 防大数溢出。

力扣 · 33搜索旋转排序数组判断有序半区 · 二分

【力扣 33】数组原本升序，在某个位置做了旋转，例如 [4,5,6,7,0,1,2]，要求 O(log n) 找到目标。旋转数组的妙处是：从中间一分为二，至少有一半是严格升序的。我们通过比较 nums[left] 和 nums[mid] 判断哪一半有序，再看目标是否落在该有序区间内，据此收缩区间。

python
# ============ 力扣 33. 搜索旋转排序数组 ============
def search(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        if nums[left] <= nums[mid]:              # 左半段有序
            if nums[left] <= target < nums[mid]:
                right = mid - 1                  # target 在左半段
            else:
                left = mid + 1
        else:                                    # 否则右半段有序
            if nums[mid] < target <= nums[right]:
                left = mid + 1
            else:
                right = mid - 1
    return -1

print(search([4, 5, 6, 7, 0, 1, 2], 0))   # 4
print(search([4, 5, 6, 7, 0, 1, 2], 3))   # -1
print(search([1], 0))                      # -1
情形有序半区判断目标在哪收缩
nums[left] <= nums[mid]左半段升序nums[left] <= target < nums[mid]进左半，否则进右半
nums[left] > nums[mid]右半段升序nums[mid] < target <= nums[right]进右半，否则进左半
★

核心要点：旋转数组断点一侧无序，但另一侧必有序。先定位「哪半有序」，再判断目标是否落在这个有序段里，就能像普通二分一样收缩。`O(log n)`、`O(1)` 空间即达标。

!

易错点：边界判断要含端点：左半用 nums[left] <= target < nums[mid]，右半用 nums[mid] < target <= nums[right]。若写成开区间或漏掉端点，会在旋转点附近漏判。若有重复元素（力扣 81），nums[left]==nums[mid] 需单独处理（如 left+=1）。

力扣 · 56合并区间排序 + 贪心

【力扣 56】给一些区间（如 [1,3],[2,6],[8,10],[15,18]），合并所有重叠或相接的区间，返回不重叠的区间列表。这题的突破口是先把区间按起点排序：排序后，任何重叠只可能发生在相邻区间之间，于是只需要依次判断当前区间是否能接在结果尾部后面即可——典型的排序 + 贪心。

python
# ============ 力扣 56. 合并区间 ============
def merge(intervals):
    if not intervals:
        return []
    intervals.sort(key=lambda x: x[0])        # 按起点升序是关键
    res = [intervals[0]]
    for s, e in intervals[1:]:
        last_s, last_e = res[-1]
        if s <= last_e:                      # 重叠或相接（[1,4] 与 [4,5] 也合并）
            res[-1][1] = max(last_e, e)      # 只更新右端点为较大的那个
        else:                                # 不重叠，追加为新区间
            res.append([s, e])
    return res

print(merge([[1, 3], [2, 6], [8, 10], [15, 18]]))   # [[1, 6], [8, 10], [15, 18]]
print(merge([[1, 4], [4, 5]]))                       # [[1, 5]]
print(merge([[1, 4], [5, 6]]))                       # [[1, 4], [5, 6]]（不相接不合并）
flowchart TD A["原始区间数组"] --> B["按起点排序"] B --> C{"当前区间与结果尾部重叠?"} C -- 是 · 重叠/相接 --> D["更新右端点 = max"] C -- 否 · 不重叠 --> E["追加为新区间"] D --> F["处理下一个区间"] E --> F
★

核心要点：排序（O(n log n)）+ 一趟线性扫描（O(n)）＝总复杂度 O(n log n)、O(log n) 排序栈空间。判断重叠用 s <= last_e（相接也算重叠），合并时只把右端点更新为 max，左端点不用动。

!

易错点：忘记排序会无从下手；懒省事直接 sort() 会比较整行元素，多区间起点相同时会按终点排，无伤大雅但最好显式 sort(key=lambda x: x[0])。重叠条件写成 s < last_e 会漏掉「端点相接」的区间（如 [1,4] 与 [4,5]），应用 <=。
