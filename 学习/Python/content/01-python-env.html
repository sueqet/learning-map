Python 环境与运行

搞定 Python 的第一步：装好解释器、认识 版本、会跑 交互式 REPL 和 .py 脚本，并用 pip / venv 管理依赖——这是之后一切代码练习的地基。

✓本节学习目标

  • 学完后，你能说明 Python 解释器（CPython）与「代码 · 版本 · 运行时环境」的关系，并读懂版本号 3.12.x 的含义。
  • 学完后，你能在一台新机器上确认 Python 已安装并用 python --version / which python 定位解释器。
  • 学完后，你能进入 交互式 REPL 边写边运行，并正确 退出 它、识别 >>> 提示符。
  • 学完后，你能创建并运行一个 .py 脚本，理解代码是从上到下逐行执行的。
  • 学完后，你能用 pip 安装 / 查看 / 卸载第三方包，并解释它装到了哪里。
  • 学完后，你能为项目创建 虚拟环境 venv 并激活它，从而隔离不同项目的依赖。
Prerequisites · 前置知识

前置：你只需会打开一个终端 / 命令行窗口，了解文件与目录的基本概念即可。本节所有命令都需要在终端里敲，因此先确认你知道怎么打开你的终端（Windows 的 PowerShell / 终端，macOS 与 Linux 的 Terminal）。

01环境与运行
从解释器到脚本

1.1认识 Python 与解释器代码如何被「读懂」

Python 是一门解释型、动态类型的高级语言。你写的源码是纯文本，机器并不直接认识它；真正「读懂并执行」它的是解释器。我们最常用的官方实现叫 CPython（用 C 写成的 Python）。

「写一行，执行一行」是解释型语言最直观的印象，也是它上手快、适合交互式探索的原因。
flowchart LR A[你写的 .py 源码] --> B[CPython 解释器] B --> C[逐行翻译为字节码] C --> D[Python 虚拟机执行] D --> E[程序结果 / 输出]
★

核心要点：Python 源码 不是被直接编译成机器码，而是由解释器分词、解析、翻译成字节码再交给虚拟机执行。这个「解释执行」流程让你改完一行就能立刻看到效果。

概念是什么一句话记忆
解释器读取并执行 Python 源码的程序「执行 Python 的人」
CPython官方 / 最常用的解释器实现用 C 写的 Python
字节码解释器翻译出的中间表示源码 → 字节码 → 执行
REPL读入-求值-打印 循环>>> 提示符

1.2安装与检查环境

先检查机器上是否已有 Python，再决定装不装。不同系统装法不同，但验证方式完全一致。

shell
# 查看版本（最常用）
python --version
python3 --version

# 定位解释器可执行文件的位置
which python
which python3
系统常见安装方式验证命令
WindowsMicrosoft Store 或 python.org 安装程序python --version
macOSHomebrew：brew install pythonpython3 --version
Linux包管理器：apt install python3python3 --version
⚠

易错点：macOS / 多数 Linux 上，命令是 python3 而不是 python（python 常指向旧版或不存在）。Windows 上习惯用 python。写脚本、装包前先用 --version 确认你操作的是哪个解释器。

♥

关于版本号：Python 采用「主版本.次版本.微版本」，例如 3.12.4。当前通常选 3.11 及以上的稳定版；前两位（3.12）决定语法特性，第三位（.4）是安全修补版本。

1.3交互式 REPL：边写边跑

在终端直接输入 python（或 python3），就进入交互式 REPL——见到 >>> 提示符，你每敲一行回车就立刻执行并打印结果。适合做小实验、验证语法、当计算器。

python REPL
>>> 2 + 3
5
>>> print("Hello, Python!")
Hello, Python!
>>> name = "小琳"          # 赋值：不会打印任何东西
>>> name
'小琳'
>>> len("你好")
2                         # len() 数的是字符个数
>>> exit()               # 或用 Ctrl + D / Ctrl + Z 退出
★

核心要点：在 REPL 里，裸写一个表达式（如 2+3）会直接显示它的值；print() 则会打印并输出字符串。而赋值语句（如 name = ...）不显示任何结果，这是初学者最常见的困惑。

⚠

易错点：看到 ...（三个点）说明你还在一个未完成的语句里（比如有一个没闭合的括号或引号），直接回车会继续等待，而不是新语句。此时按 Ctrl+C 可取消。

1.4运行 .py 脚本

当你需要写一段较长的程序，就把代码存成 .py 文件，再用解释器一次性执行整个文件。脚本从第一行逐行向下执行，适合真正的项目与自动化。

hello.py
# 文件名：hello.py
# 这是注释，解释器会忽略它

name = "Python"
print("Hello, " + name + "!")
print("1 + 2 =", 1 + 2)     # print 可接收多个参数，用逗号分隔

for i in range(1, 4):       # 循环打印 1 到 3
    print("第", i, "次")
shell
# 在终端里运行整个脚本
python hello.py
python3 hello.py
♥

运行前记住：用 cd 切到 hello.py 所在的目录，或给出完整路径，否则会报 FileNotFoundError。报错信息里的 Traceback 会告诉你「哪个文件、第几行、什么问题」——它不可怕，反而是调试线索。

★

区分两种运行方式：REPL 是一次一行、边想边试；脚本是一次一文件、从上到下执行。写正式代码用脚本，临时验证语法用 REPL。

1.5用 pip 与 venv 管理依赖

pip 是 Python 的包管理器，用来安装、查看、卸载第三方库。venv 是虚拟环境，为每个项目创建一套隔离的 Python 环境，避免不同项目依赖版本互相打架。

shell
# --- pip：安装 / 查看 / 卸载第三方包 ---
pip install requests          # 安装某个包
pip list                      # 列出已安装的包
pip uninstall requests        # 卸载某个包

# --- venv：创建并激活虚拟环境 ---
python -m venv .venv          # 在当前目录创建名为 .venv 的虚拟环境

# Windows（PowerShell）
.venv\Scripts\Activate.ps1

# macOS / Linux
source .venv/bin/activate
命令作用
python -m venv .venv创建虚拟环境目录（含独立的解释器与 pip）
.venv\Scripts\Activate.ps1Windows 激活虚拟环境
source .venv/bin/activatemacOS / Linux 激活虚拟环境
deactivate退出虚拟环境
★

核心要点：进入虚拟环境后，pip install 装的包只属于当前项目，不会污染系统的全局 Python。看到命令行前缀出现 (.venv) 就表示它已激活。

⚠

易错点：`venv` 装出来的环境不随项目自动共享，只在你自己的电脑上。项目要交给别人时，应把依赖清单导出成 requirements.txt（pip freeze > requirements.txt），对方在新环境里用 pip install -r requirements.txt 重建。

1.6编辑器、IDE 与运行方式一览

除了终端，现代开发通常用编辑器 / IDE（如 VS Code、PyCharm），它们提供高亮、补全、调试，还能一键运行和「运行单个单元格」。下面梳理常用运行场所。

场所适合场景特点
REPL（终端）验证语法、快速实验一行一行，即时反馈
脚本文件正式程序 / 自动化整文件从上到下执行，可复用
VS Code | PyCharm中大型项目高亮 / 补全 / 断点调试
Jupyter 笔记本（.ipynb）数据分析 / 教学单元格可保存状态，分段运行
Windows 记事本 / 精简编辑器最早期的入门练习只适合极小片段，不推荐正式使用
♥

建议：新手阶段用 VS Code + Python 插件即可：按 Ctrl+` 打开内置终端，右键「Run Python File」或按 F5 运行当前脚本，既保留终端能力，又有编辑器便利。
