脚本、requests 与FastAPI

把 Python 从「随手写的小脚本」升级成能自动化干活、也能对外提供接口的服务。本节先练好命令行脚本与虚拟环境，再用 requests 让程序主动请求别人，最后用 FastAPI 让程序响应别人的请求——完整跑通「客户端 → 服务端」闭环。

✓本节学习目标

  • 学完后，你能用 shebang、sys.argv 与 argparse 写出可复用的命令行脚本，并正确用 __main__ 入口。
  • 学完后，你能创建 Python 虚拟环境，用 pip 安装与管理第三方包，并解释「每个项目各用一套环境」的价值。
  • 学完后，你能用 requests 发送 GET/POST 请求，携带 params/headers/json，并处理好超时与状态码。
  • 学完后，你能读懂 HTTP 的方法与常见状态码，理解 JSON 请求/响应的结构。
  • 学完后，你能用类型注解给函数签名加「说明书」，理解它在现代开发与工具链中的价值。
  • 学完后，你能用 FastAPI 写出带路由、路径参数、查询参数的最小接口，并通过 /docs 自动文档与 uvicorn 启动验证。
Prerequisites · 前置知识

请先掌握 函数与参数、模块/包与 import、异常处理，并对 JSON、f-string 与类型有一定了解；会用终端执行命令。本节从「写脚本」走向「做成可被调用的服务」，属于工程化方向。

小节命令行脚本与虚拟环境shebang · sys.argv · argparse · venv · pip

日常自动化最常见的形式是「一个 .py 文件直接跑起来」。要写好脚本，先学会三件事：让系统知道用哪个解释器跑、接收命令行参数、以及隔离第三方依赖。

shell
#!/usr/bin/env python3          # shebang：让系统用 python3 解释器跑此脚本
# 保存为 hello.py，然后在终端执行：
#   chmod +x hello.py      # 赋予可执行位（Linux/macOS）
#   ./hello.py Alice       # 运行并传入一个参数

import sys
if __name__ == "__main__":      # 仅作为脚本运行时执行
    print("Hello,", sys.argv[1] if len(sys.argv) > 1 else "world")

参数变多、还要支持 --flag 时，用标准库 argparse 更清晰：它自动生成帮助信息、校验参数、并把非法输入转成友好报错。

python
import argparse

def main():
    p = argparse.ArgumentParser(description="批量重命名图片")
    p.add_argument("dir", help="图片所在目录")
    p.add_argument("--prefix", default="img", help="新文件名前缀")
    p.add_argument("--verbose", action="store_true", help="打印详细日志")
    args = p.parse_args()

    print(f"处理目录: {args.dir}, 前缀: {args.prefix}, 详细: {args.verbose}")

if __name__ == "__main__":
    main()

虚拟环境（venv）为每个项目建一套隔离的 Python 与第三方包，避免不同项目互相覆盖版本。装完激活后，pip install xxx 只装进当前环境。

shell
# 创建并激活虚拟环境
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# 安装第三方包（只安装到当前虚拟环境）
pip install fastapi "uvicorn[standard]" requests

# 把依赖固化成清单，方便别人一键复现
pip freeze > requirements.txt
# pip install -r requirements.txt
★

核心要点：写脚本三件套——shebang + `__main__` 入口让它可运行、argparse 让参数清晰、venv + requirements.txt 让依赖可控。一份能复现的环境，是工程化最被低估的一环。

!

易错点：sys.argv[0] 是脚本文件名，真正参数从 sys.argv[1] 开始。别把第三方包装到系统级环境里——用虚拟环境，并记住 pip freeze 导出清单，避免「我机器上能跑、别人跑不了」。

小节HTTP 与 JSON：请求的门面GET/POST · 状态码 · JSON

不管发请求（requests）还是做接口（FastAPI），都在玩同一套 HTTP 规则：客户端发一个请求，服务器回一个响应。先看懂这张「语言表」，后面就水到渠成。

方法含义典型用途是否带请求体
GET读取 / 查询拿数据、搜索列表通常不带
POST创建提交表单、新建资源带（JSON/form）
PUT / PATCH更新整改 / 局部改带
DELETE删除删除资源常不带
状态码含义示例
2xx成功200 OK、201 Created
3xx重定向301 永久、302 临时
4xx客户端出错404 不存在、422 参数校验失败
5xx服务器出错500 内部错误

现代 API 用 JSON 传数据：请求体是 JSON 字符串，响应体通常也是 JSON，用 .json() 直接解析成 Python 字典。

python
import json

payload = {"name": "Alice", "skills": ["Python", "FastAPI"]}
text = json.dumps(payload, ensure_ascii=False)   # dict -> JSON 字符串
print(text)
print(json.loads(text)["name"])                  # JSON 字符串 -> dict

# 等价的 f-string 也能拼 JSON，但 json.dumps 更可靠、会转义引号等。
print(f'{{"name": "Alice"}}')
flowchart LR A[客户端
requests 脚本] -->|发送 HTTP 请求| B[服务器
FastAPI 应用] B -->|返回 HTTP 响应
JSON| A A -.解析 JSON.- A
★

核心要点：把 HTTP 想成「一问一答」：方法（怎么问）+ URL（问谁）+ 状态码（答得怎样）+ JSON（内容）。requests 是「问」，FastAPI 是「答」，两者共享同一套规则。

!

易错点：别把「请求成功发出」和「服务器返回 200」混为一谈。只要网络通，请求就算发出去了，状态码才表示这次操作的结果——404/500 同样是一个「成功到达服务器」的响应。

小节requests：让程序主动发请求get · post · params · headers · json · timeout · raise_for_status

requests 是 Python 最常用的第三方 HTTP 客户端。核心就一件事：把「我要访问哪个地址、带什么参数、要什么结果」用一行表达出来。

python
import requests

# GET：取数据，查询参数放在 params 里
resp = requests.get(
    "https://httpbin.org/get",
    params={"q": "python", "page": 2},
    headers={"User-Agent": "my-script/1.0"},
    timeout=10,
)
print(resp.status_code)          # 200
print(resp.json())               # 服务器返回的 JSON -> dict

# POST：提交数据，JSON 用 json= 参数（自动设置 Content-Type）
resp = requests.post(
    "https://httpbin.org/post",
    json={"name": "Alice", "age": 30},
    timeout=10,
)
print(resp.json()["json"])       # 回显提交的 JSON

# 关键：状态码不是 2xx 时就抛异常，避免"骗自己成功"
resp.raise_for_status()

多个请求共享同一会话（如登录态 cookie、默认请求头）时，用 requests.Session() 复用连接，比每次 get/post 更快、更省事。

python
import requests

s = requests.Session()
s.headers.update({"Authorization": "Bearer token123"})
r1 = s.get("https://httpbin.org/anything/1", timeout=10)
r2 = s.get("https://httpbin.org/anything/2", timeout=10)
★

核心要点：一定要设 timeout（默认为无、可能永远卡住）；拿到响应先看 status_code，必要时 raise_for_status()；解析数据用 .json() 或 .text。

!

提醒：网络请求随时会失败（域名错、超时、被限流）。要用 try/except 捕获 requests.exceptions.RequestException，并加上重试与日志，否则一个网络抖动就能让整个脚本崩掉。

小节类型注解：给代码加说明书: list[int] · Optional · -> · mypy

Python 是动态类型，但我们可以用类型注解「声明」参数与返回值的预期类型。它不影响运行，却能给编辑器、静态检查器（mypy）和人看，等于一份随代码走、永不失效的说明书。

python
from typing import Optional   # 旧写法；Python 3.10+ 直接用 str | None

def greet(name: str, age: int = 18) -> str:
    """返回一句问候。参数与返回值的类型都用注解标明了。"""
    return f"{name} 今年 {age} 岁"

def sum_scores(scores: list[int]) -> int:
    return sum(scores)          # 编辑器已知 scores 是列表，提示更准

def find_user(uid: int) -> Optional[str]:
    return {"1": "Alice"}.get(str(uid))

def find_user2(uid: int) -> str | None:   # 3.10+ 更简洁
    return {"1": "Alice"}.get(str(uid))
不加注解加注解
编辑体验不知道参数类型，补全/提示盲区IDE 有类型信息，补全、跳转、改引用更准
错误发现运行时才暴露mypy/pyright 在运行前标出类型不匹配
可读性靠注释和约定签名即文档，自解释
运行不受影响同样不受影响（注解默认不校验）
★

核心要点：注解是声明性元数据，默认不会在运行期强制校验，但能给工具链和同事提供精确信息。结合 mypy，你能把大量「运行时才发现」的错误提前到「保存时就报错」。

!

易错点：不要误以为「加上 x: int = 5 就安全了」——普通注解在运行期不会校验，传个字符串照样跑出事。真正在运行期强制校验、并且把注解变成「接口契约」的，正是下面要讲的 FastAPI / Pydantic。

小节FastAPI：极简 Web 接口@app.get · 路径参数 · 查询参数 · Pydantic · uvicorn

FastAPI 用「装饰器 + 类型注解」把「HTTP 路由」写得几乎和普通函数一样。你只管写函数、标注类型，校验、参数解析、序列化、接口文档它都替你干了。

python
from pydantic import BaseModel
from fastapi import FastAPI

app = FastAPI()                       # 应用实例

class Item(BaseModel):                # 数据模型：注解即 => 自动校验
    name: str
    price: float
    tags: list[str] = []

@app.get("/")                         # 路由：GET 根路径
def root():
    return {"message": "Hello, FastAPI"}

@app.get("/items/{item_id}")          # 路径参数：URL 里的 {item_id}
def get_item(item_id: int):
    return {"item_id": item_id, "name": f"Item {item_id}"}

@app.get("/search")                   # 查询参数：?q=...&limit=...
def search(q: str, limit: int = 10):
    return {"q": q, "limit": limit}

@app.post("/items")                   # 请求体：Pydantic 模型自动校验
def create_item(item: Item):
    return {"ok": True, "item": item}

用 uvicorn 启动（FastAPI 本身只是 WSGI 之外的 ASGI 框架，需要一个 ASGI 服务器来跑）：

shell
# main.py 里定义了 app 后用 ASGI 服务器 uvicorn 启动
uvicorn main:app --reload --port 8000

# 命令含义：模块名 变量名 --reload(改代码自动重启)
# 然后浏览器访问：
#   http://127.0.0.1:8000/items/3
#   http://127.0.0.1:8000/search?q=python&limit=5
#   http://127.0.0.1:8000/docs          # 自动生成的交互式接口文档
flowchart TD A[浏览器/curl/requests] -->|"GET /items/3"| B[FastAPI app] B -->|item_id: int 注解| C[Pydantic 校验并转换为 int] C -->|调用 get_item| D[返回字典] D -->|序列化为 JSON| A

因为每个函数都标注了类型，FastAPI 据此自动校验参数（比如 /items/abc 会返回 422，而不是崩溃），并自动生成 OpenAPI 文档（/docs 可交互调试）。

★

核心要点：FastAPI 的心法就一句——「写好一个带类型注解的普通函数，就等于写好一个接口」。类型注解在这里不是装饰，而是被转换成了 校验规则 + 交互式文档 + 序列化契约。

!

易错点：路径参数 /items/{item_id} 里的 {item_id} 必须和函数参数名完全一致；查询参数则是函数里未出现在路径中的参数；带 default 的参数可省略、无默认值的是必填。三者靠「名字」对应，写错名字就会报错或意外必填。
