迭代器、生成器与装饰器

迭代、惰性与「函数套函数」是 Python 从「会写」迈向「写好」的三个招牌特性：学会迭代协议看穿 for 的循环本质，用yield 生成器写出省内存、可流式处理的管道代码，再用装饰器给函数优雅地加上缓存、计时、日志等能力。

✓本节学习目标

  • 学完后，你能讲清楚 for 循环内部如何借助 __iter__ / __next__ 的迭代协议工作，并准确区分「可迭代对象」与「迭代器」。
  • 学完后，你能用 yield 写出惰性求值的生成器函数与生成器表达式，并解释它为何比一次性构建列表更省内存。
  • 学完后，你能用 send / yield from 写状态机与可组合的生成器「管道」。
  • 学完后，你能说出闭包的原理（函数是一等公民、嵌套函数、nonlocal），并理解装饰器对它的依赖。
  • 学完后，你能用 @装饰器 语法配合 functools.wraps、*args/**kwargs 编写可复用的装饰器（如计时、日志、带参数）。
  • 学完后，你能用 functools.lru_cache 对递归做记忆化，把指数级算法降为线性。
Prerequisites · 前置知识

先掌握 函数（定义、参数、返回值、作用域）、列表/元组推导式 与 for 循环 即可。若能先建立「在 Python 里函数本身也是一种对象、可以被传递与返回」的直觉，学闭包和装饰器会顺畅很多。

小节迭代协议：for 循环背后的秘密__iter__ · __next__ · StopIteration

你每天都在用 for，但它其实是个「协议」：任何对象只要实现 __iter__() 方法，就能被 for 遍历。理解这层协议，才能明白为什么列表、字符串、字典、range、生成器都能被统一的循环处理，也能让你写出自己「可被 for」的类。

python
# for 的写法
nums = [1, 2, 3]
for n in nums:
    print(n)

# for 的本质：先拿迭代器，再逐个 next()
nums = [1, 2, 3]
it = iter(nums)          # 调 __iter__() 返回迭代器
print(next(it))          # 1  -> 调 __next__()
print(next(it))          # 2
print(next(it))          # 3
# print(next(it))        # StopIteration 异常（for 内部捕获后结束循环）

# 自定义一个可迭代类
class CountDown:
    def __init__(self, start):
        self.n = start
    def __iter__(self):
        return self                 # 返回自身（自己既是可迭代对象也是迭代器）
    def __next__(self):
        if self.n <= 0:
            raise StopIteration     # 没有更多元素时抛异常
        self.n -= 1
        return self.n + 1

for x in CountDown(3):
    print(x)            # 3  2  1

迭代器
(iterator)		存有「当前进度」、每次 next() 吐出下一个的对象__iter__() + __next__()迭代器对象、生成器、enumerate、zip、map/filter
flowchart TD A[for x in obj] --> B[it = iter obj] B --> C{还有下一个?} C -- 有 --> D[x = next it] D --> E[执行循环体] E --> C C -- 没有 --> F[捕获 StopIteration] F --> G[结束 for]
★

核心要点：for 循环本质是「iter() 拿迭代器 → 反复 next() → 捕获 StopIteration 结束」。迭代器是一次性/有状态的，遍历完就「耗尽」了。

小节生成器：用 yield 写惰性代码yield · 生成器表达式 · 内存

只要函数里出现 yield，它就变成生成器函数。调用它不会立即执行函数体，而是返回一个生成器对象；只有当 next() 或 for 触发时，才「执行到下一个 yield 并暂停」。这就是惰性求值——需要多少算多少，因此特别适合大文件、无限序列和流式处理。

python
# 生成器函数：yield 送出值并暂停
def count_up(n):
    i = 0
    while i < n:
        yield i          # 每次 yield 送出 i 并暂停在这里
        i += 1

g = count_up(3)
print(type(g))           # <class 'generator'>
print(next(g))           # 0
print(next(g))           # 1
print(next(g))           # 2
# print(next(g))         # StopIteration

for x in count_up(5):    # for 里自动结束
    print(x)

# 生成器表达式：惰性的「圆括号推导式」
squares = (x * x for x in range(10))
print(next(squares))     # 0
print(next(squares))     # 1

# 大文件逐行读：内存只占一行，而不是整个文件
def read_lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.rstrip()
特性列表推导式 [...]生成器表达式 (...)
运行时机立即算出全部元素惰性，每取一个才算一个
返回类型listgenerator
内存占用随元素数量增长恒定（与元素总数无关）
能否多次遍历可以只能遍历一次（耗尽即结束）
★

核心要点：数据量很大、或可以「流式」逐段处理时——逐行读大文件、无限序列、网络流——优先用生成器，因为它随用随算、几乎不占内存。

!

易错点：生成器只能被迭代一次。要复用，就重新调用生成器函数，或用 tuple(...) / list(...) 把它物化成一次性可复用容器。

小节生成器进阶：send 与 yield fromsend · yield from · 管道

生成器不仅能「吐出」值，还能「接收」值。用 send() 向生成器内部传参，用 yield from 把子生成器委托出去，就能写出协作式状态机和可组合的数据管道——这是处理大数据、构建流式处理链的利器。

python
# send()：向生成器内部传值，并推进到下一个 yield
def echo():
    while True:
        received = yield
        if received is None:
            continue
        yield received.upper()

g = echo()
next(g)                   # 先推进到第一个 yield（received 为 None）
print(g.send("hello"))    # HELLO
print(g.send("world"))    # WORLD

# yield from：把子生成器「委托」出去，简化嵌套
def chain(*iters):
    for it in iters:
        yield from it

print(list(chain([1, 2], (3, 4), "ab")))   # [1, 2, 3, 4, 'a', 'b']

# 管道：多个生成器首尾相接，惰性链式处理
def numbers():
    for n in range(20):
        yield n

def evens(iterable):
    for n in iterable:
        if n % 2 == 0:
            yield n

def double(iterable):
    for n in iterable:
        yield n * 2

print(list(double(evens(numbers()))))
# [0, 4, 8, 12, 16, 20, 24, 28, 32, 36]
★

核心要点：yield from 相当于把内层生成器的每个值逐个转发出去，写嵌套生成器最简洁；send() 让生成器既能「吐出」又能「接收」，适合状态机和协作式任务。

!

易错点：对一个刚启动的生成器直接 send(值) 会抛 TypeError: can't send non-None value to a just-started generator。规范做法是先 next(g) 或 g.send(None) 推进到第一个 yield。

小节闭包：装饰器的地基一等公民 · nonlocal · 函数返回函数

在 Python 里，函数也是对象（一等公民）：可以赋值给变量、作为参数传入、作为返回值返回。当内层函数「记住」了外层作用域的变量，这种组合就叫闭包。装饰器本质上就是「函数返回函数 + 闭包捕获」。

python
# 函数是一等公民
def outer(msg):
    def inner():
        return msg + "!"
    return inner          # 返回的是函数对象，不是调用结果

greet = outer("Hi")       # greet 现在是一个函数
print(greet())            # Hi!

# 闭包：内层函数「记住」了外层变量 msg
def make_counter():
    count = 0
    def add():
        nonlocal count    # 修改外层（非全局）变量必须 nonlocal
        count += 1
        return count
    return add

c = make_counter()
print(c())                # 1
print(c())                # 2
★

核心要点：即使外部函数已经返回，内层函数仍能访问它创建时所在作用域的变量，并可通过 nonlocal 修改它们。这正是「装饰器用闭包保存上下文」的前提。

小节装饰器：给函数「加料」@语法 · *args/**kwargs · functools.wraps

装饰器是一个接收函数、返回新函数的高阶函数。在定义前加 @装饰器 只是 f = 装饰器(f) 的语法糖，用来在不改动原函数代码的前提下，为其附加日志、计时、权限校验等能力。

python
import functools

# 装饰器：接收函数 func，返回包装后的 wrapper
def logger(func):
    @functools.wraps(func)          # 保留原函数的 __name__ / __doc__ 等
    def wrapper(*args, **kwargs):   # 必须透传参数
        print(f"调用 {func.__name__}，参数 {args} {kwargs}")
        result = func(*args, **kwargs)
        print(f"{func.__name__} 返回 {result}")
        return result
    return wrapper

@logger            # 等价于 add = logger(add)
def add(a, b):
    """两数相加。"""
    return a + b

print(add(3, 5))
# 调用 add，参数 (3, 5) {}
# add 返回 8
# 8

print(add.__name__)   # add（若没有 @wraps，会变成 wrapper）
无糖写法糖写法（两者完全等价）
def add(a, b): ...
add = logger(add)		@logger
def add(a, b): ...
flowchart LR A[原始函数 f] --> B[deco1 包裹得 g] B --> C[deco2 包裹得 h] C --> D[h 供调用]

多个装饰器自下而上逐个包裹：

python
@deco1
@deco2
def f(): ...
# 等价于 f = deco1(deco2(f))   -> 离函数最近的 deco2 先执行
★

核心要点：@decorator 不过是 f = decorator(f) 的语法糖。装饰器返回的是包装函数，所以要透传 *args, **kwargs 并 返回原函数的返回值，否则被装饰函数行为会「走样」。

!

易错点：忘了 @functools.wraps(func)，被装饰函数的 __name__、__doc__ 会被包装函数覆盖，调试和生成文档时会看到一堆 wrapper。

小节装饰器进阶与 functools.lru_cache带参装饰器 · 记忆化 · 时间换空间

装饰器还可以带参数（再多套一层函数），从而让同一个装饰器有不同的配置；而标准库 functools.lru_cache 本身就是一种神奇的装饰器，它会缓存函数参数与结果，避免重复计算——对递归函数尤其有效。

python
import functools
import time

# 带参数装饰器：比普通装饰器再套一层
def timer(label="耗时"):
    def deco(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            start = time.perf_counter()
            result = func(*args, **kwargs)
            print(f"[{label}] {func.__name__}: {time.perf_counter() - start:.4f}s")
            return result
        return wrapper
    return deco

@timer(label="斐波那契")
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

# 记忆化：lru_cache 缓存函数结果，避免重复递归
@functools.lru_cache(maxsize=None)
def fib_cached(n):
    return n if n < 2 else fib_cached(n - 1) + fib_cached(n - 2)

print(fib_cached(30))                 # 832040  快：每个 n 只算一次
print(fib_cached.cache_info())        # CacheInfo(hits=..., misses=31, maxsize=None, currsize=31)
版本时间复杂度说明
朴素递归斐波那契O(2n)大量重复计算子问题
+ @functools.lru_cacheO(n)每个 n 只算一次并缓存，之后直接命中
迭代（循环）O(n)可用循环替代，同样线性
★

核心要点：lru_cache 是「空间换时间」的典型：用内存缓存结果，把指数级的重复递归降到线性。它只对纯函数（相同输入永远相同输出）安全。

!

提醒：被 lru_cache 修饰的函数，参数必须可哈希（list、dict 不行）。若想自动清理、无上限缓存，Python 3.9+ 还提供了更简洁的 @functools.cache。
