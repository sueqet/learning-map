算法 · 链表

上一节你用数组把栈和队列玩得很溜；这一节换一种「靠指针串起来」的结构——链表。它没有 Python 内置写法，却是力扣最简单也最常考的题型：反转、合并、查环、删倒数第 N 个，靠的都是虚拟头节点 + 快慢指针这对黄金搭档。学会它，你就拿到了「原地操作」类算法题的第一块拼图。

✓本节学习目标

  • 学完后，你能在 Python 里用 class ListNode 表示一个单链表节点，并用「虚拟头节点」把一串值构建成链表、用 while cur: 遍历/打印出来。
  • 学完后，你能说清数组 vs 链表在随机访问、增删、内存布局上的差异，并解释为什么「在头部插入/删除」链表是 O(1)、数组却是 O(n)。
  • 学完后，你能手写反转链表（力扣 206）：迭代版用 prev / cur / nxt 三个指针，递归版理解「先反转后半段再回头指」的递推关系，并说出两者的复杂度。
  • 学完后，你能用「虚拟头节点 + 双指针」合并两个有序链表（力扣 21），且不会漏接剩余的那一段节点。
  • 学完后，你能用快慢指针判断链表是否有环（力扣 141）、找到链表中间节点，并解释这样做的空间复杂度为什么是 O(1)。
  • 学完后，你能用「快指针先走 n+1 步」删除倒数第 N 个节点（力扣 19），并理解 LRU 缓存（力扣 146）为什么需要「哈希表 + 双向链表」的配合。
Prerequisites · 前置知识

已学过 Python 的函数、类与 is / 引用（明白 b = a 只是引用别名、修改共享对象两边一起变），以及上一节「算法 · 栈与队列」的指针 / 遍历思维；如果你熟悉递归，看反转链表的递归版会更快上手。能读懂 class ListNode 和 while cur: 即可。

01链表：用「引用」连接的序列
（虚拟头节点 + 快慢指针，五大力扣常考题型）

基础表示链表与虚拟头节点ListNode · dummy · 数组 vs 链表

链表（Linked List）是由一个个节点（node）串起来的线性结构：每个节点存一份数据和一个指向下一个节点的指针。Python 没有内置类型，但为了方便刷题，力扣会默认给你 ListNode。它的好处是：插入 / 删除节点只需改动指针，不需要像数组那样搬移整个区间。

python
# 力扣默认提供的链表节点定义
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

# 用「虚拟头节点」把一串值构建成链表
def build(vals):
    dummy = ListNode()        # 虚拟头：真正返回的是 dummy.next
    cur = dummy
    for v in vals:
        cur.next = ListNode(v)
        cur = cur.next
    return dummy.next

# 遍历 / 打印
def to_list(head):
    res = []
    while head:               # while cur: 就是「还有节点就继续」
        res.append(head.val)
        head = head.next
    return res

head = build([1, 2, 3])
print(to_list(head))          # [1, 2, 3]
print(head.val)               # 1（返回的是第一个真实节点）
维度数组（Python list）链表
内存连续，需要一整块零散，靠指针链接
随机访问 a[i]O(1)O(n)，必须从头遍历
头部插入 / 删除O(n)，要搬移元素O(1)，只改指针

Python 支持内置 list需自己写 ListNode
适合场景频繁随机读、缓存友好频繁增删、栈/队列/哈希桶
★

核心要点：虚拟头节点（dummy）是链表题的万能技巧——先造一个 dummy，让 dummy.next 指向真实头节点。这样「操作头节点」和「操作中间节点」的代码完全统一，省去对「空链表 / 头节点」的特判，结尾直接返回 dummy.next 即可。

✕

高频错误：把 cur.next 改挂了又不备份。链表题里「先保存后继、再改指针、最后整体右移」的三步必须记牢（nxt = cur.next → cur.next = ... → cur = nxt）；否则一旦 cur.next 被改掉，原来的后继就找不回来了。

核心【力扣 206】反转链表Reverse Linked List · 迭代 / 递归

「反转」是链表最经典的入门题，也是你理解「指针重新指向」的入口。核心思想：从头到尾跑一遍，把每个节点的 next 从「指向下一个」改为「指向它前面的节点」，于是链表就被反过来了。

flowchart LR
  subgraph 反转前
    A["1"] --> B["2"] --> C["3"] --> D["None"]
  end
  subgraph 反转后
    D2["None"] --> C2["3"] --> B2["2"] --> A2["1"]
  end
python
# 迭代版：prev 保存「已反转部分的头」，cur 指向「待处理节点」
def reverseList(head):
    prev = None
    cur = head
    while cur:
        nxt = cur.next    # ① 先保存下一个，否则等下被覆盖
        cur.next = prev   # ② 把当前节点的 next 指回前面（反转）
        prev = cur        # ③ prev 前进到当前节点
        cur = nxt         # ④ cur 前进到原来的下一个
    return prev           # 循环结束，prev 就是新的头

# 递归版：先反转后半段，再让 head 的"下一个"回头指向 head
def reverseListRec(head):
    if head is None or head.next is None:
        return head                   # 递归出口：空链或只剩一个
    new_head = reverseListRec(head.next)
    head.next.next = head             # 让后面的节点指回 head
    head.next = None                  # 断开，避免成环
    return new_head
★

核心要点：迭代版的关键是三个引用 prev / cur / nxt 的彼此推进——缺一不可。递归版则抓住「head.next.next = head 把下一个节点指回自己」，再用 head.next = None 断开旧连接。两版复杂度都是 时间 O(n)、迭代空间 O(1)；递归版额外用 O(n) 递归栈。

!

易错点：递归版最后一定要写 head.next = None，否则反转后的链表会成环（旧头节点的 next 仍指向原第二个节点）。另外迭代版返回的是 prev 而非 cur——cur 结束时已经走到 None 了。

进阶【力扣 21】合并两个有序链表Merge Two Sorted Lists · 虚拟头 + 双指针

两个链表都已升序，把它们合成一个升序链表。思路和归并排序的「合并」一致：两个指针各指向两个链表的头，谁小接谁；接完把指针往后挪；哪边先空，就把另一边整段接上。

python
def mergeTwoLists(l1, l2):
    dummy = ListNode()          # 虚拟头，避免对第一个节点特判
    cur = dummy
    while l1 and l2:            # 两个都还有节点才比较
        if l1.val <= l2.val:
            cur.next = l1       # 接更小的那个
            l1 = l1.next
        else:
            cur.next = l2
            l2 = l2.next
        cur = cur.next          # 新链表的指针前进
    cur.next = l1 or l2         # 接上剩余的那一段（很关键！）
    return dummy.next
★

核心要点：结尾的 cur.next = l1 or l2 一石二鸟：l1 or l2 在 Python 里返回「那个不为 None 的对象」，于是既能接上剩余整段，又能优雅处理「其中一个已是空链表」的情况。时间复杂度 O(m+n)、空间 O(1)。

✕

高频错误：比较时用 l1.val < l2.val 却忘了处理相等，或漏写「接剩余段」，导致合并结果丢节点/少一段。另外别去 new 新节点——合并应该复用已有节点、只改指针，否则空间变成 O(m+n) 且破坏原链表。

进阶【力扣 141】环形链表 · 快慢指针Linked List Cycle · Floyd 判圈

快慢指针是链表最实用的技巧：让慢指针 slow 每次走 1 步、快指针 fast 每次走 2 步。若有环，快指针「追」慢指针、必然相遇；若无环，快指针先走到尽头。它只用 O(1) 空间就能判环（不像用集合存节点要 O(n)）。

flowchart TD
  A["从 head 出发"] --> S["slow 走 1 步"]
  A --> F["fast 走 2 步"]
  S --> Q{"fast 或 fast.next 为空?"}
  F --> Q
  Q -- "是（到末尾）" --> R["无环，返回 False"]
  Q -- "否" --> C{"slow == fast ?"}
  C -- "是" --> H["有环，返回 True"]
  C -- "否" --> S
python
def hasCycle(head):
    slow = fast = head
    while fast and fast.next:      # 确保 fast 能走两步
        slow = slow.next           # 慢指针走 1 步
        fast = fast.next.next      # 快指针走 2 步
        if slow is fast:           # 相遇 = 有环
            return True
    return False                    # 走到末尾 = 无环

# 顺带：找链表中点（也是快慢指针，slow 恰好停在中间）
def middleNode(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow

# 进阶：找环的入口节点（力扣 142）
def detectCycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:           # 相遇后，另起一个指针从 head 出发
            p = head
            while p is not slow:   # 两边各走 1 步，相遇处即环入口
                p = p.next
                slow = slow.next
            return p
    return None
★

核心要点：while 条件写成 while fast and fast.next，是为了保证 fast.next.next 这一取不会越界/报错。判环用相遇；找环入口用「同速再走」（把其中一个指针放回 head，二者各走 1 步，相遇点就是入口）。复杂度：时间 O(n)、空间 O(1)。

!

易错点：相遇后不要忘记「把 fast（或新指针）放回 head，再同步走 1 步」这一步——很多人只会判环，却不知如何定位入口。另外，找中点时（无环链表）slow 在 偶数长度时落在靠中间偏右的那个节点，面试时最好主动说明。

进阶【力扣 19】删除倒数第 N 个节点Remove Nth Node From End · 快指针先走 N+1

只遍历一遍，却要删除「倒数第 N 个」节点。做法：让快指针先走 n+1 步，此时快慢指针之间恰好隔 n 个节点；然后两个指针同步前进，快指针走到末尾（None）时，慢指针正好停在「倒数第 N 个」节点的前一个——删掉它的下一个即可。

python
def removeNthFromEnd(head, n):
    dummy = ListNode(0, head)     # 虚拟头，让删除"头节点"也能统一处理
    slow = fast = dummy
    # 快指针先走 n+1 步，让 slow 与 fast 间隔 n 个节点
    for _ in range(n + 1):
        fast = fast.next
    while fast:                    # 快指针没到末尾就同步走
        slow = slow.next
        fast = fast.next
    slow.next = slow.next.next    # 跳过"倒数第 N 个"节点
    return dummy.next              # 返回真实头（可能被删过、也可能是原头）
★

核心要点：虚拟头在这里必不可少——若 n 恰好等于链表长度（要删的是头节点），没有 dummy 就无法统一返回新头。时间 O(n)、空间 O(1)。

✕

高频错误：快指针只走 n 步而非 n+1 步，会把 slow 落在「倒数第 N 个」本身而不是它的前一个，导致删错或报 AttributeError。牢记：删除某节点 = 操作它的前驱节点，所以 fast 要多走 1 步。

综合【力扣 146】LRU 缓存LRU Cache · 哈希表 + 双向链表

LRU（最近最少使用）缓存是链表与哈希表结合的经典难题，也是面试官最爱的「设计题」之一。要求 get 和 put 都 O(1)：哈希表负责 O(1) 定位节点，双向链表负责 O(1) 的「移到头部 / 删尾」。头部 = 最近使用，尾部 = 最久未使用。

python
class DLinkedNode:
    def __init__(self, key=0, value=0):
        self.key, self.value = key, value
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.cache = {}                 # key -> 节点（O(1) 定位）
        self.head = DLinkedNode()       # 伪头/伪尾，避免判空
        self.tail = DLinkedNode()
        self.head.next, self.tail.prev = self.tail, self.head
        self.size = 0

    def _remove(self, node):            # 摘下节点
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_head(self, node):          # 插到头部（最近使用）
        node.prev, node.next = self.head, self.head.next
        self.head.next.prev = node
        self.head.next = node

    def _move_to_head(self, node):
        self._remove(node)
        self._add_head(node)

    def get(self, key):
        if key not in self.cache:
            return -1
        node = self.cache[key]
        self._move_to_head(node)        # 被访问过 → 提到头部
        return node.value

    def put(self, key, value):
        if key in self.cache:
            node = self.cache[key]
            node.value = value          # 更新值并提到头部
            self._move_to_head(node)
        else:
            node = DLinkedNode(key, value)
            self.cache[key] = node
            self._add_head(node)
            self.size += 1
            if self.size > self.cap:    # 超容量：删最久未用（尾部）
                removed = self.tail.prev
                self._remove(removed)
                del self.cache[removed.key]
                self.size -= 1
★

核心要点：为什么是双向链表？因为「删除尾节点」需要 O(1) 拿到尾节点的前驱并接好指针——单向链表做不到。用伪头/伪尾（self.head / self.tail）能让首尾操作不加特判。两操作均为均摊 O(1)，空间 O(capacity)。

想省手写链表，也可用 from collections import OrderedDict，它内部就是「哈希表 + 双向链表」，用 move_to_end + popitem(last=False) 即可（面试常作为「偷懒写法」提及）。

python
from collections import OrderedDict

class LRUCacheOD:
    def __init__(self, capacity):
        self.cap = capacity
        self.cache = OrderedDict()
    def get(self, key):
        if key not in self.cache:
            return -1
        self.cache.move_to_end(key)     # 访问过 → 移到队尾（最新）
        return self.cache[key]
    def put(self, key, value):
        if key in self.cache:
            self.cache.move_to_end(key)
        self.cache[key] = value
        if len(self.cache) > self.cap:
            self.cache.popitem(last=False)   # 删最旧（队首）
