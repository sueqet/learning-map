01栈与队列：抽象数据类型，
到力扣高频题的套路

基础栈与队列：两种最基本的线性结构LIFO · FIFO · list/deque

栈（Stack）是后进先出（LIFO）结构，后加入的元素先被取出；队列（Queue）是先进先出（FIFO）结构，先加入的元素先被取出。两者是「受限制的线性表」：栈只能在一端（栈顶）操作，队列在一端进、另一端出。

特征栈 Stack队列 Queue
顺序后进先出 LIFO先进先出 FIFO
典型操作push / pop / top / emptyenqueue / dequeue / front
Python 实现list（对尾部操作）collections.deque
直觉场景撤销、括号、递归/函数调用、DFS任务排队、消息队列、BFS、打印缓冲
时间复杂度push/pop/top 均 O(1)enqueue/dequeue 均 O(1)
python
from collections import deque

# ---- 栈 Stack：LIFO（后进先出），用 list 对尾部操作 ----
stack = []
stack.append(1)      # push 入栈（栈顶）
stack.append(2)
top = stack[-1]      # 查看栈顶，不弹出
popped = stack.pop() # pop 弹出栈顶 -> 2（后进先出）
empty = not stack    # 判空
print(stack, top, popped, empty)   # [1] 1 2 False

# ---- 队列 Queue：FIFO（先进先出），用 deque ----
q = deque()
q.append(1)          # 入队（队尾）
q.append(2)
front = q[0]         # 查看队头，不弹出
out = q.popleft()    # 出队（队头）-> 1（先进先出）
print(q, front, out) # deque([2]) 1 1

# ---- 对比：用 list 当队列弹出的代价 ----
lst = [1, 2, 3]
lst.pop(0)           # O(n)：要整体左移，数据量大时很慢
★

核心要点：栈与队列操作在最坏情况下都是 O(1)，但前提是「用的地方对」——栈在 list 的尾部操作是 O(1)，而 list.pop(0) 是 O(n)；队列要用 deque 的 popleft() 才回到 O(1)。

!

易错点：不要用 list 当作队列并频繁 pop(0)，也不必手写链表——标准库 collections.deque 就是为你准备的。

力扣 20有效括号 · 栈的经典入门LeetCode 20 · Easy

【力扣题号】20 · 有效的括号

题目：给定只含 ()[]、{}[] 的字符串，判断括号是否有效（顺序正确且类型匹配）。栈天然适合「配对最近的未匹配左括号」——遇到左括号就压栈，遇到右括号就与栈顶匹配，能配上就弹，否则失败。

python
def isValid(s: str) -> bool:
    mapping = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in mapping:               # 是「右括号」
            # 栈为空(没有可配的左括号)，或栈顶不是对应的左括号 -> 失败
            if not stack or stack.pop() != mapping[ch]:
                return False
        else:                            # 是「左括号」-> 入栈
            stack.append(ch)
    return not stack                     # 遍历完栈应恰好为空

print(isValid("()[]{}"))   # True
print(isValid("(]"))       # False
print(isValid("([)]"))     # False  类型交错：先遇到 ] 时栈顶是 [，对不上
print(isValid("{[]}"))     # True

复杂度：时间 O(n)（每个字符入栈或出栈至多一次），空间 O(n)（栈最多存一半长度的左括号，最坏 O(n)）。

★

解题模板：「遇到左括号入栈、遇到右括号弹出并核对」是栈解决「配对 / 匹配 / 就近消除」类问题的通用思路，只是这次配对的是括号字符。

!

易错点：两个必须检查的边界——① 遇到右括号时栈可能已空（如首字符是 )），直接返回 False；② 循环结束后栈可能不为空（如 "(("），必须返回 not stack。

力扣 155最小栈 · 辅助栈设计LeetCode 155 · Easy

【力扣题号】155 · 最小栈

题目：设计一个支持 push/pop/top 且能在 O(1) 内取到 getMin() 的栈。暴力 min(stack) 是 O(n)，要 O(1) 就得用辅助栈同步记录「当前最小值」。

python
class MinStack:
    def __init__(self):
        self.stack = []        # 数据栈
        self.min_stack = []    # 辅助栈：栈顶永远是「当前最小值」

    def push(self, val: int) -> None:
        self.stack.append(val)
        # 辅助栈每次都压入「到当前为止的最小值」，保持两栈等长
        if not self.min_stack or val <= self.min_stack[-1]:
            self.min_stack.append(val)
        else:
            self.min_stack.append(self.min_stack[-1])

    def pop(self) -> None:
        self.stack.pop()
        self.min_stack.pop()   # 等长，因此同步弹出

    def top(self) -> int:
        return self.stack[-1]

    def getMin(self) -> int:
        return self.min_stack[-1]   # O(1)

obj = MinStack()
obj.push(-2); obj.push(0); obj.push(-3)
print(obj.getMin())   # -3
obj.pop()
print(obj.top())      # 0
print(obj.getMin())   # -2

复杂度：每个操作（push/pop/top/getMin）都是 O(1)；空间 O(n)（两个栈）。

★

设计思路：「要 O(1) 拿到某个极值，就用 额外空间换时间」。辅助栈记录历史最小值，就能随时取到当前最小值，这是「空间换时间」的标准范式。

力扣 232用栈实现队列 · 双栈LeetCode 232 · Easy

【力扣题号】232 · 用栈实现队列

题目：只允许用两个栈实现队列的 push/pop/peek/empty。核心是负负得正：一个栈负责入队（in），把元素压入；需要出队/看队头时，把 in 全部倒到另一个栈（out），顺序就反转成「先进先出」了。

python
class MyQueue:
    def __init__(self):
        self.in_stack = []    # 入队：只管压入
        self.out_stack = []   # 出队：倒过来后弹出队头

    def push(self, x: int) -> None:
        self.in_stack.append(x)

    def _move(self) -> None:
        # 只有当 out 栈空时才倒一次，倒完顺序反转，得到 FIFO
        if not self.out_stack:
            while self.in_stack:
                self.out_stack.append(self.in_stack.pop())

    def pop(self) -> int:
        self._move()
        return self.out_stack.pop()

    def peek(self) -> int:
        self._move()
        return self.out_stack[-1]

    def empty(self) -> bool:
        return not self.in_stack and not self.out_stack

q = MyQueue()
q.push(1); q.push(2)
print(q.peek())   # 1
print(q.pop())    # 1
print(q.empty())  # False

复杂度：每个元素至多被移动两次（进 in 一次、倒到 out 一次、弹出一次），所以均摊每个操作 O(1)；空间 O(n)。

★

关键点：不要把 _move 写成每次 pop/peek 都倒一次（那会退化为 O(n²)）。只在 out 为空时才倒，均摊成本才为 O(1)。

力扣 239滑动窗口最大值 · 单调队列LeetCode 239 · Hard

【力扣题号】239 · 滑动窗口最大值

题目：给定数组与窗口大小 k，窗口每次右移一格，求每个窗口的最大值。暴力是 O(n·k)。用单调递减队列能压到 O(n)：队列里存下标，并保持从队头到队尾递减，这样队头永远是当前窗口的最大值。

flowchart TD A["遍历每个元素 nums[i]"] --> B{"队头是否已滑出窗口?
(下标 <= i-k)"} B -- 是 --> C["弹出队头 popleft"] B -- 否 --> D{"队尾元素是否 < 当前值?"} C --> D D -- 是 --> E["弹出队尾 pop（保持递减）"] D -- 否 --> F["窗口成型则取队头为最大值"] E --> F F --> A
python
from collections import deque

def maxSlidingWindow(nums: list[int], k: int) -> list[int]:
    dq = deque()        # 单调递减队列，存的是「下标」
    res = []
    for i, v in enumerate(nums):
        # 1) 队头若已滑出窗口（下标不在 [i-k+1, i] 内），弹出
        if dq and dq[0] <= i - k:
            dq.popleft()
        # 2) 保持递减：把比 v 小的队尾全部弹出（它们不可能是最大值了）
        while dq and nums[dq[-1]] < v:
            dq.pop()
        dq.append(i)     # 当前下标入队
        # 3) 窗口成型后，队头就是窗口最大值
        if i >= k - 1:
            res.append(nums[dq[0]])
    return res

print(maxSlidingWindow([1,3,-1,-3,5,3,6,7], 3))  # [3,3,5,5,6,7]

复杂度：时间 O(n)（每个下标至多入队一次、出队一次），空间 O(k)（队列最多存 k 个下标）。

★

单调队列模板：「先用下标判出窗、再用值维护单调、最后取队头」。判出窗和取队头都要用下标（不能只看值），这样才能知道元素何时过期。

!

易错点：为什么不用普通队列/直接 max()？因为窗口每次移动，被挤出去的「最大值」难以快速定位，单调队列用一次入队 + 一次出队摊平了这份开销，才能在 O(n) 内完成。

力扣 739每日温度 · 单调栈LeetCode 739 · Medium

【力扣题号】739 · 每日温度

题目：给定温度数组，求「每个温度后，要等几天才出现更高温」，没有就填 0。用单调递减栈存「还没等到更高温」的下标：一旦遇到更高温，就把栈里所有更小的下标弹出并结算等待天数。

python
def dailyTemperatures(temperatures: list[int]) -> list[int]:
    n = len(temperatures)
    ans = [0] * n
    stack = []          # 单调递减栈，存「还没等到更高温」的下标
    for i, v in enumerate(temperatures):
        # 遇到更高温：把更小的下标弹出，并计算 i - prev（等待几天）
        while stack and temperatures[stack[-1]] < v:
            prev = stack.pop()
            ans[prev] = i - prev
        stack.append(i)  # 当前下标入栈
    return ans           # 留在栈里的(没等到更高温)保持 0

print(dailyTemperatures([73,74,75,71,69,72,76,73]))
# [1, 1, 4, 2, 1, 1, 0, 0]

复杂度：时间 O(n)（内层 while 看似嵌套，但每个下标至多入栈一次、出栈一次，均摊 O(n)），空间 O(n)。

★

单调栈模板：「遇到更大值就结算栈顶」。单调栈特别适合「找下一个更大/更小元素」「求某元素左右边界」这类题，能把暴力从 O(n²) 降到 O(n)。

!

易错点：别把 while 当成每次外层循环都要 O(n)——它每次弹出一个之前压入的下标，总数不超过 n，所以整体是 O(n)。这正是「摊还分析」的直观体现。
