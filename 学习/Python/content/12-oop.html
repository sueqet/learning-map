面向对象

面向对象用「类」把数据和行为组织在一起：学会定义类与对象、用继承与多态复用代码、用魔术方法与 @property 让对象更像内置类型——让程序从「一长串过程」变成可扩展、可维护的模型。

✓本节学习目标

  • 学完后，你能用 class 定义一个类，用 __init__ 初始化属性，并创建出一个个对象实例。
  • 学完后，你能说清 self、实例属性、类属性与 __init__ 的含义及调用时机。
  • 学完后，你能用继承复用父类代码、用 super() 调用父类初始化，并通过重写方法实现多态。
  • 学完后，你能用 __repr__/__str__/__eq__/__len__ 等魔术方法让对象支持打印、比较、排序与遍历。
  • 学完后，你能用 @property 实现受控属性，并区分 @classmethod 与 @staticmethod。
  • 学完后，你能判断何时用「继承」、何时用「组合」，写出低耦合、易扩展的类。
Prerequisites · 前置知识

先掌握 函数、作用域 以及 列表/字典 等容器即可。理解「变量可以引用任何对象」之后，就能把「一类东西的属性与行为」封装进一个类里。

Learning Content · 学习内容

01对象与类
从「蓝图 → 实例」看面向对象本质

小节类是蓝图，对象是实例class · __init__ · self

类用来描述「一类东西」共有的属性（数据）和行为（方法）；对象（也叫实例）则是按照这份蓝图造出来的具体个体。定义类时，__init__ 会在创建对象时自动调用，用于给实例设置初始属性；方法的第一个参数 self 由 Python 自动传入，指向当前这个实例。

python
class Dog:
    # __init__：创建对象时自动调用，用来给实例设置初始属性
    def __init__(self, name, age):
        self.name = name       # 实例属性：每个对象各自独立
        self.age  = age

    # 实例方法：第一个参数必须是 self
    def bark(self):
        return f"{self.name} 在汪汪叫!"

# 创建对象（实例化）——不需要 new，直接像调用函数一样
d = Dog("旺财", 3)
print(d.name)      # 旺财
print(d.bark())    # 旺财 在汪汪叫!
print(type(d))     # <class '__main__.Dog'>

# self 就是对象本身，是调用时自动传进来的
print(d is d)      # True
概念说明例子
class定义类型的「蓝图」class Dog: ...
对象 / 实例按蓝图造出的具体个体d = Dog("旺财", 3)
__init__初始化方法，实例化时自动调用def __init__(self, name):
self指向当前实例，由 Python 自动传入self.name = name
方法定义在类里的函数，描述行为def bark(self):
★

核心要点：创建对象不需要 new 关键字，直接 Dog(...) 即可；self 是当前实例，是 Python 自动传进去的，调用时不要再手动传 self。

!

易错点：忘写 self 参数、或方法里漏掉 self. 前缀，会让属性变成「只属于方法内部的局部变量」，对象之间就取不到各自的数据。

小节继承与多态：复用与统一class Child(Parent) · super · 重写

继承让子类自动拥有父类的属性和方法，从而复用代码；子类可以重写父类方法给出更具体的表现。当不同子类以同一个方法名、却按各自的类型输出不同结果时，这就是多态——调用者只需要知道「它会 speak()」，不用关心它是狗还是猫。

python
class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return f"{self.name} 发出了声音"

class Dog(Animal):                 # Dog 继承 Animal
    def __init__(self, name, breed):
        super().__init__(name)     # 复用父类初始化逻辑
        self.breed = breed
    def speak(self):               # 重写(override)父类方法
        return f"{self.name} 汪汪叫"

class Cat(Animal):
    def speak(self):
        return f"{self.name} 喵喵叫"

# 同一个方法名，不同类型 → 不同表现：多态
animals = [Dog("旺财", "金毛"), Cat("小花")]
for a in animals:
    print(a.speak())       # 旺财 汪汪叫 / 小花 喵喵叫

# 关系判断
print(isinstance(Dog("旺财", "金毛"), Animal))   # True
print(issubclass(Dog, Animal))                  # True
flowchart TD A["Animal 基类"] --> B["Dog 子类"] A --> C["Cat 子类"] B --> D["实例 旺财"] C --> E["实例 小花"] D -. "同一消息" .-> F["各自输出 = 多态"] E -. "同一消息" .-> F
★

核心要点：在子类里用 super().__init__(...) 复用父类初始化，而不是硬编码父类名（如 Animal.__init__(self,...)）——这样在多继承时也能遵循正确的解析顺序(MRO)。

!

易错点：一旦子类定义了 __init__，Python 就会覆盖父类的 __init__，此时父类的初始化不会自动执行；若你需要父类属性，必须显式调用 super().__init__()。

小节魔术方法：让对象更像内置类型__repr__ · __str__ · __eq__ · __len__ · __lt__

以双下划线开头和结尾的方法叫魔术方法（也叫特殊方法/dunder）。它们让自定义对象支持内置语法：打印时调用 __str__、交互式展示用 __repr__、== 比较用 __eq__、len() 用 __len__、排序用 __lt__ 等。实现了这些，对象用起来就和内置类型一样自然。

python
class Book:
    def __init__(self, title, pages):
        self.title = title
        self.pages = pages

    def __repr__(self):                 # 面向开发者的精确表示（repr() 与容器打印用）
        return f"Book({self.title!r}, {self.pages})"

    def __str__(self):                  # 面向用户的友好表示（print()/str() 优先用）
        return f"《{self.title}》共 {self.pages} 页"

    def __eq__(self, other):            # 让 == 按内容比较
        return self.title == other.title and self.pages == other.pages

    def __lt__(self, other):            # 让对象支持小于号，从而可排序
        return self.pages < other.pages

    def __len__(self):                  # 支持 len()
        return self.pages

b1 = Book("三体", 302)
b2 = Book("球状闪电", 200)
print(b1)                    # 用 __str__：《三体》共 302 页
print(repr(b1))              # 用 __repr__：Book('三体', 302)
print([b2, b1])              # 容器里用 __repr__
print(sorted([b1, b2]))      # 用 __lt__ 按页数排序
print(len(b1))               # 用 __len__：302
!

易错点：__repr__ 面向开发者（可复现、无歧义），__str__ 面向用户（美观）。print() 优先用 __str__；若只实现了 __repr__，print 会回退用它。两者都不要返回非字符串。

小节@property 与封装：受控地读写属性@property · setter · _ 约定 · name mangling

封装解决「外部应怎么读/写属性」的问题。约定用单个下划线 _balance 表示「内部属性」；再用 @property 把取值方法包装成「像属性一样访问」的接口，并在 setter 里做校验。这样既保留了 a.balance 的简洁，又能在赋值时拦截非法值。

python
class Account:
    def __init__(self, balance):
        self._balance = balance          # 约定：单下划线 = 内部属性

    @property                            # 把取值方法变成 "属性"
    def balance(self):
        return self._balance

    @balance.setter                      # 定义赋值时逻辑
    def balance(self, value):
        if value < 0:
            raise ValueError("余额不能为负")
        self._balance = value

a = Account(100)
print(a.balance)      # 100  像访问属性，其实是方法
a.balance = 250       # 触发上面的 setter
# a.balance = -5      # 抛 ValueError: 余额不能为负

# name mangling：以双下划线开头的名字会被改写
class Person:
    def __init__(self):
        self.__secret = "x"
    def reveal(self):
        return self.__secret

p = Person()
# p.__secret          # AttributeError
print(p._Person__secret)   # 实际被改写为这个名字（仍是约定式私有）
写法作用说明
@property属性读取把方法包装成属性访问，可在其中校验/惰性计算
@x.setter属性赋值当对实例的 x 赋值时触发
@x.deleter属性删除当 del 实例.x 时触发（可选）
_name约定私有仅规范，外部仍能访问
__name名称改写被改写为 _类名__name，外部直接访问会报错
★

核心要点：@property 的妙处在于：外部代码仍然写 a.balance，但你不用改调用方就能在中间加校验、日志或缓存。它是「接口不变、实现可变」的典型手法。

小节实例方法 · 类方法 · 静态方法self · cls · @classmethod · @staticmethod

三种方法的区别在于「第一个参数是谁」。实例方法第一个参数是 self（当前实例）；类方法用 @classmethod 装饰，第一个参数是 cls（类本身），可访问/修改类属性；静态方法用 @staticmethod 装饰，既不接收 self 也不接收 cls，只是一个「放在类里的普通函数」，常见于工具函数或工厂。

python
class Employee:
    company = "ACME"          # 类属性：所有实例共享

    def __init__(self, name):
        self.name = name      # 实例属性：每个实例独立

    def intro(self):          # 实例方法：第一个参数 self
        return f"{self.name} @ {self.company}"

    @classmethod              # 类方法：第一个参数 cls（类本身）
    def set_company(cls, name):
        cls.company = name

    @staticmethod             # 静态方法：没有 self / cls
    def is_adult(age):
        return age >= 18

e = Employee("Ann")
print(e.intro())              # Ann @ ACME
e.set_company("ACME2")        # 通过实例也能调，但改的是类属性
print(e.intro())              # Ann @ ACME2
print(Employee.is_adult(20))  # True
print(Employee.is_adult(17))  # False
类型装饰器第一个参数能访问什么典型用途
实例方法无self实例属性 + 类属性依赖具体实例状态的行为
类方法@classmethodcls类属性、其它类方法工厂方法、修改类级配置
静态方法@staticmethod无什么都不依赖实例/类工具函数、纯计算
!

易错点：把「与实例无关的纯逻辑」写成实例方法，会让它需要 self 却用不到，又容易让人误以为它依赖实例状态。该用 @staticmethod 或 @classmethod 时，别图省事全写成实例方法。

小节实战：dataclass 与设计取舍@dataclass · 组合优于继承

当一个类主要是「存放若干字段」的数据容器时，手写 __init__/__repr__/__eq__ 很繁琐。用 @dataclass 装饰器可以自动生成这些样板代码，让类更清爽。同时在设计阶段要思考：何时用继承（is-a），何时用组合（has-a）。

python
from dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float
    def dist(self):                  # 仍可自定义方法
        return (self.x ** 2 + self.y ** 2) ** 0.5

p1 = Point(3, 4)
print(p1)          # Point(x=3, y=4)    自动生成 __repr__
print(p1.dist())   # 5.0
print(Point(1, 2) == Point(1, 2))      # True  自动生成 __eq__

# --- 组合 vs 继承：汽车“拥有”引擎（has-a），而不是“是”引擎（is-a）---
class Engine:
    def start(self):
        return "引擎启动"

class Car:
    def __init__(self):
        self.engine = Engine()     # 组合：Car 拥有一个 Engine
    def start(self):
        return "Car: " + self.engine.start()

print(Car().start())   # Car: 引擎启动
★

核心要点：优先用组合（has-a）复用——它耦合更低、更灵活、更容易测试；只在「子类确实是一类父类」（is-a）且层次清晰、确实需要多态时，才用继承。避免为了复用而造过深的继承链。

!

易错点：为「省代码」硬造继承（比如让 Car 继承 Engine），会让概念错位、产生不该有的方法。这种「为了复用而继承」是典型坏味道。
