GIT · 协作

安装与配置 Git

从零把 Git 装进你的电脑、跑通第一次身份配置。学完你不仅能安装并验证 Git，还能安全地设置提交者身份、理解三类配置文件，避开新手最常见的坑。

✓本节学习目标

  • 学完后，你能说清 Git 是什么，以及它和集中式版本控制（如 SVN）的本质区别。
  • 学完后，你能在 Windows / macOS / Linux 上安装 Git，并用 git --version 确认安装成功。
  • 学完后，你能用 git config 正确配置 user.name 与 user.email，并说清 system / global / local 三层配置的作用与优先级。
  • 学完后，你能借助 git help / --help 查阅命令用法，并掌握 shell 的 Tab 键补全。
  • 学完后，你能避开新手最常见的配置误区（未设身份就提交、误以为 add 等于保存等）。
Prerequisites · 前置知识

会用最基本的命令行：打开终端、切换目录、运行一条命令并读懂常见英文报错（本课程会把高频报错逐一翻译对照）；知道「文件」「文件夹」「保存」是什么；从未用过版本控制也没关系，本节从概念讲起。

Learning Content · 学习内容

01基础篇 · 让 Git 在你的机器上跑起来

01为什么需要版本控制· Git 是什么 · 分布式 vs 集中式

写代码、改文档、调配置，最怕的就是「改坏了回不去」。版本控制系统（Version Control System，VCS）的核心价值就是记录每一次改动：你可以随时回看任何一个历史版本、查出某行代码是谁在哪次改动里引入的，还能安全地和别人一起修改同一份代码而不互相覆盖。

Git 是当今最流行的分布式版本控制系统（Distributed Version Control System，DVCS）。「分布式」是相对老式的「集中式」（以 SVN 为代表）而言的，理解这一层，你就摸到了 Git 一半的设计哲学。

shell
# 让 Git 管理一个项目的极简流程（先混个眼熟，原理后面会展开）
mkdir demo && cd demo        # 建一个项目目录并进入
git init                     # 初始化：让 Git 开始跟踪这个目录
echo "Hello Git" > a.txt     # 随便写一个文件
git add a.txt                # 把改动放上「暂存区」
git commit -m "first commit" # 生成一个不可变的历史快照
对比维度集中式（SVN）分布式（Git）
仓库位置只有一份，放在中央服务器每个人本地都有一份完整副本
提交（commit）必须联网，提交到中央服务器先在本地提交，离线也能完成
查看历史依赖服务器本地随时可看完整历史
分支（branch）较重、开销大轻量，鼓励频繁使用
单点故障服务器挂了，全员无法工作任意一个副本都能恢复整个仓库
flowchart LR subgraph CVCS["集中式（SVN）"] direction TB C[(中央仓库)] C --> A1["开发者 A"] C --> A2["开发者 B"] C --> A3["开发者 C"] end subgraph DVCS["分布式（Git）"] direction TB R1[(本地仓库 1)] <--> R2[(本地仓库 2)] R2 <--> R3[(本地仓库 3)] R1 <--> R[(远程仓库)] end
★

核心要点：在 Git 里，每位开发者的本地仓库都是完整的副本，包含全部历史。正因如此，没有网络也能提交、也能查历史——这就是「分布式」最直白的好处。

02安装与检查版本· git --version

Git 支持 Windows、macOS、Linux 三大平台。安装方式因系统而异，但判断「是否装好」的方式完全一样——在终端里输入 git --version，看到版本号就说明 Git 就绪了。

shell
# Windows：去 git-scm.com 下载 .exe，或一键安装
winget install --id Git.Git -e

# macOS：用 Homebrew（需先装好 brew）
brew install git

# Linux（Debian / Ubuntu 系）：
sudo apt-get update && sudo apt-get install git

# 无论哪种方式，装好后都打开一个【新的】终端窗口，再验证：
git --version    # 期望形如：git version 2.45.0.windows.1

为什么一定要开新终端？因为终端在启动时会加载环境变量，安装程序写入的路径只有在新窗口才生效。老窗口里运行 git 可能仍提示「不是内部或外部命令」。

★

核心要点：判断是否装好，只看 git --version 有没有输出版本号。若报「找不到命令」，多半不是没装，而是 shell 还没找到它——先开个新终端窗口再试。

!

常见 Linux 报错：有时候会看到 can't find 'remote-https'。这不是 Git 坏了，而是系统只装了命令本体、缺少 git-remote-https 等配套包，用 sudo apt-get install git 装完整即可。

03用户信息与三类配置文件· system / global / local

Git 每次提交都会记录「是谁、用哪个邮箱」做的修改，所以第一次用之前必须设置 user.name 与 user.email，否则提交会直接失败。这些配置存在三类不同范围的配置文件里，统一用 git config 读写。

shell
# 设置这台机器上的全局身份（推荐，只需一次）
git config --global user.name  "你的名字"
git config --global user.email "you@example.com"

# 只想让【某个项目】用不同身份，就进到该项目目录里再设（不加 --global）
git config user.name  "项目专用名字"

# 查看当前生效的所有配置（同键若有多个值，后面的覆盖前面的）
git config --list

# 只查看某一项
git config user.name
层级作用范围配置文件位置何时使用
--system整台机器、所有用户安装目录下的 gitconfig极少用，影响全系统
--global当前用户、所有仓库用户主目录的 ~/.gitconfig日常个人设置（最常用）
--local仅当前这个仓库仓库内 .git/config给单个项目覆盖全局
★

优先级：取值时按 local → global → system 依次覆盖，即越靠近具体仓库，优先级越高。同一个配置项，仓库内的 local 会盖掉 global。

✖

最容易卡住新手的错：还没设 user.email 就去 git commit，会看到报错 Please tell me who you are。别去改 --system，直接用 git config --global ... 设置即可，然后重试提交。

04使用 --help、命令补全与常见误区· 自学与避坑

Git 命令繁多记不住很正常，它内置了离线文档：遇到不确定的命令，用 --help 查一下就够；再配合 shell 的 Tab 键补全，日常效率会高很多。

shell
# 三种等价查法，任选其一
git help config          # 打开完整手册页（man page）
git config --help        # 命令后跟 --help，同上
git config -h            # 简版帮助：只列出常用参数，更短更快

# 用 Tab 键补全命令与参数（bash / zsh）
git ch[TAB]              # 自动补全为 git checkout
git checkout m[TAB]      # 自动补全分支或文件名
!

误区一：文档与教程读得越多越记不住。正确姿势是「到什么场景查什么命令」：先记住少量高频命令，真用到了再查。

!

误区二：以为 git add . 就是把文件「保存」了。其实 add 只是把改动放进暂存区（staging area），真正生成历史快照的是 commit。这个差别下一节「三大区域」会重点讲。

!

误区三：看 git config --list 时同一项出现两次是正常的——前面是系统/全局的值，后面是当前仓库覆盖后的值，别误以为是重复配置。

▲ 进阶挑战

  • 在本机完成安装后，用 git --version 验证并把输出记下来（Windows 下记得开新终端，确认不是旧窗口的环境变量问题）。

  • 运行 git config --list，挑一个出现两次的键（如 user.name），解释两次出现的来源，并判断当前实际生效的是哪一个值。
