GIT · 协作

分支与切换

开发不只有一条主线。这一节告诉你：分支的本质是指向某个 commit 的引用，HEAD 指向当前分支；你用 git branch / switch / merge 在一条条线上并行工作，再干净地把它们合回来。

✓本节学习目标

  • 学完后，你能准确说出「分支」的本质：它是指向某个 commit 的可移动引用，而不是代码副本，因此创建分支几乎零成本。
  • 你能说清 HEAD 与当前分支的关系，并解释为什么「切分支」只是让 HEAD 改指另一条。
  • 你能用 git branch / switch -c / checkout -b 创建、切换、删除分支，并在正确的线上提交。
  • 你能用 git branch -a/-v/--merged 与 git diff 查看、重命名并比较各分支。
  • 你能用 git merge -m 合并分支，并分辨快进（fast-forward）与普通合并的差别。
Prerequisites · 前置知识

会用命令行；会用 git init / add / commit / log 建立并查看提交，理解「一次 commit 就是一份快照」。还没碰过分支？没关系，这一节就从你已有的提交说起。

04分支与切换
一支可移动的指针

小节分支的本质：一支可移动的指针reference · HEAD

很多人以为分支是「复制一份代码」——这是最大的误解。分支（branch）本质是一个指向某个 commit 的引用（reference），就像给一个提交贴了张可移动的标签。它极其轻量：只是「名字 + 提交哈希」，不复制任何文件。所以 git branch 建分支快得惊人。

  • 分支 = 指向某 commit 的指针：每次在它上面提交，这个指针就自动前移到最新提交。你看到的「分叉」，其实是两条指针各自往前走。
  • HEAD 指向当前分支：HEAD 是一个引用，指向「你正在工作的那条分支」。git branch 里打 * 的分支就是 HEAD 所在。切分支，就是让 HEAD 改指向另一条分支，工作区内容随之切换。
  • 各分支默认互不影响：这就是多人/多任务能并行开发、互不打扰的原因；需要汇合时用 merge（见第 4 小节）。
%% 分支是一支可移动的指针：feature 的指针随提交不断前移；HEAD 指向当前分支（这里先 feature 后 main）；最后 merge 把分叉合回一条线。 gitGraph commit id: "C1" commit id: "C2" branch feature commit id: "F1" commit id: "F2" checkout main commit id: "C3" merge feature

上图里：feature 从 C2 分出后自己前进了两步（F1、F2），main 原地又提交了 C3——于是两条线分叉；一次 merge feature 把它们重新汇合。全程没有复制一份代码，只是让不同的指针移动、再合并。

★

核心要点：分支不是代码副本，而是一支指向某个 commit 的可移动指针。HEAD 不指向提交，而是指向当前分支；你切的不是「代码」，而是让 HEAD 换了一条指针。

小节创建、切换与删除分支git branch · switch · checkout -b

一张图看懂这套命令：创建只是加一条名字，切换才移动 HEAD。最常用的组合是「建一条新分支并马上切过去」，用 git switch -c（旧版写作 git checkout -b）。

shell
git branch feature            # 新建 feature，但仍在 main（HEAD 不动）
git branch                    # 列表里出现 feature，* 仍在 main
git switch feature            # 切到 feature（HEAD 改指它）
git switch -c newpage         # 新建 newpage 并立刻切过去（最常用）
git checkout -b newpage       # 等价旧写法（checkout -b）

git branch -d feature         # 删除已合并的分支（安全）
git branch -D feature         # 强制删除未合并的分支（慎用）
命令作用要点
git branch <name>新建分支只加一条名字，HEAD / 当前分支不变
git switch <name>切换分支HEAD 改指该分支，工作区内容随之切换
git switch -c <name>新建并切换建 + 切一步到位；等价旧写法 checkout -b
git checkout <name>切换分支（老命令）身兼「恢复文件」职责，易混淆，推荐 switch
git branch -d <name>删除已合并分支未合并且有独特提交时会拒绝，需 -D 强制
⚠

关于 checkout：它是老命令，既能切分支，也能用 git checkout -- file 撤销某个文件的改动——两件事混在一起，初学者常混淆。用 git switch 只处理「切换」，语义更清晰。

!

未提交的改动不属于任何分支。如果你在工作区留了改动再 git switch，这些改动会被「带着走」到新分支。想干净地切换，先 git commit 或 git stash 暂存，否则容易改错地方。

小节查看、重命名与比较分支branch -a/-v/--merged · diff

分支多了要能看清每一支的位置。几个常用「查看」命令，配合 git diff 就能比较任意两个分支的差异。

shell
git branch -a                         # 列出所有本地分支 + 远程分支（origin/xxx）
git branch -v                         # 每个分支 + 它指向的提交哈希 + 最近提交信息
git branch --merged                   # 已并入当前分支的分支（通常可安全删除）
git branch --no-merged                # 尚未并入的分支（删除需谨慎）

git branch -m newname                 # 重命名【当前】分支
git branch -m oldname newname         # 重命名指定的分支

git diff main feature                 # 比较 main 与 feature 的内容差异
git diff --stat main feature          # 只看文件级改动统计（行数）
命令用途
git branch -v显示每条分支指向的提交，快速看清各分支顶端
git branch -a包含远程分支（以 remotes/origin/xxx 开头）
git branch --merged列出已并入当前分支的分支，是「可安全删除」的依据
git branch -m重命名分支；不改变任何提交，安全
git diff A B比较 A、B 两个分支（或提交）的内容差异
★

核心要点：分支名只是给人看的「名字」，Git 真正认的是提交哈希。所以重命名、删除一个已合并的分支都不会丢任何提交——它们只是把「那支指针」或「那条名字」收走而已。

小节快进合并与普通合并fast-forward · merge

合并（git merge）就是让当前分支指针去「够到」另一条分支。它有两种结果，取决于两条分支是否分叉。

shell
# 场景一：feature 直接领先 main（main 没有新提交）→ 快进
git switch main
git merge feature              # 快进：main 指针直接滑到 feature 尽头，无合并提交

# 场景二：main 在 feature 分出后又提交过 → 普通合并
git switch main
git commit -m "main 独自的提交"
git merge feature -m "merge feature 到 main"   # 生成一个合并提交（merge commit）
%% 普通合并（three-way merge）：main 与 feature 各自前进形成分叉，merge 生成一个合并提交把两条线连起来。 gitGraph commit id: "C1" commit id: "C2" branch feature commit id: "F1" checkout main commit id: "C3" merge feature commit id: "C4"
合并类型发生时机结果是否新增提交
快进合并快进
fast-forward		目标分支直接领先，未分叉直线推进（一条直线）否，main 指针直接后移
普通合并
three-way merge		两条分支各自有新提交（已分叉）生成一个合并提交把两边连起来是，多出一个 merge commit
★

核心要点：合并就是「让当前分支指针指向目标」。快进（fast-forward）只在当前分支没有新提交时发生——指针往后滑一步，历史是一条直线、不产生合并提交；一旦分叉，就必须做一次普通合并、留下一个 merge commit 来连接两条线。

!

想要「保留分支痕迹」时就别用默认快进。如果你希望历史里能看到「这条改动是在 feature 分支上开发的」，用 git merge --no-ff feature 强制生成一次普通合并（留下 merge commit）；只想历史平整时，默认的快进就够。
