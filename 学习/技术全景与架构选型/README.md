# 技术全景与架构选型 学习区

> **定位：本仓库的「总地图」。** 不背 API、不抠配置项，而是建立一张技术全景地图：听到任何技术名词（Vue、React、FastAPI、微服务、Docker……），能快速说出它**在哪一层、解决什么问题、代价是什么、什么场景不该用**；AI 给出方案时，能**问出关键问题**并**用最小成本验证**。
>
> 需求来源与完整的掌握清单见 [`学习需求与掌握清单.md`](学习需求与掌握清单.md)。

## 四个入口

| 入口 | 是什么 | 适合什么时候用 |
| --- | --- | --- |
| [`index.html`](index.html) 学习大纲 | 13 个模块 / 76 个知识点，六个阶段，可勾选进度 | 系统地学一遍 |
| [`atlas.html`](atlas.html) 技术图鉴 | 111 个技术名词按六层铺成地图；每个名词都写明在哪层、解决什么、代价、什么时候别用、常搭配、可替代；可并排对比 | 听到一个陌生名词时查；想看「全景」时逛 |
| [`sandbox.html`](sandbox.html) 架构沙盘 | 三个场景（校园二手交易、电商大促、企业 AI 知识库）。在人力预算内选型，然后「上线运行一年」，经历账单、越权、密钥泄露、重复扣款、误删库、流量洪峰等事件，最后评级并逐项复盘 | 学完一阶段后检验判断力 |
| [`review.html`](review.html) 闪卡复习 | 间隔重复（5 档），「名词 → 用途」与「用途 → 名词」两种练法，记录连续学习天数 | 每天几分钟，把名词记牢 |

## 学习目标：会问、会判、会验

| 能力 | 含义 | 例子 |
| --- | --- | --- |
| 会问 | 找出方案没说清的边界、代价、失败模式 | 「支付失败自动重试，会不会扣两次钱？」 |
| 会判 | 拿方案对照当前阶段的约束 | 「3 人团队上 12 个微服务 + K8s，过度设计了」 |
| 会验 | 用最小原型、测试、日志、压测拿证据 | 「同一个幂等键请求两次，断言只扣一次款」 |

## 全站体验

- **深色模式**：右上角切换「跟随系统 / 浅色 / 深色」，所有页面同步。
- **全局搜索**：任意页面按 `⌘K` / `Ctrl K` 或 `/`，同时搜索模块、知识点、图鉴名词和工具。
- **名词悬停卡片**：详解页正文里出现的技术名词带虚线下划线，悬停或点按即弹出图鉴卡片。
- **阅读辅助**：顶部阅读进度条；宽屏左侧目录（滚动高亮、已学会打勾）；`←` `→` 键翻页；学完一节自动推荐下一个未学会的知识点。
- **继续学习**：大纲和仓库总入口都会显示「上次学到哪」和今天到期的闪卡数。

## 如何维护

- **加知识点**：改 `content/assets/modules.js` 的 `pts`，并在详解页加同 id 的 `<section class="topic">`。
- **加图鉴名词**：在 `content/assets/atlas-data.js` 加一条记录；图鉴、闪卡、搜索和悬停卡片会自动出现。
- **加详解页**：复制 `content/_template.html`；进度、翻页、考核、目录都由 `learn.js` 处理，页面里只写内容、`CONFIG`、`QUZ` 和演示脚本。
- 改完运行校验（Windows / macOS / Linux 通用）：

```bash
node content/_validate.js
```

- 有 Playwright 时再跑浏览器冒烟测试：

```bash
node content/_smoke.js
```

## 说明

- 纯静态 HTML / CSS / JS，双击即可离线使用（字体从 Google Fonts 加载，离线时回退为系统字体）。
- 内容按「概念级」组织，代码片段只用于理解「它长什么样」。产品架构拆解描述的是业界公开做法的抽象，不代表任何公司的真实内部架构。技术生态变化快，做真实选型前请再查一次官方文档。
