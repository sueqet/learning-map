# 技术全景与架构选型 学习区

> **定位：本仓库的「总地图」。** 不背 API、不抠配置项，而是建立一张技术全景地图：听到任何技术名词（Vue、React、FastAPI、微服务、Docker……），能快速说出它**在哪一层、解决什么问题、代价是什么、什么场景不该用**；AI 给出方案时，能**问出关键问题**并**用最小成本验证**。
>
> 需求来源与完整的掌握清单见 [`学习需求与掌握清单.md`](学习需求与掌握清单.md)。

## 主入口：交互式学习大纲

用浏览器打开 **`index.html`** 开始学习：

- **12 个模块 / 69 个知识点**，按「建地图 → 学比较 → 练判断 → 练验证 → 练 AI 协作」五个阶段推进。
- 每个模块卡片底部有 **「掌握标志」**：能用自己的话讲出来，才算学会。
- **可打勾记录进度**（localStorage 键 `arch_outline_progress_v1`），大纲与详解页**双向同步**。
- **可搜索 / 可筛选**：直接搜「缓存」「幂等」「Docker」等关键词。

## 学习目标：会问、会判、会验

| 能力 | 含义 | 例子 |
| --- | --- | --- |
| 会问 | 找出方案没说清的边界、代价、失败模式 | 「支付失败自动重试，会不会扣两次钱？」 |
| 会判 | 拿方案对照当前阶段的约束 | 「3 人团队上 12 个微服务 + K8s，过度设计了」 |
| 会验 | 用最小原型、测试、日志、压测拿证据 | 「同一个幂等键请求两次，断言只扣一次款」 |

## 如何维护

- 大纲数据在 `index.html` 的 `STAGES` / `MODULES` 数组里；新增知识点时同步在详解页加同 id 的 `<section class="topic">`。
- 详解页只写内容和底部的 `CONFIG` / `QUZ` / 演示脚本；进度、翻页、判分都在 `content/assets/learn.js`，不要在页面里重复实现。
- 改完运行校验（Windows / macOS / Linux 通用）：

```bash
node content/_validate.js
```

- 有 Playwright 时可以再跑浏览器冒烟测试：

```bash
node content/_smoke.js
```

## 说明

- 纯静态 HTML / CSS / JS，双击 `index.html` 即可离线使用（字体从 Google Fonts 加载，离线时自动回退为系统字体）。
- 内容按「概念级」组织，代码片段只用于理解「它长什么样」。技术生态变化快，文中工具以 2026 年的主流选择为准；做真实选型前请再查一次官方文档。
