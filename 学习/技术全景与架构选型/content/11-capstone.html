MODULE 11 · 技术全景

最小闭环：一条线跑通

不贪多，先跑通一条线。

✓本节学习目标

  • 说出为什么推荐 Vue + FastAPI + PostgreSQL + Docker 作为初学者的第一条完整技术线。
  • 讲清一个待办应用从「点添加」到「数据入库」再到「列表刷新」的每一步，各在哪一层。
  • 理解「接口文档就是契约」，知道契约如何让前后端并行开发。
  • 遇到白屏、422、500、数据丢失、本地能跑容器里不行等症状，知道先查哪一层、看哪里。
  • 说出替换任意一环（换 React、换 Django、换 MySQL）要改什么、不用改什么。
Pre-requisites · 前置知识

学完 02–10 模块。本节的代码都只要求「读得懂它在干什么」；想真正动手，可以把本页代码交给 AI 生成完整项目，再用本页的排障表去验证和调试——这本身就是 12 模块要练的「AI 协作」。

Part 1 · 一条线

01界面 → 接口 → 数据 → 部署

知识点 1推荐起点：为什么是这四件starter stack · 每层一件，覆盖闭环

面对这么多选择，「不贪多，先跑通一条线」最有效。下面这条线每一环都对初学者友好，四件东西各占一层，组合起来正好是一个完整闭环。用它做出一个能实际运行的小项目后，再回头看其他语言或框架，你会清楚地知道它们在解决什么问题、替换的是这条线上的哪一环。

层选择为什么适合起步学会后能迁移到
前端Vue模板接近 HTML，学习曲线最平缓，中文文档好React、Svelte：组件 / 状态 / 路由概念相通
后端FastAPI代码简洁，自动生成接口文档，契约「看得见」Django、Spring Boot、Gin：都是「接请求 → 校验 → 业务 → 数据 → 响应」
数据PostgreSQL最主流的关系型数据库之一，SQL 学一次到处能用MySQL 等关系型数据库；本仓库 SQL 学习包
部署Docker（Compose）一条命令把三样东西一起跑起来，环境一致CI/CD、Kubernetes、各类云平台
★

核心要点：这个阶段的目标不是功能多，而是知道每层怎么连、出了问题怎么查。一个只有「增删改查」的待办清单就足够了。

知识点 2每层怎么连：「待办清单」的数据流wire-up · 从点击到入库

以「添加一条待办：买牛奶」为例，看数据如何穿过四层。下面三段代码分别属于前端、后端、部署（看懂即可）：

frontend · Vue：点「添加」时调用后端接口
async function addTodo() {
  const res = await fetch("/api/todos", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ title: newTitle.value }),
  });
  if (!res.ok) { error.value = "添加失败：" + res.status; return; }  // 处理失败分支
  todos.value.push(await res.json());   // 状态一变，列表自动刷新
}
backend · FastAPI：校验、写库、返回
class TodoIn(BaseModel):
    title: str = Field(min_length=1, max_length=100)   # 契约：标题 1–100 个字符

@app.post("/api/todos", status_code=201)
def create_todo(todo: TodoIn, db: Session = Depends(get_db)):
    row = Todo(title=todo.title, done=False)
    db.add(row)
    db.commit()          # 提交事务，数据才真正写进 PostgreSQL
    db.refresh(row)      # 拿到数据库生成的 id
    return {"id": row.id, "title": row.title, "done": row.done}
docker-compose.yml：一条命令启动三件套
services:
  web:                       # 前端：Vue 打包后的静态文件，由 Nginx 提供，并把 /api 转发给后端
    build: ./frontend
    ports: ["8080:80"]
  api:                       # 后端：FastAPI
    build: ./backend
    environment:
      DATABASE_URL: postgresql://app:${DB_PASSWORD}@db:5432/todo   # 主机名是服务名 db，不是 localhost
    depends_on: [db]
  db:                        # 数据库：PostgreSQL
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: ${DB_PASSWORD}   # 密码从 .env 读取，不写死在文件里
      POSTGRES_DB: todo
    volumes: ["pgdata:/var/lib/postgresql/data"]   # 数据卷：容器重建，数据也不丢
volumes:
  pgdata:
环节连接方式约定
浏览器 → 前端服务HTTP，访问 localhost:8080Nginx 提供静态文件
前端 → 后端HTTP + JSON，同域的 /api 路径由 Nginx 转发接口契约（下一个知识点）
后端 → 数据库数据库连接串 DATABASE_URL表结构：todos(id, title, done)
三者之间Docker Compose 创建的内部网络，用服务名互相访问web、api、db 三个服务名
★

核心要点：每两层之间都有一个「接口」：前端和后端之间是 HTTP 契约，后端和数据库之间是连接串和表结构，服务和服务之间是 Compose 网络。问题几乎总是出在这些接缝上。

知识点 3接口文档就是契约contract first · 先约定，再各写各的

FastAPI 会根据代码自动生成 OpenAPI 格式的接口文档（访问 /docs）。这份文档就是前后端之间的合同：前端照着它调用，后端照着它实现。更进一步的做法是契约优先：先把接口定下来，前端用假数据（mock）先开发界面，后端同时实现接口，最后对接。

接口请求成功响应常见失败
GET /api/todos—200 待办列表—
POST /api/todos{"title": "买牛奶"}201 新建的待办（含 id）422 标题为空或超过 100 字
PATCH /api/todos/{id}{"done": true}200 更新后的待办404 id 不存在
DELETE /api/todos/{id}—204 无内容404 id 不存在
!

契约要被尊重：后端想把 title 改名为 name，就必须同步通知前端，或者先兼容两个字段。很多「前端突然显示空白」的事故，根源都是契约被悄悄改了。

Part 2 · 出问题与换零件

02排障与替换

知识点 4出问题先查哪一层：分层排障法debug by layer · 先定位，再修复

出问题时，AI 可以帮你猜原因，但你要先判断问题在哪一层：前端状态、接口契约、后端逻辑、数据库，还是部署环境。按症状找到第一步该看的地方，问题通常就缩小了一大半。

症状先查哪层第一步看哪里
页面白屏前端浏览器 Console 的报错
点了没反应，Network 里没有请求前端事件绑定、按钮是否被禁用、前端校验
请求报 CORS 跨域错误后端 / 网关配置后端是否允许前端的域名，或改为同域反向代理
接口返回 422接口契约响应里的 detail 字段，对照 /docs
接口返回 500后端后端日志里的错误堆栈（traceback）
数据刷新后不见了后端 / 数据库 / 部署事务有没有提交；数据库容器有没有挂数据卷
本地能跑，容器里连不上数据库部署环境连接串里写的是不是 localhost；环境变量有没有传进容器
!

易错：容器里的 localhost 指的是容器自己，不是你的电脑，也不是数据库容器。在 Docker Compose 里要用服务名（如 db）访问其他容器。这是初学者最常踩的部署坑之一。

知识点 5替换一环：换 React / Django / MySQL 会怎样swap a part · 分层与契约的回报

分层和契约的最大回报是：替换一环时，影响被限制在这一环。这也是为什么学会一条线后，再学其他技术会很快——你只是在换掉一个零件。

替换要改哪里不用改哪里注意
Vue → React前端代码后端、数据库、接口契约组件、状态、路由的概念都通用
FastAPI → Django / Spring Boot后端代码前端（只要契约不变）、数据库表新框架要实现完全相同的接口
PostgreSQL → MySQL数据访问层、连接配置前端、接口契约SQL 方言有差异，需要迁移数据
Docker Compose → Kubernetes部署配置应用代码镜像可以直接复用
新增 Redis 缓存后端加缓存逻辑前端、数据库表要处理缓存失效（06 模块）
★

核心要点：如果换一个前端框架还要改数据库，说明分层被打破了。「替换某一环要改多少地方」是检验架构是否健康的好指标。
