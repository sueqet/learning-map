MODULE 05 · 技术全景

后端与 API 框架

产品的「大脑」和「引擎」。

✓本节学习目标

  • 说出后端的职责，以及为什么价格计算、权限检查必须放在后端。
  • 读懂一个 HTTP 请求和响应：方法、路径、请求体、状态码；分清 2xx / 4xx / 5xx。
  • 听到 FastAPI 就知道：它是 Python 的后端 API 框架，特点是自动校验、自动文档、异步，适合 API 和 AI 服务化。
  • 比较 FastAPI、Django、Flask，以及 Spring Boot、NestJS / Express、Go 的性格。
  • 解释同步和异步的区别：为什么「等待」多时异步更划算，而计算密集时它帮不上忙。
Pre-requisites · 前置知识

学完 02 全景地图（请求旅程、接口契约）与 03 编程语言的性格。想动手写一个 FastAPI 接口，可以看 Python 学习包的 21 · FastAPI 入门。

Part 1 · 后端与接口

01后端做什么，怎么被调用

知识点 1后端做什么：规则、鉴权、调数据backend role · 看不见的大脑

后端运行在你控制的服务器上，用户看不见它，但所有关键规则都在这里执行。原因很简单：前端代码运行在用户的浏览器里，用户可以随意修改；只有后端是可信的。

职责例子为什么必须在后端
业务规则计算订单总价、判断优惠券能不能用、扣库存放在前端，用户改一行代码就能把价格改成 0.01
身份验证与权限检查登录令牌、判断能不能看别人的订单前端的权限判断只是「隐藏按钮」，挡不住直接调接口
数据读写查询、写入数据库，开启事务数据库密码不能出现在浏览器里
调用第三方支付、短信、地图、大模型 API第三方的密钥必须保密
后台任务发邮件、生成报表、定时清理数据用户关掉网页后任务仍要继续
★

核心要点：前端校验是为了体验（及时提示用户填错了），后端校验是为了安全和正确。两者都要有，但只有后端那一道是不能省的。

知识点 2HTTP 与 REST API：请求、响应、状态码HTTP · 前后端的通用语言

前端和后端用 HTTP 协议对话。一次对话就是「请求 + 响应」。最常见的接口风格是 REST：把数据看成「资源」（例如 /items），用不同的方法表示对它做什么。

方法含义例子
GET查询（不改数据）GET /items/42 查 42 号商品
POST新建POST /orders 创建订单
PUT / PATCH整体替换 / 部分修改PATCH /items/42 改价格
DELETE删除DELETE /items/42
状态码意思谁的问题
200 / 201成功 / 创建成功—
400 / 422请求格式不对 / 字段校验失败调用方：参数传错了
401没登录（不知道你是谁）调用方：缺少或过期的登录令牌
403登录了，但没权限调用方：越权访问
404资源不存在调用方：地址或 id 不对
429请求太频繁，被限流调用方：慢一点
500服务器内部错误服务端：代码出 bug 了
502 / 503 / 504网关拿不到后端的正常响应 / 服务暂不可用 / 后端超时服务端或基础设施
!

其他接口风格：REST 最常见，但还有 GraphQL（前端按需指定要哪些字段）、gRPC（服务之间高性能调用，多用于微服务内部）、WebSocket（长连接，实时聊天、协作）。知道它们存在、各自解决什么问题即可。

Part 2 · 主流后端框架

02FastAPI 与它的同行们

知识点 3FastAPI：Python 的现代 API 框架FastAPI · 主打快的速食店

FastAPI 是一个用 Python 写后端 API 的框架。它的核心优势是：你用 Python 的类型标注声明「参数长什么样」，它就自动校验数据、自动生成可交互的接口文档；同时对异步支持很好，在 Python 框架里性能靠前。可以把它想象成一家「主打快的速食店」：出餐快，菜单（接口文档）还自动帮你印好了。

main.py —— 一个最小的 FastAPI 接口（看懂即可）
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):        # 声明请求体长什么样
    name: str
    price: float              # 传 "abc" 会被自动拒绝，返回 422

@app.post("/items", status_code=201)
async def create_item(item: Item):
    return {"id": 1, "name": item.name, "price": item.price}

# 运行：fastapi dev main.py
# 打开 http://127.0.0.1:8000/docs 就能看到自动生成的接口文档，还能直接点按钮试调用
适合不太适合主要代价
前后端分离项目的 API、AI 模型服务化（把模型包装成接口）、高并发 I/O 型接口、微服务中的单个服务需要现成管理后台和完整用户系统的内容型网站（Django 更省事）；纯 CPU 密集的计算只管 API 这一块，数据库、权限、后台等要自己挑库组合；项目结构需要自己定规范
★

核心要点：FastAPI 的「快」包含两层：开发快（类型即校验即文档）和I/O 并发好（异步）。它不会让 CPU 计算变快。

知识点 4Django 与 Flask：全家桶 vs 自助餐Django · Flask · Python 三兄弟

Python 后端最常见的是三个框架。它们的区别不在「谁更好」，而在自带多少东西：

DjangoFlaskFastAPI
比喻拎包入住的写字楼（全家桶）自助餐（极简，自己挑）速食店（专做 API）
自带ORM、管理后台、用户认证、表单、模板只有路由和请求处理，其余靠插件路由、数据校验、接口文档、异步
适合带管理后台的业务系统、内容网站、需要快速搭完整功能小工具、简单服务、想完全掌控结构前后端分离的 API、AI 服务、高并发接口
代价较重，约定多，灵活度低一些项目大了要自己定规范，容易各写各的非 API 的功能要自己组合
!

不是非此即彼：Django 也能做 API（配合 Django REST Framework 等），FastAPI 也能接 ORM（如 SQLAlchemy、SQLModel）。选择时问自己：我需要它「自带」哪些东西？

知识点 5Spring Boot、NestJS / Express、Goother stacks · 其他语言的主流框架

每种语言都有自己的主流后端框架。选框架，基本等于选这门语言的生态：

框架语言性格适合
Spring BootJava / Kotlin企业级「压舱石」，事务、安全、监控一应俱全；Spring Cloud 提供微服务全家桶金融、电商、政企等大型系统
NestJSTypeScript结构严谨、分层清晰的 Node.js 企业级框架想用 TS 统一前后端的中大型团队
ExpressJavaScript / TS极简、灵活，Node.js 生态最老牌小服务、原型、学习
Gin / Echo / 标准库Go轻量、高性能，Go 社区偏爱「少依赖」高并发 API、微服务、网关
ASP.NET CoreC#微软生态的高性能企业框架.NET 技术栈的企业
Laravel / RailsPHP / Ruby约定优于配置，开发效率高快速建站、中小型业务
★

核心要点：这些框架都在做同样的事：接请求 → 校验 → 跑业务逻辑 → 读写数据 → 回响应。学会了一个的概念，换另一个只是语法和约定不同。

知识点 6同步 vs 异步：I/O 多时异步更划算sync vs async · 等待时去干别的

想象一个服务员：同步模式下，他把菜单交给后厨后就站在窗口傻等，菜出来了才去接下一桌；异步模式下，他下完单就去招呼别的桌，菜好了再回来端。后端大部分时间都在「等」——等数据库、等第三方接口、等大模型返回。这种 I/O 密集的场景，异步能让同样的机器服务多得多的请求。

场景瓶颈异步有没有用常见做法
调大模型 API、查数据库、调第三方接口等待（I/O）很有用async 接口、连接池
图片压缩、视频转码、本地跑模型推理CPU 计算帮不上，还会卡住其他请求放进后台任务队列（如 Celery）、多进程或单独的服务
发邮件、生成报表这类不需要立刻返回的事耗时长部分有用先返回「已受理」，后台慢慢做
!

易错：在 async 接口里直接做大量 CPU 计算（或调用不支持异步的阻塞库），会卡住整个事件循环，所有请求一起变慢。这是 FastAPI 新手最常见的性能坑之一。
