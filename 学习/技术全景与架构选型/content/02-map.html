MODULE 02 · 技术全景

全景地图：软件产品的分层

把所有名词放进一张分层地图。

✓本节学习目标

  • 说出软件产品的四层（前端、后端、数据、基础设施），以及每层负责什么。
  • 描述一次请求从「点按钮」到「看到结果」的完整旅程，并指出每一步可能出什么问题。
  • 区分语言、框架、库、架构模式、工具、平台这几类名词。
  • 解释 API 与接口契约的作用，以及前后端为什么能靠它分开开发。
  • 听到一个新名词时，用「三问」快速给它定位。
Pre-requisites · 前置知识

学完 01 学习目标。知道「网页是在浏览器里打开的」「数据存在某个服务器上」就够了。

Part 1 · 一栋楼的结构

01分层与数据流

知识点 1四层：前端、后端、数据、基础设施layers · 地图的骨架

一个软件产品可以看成一家餐厅：前厅（菜单、服务员）是用户直接接触的部分；后厨按菜谱做菜，顾客看不见但所有规则都在这里执行；仓库和冰箱存放食材；水电、燃气、配送、消防保证整家店能开门营业。对应到软件，就是下面四层。

前端层FRONTEND把界面画出来，响应点击和输入。HTML / CSS / JavaScript、Vue、React、小程序、App 界面。
后端层BACKEND业务规则、身份验证、调用数据库。Python + FastAPI、Java + Spring Boot、Go、Node.js。
数据层DATA持久化存储与查询。PostgreSQL / MySQL、Redis、MongoDB、向量数据库。
基础设施层INFRA / DEVOPS把代码安全、自动地送上线并保持运行。Git、Docker、CI/CD、Kubernetes、云服务、监控。
层负责什么用户看得见吗本学习包
前端层展示、交互、调用后端接口看得见04 前端层
后端层业务规则、鉴权、编排数据看不见，但规则都在这里05 后端与 API 框架
数据层存、取、保证数据不丢不乱看不见06 数据层
基础设施层打包、部署、扩缩容、监控看不见，挂了大家都看得见08 基础设施与 DevOps
★

核心要点：绝大多数技术名词都能放进这四层。放不进的，通常是贯穿各层的组织方式（单体、微服务、分层架构，见 07 架构模式）或横切关注点（安全、监控、成本，见 09、10 模块）。

知识点 2一次请求的旅程（数据流）request journey · 排障的路线图

以「在购物网站点下单」为例，一次请求会依次穿过所有层，再原路返回。这条路线就是数据流。它是理解系统最重要的一张图：设计时用它检查每一步的职责，出问题时沿着它逐段排查。

#发生了什么所在层典型技术可能出的问题
1用户点「下单」，前端组件收集商品和数量前端Vue / React按钮重复点击、表单没校验
2浏览器发出 HTTPS 请求网络DNS、TLS 证书断网、证书过期、跨域被拦
3网关 / 反向代理接住请求，转给后端基础设施Nginx、云负载均衡限流、后端全挂时报 502 / 504
4后端框架匹配接口、校验参数、检查登录后端FastAPI、Spring Boot参数不合法（422）、没登录（401）
5业务逻辑：查库存、算价格、生成订单后端你写的业务代码逻辑 bug、超卖、调用第三方超时
6读写数据库和缓存数据PostgreSQL、Redis慢查询、锁等待、缓存是旧数据
7后端返回 JSON 响应后端 → 前端HTTP 状态码 + JSON500 服务器错误、字段名和前端约定的不一样
8前端更新状态，界面自动刷新前端Vue / React 的状态驱动没处理错误，页面卡在「加载中」
★

核心要点：出问题时，先确定请求走到了第几步。浏览器开发者工具的 Network 面板能告诉你：请求发出去了吗？状态码是多少？响应内容是什么？这一步就能把问题缩小到某一层。

Part 2 · 名词与连接

02给名词分类，看清层与层怎么连

知识点 3名词分类：语言 / 框架 / 库 / 架构 / 工具 / 平台noun types · 先分类再理解

之前容易混乱，是因为把不同种类的名词放在一起比较。「Python 和 FastAPI 哪个好」就像问「水泥和户型图哪个好」，它们根本不是同一类东西。先分类，很多问题自然就清楚了。

类别是什么比喻例子
编程语言写程序用的语言，决定语法和基本能力砖头和水泥Python、Java、Go、JavaScript、TypeScript、Rust
运行时让某种语言的程序跑起来的环境施工现场Node.js（让 JS 跑在服务器上）、JVM、CPython
框架预先搭好的骨架，你往里填业务代码，框架调用你的代码精装房的框架结构Vue、FastAPI、Django、Spring Boot、NestJS
库一组现成的函数或组件，你主动调用它工具箱React（官方自称库）、requests、NumPy、Axios
架构模式系统各部分怎么组织、怎么协作户型和公司组织架构单体、微服务、分层架构、事件驱动
工具帮助开发、构建、部署的软件施工工具Git、Docker、VS Code、npm、pip
平台 / 服务别人运营好、你直接使用的场地或能力场地和物业GitHub、阿里云 / AWS、Vercel、托管数据库
!

不必较真：React 自称「库」，Vue 自称「渐进式框架」，社区常常把它们都叫框架。边界有些模糊没关系，重要的是知道它们都在前端层、都解决「界面怎么搭」的问题。

知识点 4层与层之间靠什么连：API 与接口契约API contract · 两边的约定

API（Application Programming Interface，应用程序接口）是一层对另一层提供服务的「窗口」。前后端之间最常见的是 Web API：前端按约定发请求，后端按约定回数据。这份约定就叫接口契约，像餐厅的点菜单：顾客只看菜单点菜，不需要知道后厨怎么做。

一份接口契约长什么样（看懂即可）
POST /api/v1/orders            ← 方法 + 地址（带版本号 v1）
Authorization: Bearer xxxxx    ← 要求先登录
{ "product_id": 42, "quantity": 2 }        ← 请求体：字段名和类型

201 Created                    ← 成功：状态码
{ "order_id": 1001, "status": "pending", "total": 199.0 }

422 Unprocessable Content      ← 失败：参数不合法（例如 quantity 是负数）
401 Unauthorized               ← 失败：没登录
契约要素例子两边不一致会怎样
地址和方法POST /api/v1/orders404 找不到接口，或 405 方法不允许
请求字段与类型quantity 是正整数后端校验失败返回 422，或者更糟：错误数据入库
响应字段order_id、status前端读不到字段，页面显示空白或 undefined
状态码与错误格式201 成功、422 参数错、401 未登录前端不知道该提示什么，只能显示「出错了」
鉴权要求需要登录令牌接口被未授权的人调用
版本/v1、/v2后端一改字段，所有老版本 App 全部出错
★

核心要点：契约稳定，前后端就能各自独立开发、独立替换：后端从 Django 换成 FastAPI，只要契约不变，前端无感。契约要改，就加版本号，给调用方迁移时间。契约里不包含后端用什么语言、什么数据库，那些是实现细节。

知识点 5听到新名词，先问「它在哪一层」locate any term · 三问法

以后遇到没听过的技术名词，不要急着搜教程，先用三个问题给它定位：

  1. 它是哪一类？语言、框架、库、架构模式、工具，还是平台？
  2. 它在哪一层？前端、后端、数据、基础设施，还是贯穿各层？
  3. 它解决什么问题？替换它会影响谁？它的代价是什么？
名词哪一类哪一层解决什么问题
Nginx工具 / 服务软件基础设施（接入）反向代理、负载均衡、托管静态文件
Kafka中间件（消息队列）后端与数据之间服务之间异步传消息，削峰、解耦
Next.js框架（基于 React）前端（也能写简单后端）服务端渲染、首屏速度、SEO
Tailwind CSSCSS 框架前端用现成的样式类快速美化页面
★

核心要点：三问答完，你就已经知道它和你已有知识的关系。剩下「具体怎么用」的部分，正是可以交给 AI 和文档的操作细节。
