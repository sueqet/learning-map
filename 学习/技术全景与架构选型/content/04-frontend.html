Part 1 · 前端的地基

01三件套与框架

知识点 1HTML / CSS / JavaScript 三件套fe basics · 结构、样式、交互

前端层的工作是把界面画出来，并让它能响应用户的操作。不管用什么框架，浏览器最终只认三样东西：HTML 管结构，CSS 管样式，JavaScript 管交互。

一个按钮的三件套（看懂即可）
<button id="buy">加入购物车</button>            ← HTML：页面上有一个按钮

#buy { background: green; color: white; }      ← CSS：按钮是绿底白字

document.querySelector("#buy")                  ← JavaScript：点击后做点什么
  .addEventListener("click", () => { /* 调后端接口 */ });
技术负责比喻出问题时的表现
HTML页面结构和内容房子的骨架和房间内容缺失、结构错乱
CSS颜色、字体、布局、动画装修和家具摆放错位、手机上挤成一团
JavaScript交互、调接口、更新页面水电和开关点了没反应、白屏、控制台报错
★

核心要点：Vue、React、Tailwind 等工具最终都会产出 HTML / CSS / JavaScript。按 F12 打开浏览器开发者工具，Elements 看结构和样式，Console 看报错，Network 看接口请求，这是前端排障的三个入口。

知识点 2为什么需要框架：组件化、声明式、状态驱动why framework · 数据变了界面自动变

以前写网页要手动操作页面元素：数量加 1，就去找到数量那个格子改掉，再找到总价改掉，再找到购物车角标改掉……页面一复杂，总有地方忘了改，界面和真实数据就对不上了。Vue / React 的核心思路是：

★

你只描述「数据是这样时，界面应该长什么样」；数据变了，框架自动把界面更新到对应的样子。

概念意思带来的好处
组件化把按钮、表单、导航栏拆成独立的小组件，像积木一样拼页面复用、分工、单独测试
声明式渲染写「长什么样」，而不是一步步命令浏览器「怎么改」代码更短，更不容易漏改
状态驱动界面 = 状态的函数；改状态，界面跟着变界面和数据永远一致
生态配套路由、状态管理、构建工具都有成熟方案不用从零造轮子
同一个计数器：Vue 与 React 写法（看懂即可）
<!-- Vue：模板接近 HTML -->
<button @click="count++">点了 {{ count }} 次</button>

// React：用 JSX 在 JavaScript 里写界面
const [count, setCount] = useState(0);
return <button onClick={() => setCount(count + 1)}>点了 {count} 次</button>;

知识点 3Vue、React、Svelte、Angular 怎么比framework comparison · 性格差异

先纠正一个常见误解：Vue 和 React 不是编程语言，也不是后端架构，它们是构建网页界面的工具。JavaScript 是砖头和水泥，Vue / React 是「盖界面的工具箱」，单体 / 微服务管的是后端怎么组织。四个主流选项的能力其实差不多，差别在性格：

VueReactSvelteAngular
定位渐进式框架，官方配套完整UI 库，只管视图，其余靠生态组合编译时框架，运行时代码极少企业级「全家桶」
上手模板接近 HTML，最平缓要理解 JSX 和函数式思路，中等语法极简，平缓强制 TypeScript、概念多，最陡
灵活度约定多，开箱即用非常灵活，方案多但选择也多简洁，约定适中规范严格，统一性强
生态与招聘国内使用极广，中文文档友好全球生态最大，招聘面最广，可延伸到移动端生态较小大型企业、外企较多
适合快速开发、中小型项目、希望官方方案统一大型复杂应用、跨端、喜欢自由组合小工具、对体积敏感的页面大团队长期协作的企业应用
!

怎么选：能力上它们都够用，真正的决定因素是团队熟悉哪个、招人容易不容易、需不需要跨端。已经用 Vue 跑得很好的项目，没有必要因为「React 更流行」而重写。

Part 2 · 页面怎么送到浏览器

02渲染方式与生态

知识点 4渲染方式：SPA / SSR / SSGrendering · 谁来生成 HTML、什么时候生成

同样是 Vue / React 写的页面，HTML 由谁、在什么时候生成，会直接影响首屏速度、搜索引擎能不能抓到内容（SEO）、服务器压力。三种主流方式：

方式怎么工作优点缺点适合
SPA 单页应用浏览器先下载一个空壳和 JS，由 JS 在浏览器里生成页面；之后切换页面不刷新切换流畅、服务器只需提供 API首屏慢、搜索引擎抓取不友好后台管理系统、登录后才能用的工具
SSR 服务端渲染每次请求，服务器先把页面渲染成完整 HTML 再发出，浏览器拿到就能看首屏快、利于 SEO、内容实时服务器压力大，部署更复杂电商商品页、新闻、需要 SEO 的动态内容
SSG 静态生成构建时就把所有页面生成好 HTML，放到 CDN 上最快、最便宜、最稳内容变了要重新构建博客、文档站、官网
★

核心要点：三者可以混用。Next.js、Nuxt 允许同一个网站里：首页 SSG、商品页 SSR、个人中心 SPA。还有一种折中叫 ISR（增量静态再生成）：静态页面过一段时间自动重新生成。

知识点 5Next.js / Nuxt、UI 库与跨端方案ecosystem · 围绕框架的工具

框架之外，前端还有一圈配套工具。记住它们各自解决什么问题就够了：

需求常见方案一句话
需要 SSR / SSG、首屏和 SEONext.js（React）、Nuxt（Vue）、SvelteKit、Astro基于 UI 框架的「全栈框架」，还能写简单的后端接口
快速美化页面Tailwind CSS、BootstrapCSS 框架：用现成的样式类拼出界面
现成的按钮、表格、弹窗Element Plus（Vue）、Ant Design（React）、shadcn/uiUI 组件库：后台系统几小时就能搭出雏形
开发时实时预览、打包上线Vite、webpack构建工具：把源码打包成浏览器能高效加载的文件
一套代码做 iOS + AndroidReact Native、Flutter（Dart 语言）跨端框架：省人力，复杂动画和原生能力略逊
微信等小程序原生小程序、uni-app（Vue 写法）、Taro（React 写法）国内特有的重要「前端」平台
桌面应用Electron、Tauri用网页技术做桌面软件，VS Code 就是 Electron 做的
!

别追新：前端工具更新极快，名字两三年就换一批。抓住不变的四个概念——组件、状态、路由、请求接口，换任何框架都能很快上手。
