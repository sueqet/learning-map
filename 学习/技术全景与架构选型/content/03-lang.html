MODULE 03 · 技术全景

编程语言的性格

每种语言都有自己的「性格」。

✓本节学习目标

  • 解释「语言不决定架构，但影响倾向」：哪些语言特性会影响系统设计。
  • 用一个比喻 + 一句话说出 Java、Python、Go、JavaScript / TypeScript、Rust 各自的性格。
  • 说出每种语言适合和不太适合的场景，以及它的主要代价。
  • 按「场景硬约束 → 团队 → 生态 → 性能 → 招聘」的顺序做语言选择，避免「为了性能盲目换语言」。
Pre-requisites · 前置知识

学完 02 全景地图，知道「语言、框架、运行时」是不同类别的名词。不需要会写任何一种语言。

Part 1 · 语言和架构的关系

01先看语言影响什么

知识点 1语言不决定架构，但影响倾向language vs architecture · 设计哲学

用 Python 可以写微服务，用 Go 也可以写单体，语言本身不决定架构。但每种语言的设计哲学不同：有的追求开发速度，有的追求运行性能，有的追求安全。这些取舍会让某些系统写起来更顺手，所以语言会影响倾向。可以把语言想成不同性格的公司：同样能做生意，擅长的生意不一样。

语言特性有哪些做法会影响什么
执行方式编译成机器码（Go、Rust）/ 虚拟机（Java）/ 解释执行（Python）/ JIT 引擎（JavaScript）运行速度、启动速度、部署形态（一个文件还是要装环境）
并发模型线程（Java）、轻量协程（Go 的 goroutine）、事件循环 + async（JavaScript、Python）同时能扛多少连接、写并发代码难不难
类型系统静态类型（Java、Go、Rust、TypeScript）/ 动态类型（Python、JavaScript）写起来快不快 vs 大团队重构时安不安心
内存管理垃圾回收 GC（Java、Go、Python、JS）/ 编译期所有权检查（Rust）/ 手动（C）内存占用、偶发停顿、内存安全
生态库、框架、工具、社区、招聘市场能不能快速找到现成方案和合适的人
★

核心要点：选语言，很大程度上是在选生态和团队。语法差异反而是最不重要的。

Part 2 · 五种主流语言

02五种性格

知识点 2Java：稳重的「大企业」Java · 一次编写，到处运行

Java 程序运行在 JVM（Java 虚拟机）上，追求「一次编写，到处运行」。它有近三十年的积累，生态极度成熟，强类型和严格的工程规范适合几十上百人长期维护同一个系统。银行、保险、电商、政企的核心系统大量使用 Java，主流框架是 Spring Boot。

适合不太适合代表框架 / 场景主要代价
复杂业务、需要事务管理、长期维护的大型企业系统小脚本、快速原型、对启动速度和内存极敏感的场景Spring Boot、Spring Cloud；金融核心系统、大型电商后台；Android 历史上的主力语言启动较慢、内存占用较高、代码相对啰嗦
!

别用老印象判断：新版本 Java 一直在改进，例如 Java 21 的虚拟线程让高并发写法简单了很多；同在 JVM 上的 Kotlin 写法更简洁，可以复用整个 Java 生态。

知识点 3Python：灵巧的「多面手」Python · 开发速度优先

Python 语法接近自然语言，开发速度极快。它在数据分析、AI、快速原型上几乎无可替代：NumPy、Pandas、PyTorch 等库让它成了 AI 的主力语言。后端方向有 FastAPI、Django，运维和测试也常用它写自动化脚本。

适合不太适合代表框架 / 场景主要代价
AI / 数据、API 服务、自动化脚本、快速验证想法纯 Python 写的计算密集代码、对延迟极敏感的核心链路、浏览器端FastAPI、Django、Flask；PyTorch、Pandas；各类运维脚本原生执行慢；GIL 限制多线程并行；动态类型在大项目里容易藏 bug
★

为什么「慢」的 Python 能统治 AI？因为真正耗时的矩阵计算由底层的 C / C++ / CUDA 完成，Python 只负责「指挥」。所以性能问题常靠调用底层库、多进程、异步 I/O解决。另外，Python 3.13 起提供了实验性的无 GIL 版本，并在后续版本中逐步成熟，但大多数生产环境仍以默认版本为主。

知识点 4Go：高效的「现代工厂」Go · 为高并发网络服务而生

Go 由 Google 设计，目标是让写高并发网络服务变简单。它的 goroutine 是极轻量的协程，一台机器可以同时跑成千上万个；程序编译成单个可执行文件，启动快、内存小、部署简单。所以 Go 成了云原生基础设施的热门语言：Docker、Kubernetes、Prometheus 都是用 Go 写的。

适合不太适合代表框架 / 场景主要代价
微服务、API 网关、云平台组件、命令行工具、高并发后端业务规则特别复杂的领域建模、AI 训练与数据分析Gin、Echo、标准库 net/http；Docker、Kubernetes、etcd语言刻意朴素，表达复杂业务不如 Java 丰富；错误处理写法啰嗦；AI / 数据生态弱
★

核心要点：Go 的「简单」是一种取舍：语言特性少，团队代码风格统一、好读好维护；代价是有些抽象写起来更长。

知识点 5JavaScript / TypeScript：无处不在的「连接器」JS / TS · 浏览器的母语

JavaScript 是浏览器原生支持的编程语言，任何有丰富交互的网页都离不开它，是 Web 前端事实上的标准。有了 Node.js 运行时，它也能写后端，于是一个团队可以前后端用同一种语言。TypeScript 是 JavaScript 的超集，给它加上静态类型，大中型项目基本都用 TypeScript。

JavaScript 的历史包袱（看个热闹）
"1" + 1      // "11"  ← 数字被悄悄转成了字符串
"5" - 2      // 3     ← 这次字符串又被转成了数字
0.1 + 0.2    // 0.30000000000000004（多数语言的浮点数都这样）

// TypeScript 在写代码时就能拦住类型不匹配：
function total(price: number, qty: number) { return price * qty; }
total("9.9", 2);   // ✗ 编译报错：string 不能传给 number
适合不太适合代表框架 / 场景主要代价
所有网页前端、全栈小团队、实时应用（聊天、协作）、跨端（桌面 Electron、移动 React Native）CPU 密集计算（单线程事件循环会被卡住）、对类型安全要求极高却不用 TS 的大项目Vue、React、Next.js；后端 Express、NestJS历史遗留的「古怪」设计容易埋 bug；npm 依赖多，供应链风险需要管理
!

易错：Java 和 JavaScript 除了名字像，几乎没有关系。JavaScript 的名字是当年的营销决定。

知识点 6Rust：极致的「安全狂人」Rust · 不牺牲性能的内存安全

Rust 通过独特的所有权和借用检查，在编译期就排除空指针、数据竞争等一大类内存错误，而且不需要垃圾回收，性能接近 C / C++。代价是规则多、学习曲线陡，新手经常和编译器「搏斗」。很多新一代开发工具用 Rust 重写后速度大幅提升，例如 Python 生态里的 Ruff、uv、Polars。

适合不太适合代表场景主要代价
对安全和速度都有极致要求的系统编程：浏览器引擎、数据库、网络代理、操作系统组件、WebAssembly需求天天变的业务后台、团队里没人会 Rust 的项目、快速原型开发者工具链、高性能基础组件；Linux 内核也已接纳 Rust 编写的部分驱动学习曲线陡、编译慢、招聘难、业务开发速度慢
★

核心要点：Rust 适合「写一次、跑很久、不能出错、要很快」的底层组件，而不是「需求每周都改」的业务代码。

Part 3 · 怎么选

03选语言的顺序

知识点 7怎么选语言：团队、生态、场景choosing · 先硬约束后偏好

选语言时按下面的顺序问，前面的问题优先级更高：

  1. 场景有没有硬约束？浏览器里只能用 JavaScript / TypeScript；iOS 首选 Swift；Android 首选 Kotlin；训练 AI 模型几乎只能用 Python。
  2. 团队已经会什么？3 个人都熟 Python，就别为了「更快」改用 Rust。
  3. 生态里有没有现成方案？要接支付、做报表、调大模型，看哪个语言的库最成熟。
  4. 性能真的是瓶颈吗？大多数业务系统慢在数据库和网络，不在语言本身。
  5. 以后好不好招人？小众语言写的系统，人员一走就没人能维护。
其他常见语言一句话性格典型场景
C / C++贴近硬件的「老匠人」，最快但最容易踩内存坑操作系统、游戏引擎、嵌入式、高性能计算
C#微软生态的「全能选手」.NET 企业应用、Windows 桌面、Unity 游戏
Kotlin更现代的 Java 兄弟Android App、JVM 后端
Swift苹果生态的官方语言iOS / macOS App
PHP老牌建站语言，部署简单WordPress、传统网站、Laravel 后端
SQL和数据库说话的语言几乎所有方向都要会，本仓库有专门的 SQL 学习包
!

常见误区：「服务慢，用 Go / Rust 重写吧」。重写前先测量：如果 90% 的时间花在等数据库，换语言几乎没用，加索引、加缓存、改查询才有用。
